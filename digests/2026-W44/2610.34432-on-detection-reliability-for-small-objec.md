# On Detection Reliability for Small Object Segmentation

**Authors:** Olivier Rukundo

**arXiv:** [2610.34432](https://arxiv.org/abs/2610.34432)

**Categories:** cs.CV

**Submitted:** 2026-10-25

**Relevance:** 6/10 — matched: Onboard object detection from a moving UAV

## TL;DR
This paper asks a narrow but practically important question: if you detect small objects (adenovirus particles in electron-microscopy images) with one model and segment them with another, is it safe to only segment inside the detector's predicted boxes? Using centroid-matching between predicted masks and ground truth, the authors find that for a YOLO26 detector/segmentor pair, over half of correctly-matched segmentation predictions fall outside the predicted boxes or have no match at all, while Mask R-CNN (which produces boxes and masks jointly) is far more self-consistent. The takeaway: cropping segmentation to detector boxes is risky when detection and segmentation come from separate models.

## First-principles breakdown

**The problem.** In many vision pipelines, you first run a detector to find rough locations of objects (bounding boxes), then run a segmentor only inside those boxes to get precise pixel masks — this saves compute and is common practice (e.g., SAM prompted by boxes). This only works if the detector's boxes reliably cover every object the segmentor would otherwise find. If the detector misses an object or draws a box that doesn't fully contain it, the segmentor never gets a chance to produce a mask for it there, creating a false negative that isn't the segmentor's fault — it's inherited from the detector.

**Why prior approaches don't answer this.** Standard metrics like detection precision/recall or segmentation IoU describe each model in isolation. Precision tells you "of the boxes predicted, how many were correct," not "did every real object get a usable box." IoU/Dice tell you how well masks overlap ground truth overall, but not whether a *specific* predicted mask's location agrees with what the detector proposed. Prior work (e.g., BREPS, SAM-box-prompt studies) looked at how sensitive segmentation *quality* is to box prompts, or built pipelines that lean on detector boxes as prompts — but none directly measured the spatial agreement between an independently-run segmentor's output and an independently-run detector's output, which is the actual question when deciding whether to gate segmentation by boxes.

**The method, step by step.**
1. Each ground-truth object is a connected blob in a binary mask; its centroid is computed via image moments (basically the average x,y of all foreground pixels).
2. Each predicted mask (from the segmentation model) is also reduced to a centroid.
3. Predicted mask centroids are matched to ground-truth object centroids by solving an optimal assignment problem (minimize total distance, via the Jonker-Volgenant algorithm — essentially the standard "bipartite matching" trick used for tracking/detection evaluation).
4. For each matched pair, check: is the predicted mask's centroid inside at least one of the detector's predicted bounding boxes?
   - **Inside match**: centroid falls within a predicted box — detector and segmentor agree on location.
   - **Outside match**: predicted mask exists and matches a real object, but its centroid falls outside every predicted box — if you'd restricted segmentation to boxes, you'd have missed this correct finding.
   - **No match**: the ground-truth object has no corresponding predicted mask at all (a segmentation miss, independent of boxes).
5. Before any of this, they sanity-checked their own annotations: for 71 reference objects, do bounding-box centers and mask centroids roughly coincide (within 5 pixels) and are mask centroids contained in their own boxes? (Yes, ~97–100%, confirming annotations are internally consistent, so later mismatches aren't just annotation noise.)
6. This full analysis is run twice: once using YOLO26x (detector) + YOLO26x-Sem (segmentor) as two separate models, and once using Mask R-CNN, which outputs boxes and masks from the *same* model/forward pass.

**Results in plain terms.** With the two independent YOLO models, only ~48% of matched predicted masks landed inside a predicted box; ~11% landed outside all boxes (would be wrongly discarded if segmentation were box-gated); ~41% had no matching prediction at all (a separate segmentation-quality issue). With Mask R-CNN, 97% were inside, 0% outside, 2% unmatched — essentially self-consistent because the box and mask come from the same inference.

## Key insights

- **Genuinely new/useful**: A simple, concrete diagnostic (centroid-matching + inside/outside/no-match categorization) for auditing whether a detect-then-crop-segment pipeline is safe, rather than just reporting detection and segmentation metrics separately. This is a useful methodological contribution even though it's simple — it isolates a failure mode (detector-induced false negatives in segmentation) that aggregate metrics hide.
- **Core finding supported by evidence**: When detection and segmentation are two separate models (YOLO26x + YOLO26x-Sem), restricting segmentation to predicted boxes would discard a nontrivial fraction (11.27% outside + implicitly some of the 40.85% unmatched would be unresolvable by cropping) of otherwise-correct segmentation predictions. This is a real, measured result on their dataset.
- **Secondary finding supported by evidence**: A joint detect-and-segment model (Mask R-CNN) is far more self-consistent (97% inside) simply because box and mask derive from one inference pass — this is more a structural/architectural observation than a novel discovery, but it's demonstrated empirically here.
- **What's claimed vs. what's shown**: The paper explicitly frames its results as "preliminary" and limited to one small dataset (71 objects, 32 test patches) and one object type (adenovirus in TEM images). The authors do NOT claim this generalizes broadly — they call for "matching-sensitivity analysis and evaluation on broader datasets" before generalizing. So the insight "box-gated segmentation is risky" is well-supported *for this specific setup*, but its generality is an open question the authors themselves flag.

## Caveats — stated and inferred

- **Preliminary / single dataset, small N**: stated. The authors repeatedly call findings "preliminary" and note only 71 reference objects across 32 test patches; they explicitly say broader-dataset evaluation is needed before generalizing.
- **Single object type/domain**: inferred. All experiments use adenovirus particles in TEM microscopy images — a narrow, specialized imaging domain with its own object size/density/contrast characteristics; results may not transfer to natural images or other small-object tasks (e.g., aerial imagery, general small-object COCO benchmarks).
- **No matching-sensitivity analysis**: stated. The authors explicitly note that centroid-based matching is a specific design choice and that "matching-sensitivity analysis... are needed before generalizing the findings" — i.e., they haven't tested whether a different matching rule (e.g., IoU-based matching, different distance thresholds) would change the conclusions.
- **Centroid-based matching is a strong simplifying assumption**: inferred. Using centroid distance/containment rather than mask overlap (IoU) to decide "inside/outside" is simpler but could misclassify cases where a large or oddly-shaped mask's centroid falls outside a box even though most of its area overlaps the box, or vice versa. This isn't tested against an IoU-based alternative.
- **Comparison between YOLO branch and Mask R-CNN isn't fully apples-to-apples**: stated (indirectly). The paper itself notes "direct detection comparisons with Mask R-CNN require harmonized matching protocols," and that Mask R-CNN's precision/recall were computed via centroid matching while YOLO26's came from its own detector evaluation procedure — a methodological inconsistency acknowledged in a table note.
- **No held-out/external test set**: inferred. Train/val/test splits (87/26/32 patches) come from one dataset (SSP, derived from one TEM virus dataset); no cross-dataset or cross-domain validation is reported.
- **"No matched segmentation" conflates two different failures**: stated. The authors clarify that "no matched segmentation" doesn't mean "no segmentation" — the model may have produced masks that simply failed the matching criterion — so this 40.85%/2.82% category muddles true misses with matching-criterion artifacts, which they flag but don't fully disentangle.
- **No ablation on detection/segmentation confidence thresholds**: inferred. Thresholds (0.25 detection confidence, 0.50 foreground probability) are fixed without sensitivity analysis; varying these could change box coverage and thus the inside/outside/no-match proportions substantially.
- **Qualitative figures appear illustrative, not systematically sampled**: inferred. Figure 6's examples are described as "representative," with no indication of how many such cases were manually reviewed or how they were selected, raising a mild cherry-picking risk for the qualitative portion.
