# WildDepth-v2: A Synchronized RGB--LiDAR--Radar Dataset and Benchmark for Metric Depth, Motion, and Tracking of Wildlife

**Authors:** Muhammad Aamir, Sangyun Shin, Naoya Muramatsu, Matthew Wijers, Amir Patel, Andrew Loveridge, Andrew Markham

**arXiv:** [2610.31123](https://arxiv.org/abs/2610.31123)

**Categories:** cs.CV

**Submitted:** 2026-10-22

**Relevance:** 9/10 — matched: Metric and temporally-consistent monocular depth

---

## TL;DR
WildDepth-v2 extends a prior RGB-LiDAR wildlife dataset with the first synchronized RGB-LiDAR-4D-imaging-radar recordings of animals (37 sequences, 19,716 frames), a frozen hidden benchmark, and new tasks for metric depth, motion, and 3D tracking. The core finding is that cheap imaging radar, used as an object-level (not per-pixel) calibration anchor, can correct monocular depth almost as well as LiDAR and cuts distance-sampling bias from -13% to -2%, while its Doppler channel — transferred onto LiDAR — yields denser motion masks and a usable (if biased) radial-speed signal. The paper is explicit about where radar fails: a ~1.8m vertical extrinsic error rules out per-pixel radar depth, and Doppler underestimates speed by roughly half.

## First-principles breakdown

**The underlying problem.** Ecologists want metric facts about wild animals — distance (for abundance estimates via "distance sampling"), size, and speed/trajectory (for movement ecology) — but almost all wildlife footage is monocular RGB video. A single RGB image/video has no absolute scale: a monocular depth estimator (MDE) can guess that one pixel is farther than another, but not how many meters away it actually is, and this ambiguity compounds for distant, non-rigid animals in unstructured terrain (unlike cars on roads, which are rigid, large, and seen in well-studied domains). You need some sensor that gives true metric scale to calibrate or validate the MDE's output.

**Why prior approaches fall short.** LiDAR (laser time-of-flight ranging) gives excellent metric ground truth but is expensive, power-hungry, and mechanically fragile, limiting deployment to a few rigs/sites. It also only measures static geometry at an instant — it doesn't measure motion directly; speed has to be inferred by differencing positions over time, which is noisy. The authors' earlier work (WildDepth v1) paired RGB with LiDAR to show MDEs are badly off in absolute terms but improve a lot once anchored to sparse LiDAR points. That solves metric depth but not motion, and doesn't solve the cost/fragility problem.

**What radar adds, and how it works here.** 4D imaging radar (Doppler mmWave radar used extensively in self-driving cars) is cheap, low-power, weather-robust, and — crucially — directly measures each return's radial velocity via the Doppler effect, not just position. But radar hardware has coarse angular resolution (here ~1.4° in azimuth and elevation), which is fine for large rigid car-sized objects but produces huge errors when trying to localize a small animal's points precisely, especially in elevation. The authors measured this: the radar-to-LiDAR extrinsic calibration has a median error of only 0.10m in range/azimuth but 1.84m in elevation. That means if you try to literally draw a radar point onto the image at pixel level, it will appear up to ~2 animal-heights off vertically — making naive per-pixel radar depth worse than having no radar at all (AbsRel 0.48, worse than an uncalibrated MDE).

**The fix: object-level, not pixel-level, association.** Instead of trusting a single radar return's projected pixel location, the method pools all radar returns whose projection falls within an animal's detected bounding box (columns = azimuth, trusted; rows = padded generously because elevation isn't trusted) and derives one robust range estimate per animal per frame (e.g., median, or densest cluster, or the subset within ±35% of the MDE's own predicted range). This "object-level radar range" is then used as a calibration anchor: fit a simple per-frame affine map (scale + offset) between the MDE's raw depth and the metric radar range at that one object, the same idea as calibrating with LiDAR but using radar points instead. Because this is one range number per animal rather than per pixel, it's robust to the elevation noise.

**Motion via Doppler transfer.** Radar returns are sparse on an animal (tens of points) while LiDAR returns are much denser (hundreds) but static (no velocity per point, standard LiDAR scans don't tag motion). The paper's technique: take each LiDAR point and search for the nearest radar return within an "anisotropic" search ellipsoid (0.6m in x, 1.0m in y, 1.5m in z — elongated vertically specifically to absorb that known elevation error) and copy over that radar return's Doppler velocity onto the LiDAR point. This "Doppler transfer" converts a few dozen velocity-tagged radar returns into a dense cloud of velocity-tagged LiDAR points, which can then be thresholded (|velocity|>0.5 m/s) to produce a dense "motion mask" distinguishing moving vs static points on an animal — something neither sensor alone provides cheaply.

**Use in tracking.** A simple 2D tracker (IoU/Hungarian matching, like SORT) links detections frame to frame; each 2D track is then "lifted" to 3D by giving each frame a depth value (from LiDAR, radar, or calibrated MDE) and smoothing with a Kalman filter. The key empirical lesson: calibrating scale once per track (fit one scale factor using the first frame, or one radar-based scale for the whole track) is far more accurate than recalibrating every single frame, because per-frame noise in the calibration itself introduces fake "jitter" that looks like spurious motion to a tracker.

**Benchmark construction.** To avoid overfitting to released data, they built a "hidden" test set from unreleased footage, filtered to static-camera frames (so multiple LiDAR sweeps could be accumulated as high-quality ground truth), with masks generated by MegaDetector (animal detector) + SAM2 (segmentation), and locked it with SHA-256 checksums so it can't be silently altered.

## Key insights

- **Genuinely new, well-supported**: Object-level radar range as a monocular-depth calibration anchor outperforms scene-level LiDAR calibration (AbsRel 0.120 vs 0.198) and needs no LiDAR at inference — this is the paper's central, quantitatively backed claim, replicated across thousands of test animals and held-out train/test sequence splits.
- **Genuinely new, well-supported**: Doppler transfer from radar to LiDAR produces motion masks 3.7× denser than raw radar at comparable (72%) precision, and gating LiDAR temporal accumulation with this motion signal cuts moving-animal depth error by 37% over a 3-second window — a reasonably convincing controlled comparison (vs. an optical-flow-based gate alternative).
- **Genuinely new, well-supported**: Once-per-track calibration (instead of per-frame) is the single biggest lever for tracking accuracy, and radar-based once-per-track scaling (0.58m position error) nearly matches LiDAR-based once-per-track scaling (0.52m) — a four-fold improvement over using MDE alone (2.20m) — and meaningfully fixes a real downstream metric (distance-sampling detection-function bias, -13% → -2%).
- **Partially supported / more exploratory**: Doppler as a speed sensor correlates with true radial speed (r=0.60) but underestimates it by ~50%, so it's a biased, "directionally useful" cue rather than an accurate speed meter — the authors are appropriately modest about this.
- **Useful negative results (the "envelope" contribution)**: per-pixel radar depth doesn't work (elevation error too large); radar doesn't extend range coverage or see through vegetation in their data; automatic per-frame extrinsic refinement actually degrades calibration versus a single fixed "anchor" calibration per sequence. These negative findings are presented as deliberately useful to the field, distinguishing this from a purely success-reporting paper.
- **Dataset/benchmark contribution**: this is, per the authors, the first published imaging-radar wildlife dataset, and the frozen checksummed hidden test set with separate animal/background scoring is a real infrastructure contribution distinct from the method claims — but its value is contingent on others actually adopting it.

## Caveats — stated and inferred

- **Single site, single day, daylight, open terrain** (stated): all radar results come from one subset (Longleat) with radar only healthy on one of two recording days (July 7 data was corrupted/discarded); authors explicitly flag that illumination-invariance and vegetation-penetration claims are "observed rather than measured."
- **Radar range degrades beyond ~30m, and advantage vanishes there** (stated): the radar calibration method is explicitly weaker at longer range, where fewer returns land on the animal; this is acknowledged plainly rather than hidden.
- **Best radar-only estimator has a heavy tail; best-performing variant is not radar-only** (stated): the top radar-range estimator uses the monocular model's own prediction to gate/select radar returns (±35%), making it technically an RGB+radar hybrid rather than a pure radar method — a potential "cherry-picked configuration" concern the authors disclose themselves.
- **Hidden test set is in-domain, not session-disjoint** (stated): 48% of hidden-test frames are within one minute of a released snippet, and a second public rig recorded the same enclosures the same days — so this benchmark measures in-domain generalization, not true cross-site/cross-session transfer, despite being called a "held-out" test.
- **Small Track A test set** (stated): only 510 detections in 352 frames for the RGB-only distance task — a fairly small benchmark that limits statistical power of leaderboard comparisons.
- **Correction of prior claims mid-paper** (stated): the authors note they are correcting two earlier analyses (a radar-to-LiDAR-snapped anchor that "does not replicate at scale," and an earlier claim of "no correlation" between Doppler and speed that is revised to r=0.60) — a positive transparency signal, but also evidence the methodology/results were unstable across iterations of their own analysis.
- **Calibration extrinsics were manually/semi-manually tuned** (stated): the radar→LiDAR extrinsic was "initialized by aligning static structure and refined manually on one sequence" — a hand-tuned, single-sequence calibration generalized to the whole dataset, which is a fairly fragile basis for a hard sensor-fusion claim.
- **Tracking reference is not independent ground truth** (stated): the "reference" 3D trajectories used to score all tracking methods are themselves LiDAR-derived, and the tracker used is a simple IoU/Kalman tracker without identity-level metrics (HOTA/IDF1) due to lack of identity labels — so track association quality itself is unverified.
- **Automatic extrinsic self-calibration silently fails** (stated as a negative result, but also an inferred red flag about calibration robustness generally): per-frame extrinsic refinement drifted up to 25° while its own optimization objective reported success, meaning any pipeline trusting automated calibration without an independent check (as they found necessary) could silently produce corrupted ground truth — a caution that likely generalizes to other similar sensor-fusion wildlife setups not using this independent check.
- **No cross-species/behavior stratification in main depth/motion metrics** (inferred): results are aggregated across species/behaviors (e.g., median over many animals) without reported breakdowns by species size, gait type, or occlusion level, so it's unclear whether gains are uniform or driven by a subset of easy cases (e.g., large, slow-walking herds where Doppler precision was highest, 0.96–0.98, vs. scenes with moving vehicles, precision 0.39).
- **Ego-motion exclusion reduces usable radar motion data substantially** (stated): 35% of vehicle-mounted frames were flagged and discarded as ego-motion-dominated, meaning the dense-motion-mask and Doppler-speed results are drawn from a reduced, static-platform-biased subset of the data, not the full radar corpus.
- **Hidden test still needs anonymization before public release** (stated): visible visitors and number plates are present and unaddressed at time of writing — a practical, non-technical caveat about the benchmark's actual public usability right now.
