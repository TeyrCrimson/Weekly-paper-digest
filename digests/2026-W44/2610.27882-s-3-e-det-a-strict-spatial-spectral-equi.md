# S$^3$E-Det: A Strict Spatial-Spectral Equivariant Detector for Multispectral Object Detection

**Authors:** Peng Zhang, Tingfa Xu, Jinrui Sui, Yuyang Tian, Jianan Li

**arXiv:** [2610.27882](https://arxiv.org/abs/2610.27882)

**Categories:** cs.CV

**Submitted:** 2026-10-20

**Relevance:** 6/10 — matched: Onboard object detection from a moving UAV

---

## TL;DR
S³E-Det is a multispectral object detector that enforces exact rotational equivariance (under 90° rotations) while also preserving the physical ordering of spectral bands and adapting feature fusion by pyramid level. It pairs three new modules — spectral order calibration (SOSC), scale-adaptive common/differential fusion (CDEF), and a response-aware prediction head (GAH) — to beat prior multispectral detectors on three benchmarks (MODA, HOD3K, DroneVehicle) with far fewer parameters. The core evidence is accuracy/parameter trade-offs plus a numerical "conformance" audit showing the network's internal features really do commute with 90°/180°/270° rotations as designed.

## First-principles breakdown

**The task.** Multispectral object detection (MOD) means detecting and drawing oriented bounding boxes around objects (vehicles, people, bikes) in images that have more than the usual 3 RGB channels — e.g., 8 or 16 spectral bands capturing how materials reflect light differently across wavelengths. This extra spectral information helps distinguish objects (e.g., a car's paint vs. asphalt) that look similar in plain RGB, especially in bad lighting. The images are typically aerial/drone shots, so objects can appear at any rotation (a car can point any direction), not just upright.

**Problem 1 — spectral order is thrown away.** Prior MOD methods (e.g., S2ADet, OSSDet) treat spectral bands mainly as "channels to select, reweight, or compress" — via band selection, PCA, attention, or masking. But bands are not arbitrary channels: they have a physical ordering by wavelength (band 3 is "between" band 2 and band 4 physically). Convolution/attention mixing across channels can scramble this order, losing information about how a material's reflectance smoothly varies across adjacent wavelengths. SOSC's fix: within each processing block, keep a 1D ordering of "spectral slots," compute a first-order derivative (finite difference) between neighboring slots (Eq. 4), and use a tiny learned network to decide, per slot, a calibrated sampling point that stays within that slot's local neighborhood (its "cell," defined by midpoints to immediate neighbors — Eq. 3, 6). Because the correction is bounded to within each cell, the final calibrated order is mathematically guaranteed to stay monotonic (Eq. 7) — no slot can "jump over" another. The calibrated value is linearly interpolated (Eq. 8) and blended back into the original feature via two learned gates: one controlling how much of the interpolated correction to use, one controlling how much of the raw derivative ("slope") to inject (Eq. 9). Net effect: a drop-in block that refines spectral features while provably preserving their relative order, without hand-tuned thresholds.

**Problem 2 — fusion across scales doesn't adapt.** In a typical feature pyramid network (FPN), features at different levels (fine/local vs. coarse/semantic) get fused with the same fixed rule everywhere. But at fine resolution, local pixel-level spectral differences between adjacent, similar-looking objects matter more; at coarse resolution, broader object context matters more. CDEF explicitly splits each pyramid level's features into a "common" branch (local spatial average = shared/background context, Eq. 11a) and a "differential" branch (local average subtracted off = fine spectral detail/residual, Eq. 11b), each reweighted by a learned per-channel gate. It then fuses the two via an "agreement gate" (Eq. 12) — effectively asking "how much do the common and differential signals agree," and combining them into a residual update added back onto the original feature (Eq. 13), rather than replacing the feature outright. This lets each pyramid level learn its own context/detail balance instead of a one-size-fits-all fusion rule.

**Problem 3 — rotation handling is "soft" (via data augmentation) rather than architecturally guaranteed.** Standard detectors just see rotated training examples and hope to learn rotation-robust behavior; nothing in the architecture *enforces* consistent behavior under rotation. The paper uses **group-equivariant** machinery (building on G-CNNs, Cohen & Welling 2016): rather than one feature per pixel, a "lifted" representation has an extra axis indexing a small set of discrete rotations (here 4, i.e. 0°/90°/180°/270°, called the group C4). A function Φ is "equivariant" if rotating the input then extracting features equals extracting features then rotating/permuting them (Eq. 1–2) — rotating the image by 90° should cyclically shift which "orientation channel" holds which response, not scramble things unpredictably. The problem: not every output of a detector should transform the same way under rotation. Class label ("is this a car") shouldn't change at all (invariant). Box width/height in the object's own frame shouldn't change (invariant). But the box's absolute orientation angle *should* rotate along with the image (equivariant). Prior equivariant detectors (ReDet, MessDet) don't make this distinction explicit in their prediction heads. GAH fixes this: it computes a pooled, rotation-invariant descriptor Q_l (pooling over the orientation-channel axis) and reads class logits and canonical box distances from Q_l (these can't be affected by which rotation channel is "active"). Separately, it decodes orientation from the *phase* of the orientation-channel responses themselves (treating the G channels as a discrete Fourier-like basis of angles, Eq. 15–16) — a cyclic shift in orientation channels directly shifts this phase, giving a built-in equivariant angle estimate, refined by a small learned residual.

**Putting it together.** SOSC runs inside each backbone stage to calibrate ordered spectral features without breaking the group structure; CDEF runs in the neck (FPN) to fuse scales adaptively while staying equivariant; GAH decodes final predictions with response-specific (invariant vs equivariant) output rules. All modules are designed so each, individually, commutes with the C4 rotation action, so the stacked network as a whole stays equivariant.

**How they check the equivariance actually holds (not just claimed).** Beyond standard accuracy metrics, the authors run a "conformance audit": they feed a fixed validation image rotated by exact multiples of 90° (where rotation needs no pixel interpolation) and measure residual error between "rotate-then-featurize" and "featurize-then-rotate-the-features" at every layer (Eq. 17–18). They find these residuals tiny (≤~0.002) through the backbone/neck, confirming near-exact equivariance on-grid, but residuals balloon for off-grid angles (30°, 60°, etc., which require interpolation) and after box decoding/NMS — showing the "strict equivariance" claim is narrowly scoped to exact quarter-turns at the raw-prediction level, not general rotation robustness end-to-end.

## Key insights

- **Genuinely new**: combining an order-preserving mechanism for spectral channels (SOSC) with scale-adaptive common/differential fusion (CDEF) and response-law-aware prediction heads (GAH) into one coherent, strictly group-equivariant pipeline. Prior MOD work addressed spectral fusion (OSSDet, S2ADet) or rotation equivariance (ReDet, MessDet) separately, not together with the output-level invariant/equivariant split.
- **GAH's response-specific decoding** (invariant classification/box-size vs. equivariant angle-via-phase) is a conceptually clean and apparently novel idea distinct from prior equivariant detectors, which the paper claims (and the per-branch residual table partly supports) improves consistency without adding much compute (GAH itself is "compact").
- **The conformance audit (Eqs 17-20, Tables VII-VIII)** is a genuinely useful methodological contribution beyond this paper — actually measuring whether claimed equivariance holds numerically at each layer, rather than only citing rotation-augmented accuracy. This distinguishes "architecture provably commutes with discrete rotations" from "model is robust to any rotation," which the paper is careful (to its credit) to separate.
- **What's actually supported by evidence**: strong mAP50/params trade-offs on three datasets (e.g., beating OSSDet by several points on MODA with ~93% fewer parameters), ablations showing each module (SOSC/CDEF/GAH) contributes additively (Table III), and smaller mAP fluctuation under rotation vs. baselines (Figure 8).
- **What's claimed but more narrowly supported**: "strict" equivariance is only verified exactly at 90°-multiples on one fixed sample; general rotational robustness in real deployment (arbitrary angles) is only indirectly evidenced via the rotation-robustness curve (Fig. 8), where accuracy still dips at intermediate angles.

## Caveats — stated and inferred

- **Single fixed validation sample for the exact-conformance audit** — the residual tables (VII, VIII) are computed on "one fixed validation input." Generalization of these tiny residuals across the dataset is not demonstrated. (inferred)
- **Off-grid rotation and post-processing performance degrades sharply** — raw-head and post-NMS discrepancy jump to 0.35–0.66 for non-90°-multiple rotations, which the authors explicitly state is outside the scope of their "strict" claim. (stated)
- **No zero-shot cross-sensor transfer, controlled sensor perturbation, or large-corpus scaling evaluated** — explicitly listed as unresolved future work. (stated)
- **Baselines not uniformly retrained** — "Baseline values are taken from the cited studies under their published benchmark protocols and were not uniformly retrained in our codebase," meaning comparisons may be confounded by differing training setups/hardware/hyperparameters rather than purely architectural differences. (stated, but also a red flag for fairness of comparison — inferred risk)
- **Increased compute/training cost despite fewer parameters** — Table II/XI show S³E-Det uses more peak GPU memory, more training time per epoch, and substantially higher FLOPs/latency on edge hardware (RKNN) than parameter-comparable baselines like YOLOv8n (e.g., 89.3 ms vs. presumably much faster for YOLOv8n-class models, lower FPS at higher group order). The parameter-count win is somewhat offset by this. (inferred from presented data, though authors do report it transparently)
- **Group order C4 chosen as "default" largely on accuracy/compute trade-off, with marginal gains from C8** — the paper doesn't explore continuous SO(2) equivariance or justify why C4 is sufficient beyond this one ablation table. (inferred)
- **Dataset/training schedules are short and dataset-specific** (e.g., 20, 14, and 12 epochs respectively) with no stated justification that these are sufficient for full convergence of baselines reimplemented vs. cited; could bias comparisons. (inferred)
- **Qualitative failure cases acknowledged**: "Crowded scenes remain challenging, with occasional failures to separate adjacent vehicles and detect small pedestrians," and similar residual errors noted for small/occluded/overlapping objects across all three datasets. (stated)
- **No ablation isolating GAH's invariant/equivariant split against a naive shared-head baseline under matched parameter count** beyond the main Table III ablation — it's unclear how much of GAH's gain comes from the invariant/equivariant decomposition specifically vs. simply being a different head architecture. (inferred)
- **The "strict equivariance" terminology could be seen as overclaiming** relative to what's measured — it is accurate only for the discrete feature pathway under exact quarter-turns, not the full detection pipeline (decoding/NMS) or arbitrary rotations; the paper does disclose this nuance in its own text, which is a mitigating factor. (stated, with inferred risk of being easy to overstate when summarized elsewhere)
