# Beyond KV Reconstruction: Functional Reconstruction for MLA Draft Models in Speculative Decoding

**Authors:** Weiye Shi, Fanxu Meng, Muhan Zhang

**arXiv:** [2607.27269](https://arxiv.org/abs/2607.27269)

**Categories:** cs.LG

**Submitted:** 2026-07-29

**Relevance:** 9/10 — matched: LLM inference efficiency and long-context serving

---

## TL;DR
Converting MHA/GQA checkpoints to Multi-head Latent Attention (MLA) makes inference cheaper but can wreck their usefulness as *draft* models in speculative decoding, because low-rank/RoPE approximation errors shift token rankings enough to tank acceptance rates. The paper proposes "Functional Reconstruction," a training-only, verifier-free fine-tuning step that makes the converted MLA attention block reproduce the original attention block's output on calibration data, rather than just reproducing its cache. Across 192 configurations (Llama/Qwen, TransMLA/MHA2MLA, HF/vLLM), this materially improves acceptance in 37/64 matched cells, leaves 26 unchanged, and hurts 1.

## First-principles breakdown

**Background: KV cache and why MLA exists.** In autoregressive Transformer decoding, each new token attends to all previous tokens' key/value (KV) vectors, which must be cached in memory. As context grows, this cache dominates memory traffic and limits throughput. GQA reduces cache size by sharing KV heads across multiple query heads, but still stores explicit K/V. MLA (from DeepSeek) goes further: instead of storing full K/V per head, it stores a small shared "latent" vector per token and reconstructs the effective K/V via learned projection matrices at attention time. This shrinks the cache dramatically. The catch: most strong open models (Llama, Qwen) were pretrained with MHA/GQA, not MLA, so to get MLA's memory benefits you must *convert* an existing checkpoint rather than retrain from scratch.

**Conversion methods and why they're imperfect.** TransMLA and MHA2MLA are two existing recipes for converting MHA/GQA weights into an MLA-shaped model. Mechanically: the original K/V projections are approximated by a low-rank factorization (a shared "latent" projection followed by an up-projection), and RoPE (rotary positional embeddings, which rotate query/key vectors based on position) has to be specially handled because it doesn't commute nicely with low-rank compression — some converters keep part of the key on a "retained RoPE" path and move the rest to a non-positional path. The paper shows mathematically (Eq. 6-7) that exact reproduction of the original stacked K/V map requires the low-rank factorization's rank to be at least as large as the rank of the original weight matrices stacked together; when the chosen latent rank is smaller (the normal, cache-efficient case), the conversion is necessarily an *approximation*, leaving a residual error in attention logits (formalized in Eq. 8, decomposed into retained-key error, positional-path error, and query-perturbation terms).

**Why this matters more for speculative decoding than standalone generation.** Speculative decoding uses a small, fast "draft" model to propose several tokens ahead, which a larger "target" model then verifies in one parallel pass; tokens that match are accepted, giving a speedup proportional to the acceptance rate. Acceptance depends on the draft's output distribution closely matching the target's — for stochastic sampling, this is governed by total-variation distance between draft and target distributions (Eq. 9); for greedy decoding (used in this paper's experiments), it's simply whether the draft's top token matches the target's top token (Eq. 10). A converted MLA model might generate perfectly reasonable text on its own (small approximation errors get "absorbed" over many tokens), but the same errors can flip which token is ranked #1 at a given step — which is catastrophic for greedy-decoding acceptance even though it's invisible in normal generation quality metrics.

**The proposed fix: Functional Reconstruction.** Instead of treating MLA conversion as "compress the cache and hope generation still looks okay" (what the existing converters do, tuning only their own local objective), the paper reframes it as: make the *converted MLA attention block's output* match the *original attention block's output* as closely as possible, given the fixed low-rank budget. Concretely: take a converter-initialized MLA checkpoint (from TransMLA or MHA2MLA), freeze the original MHA/GQA attention block, freeze the output projection WO, and run the same calibration hidden states through both the frozen original block and the trainable converted MLA block. Compute the masked mean-squared error between their post-WO outputs (Eq. 11), stop gradients through the original ("target") path, and backpropagate only into the converter-introduced query/KV projections. This is done independently per layer, needs no verifier model, no labels, and no logits from the actual target model used in speculative decoding — just calibration data and the original weights, which are already available. Critically, it doesn't change the cache format, latent rank, or inference graph at all — it's a drop-in refinement applied after conversion, before deployment.

**What's being optimized vs. what's actually measured.** The training loss is a *local, continuous* proxy (attention-output MSE) for a *discrete, end-to-end* quantity (whether greedy top-token matches across a full generation with the real target model). The paper is explicit that reducing this local residual doesn't provably improve acceptance monotonically — later layers could amplify, cancel, or ignore a given residual — so the actual benefit is established only empirically via the large evaluation matrix, not theoretically guaranteed.

## Key insights

- **Genuinely new framing**: distinguishing "conversion validity" (can you build a working MLA cache) from "functional fidelity" (does the block compute the same function) from "draft utility" (does it agree with a *separate* verifier model well enough for speculative decoding). Prior converter work (TransMLA, MHA2MLA) only optimized the first two, using converter-local objectives (e.g., reconstructing K/V factors, or partial-RoPE tricks) — this paper shows that's insufficient for the draft-model use case specifically, and evidence for this claim (severe acceptance drops after direct conversion, e.g., Llama-1B TransMLA HumanEval/HF dropping from 77.75% to 67.61% acceptance) is well supported by the reported tables.
- **The method itself is genuinely simple and cheap**: training-only, converter-agnostic, no verifier supervision, no inference-time cost or architecture change — it's a drop-in post-processing step. This is a real practical advantage if the acceptance gains hold up.
- **Evidence supports "usually helps, rarely hurts, sometimes does nothing"** rather than "reliably fixes the problem." 37/64 matched cells improve materially, 26 unchanged, 1 worse — so the claimed contribution ("converter-agnostic, broadly beneficial") is supported but the actual effect size is uneven and highly dependent on the specific model family × converter combination (e.g., all 16 Llama-MHA2MLA cells are unchanged; Qwen-TransMLA is inconsistent especially under vLLM). The paper itself flags this interaction rather than claiming uniform improvement — a good-faith self-report of a heterogeneous result.
- **Recovery is partial, not full**: even where Functional Reconstruction helps, it typically recovers only part of the acceptance gap relative to the uncompressed original GQA model, and never surpasses it in the reported matrix. This tempers the practical significance of the "improvement" — it's fixing a self-inflicted wound from conversion, not achieving parity with the un-converted model.
- **No end-to-end wall-clock speedup is demonstrated** — the paper measures acceptance rate and tok/s throughput but explicitly says it does not establish that this translates into a real speedup over the unconverted draft, since that requires mature MLA kernels which aren't the paper's focus.

## Caveats — stated and inferred

- **Small model/data scale** (stated): only two model families, four draft-target pairs (all ≤8B target), four 200-prompt benchmarks, 128-token generation cap, single fixed seed (42). No repeated-seed variance estimates are given, so the "material" 0.5pp/0.5 tok/s thresholds are descriptive conventions, not statistically validated confidence intervals (stated explicitly: "descriptive tolerances, not confidence intervals").
- **Does not surpass original (unconverted) GQA acceptance in any reported configuration** (stated) — the method mitigates but does not eliminate the conversion-induced acceptance loss; large gaps remain in severely mismatched converter/backend paths (e.g., Qwen-3B–TransMLA/vLLM NQ acceptance only recovers from 10.95% to 12.73%, versus 71.03% original).
- **No demonstrated end-to-end wall-clock speedup over the unconverted draft** (stated) — throughput results are reported, but the paper is explicit that translating acceptance gains into system-level speedup requires optimized MLA kernels not evaluated here.
- **One configuration got materially worse** (stated: −0.55pp on CNN/DM, Qwen-3B/TransMLA/vLLM) — not explained beyond noting it's borderline (0.05pp beyond tolerance).
- **Only greedy decoding is evaluated** (inferred from Evaluation Protocol/Eq. 10) — the paper derives an acceptance formula for stochastic sampling (Eq. 9) but all reported experiments use greedy decoding with a fixed seed; how the method performs under stochastic/temperature sampling (common in production) is not addressed in the paper.
- **Batch size fixed at 1** (stated in evaluation protocol) — no evidence on behavior under batched/production serving conditions.
- **Throughput measurements not repeated across multiple timing runs** (stated) — "the individual tok/s differences should be treated as a combination of acceptance effects and run-level variation," meaning the throughput numbers carry unquantified noise.
- **vLLM cross-converter throughput is not directly comparable** (stated) — TransMLA uses TP2 and MHA2MLA uses TP1 under vLLM, so absolute throughput comparisons across converters conflate parallelism configuration with model quality.
- **No ablation of loss design choices** (inferred) — the paper doesn't test alternatives to plain masked MSE (it explicitly proposes layer-sensitivity weighting or token-margin-aware reconstruction as *future* work), so it's unclear how much of the gain is specific to the chosen loss formulation versus other plausible functional-matching objectives.
- **No comparison against other draft-improvement techniques** (inferred) — the related work section surveys EAGLE, Medusa, tree-based speculative methods, etc., but the paper only compares against "Partial RoPE reconstruction" (the converter-native baseline) and "Original GQA," not against any alternative draft-quality-improvement method, leaving it unclear how this approach stacks up against other ways of building good speculative drafts.
- **Effect is highly heterogeneous across model/converter combinations without a full causal explanation** (stated as an open question) — e.g., why Llama–MHA2MLA sees essentially zero benefit while Qwen–MHA2MLA sees broad gains is described post hoc ("converter initialization determines which functional residual remains") rather than predicted or mechanistically explained in advance, which weakens the generality claim somewhat.
