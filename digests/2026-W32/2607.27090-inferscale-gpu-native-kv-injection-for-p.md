# InferScale: GPU-Native KV Injection for Personalized LLM Serving

**Authors:** Peter Li, Prashant Pandey

**arXiv:** [2607.27090](https://arxiv.org/abs/2607.27090)

**Categories:** cs.DC, cs.LG

**Submitted:** 2026-07-29

**Relevance:** 9/10 — matched: LLM inference efficiency and long-context serving

---

## TL;DR
InferScale is a vLLM plugin that replaces repeated re-prefilling of retrieved "memory" facts (as done by systems like Mem0) with direct injection of precomputed key-value (KV) tensors into the GPU-resident paged attention cache, making time-to-first-token nearly constant regardless of how much memory is retrieved. It solves two technical problems — RoPE's positional dependence and the loss of cross-fact context when facts are encoded independently — via "Chunked RoPE" (store keys pre-rotation, rotate at injection time) and "Context-Window Encoding" (encode each fact with preceding conversation turns but cache only the fact's KV). On LoCoMo across three open-weight models, it cuts TTFT 72–79% and boosts concurrent throughput 3.7–4.5x versus Mem0, at a modest (~3 percentage point) accuracy cost.

## First-principles breakdown

**The problem.** LLM chat apps increasingly attach persistent "memory" (facts extracted from past conversations) to every request so the model has personalized context. Because you can't afford to prepend a user's *entire* history every time (prefill cost grows quadratically with prompt length), production systems like Mem0, Zep, and MemGPT retrieve only the top-k most relevant facts and paste them as text into the prompt ("prompt injection"). The catch: even though the same facts get retrieved repeatedly across a user's requests, the serving engine still has to run them through the transformer's prefill pass every single time, since the model only knows how to "understand" tokens by computing fresh attention states for them. As k (the retrieval budget) grows, so does time-to-first-token (TTFT) — the latency before the first output token appears — even though nothing about the underlying memory changed.

**Why existing KV-reuse tricks don't help.** Serving engines already cache attention Key-Value (KV) tensors so that during autoregressive decoding you don't recompute past tokens' representations. vLLM's "prefix caching" lets a repeated identical prompt *prefix* skip prefill by reusing cached KV. But retrieved memory facts are assembled dynamically and differently per request — different subsets in different order/positions — so they don't form a stable, reusable prefix, and prefix caching essentially never fires.

**The core mechanism — KV injection instead of prompt injection.** In causal (autoregressive) attention, a token's key/value representation depends only on itself and earlier tokens, never on tokens that come after it (that's what "causal" masking means). So a memory fact's KV representation is completely independent of whatever query eventually follows it. That means it can be computed once, offline, and reused for any future request — instead of being re-computed by prefill every time. The paper formalizes this: they prove (Theorem 3) that if you inject a fact's precomputed KV directly into the attention cache at the position it would have occupied, the resulting hidden states for the query tokens are *mathematically identical* (not approximately close) to what you'd get from full prompt prefill. This is a clean proof by induction over transformer layers, not an empirical claim.

**Two engineering obstacles and how they're solved:**

1. *Positional encoding breaks naive reuse.* Most modern LLMs use Rotary Position Embeddings (RoPE), which "rotate" each key/query vector by an amount depending on its position in the sequence, so that attention scores depend on relative distance between tokens. Since retrieved facts land at different, unpredictable prompt positions across different requests, a KV cached at one position is wrong if reused at another position. InferScale's fix, "Chunked RoPE," stores keys *before* the rotation is applied (i.e., right after the key projection, pre-RoPE) and applies the position-specific rotation on the fly at injection time, using whatever virtual position the fact happens to land at for that request. Because RoPE rotations compose algebraically (rotating by a then attending is equivalent to rotating by the relative offset), this re-rotation at serving time is mathematically exact (Theorem 6) — not an approximation.

2. *Facts lose context when encoded alone.* If you encode "He walks the dog" as an isolated fact, the model doesn't know who "he" refers to — that context came from earlier conversation turns that would normally be jointly prefilled. Encoding facts in total isolation would hurt answer quality. "Context-Window Encoding" fixes this by, at encoding time (offline, once), running the fact through the transformer together with a window of w preceding conversation turns so the fact's KV representation absorbs that disambiguating context (e.g., "he" resolves to "Rex") — but only the fact's own KV slice is kept and cached; the context tokens are discarded and never retrieved or re-prefilled at serving time. This costs nothing extra at serving time since it's a one-time offline computation.

**System design.** InferScale keeps two GPU-resident data structures keyed by a shared fact ID: (a) a "Jasper" GPU-native approximate-nearest-neighbor vector index for retrieving relevant facts by semantic similarity, and (b) a pre-RoPE KV store holding each fact's raw key/value tensors. At serving time: embed the query → retrieve top-k fact IDs → compose their pre-RoPE KV at contiguous virtual positions → apply Chunked RoPE rotation → scatter-copy directly into vLLM's paged KV-cache blocks via vLLM's official "KV connector" plugin interface (no engine modification needed) → only the query tokens actually get prefilled by the model; retrieved memory never crosses the PCIe bus and is never re-computed.

## Key insights

- **Genuinely new theoretical claim**: KV injection is an *exact* equivalent of prompt injection under causal attention (Theorem 3), not a lossy approximation — this is a clean, general result (holds for any attention variant/positional scheme) that the paper actually proves, not just asserts empirically.
- **Chunked RoPE is the practical enabler**: storing keys pre-rotation and re-rotating at injection is what lets a fact be cached once and reused at arbitrary future positions — this is the mechanism that makes the theoretical equivalence deployable for *dynamically retrieved* (not fixed-prefix) content, which is what distinguishes it from existing prefix-caching/KV-reuse work (Block-Attention, CacheBlend, LMCache) that requires fixed layouts or fine-tuning/recomputation.
- **Context-Window Encoding is the practical accuracy fix**: the one genuinely approximate step (independent fact encoding losing cross-fact attention) is mitigated, not eliminated — accuracy is restored to near-Mem0 levels for single-hop/temporal/open questions, but a real residual gap remains concentrated in multi-hop questions (which inherently need cross-fact reasoning at serving time that this design structurally can't provide without joint prefill).
- **Evidence supports the latency/throughput claims strongly**: TTFT flat vs. k (~4% growth vs. Mem0's ~106%), 3.6–4.8x TTFT reduction, 3.7–4.5x throughput gains — these are measured on real engine metrics (vLLM TTFT) across 3–4 models, with an ablation isolating retrieval-backend (Jasper vs Qdrant) effects from the injection mechanism's effects, which is good practice.
- **Accuracy claim is more nuanced than the abstract implies**: "60.3% vs 63.3%" is the headline, but the per-category breakdown shows InferScale sometimes *beats* Mem0 (open-ended questions on Llama/Mistral) and sometimes trails by up to 16 points (multi-hop at k=50). The abstract's single aggregate number obscures this variance.
- **The independent-encoding-only variant (w=0) is a genuinely useful negative result**: it shows accuracy actively *degrades* as k grows when facts are encoded without context, which motivates why Context-Window Encoding is necessary rather than optional — a good ablation supporting the paper's design choice.

## Caveats — stated and inferred

- **Accuracy ceiling not fully closed** (stated): Mem0's full prompt-injection remains the accuracy ceiling, especially on multi-hop reasoning questions requiring cross-fact attention that InferScale's independently-encoded facts cannot fully capture; the paper attributes this explicitly to the loss of cross-chunk attention (Theorem 6(3) discussion).
- **Larger encoding window costs more offline compute/storage** (stated implicitly): increasing w only affects one-time offline preprocessing cost, but the paper doesn't quantify how this preprocessing cost scales or report it as a wall-clock/dollar cost anywhere in the visible text — inferred that this tradeoff is understated since offline cost is only ever described as "excluded from reported latency."
- **Single-hardware, single-server evaluation** (inferred): all experiments run on one NVIDIA RTX PRO 6000 Blackwell GPU; no evaluation of multi-GPU serving, network-attached storage, or heterogeneous hardware, which is the norm in production LLM serving fleets — generalization to that setting is not addressed in the paper.
- **Baseline comparison is against Mem0's default config only** (inferred/stated): the paper compares mainly against Mem0's "default production configuration" (Qdrant + prompt injection); other prefix/KV-reuse baselines mentioned in related work (Block-Attention, CacheBlend, LazyAttention, LMCache, RetroInfer, RetrievalAttention) are discussed qualitatively but not benchmarked empirically head-to-head — so the quantitative superiority claims are only established relative to Mem0, not the broader KV-reuse literature.
- **LLM-judge accuracy evaluation** (inferred): "accuracy" is judged by another LLM (Gemma-2-9B-Instruct) prompted zero-shot for a binary verdict — this is a common but imperfect proxy for correctness, and no human validation or inter-rater/judge-agreement check is reported in the visible text.
- **Storage/memory cost scaling not fully explored** (inferred): the paper gives a per-fact/per-conversation storage estimate (1.8–4.8GB per conversation, ~128MB per 1024 memory tokens for Llama-3.1-8B) but doesn't address how this scales to many simultaneous users' memory stores resident on GPU/host DRAM in aggregate at production scale, beyond the single CPU-offload latency experiment.
- **Single dataset (LoCoMo)** (inferred): all accuracy and most latency/throughput results are evaluated on one benchmark (LoCoMo, a 10-conversation subset with 1,540 QA pairs); no cross-dataset generalization test is shown, so claims of accuracy preservation may not transfer to other memory/QA distributions.
- **Simulated concurrent load, not live production traffic** (inferred): throughput experiments use synthetic batches of LoCoMo queries submitted simultaneously with fixed 50-token greedy decoding, rather than realistic, variable-length, bursty production traffic patterns.
- **Precomputed/cached embeddings used in the request path** (stated): the paper explicitly notes embeddings for both memory facts and questions are precomputed and cached on disk, so "the measured request path performs a cached vector lookup rather than a live embedding call" — meaning reported end-to-end latencies exclude real-time embedding-model inference cost, which would be present in an actual production system.
- **Middle/appendix content was truncated in the extracted text** — some sections (e.g., full RQ4 CPU-offloading discussion, some appendix details) were cut off, so any conclusions specifically dependent on that truncated material are not fully assessed here.
