# CoSA: Accelerating Long-Context Inference via Proxy-Kernel Co-Designed Sparse Attention

**Authors:** Yufei Xue, Lin Niu, Hong Liu, Siran Liu, Hanyong Shao, Wei Liu, Guanghua Yu, Jianchen Zhu, Jun Zhang

**arXiv:** [2607.25291](https://arxiv.org/abs/2607.25291)

**Categories:** cs.CL

**Submitted:** 2026-07-28

**Relevance:** 9/10 — matched: LLM inference efficiency and long-context serving

---

## TL;DR
CoSA is a training-free sparse-attention scheme for long-context LLM prefill that couples a "kernel-aware" block-selection proxy with a matching attention kernel, instead of treating the two as separate stages the way prior methods do. By having the proxy output an *ordered* mask (not just a binary one) that tells the kernel which blocks to visit and in what order, and letting the kernel then skip additional blocks using exact online-softmax statistics, CoSA reaches higher accuracy at much lower compute budgets than existing block-sparse baselines. Reported results: 4.93× attention speedup and 2.53× time-to-first-token speedup at 128K context with "negligible" accuracy loss.

## First-principles breakdown

**The underlying problem.** Self-attention cost grows quadratically with sequence length (every query token compares against every key token), so processing a 128K-token prompt ("prefill") is very expensive. "Sparse attention" cuts this cost by only computing attention for a subset of query-key block pairs that are believed to matter, skipping the rest.

**How existing sparse attention works, and where it breaks.** Attention is computed in tiles/blocks (e.g., FlashAttention groups queries and keys into blocks and streams through them, tracking a running max value per query row — the "online softmax" trick — so it never needs the full N×N score matrix in memory at once). Block-sparse methods add a cheap "proxy" step before the real computation: it estimates roughly how important each query-block/key-block pair is (e.g., via downsampled/pooled scores) and produces a binary mask marking which blocks to keep, given a "budget" (fraction of blocks kept). The kernel then only computes attention for the kept blocks.

The paper identifies two failure modes:
1. **Proxy fidelity degrades under tight budgets** (Property 1): when you force the proxy to keep very few blocks, it increasingly misses blocks that actually matter (measured via IoU against an "oracle" mask derived from true full-attention scores — Figure 2 shows this IoU dropping as budget tightens for MInference, FlexPrefill, XAttention).
2. An alternative approach, "in-kernel skipping" (e.g., BLASST), avoids relying on an approximate proxy — it computes the real query-key scores block by block and skips a block only if its local max score is provably negligible compared to the running max seen so far. This is accurate (oracle-aligned) but has two problems: (a) it still requires computing the full QK dot product for every block before deciding to skip — so it only saves the cheaper "value" step, not the expensive "QK" step (Limitation 1); (b) it's conservative — the skip decision compares against a *running* max that may not yet equal the *true global* max (a block's true global max could be located anywhere in the sequence, not just at the start or end), and a single "outlier" query row within a block can veto skipping the whole block even though the other rows are safely negligible — this is called the "bucket effect" (Limitation 2).

**CoSA's mechanism.** CoSA argues these two techniques should be co-designed rather than stacked independently, using two components:

- **Kernel-Aware Proxy (KAP)**: Instead of producing a plain binary mask, KAP downsamples queries/keys, computes cheap approximate attention scores, max-pools per block, and identifies both (a) an importance score per block and (b) an "HRM" flag — whether a block contains the position where a query row attains its row-wise maximum score. It then sorts candidate blocks so HRM blocks are visited *first*, followed by other blocks ranked by score, producing an "ordered mask" (which blocks to keep + what order to compute them in), selected under a moderate first-stage budget.

- **Ordered-Skipping Kernel (OSK)**: Consumes this ordered mask by physically jumping (via lightweight KV-page remapping, building on paged KV-cache serving) directly to the retained blocks in the prescribed order — avoiding wasted control-flow/sync overhead the naive "mask and iterate over everything" approach incurs. Crucially, because visiting HRM blocks first pushes the running max to (near) its true global value very early, OSK's subsequent in-kernel skip test (same style as BLASST's) becomes both safer (closer to comparing against the true global max) and more aggressive (fewer false "must keep" verdicts), enabling a second, tighter stage of sparsification on top of KAP's first-stage budget. This reordering doesn't change the mathematical result because online-softmax accumulation is provably order-invariant (Property 2) — summing/maxing over the same set of blocks in a different order yields the identical output.

In short: the proxy tells the kernel not just *what* to compute but *in what order*, and the kernel's exact skip logic then works better because of that order — a genuine two-way coupling ("proxy shapes kernel, kernel shapes what the proxy needs to provide").

## Key insights

- **Genuinely new**: the "computation-order mask" concept — a proxy output that encodes both block selection and visiting order, not just a binary keep/drop decision — and the observation that this order controls how effective downstream in-kernel exact skipping can be. This is the core novel idea tying proxy design and kernel design together, rather than treating them as independent pluggable components (which the authors show is how essentially all prior sparse-attention work is structured — Table A).
- **Two-stage sparsity** (moderate-budget proxy pruning + further exact in-kernel skipping) is presented as complementary: proxy pruning removes cheap-to-skip-early blocks including the expensive QK step (addressing Limitation 1 of pure in-kernel skipping), while the order-aware in-kernel skip pushes sparsity further without losing salient blocks (addressing Limitation 2).
- **Evidence support**: The ablation (Table 3) is the most direct evidence for the "co-design" claim — adding KAP alone improves accuracy over a binary-mask baseline at similar budget; adding in-kernel skipping alone slightly *hurts* accuracy on Qwen while cutting budget; but combining both with remapping ("+RMP") pushes accuracy *above* baseline while cutting budget further — supporting the specific claim that ordering + skipping need to act together, not just the general claim that sparse attention works.
- Main accuracy/efficiency claims (higher accuracy at lower budget than MInference/FlexPrefill/XAttention on RULER and LongBench-v2; 4.93× attention speedup and 2.53× TTFT speedup at 128K) are supported by Tables 1–2 and Figure 5, across two backbones (Qwen3-8B, Llama-3.1-8B-Instruct).
- The "budget" reported (e.g., 22% for CoSA vs. ~24-49% for baselines) is described as a weighted average across sequence lengths — worth noting when comparing headline numbers since it aggregates over a range of context lengths rather than reflecting a single fixed operating point.

## Caveats — stated and inferred

- **Prefill-only scope** (stated): CoSA sparsifies only the prefilling stage; decoding remains dense. The paper explicitly lists extending to decoding as future work, noting it requires "dedicated proxy and kernel designs due to its distinct query shapes and computational patterns" — i.e., the method as presented does not address decoding-time cost at all.
- **Only two model backbones tested** (inferred): Evaluation is limited to Qwen3-8B and Llama-3.1-8B-Instruct, both 8B-scale. No evidence is given for larger models (e.g., 70B+) or other architectures/attention variants (e.g., MoE, GQA edge cases beyond what these two models use), so generalization to other model families/sizes is not addressed in the paper.
- **Hardware-specific implementation** (inferred): The kernel is built around FlashAttention-4/SM90 warp-specialized design and evaluated only on NVIDIA H20 GPUs. Portability to other GPU generations/vendors is not addressed in the paper.
- **Benchmark selection** (inferred): Accuracy evaluation uses RULER (synthetic, needle-style tasks) and LongBench-v2 (real-world). This is a reasonably standard pair for this literature, but no broader suite (e.g., code, multi-document QA, math-heavy long-context tasks) is reported, so breadth of accuracy claims across task types is limited to what's shown.
- **Hyperparameter tuning per model** (stated, and a potential fragility signal): Stage-1 Top-p and the skip scale Δ are separately tuned per backbone (e.g., Δ=2000 for Qwen, Δ=200 for Llama; Llama uses an "offline-calibrated p-table"). This suggests the method needs per-model calibration to hit its reported operating points, which the paper doesn't quantify the cost/sensitivity of extensively.
- **"Negligible degradation" framing** (inferred): Tables 1–2 show CoSA is sometimes below Dense (full attention) baseline accuracy (e.g., Qwen3-8B RULER avg 88.65 vs Dense 89.20; LongBench-v2 w/CoT Qwen 36.51 vs Dense 37.48) and is not uniformly the best score in every column (e.g., MInf/XAttn beat CoSA on some individual context lengths in Table 1, like Llama at 64K where MInf and XAttn score higher than CoSA). The paper's narrative emphasizes averages and lowest-budget framing, which is accurate but somewhat selectively highlights CoSA's strongest comparisons.
- **PPL/ablation analysis uses a small sample** (inferred): The remapping and Δ-sweep analysis (Figure 6, Appendix Figure C) uses only 128 randomly sampled LongBench-v2 examples for perplexity measurement — a fairly small evaluation set for the fine-grained trade-off curves being drawn.
- **Baselines' recency** (inferred, mild): Baselines compared (MInference, FlexPrefill, XAttention) are all training-free proxy-based methods consistent with CoSA's stated category, which is appropriate; however, the paper does not compare against other recently cited methods in its own related-work section (e.g., ProxyAttn, FlashPrefill, Stem, BLASST itself as a full baseline) in the main quantitative tables — BLASST is discussed conceptually and as inspiration for the in-kernel skip mechanism but not run as a head-to-head baseline in Tables 1–2, which is a notable omission since it's the closest prior method to half of CoSA's design.
- **No error bars/statistical significance reported** (inferred): Accuracy tables report single numbers without variance across runs or seeds, so the precision of small differences (e.g., tenths of a percentage point) between methods is not addressed in the paper.
