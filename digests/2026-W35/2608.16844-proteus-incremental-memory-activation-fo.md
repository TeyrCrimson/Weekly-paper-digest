# Proteus: Incremental Memory Activation for Long-Context Sequence Modeling

**Authors:** Reza Bayat, Ali Behrouz, Vahab Mirrokni, Aaron Courville

**arXiv:** [2608.16844](https://arxiv.org/abs/2608.16844)

**Categories:** cs.LG, cs.AI, cs.CL

**Submitted:** 2026-08-17

**Relevance:** 9/10 — matched: LLM inference efficiency and long-context serving

---

## TL;DR
Recurrent/memory-based sequence models (Titans, DeltaNet-style architectures, etc.) use a fixed-size state that's fully writable from token one, causing early tokens to "hog" capacity and interfere with later ones—hurting long-context performance. Proteus fixes this with a free, drop-in trick: partition the memory into blocks and progressively unlock more blocks as the context grows, forcing early compression and giving later tokens fresh, uncontested capacity. Applied to four different memory architectures (SWLA, Comba, Titans, Hope-Attention), it consistently improves perplexity, reasoning accuracy, and especially long-context retrieval/understanding, with gains growing at longer context lengths.

## First-principles breakdown

**The problem: quadratic attention vs. lossy recurrence.** Transformers store every token (via softmax attention), giving perfect recall but cost that grows quadratically with sequence length. Recurrent/"linear attention" models instead compress the whole history into a fixed-size state (a matrix, like a hidden state), giving constant per-token cost but bounded capacity—so they must lossily summarize, and tend to generalize poorly to sequences longer than they were trained on.

**Reframing memory as optimization.** The paper adopts a framework where a recurrent model's hidden state M is treated as an "associative memory": at each step it's updated to better map keys (derived from input) to values, by (approximately) taking a gradient step on an internal loss. Different well-known architectures fall out of this view depending on the loss and update rule used:
- Linear attention = additive Hebbian update (never erases old associations).
- DeltaNet = uses an L2 reconstruction loss, so writing first erases the old value along the same key before adding the new one.
- Titans = adds momentum (a running average of past "surprise") and an adaptive forget gate.

The read/write rule is the same shape everywhere: `M_t = M_{t-1} - θ_t ∇L̃(M_{t-1}; k_t, v_t)`.

**Diagnosing the failure: static capacity.** In all these designs, the *entire* memory M is writable/readable from the very first token. Since early in the sequence there's "nothing else competing" for memory slots, the model has no incentive to compress those first tokens—it just memorizes them, using up degrees of freedom that later tokens then have to fight over, causing interference (new writes overwrite/corrupt old useful information). This mirrors known findings that models over-attend to early tokens.

**The fix: incremental memory activation.** Instead of exposing all of M always, add a time-varying binary mask `g_t` that says which parts of the memory are "active" (unlocked) at step t. Locked components are frozen: they're excluded from both the gradient update and the read operation, so they literally cannot be written to or read from until unlocked. Once unlocked, a block stays unlocked forever (monotonic schedule)—nothing is discarded, unlike pruning.

**Proteus: the concrete instantiation.** Partition the memory into E equal contiguous blocks. Use a simple linear/uniform schedule: divide the training context length N into E chunks of length Δ = N/E; after each chunk, activate one more block, until all E blocks are active by the end of the training context. So tokens 1..Δ can only read/write the first 1/E of memory, tokens Δ+1..2Δ get access to 2/E, etc. This requires no extra parameters and no extra compute—it's literally an elementwise mask multiplied into existing read/write operations, hence "no additional cost."

**Extension beyond recurrent state — MLP blocks as memory (Hope-Attention).** Via the "Nested Learning" framework, a model's own parameters (updated by gradient descent during training) can also be viewed as an associative memory writing training-sample errors into weights. Proteus applies the same masking idea to gate which MLP-block parameters get gradient updates (including momentum/variance terms in AdamW) at each training step, letting later training data get "fresh" untouched parameter capacity. This is demonstrated on Hope-Attention, whose architecture chains several MLP blocks updated at different frequencies after attention.

**Why growing (not shrinking or fixed) capacity.** The authors argue explicitly for a schedule that starts small (forcing compression when little context is available) and grows (to reduce interference as more content arrives)—this is a designed-in intuition, not something derived from theory, though it's motivated by the failure-mode analysis above.

## Key insights

- **Genuinely new framing**: treating "how much of the memory is currently writable/readable" as a schedulable, position-dependent quantity, orthogonal to the choice of update rule, optimizer, or architecture—so one mechanism can be bolted onto many different memory designs without redesigning them. This orthogonality claim (Section 2.2) is the paper's central conceptual contribution.
- **Zero added cost**: because it's just an elementwise mask on existing operations, Proteus adds no parameters and no meaningful compute overhead—a genuinely attractive practical property if it works as claimed.
- **Consistent gains across 4 architectures at 2 scales (760M/1.3B)**: Table 1 shows improved perplexity and average commonsense accuracy for SWLA, Comba, Titans, and Hope-Attention when Proteus is added—this is real, systematic evidence, not a single cherry-picked config.
- **Gains concentrate exactly where predicted**: on NIAH, retrieval (SWDE/SQuAD/FDA), and LongBench, improvements are largest at longer context lengths and on harder variants, and roughly neutral where baselines already saturate (e.g., simple pass-key retrieval). This internal consistency (effect shows up specifically where the stated mechanism predicts it should) is stronger evidence than the raw accuracy deltas alone.
- **Ablation supports the compression-bottleneck story, not just "it improves things somehow"**: perplexity is non-monotonic in the number of blocks E (best at E=16, worse at E=1 [no scheduling] and E=32 [bottleneck too tight]), and per-position perplexity shows the gap widening while blocks are still being unlocked and persisting (though narrowing) beyond the training window.
- **What's *not* strongly supported**: the MLP/Hope-Attention parameter-gating extension is validated on only one architecture and is explicitly called "a proof of concept... rather than a fully validated result" by the authors themselves—this is a much thinner piece of evidence than the recurrent-memory results.

## Caveats — stated and inferred

- **Fixed, hand-designed schedule** (stated): the uniform growth schedule and block partition are manually chosen; the paper does not characterize what schedule is actually optimal or how it should depend on data or update rule.
- **MLP/Hope extension is a proof of concept** (stated): tested on a single architecture only, not a fully validated general result, despite being framed as showing generality "beyond recurrent memory."
- **Gains are conditional/neutral in easy regimes** (stated): where base models already saturate (e.g., simple NIAH pass-key retrieval), Proteus provides no benefit — the method only helps when long-context capacity is actually the bottleneck.
- **No inference-time schedule extension tested** (stated as future work): schedule is fixed at N = training context length (8K); beyond that, full memory is always active and Proteus adds no further gating, so its benefits at very long inference-time contexts stem only from residual "better compression," an open and only lightly probed question (checked to 32K in one ablation, Figure 4).
- **Uniform/mechanical schedule vs. data-dependent alternatives** (stated as future work): the authors explicitly flag that a learned, data-dependent activation policy might do better, meaning the current results represent a lower bound / simplest-case implementation of the idea, not a ceiling.
- **All experiments are pretraining-from-scratch on FineWeb at modest scale (760M/1.3B params, 50–100B tokens)** (inferred): no evidence is given for how Proteus behaves at larger model/data scale, or when applied to pretrained checkpoints rather than trained-in from scratch; scaling trends are not addressed in the paper.
- **Baselines may not be the strongest possible versions** (inferred): comparisons are against the authors' own reimplementations of SWLA, Comba, Titans, Hope-Attention (and simpler RetNet/DeltaNet/Transformer++ references); no comparison to other recent long-context/growing-memory approaches (e.g., log-linear attention, memory caching) is run empirically — these are only discussed qualitatively in Related Work as "orthogonal."
- **Single-seed / no variance reported** (inferred): the tables report point-estimate metrics (perplexity, accuracy, NIAH scores) with no confidence intervals, standard deviations, or multiple-seed runs, making it hard to judge whether the smaller deltas (e.g., some 0.1–0.3 point accuracy gains) are statistically meaningful.
- **Mixed/negative results within tables are somewhat downplayed** (inferred): some individual metrics do not improve or slightly regress with Proteus (e.g., SWLA's LMB perplexity at 1.3B goes from 16.95→17.18, worse; some PIQA/WinoGrande entries are flat or slightly down), while the surrounding text emphasizes "consistent improvement" — the true picture is consistent improvement in aggregate/average metrics but not uniformly per-column.
- **Simulation/benchmark-only evaluation** (inferred): all evaluations are standard NLP benchmarks (perplexity, zero-shot QA/commonsense, synthetic NIAH, retrieval/LongBench); there's no real-world deployment or downstream application test, though this is standard practice for this subfield and not necessarily a flaw unique to this paper.
