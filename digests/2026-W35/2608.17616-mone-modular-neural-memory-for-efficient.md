# MoNe: Modular Neural Memory for Efficient Long Context Inference

**Authors:** Wonguk Cho, Kyubyung Chae, Tribhuvanesh Orekondy, Sunghyun Park, Hyoungwoo Park, Jeongho Kim, Arash Behboodi, Kyuwoong Hwang, Sungrack Yun

**arXiv:** [2608.17616](https://arxiv.org/abs/2608.17616)

**Categories:** cs.AI, cs.CL, cs.LG

**Submitted:** 2026-08-18

**Relevance:** 9/10 — matched: LLM inference efficiency and long-context serving

## TL;DR
MoNe is a lightweight, modular fast-weight memory module that attaches to a frozen pretrained Transformer, letting it handle contexts far beyond its training window without retraining the backbone. It reads context once in fixed-size segments to update per-layer "fast weights" via test-time gradient steps, then answers queries by reading only from that memory (never re-attending to context tokens), giving O(N) preprocessing and O(1) query cost instead of ICL's O(N²). On a 0.5B Qwen backbone it holds near-perfect accuracy on RULER retrieval tasks up to 128K tokens (32× beyond its 4K training length) while cutting FLOPs/GPU memory ~80% versus in-context learning.

## First-principles breakdown

**The problem.** Standard Transformers answer questions about a long context by putting the whole context in the prompt (in-context learning, ICL) and letting self-attention scan it. Self-attention cost scales as O(N²) with context length N, and the KV cache grows as O(N), so both compute and memory balloon as documents get longer — prohibitive on resource-constrained hardware (e.g., mobile/on-device use). Small models compound this: even when a long prompt technically fits the context window, they struggle to reliably extract facts from it.

**Why prior fixes fall short.**
- *RAG* (retrieval-augmented generation) avoids full-context attention by embedding chunks and retrieving the top-k most similar ones at query time. But it works on independently embedded chunks, so it fails when an answer requires stitching together several scattered, individually-unremarkable facts (multi-hop reasoning).
- *Recurrent/linear-attention architectures* (Mamba, TTT, Titans) get linear-time context processing by design, but they're new architectures that must be trained from scratch — they can't be bolted onto an existing pretrained Transformer without full retraining.

**MoNe's mechanism, step by step.**
1. *Segment the context.* Split the N-token context into non-overlapping segments of T=512 tokens.
2. *Attach a small memory network per layer.* Each of the L decoder layers gets its own tiny SwiGLU MLP ("fast-weight" memory M) with parameters W = {W_in, W_gate, W_out}, each of size d_h × d_h (d_h = per-head dimension) — much smaller than the backbone.
3. *Test-time learning (the "read" phase).* For each segment, the frozen backbone's own (LoRA-adapted) key/value projections produce target key-value pairs (k, v) from the segment's tokens. The memory network is trained, via one gradient step per segment, to associate each key with its value by minimizing a loss that is just the negative inner product between the memory's output and the target value (no prediction/cross-entropy needed — this is "associative memory" learning, imprinting k→v associations directly into the weights). This is like a fast, per-example weight update — reminiscent of classic "fast weights" (Schmidhuber 1992) and recent Test-Time Training work, adapted here with per-layer localization.
4. *Layer-localized gradients.* Crucially, each layer's memory update uses gradients computed only from that layer's own local activations — no gradient flows backward through other layers (Eq. 11). This keeps updates cheap and makes the module truly "plug-in": you don't need to backprop through the whole frozen network to update memory.
5. *Sequential accumulation.* Segments are processed one after another, updating the fast weights W^(l)_0 → W^(l)_1 → ... → W^(l)_S, so by the end the memory has "absorbed" the entire context into a fixed-size set of weights (not a growing KV cache).
6. *Inference (the "write" phase).* At query time, no context tokens are touched at all. The query tokens are projected through the backbone's own query matrix and fed into the now-updated memory network, which generates a fixed number (T-sized) of "memory tokens" per layer. These are turned into keys/values (via the same frozen W_k, W_v) and concatenated onto the query's own attention computation — so the query attends to its own tokens plus a constant-size memory summary, not to the original N context tokens.
7. *Position handling.* Positions are assigned locally within each segment (mod T) via RoPE, so position indices never exceed [0, T) no matter how long the actual context is — this is why the same trained module generalizes to contexts far longer than what it was trained on.
8. *What's actually trained.* The backbone stays entirely frozen. Only small LoRA adapters on W_q/W_k/W_v and a handful of meta-parameters (per-layer learning rates, momentum-decay parameters, output scaling) are trained offline, on short contexts (up to 4K tokens), via a generation loss on the answer tokens. At deployment, the fast-weight update procedure itself is a fixed, pre-learned "algorithm" that runs without further training.

**Net effect:** context processing becomes a single linear pass (O(N)) that produces a constant-size memory state, and query answering becomes O(1) with respect to context length, since attention never revisits the N context tokens.

## Key insights

- **Genuinely new/distinct framing:** unlike Mamba/TTT/Titans (which require training a whole new architecture), MoNe is explicitly designed as a *plug-in* to an already-pretrained, frozen Transformer, using layer-local gradient updates to avoid backprop through the whole stack. This modularity is the paper's central claimed contribution and is directly supported by the described mechanism (Eq. 11 locality + small LoRA-only training cost).
- **Constant-memory, length-independent inference is a real structural property**, not just an empirical trend — because query tokens only ever attend to a fixed T-sized memory, peak GPU memory during inference genuinely doesn't grow with N (confirmed by their FLOPs/memory table: 1.41GB flat at both 32K and 128K).
- **Extrapolation claim is the most striking evidence-backed result:** trained only on ≤4K-token contexts, MoNe holds 0.94–0.96 accuracy at 128K tokens (32× extrapolation) on S-NIAH/MK-NIAH/FWE, while ICL collapses (down to 0.00 on MK-NIAH at 128K) and RAG plateaus below 0.80 on multi-hop retrieval. This is a well-supported claim, directly shown in Table 1, and plausibly attributable to the bounded local-RoPE positional scheme.
- **RAG comparison, when it holds:** MoNe's outperformance over RAG specifically on tasks needing synthesis across scattered facts (MK-NIAH) is a targeted, credible claim — matches the known weakness of chunk-independent embedding retrieval.
- **Ablations support specific design choices** (full 24-layer coverage and T=512 segment size both matter substantially for long-range generalization, more than for efficiency) — these are legitimate, if narrow, ablations included in the paper (Fig. 4).
- **What's a claim vs. evidence:** the "6.4% parameter overhead" and "~80% compute/memory reduction at 128K" figures are computed/measured (Table 2), so reasonably well-supported at least for the tested setup. But claims about applicability to "on-device personalization" and "continual learning" are motivational framing, not evaluated — the paper only tests synthetic retrieval benchmarks.

## Caveats — stated and inferred

- **Single, tiny backbone (0.5B params)** — stated as a limitation ("Current experiments validate MoNe's core properties ... using a Qwen2.5-0.5B backbone"). Nothing shown for larger, more capable models where the dynamics (and the relative cost/benefit trade-off) could differ substantially. `stated`
- **Only synthetic/controlled retrieval tasks evaluated** (S-NIAH, MK-NIAH, FWE from RULER) — stated as a limitation; authors explicitly flag that naturalistic long-document QA (HotpotQA, SQuAD) and real conversational histories (LoCoMo, ZeroSCROLLS) are "a natural next step," i.e., not yet tested. `stated`
- **Workshop paper, not a main-track publication** — this is from "The AdaptFM Workshop at ICML," which typically means lighter peer review than a full conference paper. `inferred`
- **No comparison to the closest architectural relatives** (TTT, Titans, LaCT, Mamba) despite discussing them at length in Related Work — only ICL and RAG are used as baselines; no head-to-head against the very lines of work motivating the design. `inferred`
- **RAG baseline uses fairly generic settings** (128-token chunks, BGE-Large embeddings, best of K∈{1,4,8} reported) — reasonable but not an exhaustive tuning of a RAG pipeline (no query rewriting, reranking, hybrid retrieval, etc.), so the RAG comparison may understate what a stronger RAG system could do. `inferred`
- **Training/eval data distribution is synthetic and narrow** — training uses only synthetically generated samples per fixed token-count bins (N∈{2,...,8} segments, 1K–4K tokens); no diversity in task type beyond the three RULER tasks, raising the question of whether the strong extrapolation generalizes to qualitatively different tasks (e.g., long-form summarization or reasoning-heavy tasks) rather than needle-style exact-match retrieval. `inferred`
- **Metric choice (substring exact match / recall) is lenient** — Sub-EM only checks if the correct answer appears as a substring anywhere in the output, which is a relatively forgiving metric compared to full-answer correctness or downstream task success; performance on more demanding generation/reasoning metrics is not addressed in the paper. `inferred`
- **No wall-clock latency numbers**, only FLOPs and peak memory are reported — actual end-to-end latency (which depends on hardware, kernel efficiency of the custom fast-weight updates, etc.) is not addressed in the paper.
- **Multi-query reuse and incremental context extension are claimed as benefits** ("final fast-weight state can be reused across multiple queries and incrementally extended") but no experiments directly measure or validate these properties. `inferred`
- **Ablations are limited to one task (MK-NIAH)** and one model — the layer-selection and segment-size ablations (Fig. 4) are not repeated across S-NIAH/FWE or other model sizes, so it's unclear how general those specific hyperparameter conclusions (e.g., T=512 optimal) are. `inferred`
