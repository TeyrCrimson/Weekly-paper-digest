# Unifying Depth and Width Pruning for LLMs via Binary Knapsack Optimization

**Authors:** Palaash Goel, Ayan Sengupta, Akshay Nambi, Tanmoy Chakraborty

**arXiv:** [2608.12953](https://arxiv.org/abs/2608.12953)

**Categories:** cs.CL, cs.LG

**Submitted:** 2026-08-13

**Relevance:** 9/10 — matched: LLM inference efficiency and long-context serving

---

## TL;DR
SNIPER is a structured LLM pruning method that first solves a 0/1 knapsack problem (via dynamic programming) to optimally select which coarse components (attention blocks, MLP blocks, or whole layers) to remove, then runs a second fine-grained pass that trims individual MLP neurons to hit the exact target compression ratio. Across 4 architectures, 18 tasks, and 6 baselines, it achieves the best average performance retention and lowest variance, plus near-perfect adherence to the compression budget (CRAFT = 0.98 vs. baselines' up to 33% deviation). The core claim is that replacing greedy, layer-by-layer pruning heuristics with a provably-optimal (conditional on fixed importance scores) selection procedure yields more stable and reliable compression.

## First-principles breakdown

**The problem.** LLMs are too big to deploy cheaply. Structured pruning removes whole chunks of a model (layers, attention heads, MLP columns) rather than individual weights, so the resulting model is still a dense, regularly-shaped network that runs fast on ordinary hardware (unlike unstructured/weight-level pruning, which produces irregular sparsity that needs special hardware to actually speed anything up).

**Why prior structured pruning falls short.** There are two granularities in use:
- *Depth pruning* (e.g., ShortGPT, SLEB) removes entire transformer layers. It's coarse, so it's hard to hit an exact target size (you can only remove whole layers, so you overshoot or undershoot the budget — the paper calls this "capacity slack," up to 33% deviation from target).
- *Width pruning* (e.g., SliceGPT, LLM-Pruner) removes rows/columns/neurons within layers. It's finer-grained (better budget control) but leaves irregularly shaped weight matrices that don't translate into real inference speedups.

Both families also use *greedy* decision-making: they typically score components (layers, heads, neurons) independently and prune the lowest-scoring ones one at a time or layer-by-layer, without considering how pruning decisions interact across the whole network. This is myopic — a component that looks individually weak might be important in combination with others, and vice versa.

**SNIPER's mechanism, step by step.**

1. *Formulate depth-axis pruning as a knapsack problem.* Every layer is split into two candidate items: its attention block (A_l) and its MLP block (M_l), plus a third "composite" option T_l representing keeping the whole layer intact. These are mutually exclusive per layer (you either keep the full layer T_l, or you separately decide on A_l and M_l). Each item has a weight (its parameter count) and a value (its estimated importance). The goal: pick the subset of items maximizing total value subject to a total parameter budget C — exactly the classic 0/1 knapsack problem.

2. *Solve it optimally with dynamic programming*, not greedily. The standard knapsack DP builds a table f(i,j) = max value achievable using the first i items within capacity j, with the recurrence "either skip item i, or include it and add its value to the best solution using the remaining capacity." Backtracking through this table recovers the optimal subset. Because raw parameter counts can be in the billions, running DP at that resolution is computationally intractable (time scales with N × C); the authors discretize weights by a rounding factor α, trading a bit of precision for orders-of-magnitude speedup (empirically, results are identical for α between 8 and 32,768; only extreme α causes overshoot).

   Important nuance: this only gives a "conditionally optimal" solution — optimal *given* the importance scores used, not a true global optimum over all possible prunings. But that's still strictly better than baselines' greedy heuristics, which offer no optimality guarantee at all.

3. *Importance scores come from an iterative marginal-contribution estimate.* Rather than scoring each component in isolation, SNIPER measures how much a component's removal changes the model's output logits relative to a *partially-already-pruned* model (i.e., importance is computed sequentially/iteratively on the model as components get removed, capturing some interaction effects between components) — a form of ablation-based sensitivity analysis using L2 distance between logits with vs. without the component.

4. *Fine-grained residual pruning (Stage 2) closes the gap to the exact target.* Because Stage 1 only removes discrete coarse chunks, there's usually leftover budget (ΔC) that can't be exactly matched by whole-block removal. Stage 2 prunes individual neurons/columns from the MLP's gate/up/down projection matrices (GLU-style MLPs) to consume exactly the remaining budget. Layers are allocated pruning budget in inverse proportion to their Stage-1 importance score (softmax over negated importance) — i.e., prune more aggressively from layers already deemed less important. Within a layer, individual neurons are ranked by a sensitivity score (the product of the down-projection row and elementwise gate/up columns) and the lowest-sensitivity neurons are removed first.

The combination gives coarse pruning's hardware-friendly speed benefits (removing whole blocks preserves regular tensor shapes) plus fine pruning's precision in hitting the exact compression target — addressing both failure modes (capacity slack and shape irregularity) at once.

**CRAFT metric.** A new metric, Compression Ratio Adherence Factor, quantifies how close the actual pruned model size lands to the requested target ratio — essentially measuring "does the method deliver the compression it promises."

## Key insights

- **Genuinely new**: framing coarse-grained (depth+block) structured pruning as an exact 0/1 knapsack problem solvable by dynamic programming, rather than a greedy heuristic. This is the paper's central mechanistic contribution, and the evidence (mean rank 1.25 across configs, Table 2; consistently high Avg RP with low Std RP across 4 architectures in Tables 1 and 3) supports that it meaningfully improves both average retention and cross-task stability over 6 baselines including a similarly two-stage method (2SSP).
- **Budget adherence (CRAFT) is a real, demonstrated advantage**: SNIPER hits 0.98 vs. baseline average 0.78, and this claim is well-supported since it follows almost mechanically from having an explicit fine-grained stage that fills the residual budget — this is more of an engineering/design win than a deep algorithmic insight, but it's a practically important one for real deployment (exact model-size targets matter for hardware fit).
- **Ablations support the claimed complementarity of the two stages** (Table 4, Figure 3): coarse-only pruning gets strong average retention but high task variance (unstable due to whole-block removal); fine-only pruning gets a bit better average retention with far lower variance but no real speedup (irregular tensors); combining both gets the best of both. This is a real, tested claim, not just assumed.
- **The importance-estimation approach and column-selection heuristic are validated by ablation**, not just asserted: replacing the marginal/iterative importance scoring with a "leave-one-out" scheme (as in SLEB) causes a ~20% performance drop, and replacing the neuron-sensitivity metric (Ωj) with magnitude- or activation-based alternatives costs 2–4% average performance and ~13% more variance. This is decent evidence the specific design choices matter, not just the overall two-stage architecture.
- **Transferability of importance scores across compression ratios** (Section 6.2, Table 6) is an interesting practical finding — reusing scores computed at one budget for pruning at a different budget costs only marginal performance, letting users skip the most expensive step (importance computation) when exploring multiple compression levels. This is evidence-supported but modest in magnitude (~0.2-1% Avg RP difference in most cases).
- **Interpretability claim** (Section 6.3, Figure 4): pruned layers cluster in the middle of the network across different compression ratios, which the authors present as evidence the importance signal captures "real" structural redundancy rather than noise. This is a plausible qualitative observation but is more suggestive than rigorously validated (it's based on visual inspection of one figure on one model, Phi-4).
- **Runtime tradeoff is disclosed honestly**: SNIPER is only ~4 minutes slower than pure depth-only pruning (~96% of time is importance estimation, reusable across runs), but it underperforms 2SSP in realized inference throughput (16.24 vs 20.26 tok/s) — the authors attribute this to SNIPER treating both attention and MLP blocks as coarse-grained candidates (more balanced but less throughput-optimal than 2SSP's attention-only coarse stage).

## Caveats — stated and inferred

- **Not a true global optimum** (stated): SNIPER's knapsack solution is "conditionally optimal" only with respect to fixed, heuristic importance estimates — it does not guarantee the best possible pruning configuration overall, and the authors explicitly note extending optimality guarantees to the importance-estimation stage itself is left as future work.
- **Homogeneous pruning signal for MoE models** (stated): the paper acknowledges SNIPER uses the same importance-scoring approach for Mixture-of-Experts architectures (GPT-OSS-20B) as for dense models, without expert-specific signals, which they flag as a likely suboptimal choice for that architecture class.
- **Discretization approximation** (stated/inferred): the DP is only tractable because parameter counts are coarsely discretized by factor α; while the paper shows a wide robust range (α = 8–32,768), at extreme values (100,000) the method visibly over-prunes (CRAFT jumps to 1.79), showing the tractability trick has real failure boundaries that require careful tuning per model scale — inferred that similar issues could arise on models with very different layer-size distributions not tested here.
- **Throughput trade-off downplayed somewhat** (stated but understated): SNIPER achieves lower actual inference speedup than 2SSP (16.24 vs 20.26 tok/s) despite being pitched as combining "hardware-friendly" depth pruning with fine pruning — the paper frames this as an acceptable trade for robustness, but a reader focused purely on latency should note SNIPER is not the fastest option among dual-axis methods.
- **Marginal loss on one configuration** (stated): SNIPER is outperformed by ReplaceMe and ShortGPT specifically on LLaMA-3.1-8B-Instruct at 25% compression with RFT — the paper is transparent about this exception to its "SNIPER never disintegrates" narrative, though it downplays it as a minor blip given the aggregate mean rank.
- **Evaluation limited to models obtainable via HuggingFace hub, no training-from-scratch or non-transformer baselines** (inferred): all four tested architectures are Transformer-family/decoder-only LLMs (dense, MoE, fused-MLP variants); no evidence is provided for encoder-decoder, vision-language, or substantially smaller/larger model families beyond the 8B–20B range tested, so generalization claims ("robust cross-architectural generalizability") are evidenced only within that band.
- **Recovery fine-tuning (RFT) dependency**: many of the strongest reported numbers are "with RFT" — post-pruning fine-tuning that recovers a large fraction of lost performance for all methods (compare (with RFT) numbers vs without in Table 1). The paper reports both settings, which is good practice, but readers should note that without RFT, degradation is much larger across the board — the framing throughout the results section leans on RFT'd numbers as the headline figures (inferred emphasis).
- **Calibration sensitivity analysis is somewhat narrow** (inferred): robustness to calibration set size/distribution is tested only on Qwen3-8B (Section 6.1, Table 5), not across all four architectures, so it's unclear whether the claimed "significantly less sensitive to calibration choices" generalizes to Phi-4 or GPT-OSS-20B.
- **Baseline re-engineering caveat** (stated): several baselines (ReplaceMe, ShortGPT) "do not natively support newer LLM variants" and were "re-engineered" by the authors to run on the tested architectures — this introduces a risk that baseline implementations may not be fully tuned/optimal versions of those methods, which could inflate SNIPER's relative advantage (inferred risk from a stated fact).
- **No confidence intervals or repeated-run variance reported** (inferred): all results appear to be single-run point estimates (Avg RP, Std RP across tasks) without seeds/repetitions noted, so it's unclear how much of the reported "mean rank 1.25" advantage would hold up under repeated runs versus measurement noise — not addressed in the paper.
