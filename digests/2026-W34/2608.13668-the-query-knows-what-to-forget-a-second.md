# The Query Knows What to Forget: A Second Erase Direction for Linear Attention

**Authors:** Dhruman Gupta, Aritra Das, Debayan Gupta

**arXiv:** [2608.13668](https://arxiv.org/abs/2608.13668)

**Categories:** cs.LG

**Submitted:** 2026-08-13

**Relevance:** 8/10 — matched: LLM inference efficiency and long-context serving

---

## TL;DR
Linear-attention models like Gated DeltaNet-2 derive their state-erase vector solely from the current key, but retrieval interference is actually measured through the query, leaving a blind spot the erase step can't touch. The paper adds a second, gated erase direction derived from the query (orthogonal to the key) called QED, which improves long-context retrieval accuracy at every length past the training window and roughly doubles usable context on S-NIAH-1. Gains hold across two training seeds on 340M-parameter models trained on 15B tokens, with no change in validation loss.

## First-principles breakdown

**The problem: fixed-size memory and interference.** Standard softmax attention keeps a cache that grows with sequence length — expensive but lossless. Linear attention instead compresses everything into a fixed-size matrix state `S_t`, updated recurrently, giving constant memory/compute per token. The cost is that this fixed-size state must hold *all* past key-value associations simultaneously. As context grows, more items are crammed into the same-size state, and reads become mixtures of the target item plus "interference" from unrelated stored items (Equation 5 in the paper makes this explicit: a read is a weighted sum over all stored keys, and any nonzero overlap between the query and an irrelevant stored key pollutes the answer).

**Prior fixes: the delta rule and its descendants.** DeltaNet introduced an "erase-then-write" update: before writing new content, it uses a rank-one correction `(I - β k k^T)` to erase whatever was previously stored at that key `k`, then writes the new value. Gated DeltaNet added a decay term so the state also forgets gradually over time (like an LSTM-ish forget gate). Kimi Delta Attention made that decay per-channel instead of a single scalar. Gated DeltaNet-2 (GDN-2) went further, splitting the single scalar controlling both erase and write into two independent channel-wise gates (erase gate `b_t`, write gate `w_t`).

**The core flaw this paper identifies.** Despite all these refinements, every one of these models still builds its erase vector purely from the *current key* (`k_t`, or a gated version of it). But when the model *reads* from the state later, it uses the *query* to select what to retrieve. The key and query are different directions in vector space. Mathematically, the paper shows (Eq. 9) that a key-directed erase update can only change the state's response along `k_t` — it cannot affect the part of the state that's orthogonal to the key. Yet a later read via a query `q_t` picks up exactly that key-orthogonal component too (decompose `q_t = ρ_t k_t + q_t^⊥`). That `q_t^⊥` component carries old, stale content that the erase mechanism structurally cannot clean up, no matter how the gates are tuned. This is the "mismatch" the title refers to: the query knows what's contaminating its own read, but the erase step, being key-locked, can't act on that information.

**The fix: QED (Query-derived Erase Direction).** The authors add a second term to the erase vector: instead of just `a_t = b_t ⊙ k_t`, they use `a_t = b_t ⊙ k_t + λ_h · P⊥_kt(b_t ⊙ q_t)`. Breaking this down:
- `b_t ⊙ q_t`: take the query, and gate it channel-wise with the same erase gate `b_t` (so the correction only fires on channels the model has decided are being overwritten).
- `P⊥_kt(...)`: project this out of the key direction (`x - k(k^Tx)`), so the new correction only touches the part of the state the original key-based erase *couldn't* reach — it doesn't interfere with or duplicate the existing key-based erase.
- `λ_h`: a learned, per-head scalar strength (bounded by a sigmoid, capped at 0.25) controlling how strong this new correction is.

The intuition: the query itself now gets to "vote" on what stale content to erase, precisely along the direction that would otherwise leak into future reads through that query. Because the correction is orthogonal to the key, it doesn't change the eigenvalue structure that governs the original delta-rule stability (they verify this empirically — the effective correction rarely gets near the theoretical instability boundary). The added compute is one extra dot product and one subtraction per token/head — negligible.

**Why they can be confident this specific mechanism (not just "more capacity") is doing the work:** they ran ablations that strip components: no gate, no gate+no projection, and a "random direction" control where the query is replaced by a fixed random unit vector but gate+projection are kept. If QED's improvement came from just having more trainable parameters or more correction capacity in general, the random-direction control should do about as well. Instead, QED-rand consistently underperforms full QED, isolating the query-derived direction (not the extra parameters) as the active ingredient.

## Key insights

- **Novel diagnosis, not just a novel mechanism**: the paper's real contribution is identifying *why* delta-rule erasure is structurally incomplete — it's key-locked while reads are query-driven — expressed cleanly via the fast-weight/online-learning view (Eq. 9-12). This framing is a genuine conceptual contribution, and it's used to derive the fix rather than being a post-hoc explanation.
- **What the evidence actually supports**: across two seeds, QED (full) improves S-NIAH-1 accuracy at every length beyond the 2048-token training window (e.g., seed 0: 21.8%→39.8% at 16K; up to 39 point gains, per abstract) and improves FDA recall by ~3.4-3.7 points, with no loss in validation perplexity — evidence this is a targeted retrieval fix, not a general capacity increase.
- **What's NOT well-supported**: the claim that the specific design choices (channel-wise gating, key-orthogonal projection) are individually necessary is *not* established — the authors explicitly say these effects "reverse between seeds" and remain "inconclusive" (Figure 2, Section 6). Only the "use the query" component is consistently validated (via the QED-rand control beating... being beaten by full QED consistently).
- **SQuAD-completion and SWDE show null/mixed results**, and the authors are upfront that this suggests the mechanism specifically helps long-range retrieval/interference, not comprehension generally — a reasonably honest scoping of the claim.
- **The "eigenvalue safety" analysis is an interesting negative result**: they built the orthogonal projection as a theoretical safeguard against instability, but empirically found the unprojected correction never got near the danger zone at this scale — meaning the projection's stated purpose is currently "inactive" as measured, an honest admission that undercuts their own design justification somewhat.

## Caveats — stated and inferred

- **Single small model scale (340M params, 15B tokens)** — `stated`: authors explicitly call for "more training runs, model scales, context lengths" in Further Work; results may not hold at production LLM scale.
- **Only two random seeds** — `stated`: ablation component-level effects (gate, projection) "reverse between the seeds," and authors say conclusions are drawn "only from effects that are consistent across the matched 15B runs," implicitly admitting the sample size is too small for firm component-level claims.
- **Inconsistent inference-time strength test between checkpoints** — `stated`: one checkpoint shows monotonic accuracy gains with increased correction strength, the other shows no consistent direction (≤2.4 point movement); authors explicitly say this "does not show how much QED-trained models rely on the correction."
- **No training-time sweep over λ_max** — `stated`: the cap of 0.25 was fixed a priori; authors note a "training-time sweep over λ_max is needed" to know if this bound constrained results at all.
- **Narrow evaluation suite** — `inferred`: only RULER S-NIAH (1/2/3) and three Based recall tasks (SWDE, FDA, SQuAD-completion) are used; no broader downstream tasks (e.g., standard LM benchmarks, real long-document QA, code) are evaluated, so generality beyond synthetic needle-in-haystack retrieval is unverified.
- **SWDE and SQuAD-completion are null/mixed results reported alongside the positive FDA/S-NIAH numbers** — `stated`, but worth flagging: the abstract and conclusion emphasize the positive S-NIAH-1/FDA numbers prominently while the weaker/null results are less foregrounded — a mild selective-emphasis pattern, though the paper does report the negative results transparently in tables.
- **Comparison baselines are all from the same lineage (DeltaNet family)** — `inferred`: no comparison to non-linear-attention long-context approaches (e.g., sparse attention, retrieval-augmented methods, or hybrid architectures) is included, so it's unclear how QED-improved GDN-2 stacks up against alternative long-context solutions outside the delta-rule family.
- **"Doubles usable context" claim is based on one specific accuracy-threshold framing** — `inferred`: the "approximately 8K to 16K" extension claim (Section 6) is derived from where accuracy crosses some implicit comparable threshold across arms/lengths, not a formally defined metric stated up front; readers should treat the "about doubles" framing in the abstract as a paraphrase of this rather than a directly reported statistic.
- **Simulation/synthetic retrieval tasks only** — `inferred`: S-NIAH and Based-recall tasks are synthetic probes designed to stress exactly the interference phenomenon the paper targets, which is appropriate for isolating the mechanism but means real-world task performance (e.g., actual long-document reasoning) is not addressed in the paper.
