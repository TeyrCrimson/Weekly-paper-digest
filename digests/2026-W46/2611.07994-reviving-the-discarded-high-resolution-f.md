# Reviving the Discarded High-Resolution Feature for Transformer-Based Tiny Object Detection

**Authors:** Zehao Wang, Si Wu, Guiping Cao, Xin Li, Yaowei Wang

**arXiv:** [2611.07994](https://arxiv.org/abs/2611.07994)

**Categories:** cs.CV

**Submitted:** 2026-11-05

**Relevance:** 9/10 — matched: Onboard object detection from a moving UAV

---

## TL;DR
ReDHF is a plug-in module for DETR-style detectors that brings back the highest-resolution backbone feature map (normally thrown away for efficiency) and makes it usable for tiny-object detection without exploding compute or flooding the model with background noise. It does this via three pieces: a cheap semantic-enhancement+fusion module (CSDF), a training-only auxiliary supervision signal shaped to tiny objects (EGSS), and a decoder attention change that lets queries directly sample the high-res feature (FSQI). Across three DETR variants and three tiny-object benchmarks (AI-TOD-v2, VisDrone, SODA-D), it adds consistent AP gains (+1.1 to +1.6 AP, larger on tiny/small-object metrics) for a modest compute increase (e.g. +53 GFLOPs vs. +2700 GFLOPs for naively adding the raw feature).

## First-principles breakdown

**The underlying problem.** Object detectors process an image through a backbone (e.g. ResNet) that progressively downsamples it into a pyramid of feature maps at different resolutions/strides (stride 4, 8, 16, 32...). Each downsampling step aggregates nearby pixels, which is good for building up semantic understanding ("this region is a car") but bad for tiny objects: an object that's only a few pixels wide can shrink to sub-pixel size by the time it reaches a stride-16 or stride-32 map, i.e. its information is simply gone. The datasets used here (AI-TOD-v2, VisDrone, SODA-D — aerial/traffic imagery) are full of such "ultra-tiny" objects (short side ≤4 px), far more than in standard benchmarks like COCO.

**Why prior approaches fall short.** DETR-like detectors (Deformable DETR, DINO, etc.) are transformer-based: they flatten feature maps into tokens and use (deformable) attention to let a fixed set of "queries" look up image evidence and output boxes. These detectors typically keep only features from stride 8 downward (discarding the stride-4 "highest-resolution" feature, C1) because the token count scales with spatial size — attention over a stride-4 map is roughly 4x the tokens of stride-8, and deformable/global attention costs scale with token count, making it expensive. Simply re-adding C1 naively (as the paper measures) balloons encoder cost by >10x (203→2709 GFLOPs) because every layer must process far more tokens. Worse, C1 is "shallow" — it hasn't been through enough layers to acquire semantic meaning, so it responds strongly to arbitrary edges/textures in the background, not just to real objects. So there's a double problem: (1) raw cost of using it, (2) raw noisiness of it.

**CSDF (Cross-Scale Deformable Fusion) — make the high-res feature affordable and meaningful.**
Step 1: Take C1 (raw highest-res backbone feature) and P2 (the next level up, after some encoder processing, which already has decent semantics). Upsample P2 to C1's resolution, concatenate with a projected C1, and pass through a lightweight fusion block (RepNCSPELAN4, a known efficient conv block). This produces P1 — a version of C1 that inherits semantic context from P2, so it's less purely "raw edges" and more "object-aware."
Step 2: Now use P1 to enrich P2 itself. Instead of expensive dense/global attention between P1 and P2 (which would be costly because P1 has far more tokens), use deformable attention where P2 is the query and P1 is key/value — each P2 location only samples a handful of relevant points in P1 rather than attending to all of them. This is the trick that makes it cheap (cost ∝ number of sample points K, not the full token count of P1). The retrieved detail is fused back into P2 via a 1x1 conv + norm + activation to produce P2′, the "detail-enhanced shallow feature."

**EGSS (Ellipse-Guided Shallow Supervision) — keep P2′ honest during training.**
Because P2′ now contains high-res detail, it also risks carrying over background noise from P1. EGSS attaches a temporary (training-only, FCOS-style) auxiliary classification+regression head onto P2′ so that it's explicitly pushed to recognize real objects rather than texture. The twist is in how "positive" training locations are chosen: instead of the usual box-shaped region or fixed-radius circle around an object's center (which either includes too much background near object corners, or fails to adapt to elongated/thin objects), they use an ellipse matched to each ground-truth box's aspect ratio, plus a scale filter so only objects sized appropriately for this feature's receptive field count as positives (very large objects are excluded — a point on this shallow feature can't "see" a whole big object anyway, so forcing it to try would just inject confusing signal). Regression loss weight is kept low because tiny-object boxes are inherently noisy to regress precisely. This head is deleted at inference time — it costs literally nothing at test time; its only job was to shape P2′'s features during training.

**FSQI (Full-Scale Query Interaction) — let the final decoder see the high-res detail.**
In DETR, after the encoder builds a "memory" (set of per-location feature tokens), decoder queries (learned slots representing candidate objects) use cross-attention to pull information from memory and refine into final box predictions. Normally memory excludes the highest-res feature for cost reasons. FSQI concatenates P1 (the semantically-enhanced high-res feature) and P2′ along with the deeper pyramid levels into one combined memory, so queries can cross-attend into P1 directly for fine-grained cues. To avoid noise, P1 is excluded from the step where queries are initially selected/seeded (only used during cross-attention lookup) and it's given more deformable sampling points (8 vs. 4) since its finer grid needs a larger effective "search radius" per query to gather enough signal.

**Net effect:** three cooperative edits — build a smarter high-res feature cheaply (CSDF), discipline it during training (EGSS, free at test time), and expose it to the final prediction stage (FSQI) — together let the detector use information that was previously thrown away, specifically benefiting objects whose only distinguishing signal lives in that highest-resolution map.

## Key insights

- **Genuinely new**: the combination of (a) semantically "pre-digesting" the raw high-res feature before fusing it (rather than fusing it raw), (b) an ellipse+scale-filtered auxiliary supervision scheme tailored to a shallow feature's limited receptive field, and (c) exposing that enhanced feature to decoder cross-attention while excluding it from query initialization. Each piece individually borrows known techniques (deformable attention, FCOS-style auxiliary heads, RepNCSPELAN4 fusion blocks, elliptical geometric assignment is a twist on circle/box assignment) — the novelty is the specific combination and the diagnosis that reviving C1 is a three-part problem (cost + semantics + noise), not just one.
- **Supported by evidence**: consistent AP gains across 3 datasets × multiple baselines (DINO-4scale, DQ-DETR, Dome-DETR variants), with larger gains specifically on tiny/very-tiny/extremely-small metrics (APvt, APs, APeS) than on overall AP — this is the expected and verified signature if the mechanism really targets tiny objects. The ablation table (Table 3) decomposes contributions reasonably cleanly: raw C1 alone *hurts* (32.1→31.1 AP), P1 (semantically enhanced) helps, and components are shown to be complementary rather than redundant. The compute-matched comparison against simply scaling input resolution (Table 9) is a good control showing the gain isn't just "more pixels/more FLOPs" but the specific mechanism.
- **Claimed but only partially supported**: "efficient" framework — true in GFLOPs (+53 vs +2700 GFLOPs for naive C1 use) but the actual wall-clock/memory cost increase is non-trivial (Table 10: +98-208ms latency, >2x peak GPU memory increase in some cases), which is a real practical cost the GFLOPs framing understates.
- The claim that the approach is "plug-and-play" is supported by it being tested on three distinct DETR variants with consistent gains, suggesting genuine generality rather than overfitting to one architecture.

## Caveats — stated and inferred

- **Localized degradation on large objects in dense scenes** (stated) — explicitly admitted in the Conclusion ("we only observe localized degradation for large objects in dense scenes with smaller-capacity variants"), detailed further in an appendix section (F) not included in the provided text.
- **Additional inference cost not fully reflected by GFLOPs** (stated, in Appendix D.3) — latency increases of 98–208ms and peak GPU memory roughly doubling or more in some configurations; the headline "efficiency" framing (86.7% GFLOPs reduction vs. naive fusion) is true relative to a strawman baseline (raw C1 fusion) but the absolute added latency/memory versus the *original baseline* (no high-res feature at all) is still substantial.
- **Benchmarks are a narrow domain cluster** (inferred) — all three evaluation datasets (AI-TOD-v2, VisDrone, SODA-D) are aerial/traffic/drone imagery with similar tiny-object statistics; no general-purpose benchmark (e.g., COCO) result is shown in the main text (though referenced as covered in "Appendix E" which is truncated in the provided text), so generality beyond this domain cluster is not fully verifiable from what's given here.
- **Backbones and baselines are moderately dated/limited in scope** (inferred) — all tested detectors use ResNet-50 or HGNetv2 backbones; no comparison with more recent large-scale vision backbones or very recent 2026 detectors is shown, and CNN-based baselines compared against (e.g., Cascade R-CNN, DetectoRS) are older architectures, making the "state-of-the-art" claim mostly a comparison within DETR-family lineages plus a few CNN baselines rather than the broadest possible field.
- **Error bars / statistical significance**: the paper reports mean/std over 3 seeds only for one specific setting (AI-TOD-v2, full model, referenced as Table 21 in an appendix not included in this extracted text) (stated, per the NeurIPS checklist included) — the main results tables (1, 2, 6, 7) report single-run numbers without variance, so the stability of the reported gains (some as small as +1.0–1.5 AP) across runs is not verifiable from the main text.
- **Appendix-dependent claims**: several important qualifiers (full limitations discussion in "Appendix F," cross-scale generalization in "Appendix E," sampling-point and loss-design ablations in "Appendix G") are referenced but not present in the extracted text provided, so those specific claims could not be independently checked here — flagged as "not addressed in the paper" (i.e., not in the given text) rather than assumed to be adequate.
- **EGSS design choices (no centerness supervision, low regression loss weight) are justified heuristically, not ablated against alternatives in the visible main text** (inferred) — the paper states these choices are "empirically validated in Appendix G.6," which is outside the provided text, so the main-text justification is argued rather than directly evidenced here.
