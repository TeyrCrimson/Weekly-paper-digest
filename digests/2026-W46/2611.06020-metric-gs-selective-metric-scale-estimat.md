# METRIC-GS: Selective Metric-Scale Estimation for 3D Gaussian Splatting

**Authors:** Sooyeun Yang, Jongseong Brad Choi

**arXiv:** [2611.06020](https://arxiv.org/abs/2611.06020)

**Categories:** cs.CV

**Submitted:** 2026-11-04

**Relevance:** 8/10 — matched: Metric and temporally-consistent monocular depth

---

## TL;DR
3D Gaussian Splatting reconstructions come out of structure-from-motion in arbitrary (non-metric) units, and the two existing fixes for recovering real-world scale — a ceiling-height heuristic and metric-depth alignment — are both wildly unreliable on real captures (27%–71% error). METRIC-GS instead measures familiar objects (doors, tables, floor-to-ceiling gaps) in the scene via a frozen 2D segmenter, fuses these into a single scale estimate with a robust statistical method, and explicitly refuses to answer when the evidence is too thin, routing those refusals to a more expensive but more accurate metric reconstruction model (MASt3R). This "selective hybrid" matches running the expensive model on every scene while invoking it 60% less often, and the paper also shows that a competing feed-forward metric model's reported 2.3% error balloons to 28–35% once tested outside its training distribution.

## First-principles breakdown

**The core problem.** 3D Gaussian Splatting (3DGS) builds a photorealistic 3D scene from photos by optimizing a cloud of "Gaussian blobs" (each with a position, orientation/size, opacity, color) to match the input images, starting from a point cloud produced by Structure-from-Motion (SfM/COLMAP). SfM can only recover shape up to an unknown global scale factor — it doesn't know if a room is 3 meters or 30 meters across, because the same images result either way (just with correspondingly scaled camera motion). This is fine for rendering but useless for anything that needs real measurements: AR objects placed at correct size, robot navigation, measuring a room. Someone has to inject a scale factor.

**Why the existing fixes fail.** Two standard tricks exist:
1. *Quantile heuristic*: Assume room height is roughly a fixed value (e.g., 2.5m), measure the point cloud's vertical extent, and scale to match. Fragile because outlier points (noise, ceiling fixtures, etc.) corrupt the extent measurement — on 5 real tape-measured rooms it's off by 27% on average.
2. *Metric-depth alignment*: Run a monocular depth network (which predicts real-world depth, e.g. Depth Pro, MoGe-2) on the images, then rescale the SfM reconstruction to match that network's depth values. This fails because these depth networks have systematic biases specific to indoor scenes, and three different networks disagree with each other by up to 2.5x — so the "fix" imports a different, opaque error source.

**This paper's mechanism.** The insight: indoor scenes contain many objects with standardized or tightly-distributed real-world sizes — doors (~2.03m), tables (~0.74m), the floor-to-ceiling gap (~2.5m), etc. If you can identify these objects in the 3D reconstruction and measure their size in the model's arbitrary units, each one gives you a noisy "vote" for what the true scale factor should be, and many independent votes over-constrain the answer far better than any single cue. The pipeline:

1. **Semantic labeling via visibility-aware voting.** A frozen, off-the-shelf 2D image segmenter (Mask2Former) labels pixels in each training photo (door, table, floor, etc.). Each Gaussian blob, when projected into multiple camera views, collects "votes" for its class from whichever labeled pixels it lands on. The naive version of this breaks: if a Gaussian is occluded in a given view (hidden behind something), it still gets projected onto a 2D pixel and inherits that occluder's label — garbage vote. The fix is a one-sided visibility test: a view's vote only counts if the Gaussian's actual depth from the camera is less than (not just close to) the depth the model itself renders at that pixel, with a small tolerance. This asymmetry matters because a symmetric test would also throw out correct floor votes (floors are seen at grazing angles where depth rendering is noisy in either direction). This single design choice nearly doubles the number of scenes where enough reliable object measurements exist to say anything at all (16 → 28 of 47 test scenes), without changing accuracy on scenes that already worked — i.e., it's a coverage fix, not an accuracy fix.

2. **Instance-level measurement.** Gaussians sharing a label are split into spatial clusters (connected components in a 3D voxel grid) to isolate individual object instances (e.g., distinguishing one door from another), each yielding a measured extent along the semantic "up" axis (chosen as whichever of several candidate directions best separates floor from ceiling).

3. **Robust fusion into one scale factor.** Each measured object instance is a "cue": a measured size in model units, paired with a known real-world size prior (mean ± standard deviation, with a hand-set reliability weight — doors trusted more than TVs, say). These cues are combined via a maximum-likelihood fit using a robust loss (Geman-McClure, which saturates for outliers instead of being dragged by them — unlike ordinary least-squares), regularized toward the cheap heuristic's initial guess. The objective is optimized incrementally during 3DGS training (so even the model's own growth/pruning rules, which operate in real-world units, stay meaningful) and re-solved more carefully after training finishes.

4. **Abstention (the key trick).** After fitting, the method computes an "inlier mass" — essentially, how much total cue weight actually agrees with the fitted answer. If too little evidence agrees (below a threshold), the system explicitly refuses to apply its correction and just falls back to the original cheap heuristic, rather than confidently reporting a possibly-wrong number. This same abstain signal is reused as a router: scenes the system is unsure about get sent to a much more expensive but more accurate alternative (MASt3R, a learned feed-forward 3D reconstruction network), while confident scenes are handled cheaply in-house.

The result is a system that is cheap (~11 seconds overhead) and self-aware about its own reliability, as opposed to the baselines which always produce a confident number whether or not it's trustworthy.

## Key insights

- **Genuinely new**: treating metric scale recovery as a "selective" estimation problem — building in principled abstention rather than always guessing — is the paper's central novel idea, and the abstention signal usefully doubles as a free router to a more expensive fallback model. This routing result (matching full MASt3R accuracy at 60% fewer calls) is explicitly flagged by the authors as their strongest and most important contribution, over raw accuracy.
- **Visibility-aware voting** is a focused, well-justified fix to a specific failure mode (occlusion poisoning naive multi-view label voting) and is shown (via ablation) to buy coverage (16→28 usable scenes) without hurting accuracy — a clean, evidence-backed claim.
- **Robust fusion of many weak semantic cues** beats single-cue approaches mainly by eliminating catastrophic failures, not by improving typical-case accuracy (median error is similar to simpler ablations; it's the mean/worst-case that improves 2.4x). This is a real but more modest claim than "our fusion is highly accurate."
- **The benchmark-contamination finding** — that MoGe-2 scores 2.3% on ScanNet++ (which is literally in its training set) but 28–35% on the authors' own unseen captures — is a valuable, well-supported, somewhat independent contribution: a caution against trusting published metric-scale benchmark numbers generally, not specific to this paper's method.
- **What the evidence does NOT support**: that this method is more accurate than existing alternatives in general. MASt3R remains more accurate as a standalone estimator (9.9% vs 16.6% overall), and on one in-regime ETH3D scene MoGe-2 beats this method too. The claimed advantage is reliability/cost/coverage in a specific deployment niche (ordinary photo-only indoor captures), not raw accuracy superiority.

## Caveats — stated and inferred

- **Narrow operating regime, by design** (stated): the method only works on real (non-synthetic) indoor photos where architectural/furniture anchors are actually visible; it fails outright on synthetic renders (breaks the frozen 2D teacher), outdoor scenes, and close-ups that never frame a wall/door.
- **Partial-instance failure mode is unsolved** (stated): when objects are only partially reconstructed or labeled, multiple partial cues can "confidently agree" with each other while being collectively biased, and the abstention gate cannot catch this because it only measures agreement, not completeness. The paper's own uncertainty-calibration study (bootstrap confidence intervals) confirms no cue-agreement-based statistic can distinguish this failure within the active scenes.
- **Accuracy is bounded by, and sensitive to, the choice of 2D segmenter** (stated): swapping in a stronger segmenter (Swin-L) notably improves results on a subset, meaning headline numbers partly reflect an off-the-shelf model's limitations rather than the method's ceiling.
- **The nominal room-height prior is "the one sensitive input"** (stated): varying the assumed value from 2.1–3.0m shifts mean error from 13.8% to 25.3%, a fairly wide swing.
- **Weak ground truth in the in-the-wild deployment study** (stated): the 13 self-collected phone/drone captures are scored against a nominal per-venue ceiling height, not a tape measure or laser scan, so these numbers are explicitly flagged by the authors as "transfer evidence, not a second accuracy result."
- **Small sample sizes for the strongest real-world claims** (stated/inferred): the "improves all five captures it acts on, degrades none" headline result is based on only 5 acting captures out of 13, and the authors themselves call this "a small sample."
- **MASt3R comparison may understate the competing model family** (stated): the authors note MASt3R's own successors (MapAnything, AMB3R) are not evaluated, so the reported MASt3R accuracy is described as "an upper bound on that family's error" — newer competitors might do better, weakening the routing-savings claim's durability.
- **Benchmark contamination complicates the ETH3D/MoGe-2 comparison** (stated): exposure to training data and capture quality (DSLR vs. phone) co-vary across their test sets, so the authors admit they "cannot separate the two" factors.
- **Hand-tuned priors not learned** (inferred): the 19 anchor-class size priors and reliability weights are manually set from "public architectural standards" and "never tuned per dataset" — this is a reasonable design choice for generalization, but it's also a source of untested bias/coverage gaps (e.g., non-standard furniture, international building codes) not explored.
- **Single hardware/GPU, single segmenter backbone, relatively small benchmark counts** (inferred): main results rest on 47 ScanNet++ scenes plus small held-out sets (50 ARKitScenes videos, 4 ETH3D scenes, 13 self-captures) — modest scale for claims about general deployment readiness, though the authors do emphasize a frozen pre-registered configuration as a mitigating rigor measure.
- **Cost savings are described by the authors themselves as modest in absolute terms** (stated): "the saving alone does not justify the system: at ~4 min per abstained scene it is modest beside a 6–16 min reconstruction" — a notably self-critical admission that tempers the headline "60% fewer invocations" framing.
