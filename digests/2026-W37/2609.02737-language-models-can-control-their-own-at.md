# Language Models Can Control Their Own Attention

**Authors:** Namgyu Ho, Huzama Ahmad, Woosung Koh, Se-Young Yun, Tal Schuster, Cicero Nogueira dos Santos

**arXiv:** [2609.02737](https://arxiv.org/abs/2609.02737)

**Categories:** cs.CL, cs.AI, cs.LG

**Submitted:** 2026-09-02

**Relevance:** 9/10 — matched: LLM inference efficiency and long-context serving

---

## TL;DR
Declarative Attention (DA) prompts off-the-shelf LLMs to explicitly tag, inside their own chain-of-thought, whether they need to see the whole context (`<global>`), a specific chunk (`<focus>`), or nothing but prior output (`<local>`), and an inference-engine state machine uses these self-declared tags to skip most of the KV cache read. On Gemma-4-31B and Qwen-3.6-27B across 15 long-context tasks, this cuts attended tokens by 52.0% and 31.1% respectively for accuracy drops of only 1.27pp and 2.75pp, with the gap shrinking as model scale increases. It's a zero-shot prompting technique (no training) integrated into vLLM with block-aligned KV masking, projected to cut decode wall-clock to 0.71–0.77× of vanilla.

## First-principles breakdown

**The problem.** Transformer decoding is memory-bandwidth-bound at long context lengths: at every single decode step, the model must read the entire KV (key-value) cache — the stored representations of every prior token — from memory, even though empirically only a small fraction of those tokens actually matter for the current output token. For a 1M-token context, this means loading tens of gigabytes per step just to produce one new token, comparable to the cost of loading the model's own weights.

**Why prior fixes fall short.** Since you don't know in advance which tokens will matter (attention scores are only computed after doing the full computation), people either (a) use static heuristics like "keep recent tokens" or "keep tokens that were attended to a lot before" (e.g., StreamingLLM, H2O) — these are cheap but blind to what the *current* query actually needs, hurting accuracy; or (b) run a lightweight scoring pass over the whole KV cache at every step to *approximate* which tokens are relevant (e.g., Quest, DeepSeek's sparse indexer) — more accurate, but this scan itself still costs O(N) per step, so the fundamental scaling problem isn't solved, only its constant factor is reduced.

**The reframe.** The authors ask: the model already "knows" (via reasoning) what it needs to look at — why not have it just say so in text, instead of an external system trying to guess it from hidden activations? This is analogous to how chain-of-thought prompting exposes latent computation as readable text; DA extends that from "what to think" to "where to look."

**The mechanism.** DA structures the prompt into a fixed "scaffold" (system instruction, question, protocol instructions) that's always visible, plus a "context" region split into ~2K-token addressable chunks ("magic chunks"), delivered via a simulated tool-call transcript (formatted to look like the model retrieved each chunk with a `get_magic_chunk` tool call) so that chunk boundaries align with token boundaries the model already knows well from post-training (message/tool-turn delimiters), rather than arbitrary new markup.

During generation, the model freely interleaves three tagged modes:
- `<global>`: can see all chunks — used to decide which chunk to look at next (navigation).
- `<focus magic_chunks="K">`: can see only chunk K — used to extract a specific fact verbatim.
- `<local>`: can see none of the context, only its own prior output — used for synthesis/final reasoning.

A "DA state machine" inside the inference engine parses these tags as they're generated (like parsing tool calls) and, at each decode step, rewrites which KV cache blocks are visible to the attention kernel. Because vLLM stores KV cache in fixed-size blocks (16–32 tokens) and reads whole blocks, the mask is rounded to block boundaries so masking translates into actually skipping memory reads (not just zeroing out attention weights after the fact) — this is what differentiates DA from a masking scheme that saves no real I/O. Because segments are large, this incurs at most a few dozen wasted tokens at each mask edge.

**The economic argument (roofline model).** DA trades more decode steps (the model "thinks" more, ~15–35% more steps) for a cheaper per-step cost (less KV to read). Whether that trade is worth it depends on deployment regime: in large-batch serving, FFN compute cost is amortized across the batch and becomes compute-bound with a roughly fixed per-step cost, while attention KV reads remain memory-bound and scale with context length — so at long context, attention dominates decode latency, and that's exactly where DA's savings pay off most. The paper estimates (not measures) that this translates to 0.71–0.77× vanilla decode wall-clock time on optimized B200 serving.

## Key insights

- **Genuinely new framing**: using the model's own declared reasoning trace as the source of the sparsity mask, rather than approximating attention importance from proxy scores/hidden states. This removes the O(N) per-step selection cost entirely — selection now happens implicitly during the (already necessary) generation of reasoning tokens.
- **Zero-shot, no training required**: works on off-the-shelf models via prompting alone; prior related work (Self-Selected Attention Span, Jin et al. 2024) needed task-specific fine-tuning on short (2K-token) contexts. This generalization to 100K+ token zero-shot settings is the paper's main empirical claim, and the evidence (Table 2, 15 tasks, two model families) supports it reasonably well for the two largest models tested.
- **Ablation isolates the real source of savings**: the "DA-no-mask" control (same prompt/tags, but full attention) shows the *chunked prompt format itself* is nearly accuracy-neutral (matches vanilla within 0.7pp) but actually *increases* attended tokens (more decode steps, no masking benefit). This convincingly shows the efficiency gain comes specifically from the mask, not from some prompting-format side effect — a well-designed ablation, not just an add-on control.
- **Positive scaling trend**: accuracy gap to vanilla shrinks monotonically with model size in both families (29%→99% relative accuracy from smallest to largest Gemma), and the authors argue (plausibly, per their own framing) that they are reporting a *lower bound*, since post-training on the protocol could further close the gap. This is a claim about future potential, not something the paper demonstrates.
- **Absolute savings scale with context length** (up to 21M tokens saved per response at longest contexts) even though relative accuracy erodes somewhat there — meaning the technique's value proposition specifically strengthens as context grows, which is the regime it's designed for.
- Distinguishing claim vs. evidence: the wall-clock speedup (0.71–0.77×) is a **roofline projection at assumed MFU/MBU utilization values**, not a measured benchmark on real serving infrastructure — this is a claimed potential, not directly demonstrated.

## Caveats — stated and inferred

- **Non-thinking mode only** (stated): models failed to follow the DA protocol inside "thinking" traces in preliminary experiments, so all results use non-thinking mode — a real limitation given current frontier models increasingly reason via extended thinking/interleaved tool calls.
- **Zero-shot elicitation is acknowledged as suboptimal** (stated): the authors explicitly say DA runs ~15–35% more decode steps than vanilla and that "a similar RL/SFT pipeline could elicit more optimal use of DA" — meaning the reported numbers are not a ceiling, but also not what a trained system would achieve; the training-based upside is speculative/future work, not demonstrated.
- **Explicit failure modes acknowledged** (stated, Appendix D.4): 6 of ~21 sources considered were excluded or shown to fail — cases where segmentation destroys needed global information (e.g., counts across all segments, tables split across chunks) causing accuracy collapse (−30pp), or where output length scales with document length, causing attended tokens to *increase* over vanilla despite per-step savings. Some benchmarks (ruler_qa_1/2, cwe, fwe, vt) were skipped entirely because their fixed prompts forbid intermediate reasoning, which is structurally incompatible with DA.
- **Smallest models fail to follow the protocol at all** (stated): Gemma-4-E4B has only 58% focus-parse success rate and its accuracy collapse is attributed largely to protocol non-adherence, not a reasoning failure — DA appears to require a "minimum capability floor" that isn't characterized precisely.
- **Wall-clock savings are simulated/projected, not measured** (inferred/stated): Table 3's 0.71×/0.77× figures come from a roofline model with assumed MFU=40%/MBU=70%, not from actual end-to-end latency measurements on the vLLM integration described in Section 5.4. The paper is explicit that these are "a theoretical ceiling... rather than measured wall-clock time" and exclude prefill cost.
- **Judge is an LLM, not exact-match ground truth** (stated, validated): accuracy is scored by a Qwen-3.5-4B LLM judge rather than exact match, validated against Gemini-3.1-Pro (98.5% agreement) — reasonably rigorous, but still introduces judge-model bias/noise into the headline accuracy numbers.
- **Synthetic QA for 4 of 15 sources** (stated): four benchmark sources use QA pairs generated by Gemini-3-Flash rather than original human-annotated questions, which could introduce systematic biases favorable to certain answer patterns (not deeply interrogated in the text).
- **Non-termination artifacts distort some attended-token numbers** (stated): a small fraction of DA responses (up to ~6% for Gemma-4-12B) fail to terminate within the 8K generation budget, inflating attended-token sums for reasons unrelated to the masking mechanism itself — the paper adjusts for this in some figures but it signals some instability in the zero-shot protocol at smaller scale.
- **Only two "headline" models tested in depth** (inferred): the main comparison (Table 2, most figures) relies on just two backbones (Gemma-4-31B, Qwen-3.6-27B); the 6-model scaling analysis exists but is less thoroughly probed (e.g., no per-task breakdown at all six sizes), so generalization across architectures/vendors (e.g., very different models, MoE architectures) is not established.
- **DA doesn't touch efficient/linear-attention layers** (stated): DA only reduces cost in global attention layers; sliding-window and Gated DeltaNet layers are untouched, and on Gemma the fixed SWA cost caps how much of the global-attention saving translates into real wall-clock reduction (42% of DA's attention time) — meaning benefits are architecture-dependent and likely to shrink further as architectures move toward more efficient-layer-heavy designs (a tension the paper itself raises in Section 8.1 when discussing whether global attention will remain a large cost driver at all).
- **No comparison against learned/extrinsic sparse-attention baselines on the same benchmarks** (inferred): the paper positions itself against approaches like Quest/DeepSeek sparse indexers conceptually and cites them, but does not run a head-to-head empirical comparison against these baselines under the same tasks/models — so the relative efficiency-accuracy trade-off versus the "prominent approach" it explicitly contrasts itself with is not directly measured, only argued qualitatively.
