# Quality Recovery for Quantized KV Caches via Low-Rank Attention Adaptation

**Authors:** Seifeldin Abdellatif

**arXiv:** [2609.04263](https://arxiv.org/abs/2609.04263)

**Categories:** cs.AR, cs.CL

**Submitted:** 2026-09-02

**Relevance:** 9/10 — matched: LLM inference efficiency and long-context serving

---

## TL;DR
This paper freezes a quantized KV cache's format (e.g., 4-bit affine, KIVI, KVarN) and asks whether a small low-rank update to the Q/K/V projections can recover the quality lost to quantization, using knowledge distillation from a floating-point "teacher" model into a "student" that runs the real packed cache. Across TinyLlama-1.1B, Gemma-4-12B, and Llama-3.1-8B, these low-rank adapters recover roughly 38–76% of the held-out perplexity gap depending on model/quantizer, and partially — but not fully — restore long-context retrieval behavior (RULER, needle-in-a-haystack). The headline caveat is that perplexity recovery and retrieval-task recovery decouple sharply at very low bit-widths: a 2-bit cache can get perplexity almost back to floating-point levels while still failing ~94% of retrieval cases.

## First-principles breakdown

**The underlying problem.** During autoregressive (token-by-token) generation, a transformer must remember the keys (K) and values (V) it computed for every previous token, so attention at the current step can look back over the whole sequence. This "KV cache" grows linearly with sequence length and batch size, and for long contexts or large batches it becomes the dominant memory/bandwidth cost — often larger than the model weights themselves. The standard fix is to quantize the cache: instead of storing K/V in 16-bit floats, store them in 2, 4, or 8 bits per value, with some extra metadata (scale factors, offsets) to reconstruct approximate values. The problem: quantization introduces error, and this error propagates through every subsequent attention computation, degrading the model's output quality (measured by perplexity — how surprised the model is by real text — and by task accuracy).

**Why prior approaches have limits.** Existing KV-cache quantization methods (KIVI, KVQuant, SKVQ, RotateKV, KVarN, etc.) attack the *representation* problem: they design cleverer ways to encode K/V (per-channel vs per-token scales, rotations/Hadamard transforms to spread outliers, keeping a small window of full-precision "recent" tokens, etc.). Other methods (GEAR, STAR-KV, KVLinC) add *extra correction state* — low-rank or sparse residuals stored alongside the quantized cache, or extra computation woven into the attention operator itself. Both families change what's stored or how attention is computed, which can conflict with efficient kernels, add memory, or require redesigning the inference pipeline. This paper instead asks: what if you leave the cache format and the attention operator completely untouched, and only adjust the model's projection matrices (the linear layers that produce Q, K, V from hidden states) so that the *existing* quantization error is better tolerated?

**The core mechanism — LoRA-style adapters via self-distillation.**
1. Take a projection matrix W (for Q, K, or V). Freeze it, and add a low-rank update: W' = W + (α/r)·B·A, where A and B are small trainable matrices (rank r ≪ the full dimension). This is the standard LoRA trick — it adds few parameters and, if the base weight is not itself quantized, can later be merged back into W with no extra inference cost.
2. Build a "teacher" (runs the real model with a full-precision/floating cache) and a "student" (runs the same model, but every K/V that gets cached is quantized and reconstructed through the actual deployed packing pipeline — bit-packed codes + FP16 scale/offset, exactly as it would be in production).
3. Train only A/B (the adapters) by minimizing the KL divergence between the teacher's next-token distribution and the student's next-token distribution on unlabeled calibration text (self-distillation, not task-specific fine-tuning).
4. Because quantization (rounding to discrete bins) isn't differentiable, gradients flow back through a straight-through estimator (STE): forward pass uses the real quantized/reconstructed values, but backward pass pretends the reconstruction was the identity function, so gradients reach the K/V adapters.
5. Key design choice: the base weights and the quantizer are never touched — only the adapters change. This means the same technique can, in principle, sit on top of any quantizer (the paper tests custom affine/symmetric caches plus the established KIVI and KVarN formats) as long as the quantizer's full reconstruction can run inside the calibration forward pass.

**Why placement (Q vs K vs V vs combinations) matters.** Adjusting Q changes which parts of the (already-corrupted) K/V the query attends to; adjusting K/V changes what gets written into the cache before quantization, i.e., tries to make the pre-quantization values more "quantization-friendly." The paper shows algebraically that combined Q+K adaptation affects the attention logit as a sum of cross-terms (ΔQ·Kᵗ + Q·ΔKᵗ + ΔQ·ΔKᵗ), meaning query and key adjustments can compensate for each other in complementary ways — motivating trying multiple placements (Q-only, K-only, QK, QKV) empirically rather than assuming one suffices.

**Evaluation logic.** They report three numbers: floating-cache perplexity (Pf, upper-bound quality), unadapted quantized-cache perplexity (Pq, the damage), and adapted perplexity (Pa, after training). Recovery R = 100·(Pq−Pa)/(Pq−Pf) normalizes how much of the induced gap was closed — but this ratio is unstable when the original gap is tiny (e.g., their 8-bit case, where a near-zero denominator makes R meaningless despite looking dramatic). They also separately test behavioral/long-context tasks (associative needle-in-a-haystack retrieval, RULER benchmark) because a lower perplexity doesn't necessarily mean the model still finds a specific fact buried in a long context.

## Key insights

- **Genuinely new framing**: rather than designing a better quantizer or adding correction modules to the cache/attention operator, this paper shows that a small, standard LoRA-style update to attention projections — trained by self-distillation against the model's own floating-point behavior — can partially undo quantization damage without touching the cache format, the quantizer, or the attention kernel. This is a "fix the model around a frozen constraint" approach, which is architecturally simpler to deploy than cache-side correction schemes (GEAR, KVLinC, STAR-KV) since it can be merged into dense weights (standard LoRA) or kept as a small side branch for quantized (NF4) bases.
- **Evidence supports**: consistent, positive (never negative) perplexity-gap recovery across three model scales (1.1B, 8B, 12B), multiple bit-widths (2/4/8-bit), and two independently-designed established quantizers (KIVI, KVarN) — this is the well-supported claim. QKV placement beats Q/K/QK-only under matched parameter budgets, replicated with the correct ordering on two model families (though only one seed for the placement ablation itself).
- **Important qualifier, well-supported by their own data**: perplexity recovery and behavioral/retrieval recovery are not the same thing and can diverge dramatically. Their clearest demonstration: 2-bit TinyLlama perplexity recovers 99.8% of the gap (11.40 vs 10.40 floating vs 576.10 unadapted) but retrieval recovers only 11–12 of 180 cases versus 170 floating — i.e., near-perfect perplexity recovery coexists with near-total retrieval failure. This is a genuinely useful negative result: it warns practitioners not to use perplexity alone as a proxy for deployment-readiness of a recovery technique.
- **RULER results show task heterogeneity, not uniform improvement**: the adapted Gemma cache raises the macro-average RULER score above even the floating baseline (48.33 vs 46.15 floating vs 42.80 unadapted), but this masks that single-needle retrieval actually got worse under adaptation while multi-value retrieval and common-word extraction improved, and variable tracking stayed near zero everywhere — so the aggregate number is somewhat misleading about what's actually being "recovered."
- **Deployment cost is quantified but not benchmarked**: adapters add a known, small parameter count (e.g., 0.18% of Gemma's parameters, 21.9M extra MACs/token) but the authors explicitly note this does not translate directly to wall-clock latency, which depends on kernel fusion and hardware — this is a claim about theoretical overhead, not measured throughput.

## Caveats — stated and inferred

- **Stated**: Most experiments (placement ablations, KIVI/KVarN transfer, established-quantizer comparisons) use only one training seed, so "these one-seed results do not quantify variance or support comparisons between quantizers." Only the main affine 4-bit and selected 2-bit/TinyLlama results use three seeds.
- **Stated**: Only three model families were tested (TinyLlama, Gemma, Llama-3.1), all decoder-only and broadly similar architectures — authors state this "does not establish universality."
- **Stated**: Gemma's optimizer skipped a small but nonzero fraction of updates per seed (137–158 of ~6,500) due to non-finite gradients — a numerical stability limitation acknowledged directly.
- **Stated**: The recovery metric R is explicitly flagged as unstable/misleading when the unadapted gap (Pq − Pf) is near zero (their 8-bit case shows R=121%, which the authors say is uninformative).
- **Stated**: Evaluation of long-context behavior uses synthetic tasks (associative NIAH, a 4-task/200-example RULER subset covering only 4 of RULER's 13 tasks) rather than broad downstream benchmarks — authors acknowledge these "measure synthetic behavior rather than broad downstream performance."
- **Stated**: Deployment MAC/parameter overhead figures are static compute counts, not measured latency/throughput — authors explicitly say hardware, batch size, and kernel fusion could make small matmuls disproportionately costly, and that "end-to-end fused-kernel benchmarks would determine" real impact.
- **Stated**: Compatibility with other correction methods (KVQuant additive residuals, GEAR, stateful methods like KVLinC) is described as theoretical/untested within this paper.
- **Inferred**: The paper is authored by a single author with a single affiliation and self-hosted code repo, with no baseline comparison against the cache-correction competitors it cites (GEAR, STAR-KV, KVLinC) — despite discussing them at length in related work, there's no empirical head-to-head, only a conceptual positioning ("these allocate representation or operator state to correction... our post-hoc procedure leaves the cache format... unchanged"). This makes it hard to judge whether the low-rank-adapter approach is competitive with, or simply different from, those alternatives.
- **Inferred**: No ablation on calibration data distribution shift — calibration always uses generic text (WikiText-2/103), and it's unclear how the adapters would generalize to out-of-distribution downstream tasks or domains; the paper only measures held-out perplexity on the same corpus family it trained on plus synthetic retrieval, not real task benchmarks (e.g., no QA, summarization, or code tasks).
- **Inferred**: The strong RULER "improvement over floating" result for Gemma (48.33 adapted vs 46.15 floating) is somewhat suspicious/cherry-pick-adjacent as a headline number, since the paper's own breakdown shows this aggregate hides a regression on single-needle retrieval — reporting the macro-average prominently could overstate the practical benefit if a reader doesn't dig into the per-task table.
- **Inferred**: Sample sizes for behavioral eval are fairly small (90–200 cases per condition), and several "improvements" are explicitly labeled by the authors as not statistically significant (e.g., TinyLlama QKV 4-bit NIAH gains have no paired test reaching p<.05), meaning some of the retrieval improvements shown are descriptive/anecdotal rather than confirmed.
