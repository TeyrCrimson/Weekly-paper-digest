# VestigeKV: The NoPE-MLA KV Cache Carries Its Own Eviction Signal in a Vestigial Branch

**Authors:** WenJie Fan

**arXiv:** [2609.03949](https://arxiv.org/abs/2609.03949)

**Categories:** cs.LG, cs.CL

**Submitted:** 2026-09-03

**Relevance:** 9/10 — matched: LLM inference efficiency and long-context serving

---

## TL;DR
VestigeKV compresses the KV cache of a NoPE (No Positional Encoding) MLA model like Kimi Linear by reading a small, otherwise-vestigial 64-dim "positional" branch left over from RoPE, which training has repurposed into a query-independent salience signal. Because this signal doesn't depend on future queries, it can rank and evict cache rows *before* those queries exist — something attention-observation methods (H2O, SnapKV) provably cannot do — achieving lossless retrieval at 8× and near-lossless at 32–128× compression. The mechanism is architecture-specific: on RoPE models the same operator collapses to near-random performance, so the method is claimed only for NoPE-MLA caches.

## First-principles breakdown

**The problem this solves.** In autoregressive LLM inference, the KV (key-value) cache stores per-token representations so future tokens can attend back to them without recomputation. For long contexts, this cache gets huge, so systems evict/compress low-importance rows. Existing eviction methods (H2O, SnapKV, StreamingLLM) decide what's important by looking at *observed attention* — i.e., which past tokens recent queries actually attended to. The catch: in a "long-lived" cache (e.g., a document loaded once, queried many times later), compression must happen *before* the eventual queries exist. A token that will matter for a future question may have received zero attention so far, so attention-based scores are blind to it. The paper measures this failure directly: H2O and SnapKV score 0.00–0.33 on needle-retrieval tasks under this pre-query compression setting, even when given extra budget — the failure is informational, not a budget problem.

**Background: RoPE vs NoPE, and MLA.** Most transformers use RoPE (Rotary Position Embedding) to inject position information into queries/keys, rotating each vector by an angle depending on token position. MLA (Multi-head Latent Attention, from DeepSeek-V2) compresses keys/values into a low-rank shared latent, which makes it structurally awkward to rotate (rotation doesn't commute with the low-rank projection), so MLA architectures split off a separate small "decoupled branch" specifically to carry rotary position info alongside the low-rank content latent. Kimi Linear, the model studied here, forgoes positional encoding entirely (NoPE) — but the code still allocates that same 64-dim decoupled branch, it just never rotates it. That branch becomes a structural vestige: present in the architecture, but not doing its original job.

**The key theoretical move.** Under NoPE, the attention score between a query and a cached row is one fixed bilinear form (no rotation matrix depending on relative position). This means the score reduces to a property of the token's cached row and a per-head learned direction — it does *not* depend on which future query asks about it (up to the query's own fixed projection). Formally (Lemma 1), attention output is a symmetric function of the cache rows — order/position doesn't matter. From this, the paper derives:
- (a) **Query-independent salience exists**: which tokens *can* ever win an attention argmax is a small, fixed set (2.3–6.7% of tokens) determined by extremeness relative to one fixed cone — this set can be computed before queries arrive. Under RoPE, the analogous "winner set" balloons to 10–47% because the relevant cone rotates with position.
- (b) **Merging is mathematically impossible under RoPE, exact under some NoPE cases, but still empirically forced**: a compact "representative" cache that reproduces attention exactly for all future queries would need to contain every distinct row (a proof via linear independence of Fourier-like characters). Under RoPE, essentially all rows are distinct (even same content differs by position), so no merging works. Under NoPE, some merges (rows differing only by a scalar RMSNorm-invariant factor) are theoretically valid, but in practice this class is measured to be empty on real data — so selection (not merging) is the only workable strategy either way.
- (c) **Per-token certificates**: bounds on how much a compressed/approximated row can distort a future score are query-uniform under NoPE, but must hold over an entire rotation orbit under RoPE, making them far looser there.

**What the method does mechanically.**
1. *Eviction/selection*: For each cached token, read only the 64-dim decoupled branch (11% of the 576-dim row). Apply a low-pass filter (FFT-based) over the sequence and compute a "salience" score as the residual between the raw branch and its low-pass version (Eq. 3). Keep the top-m rows (plus attention sinks and a recent window) in a fast "attended tier"; move everything else, unmodified/bit-exact, to an "archive" (never delete).
2. *Recall tier (optional but recommended)*: Archived rows are indexed cheaply — exact 64-dim branch component plus a low-rank (rank-r) sketch of the 512-dim content latent, plus a residual-norm certificate. At each decode step, a cheap scan over this index estimates each archived row's score with a provable error bound (Cauchy-Schwarz), and only rows that could plausibly beat the current top score are "fetched" (exactly) into that step's attention computation. This gives a recoverable/lossless-ish safety net without paying full memory/bandwidth cost every step.
3. Nothing about the model, weights, or kernels changes — it's purely a cache-management/eviction policy layered on top of standard MLA serving.

**Why RoPE breaks this specifically.** Under RoPE, the effective bilinear form used to score a cached row rotates with the relative position between query and key, so (i) the salience ranking of a row is not stable over time — a "good" row now may score low against a later query and vice versa (proven via a Fourier/frequency-band oscillation argument), meaning eviction decisions can never be "final" and must be constantly re-scored; (ii) bounding boxes/digests used for page-level pruning (as in ArkVale) become loose because within a page, keys at different rotated positions spread out geometrically even for identical content — so recall/pruning guarantees degrade in deep layers specifically. The paper measures the analogous operator on a RoPE model (DeepSeek-V2-Lite) collapsing from 0.88 to 0.08 retrieval, confirming the mechanism (not just the architecture) is what fails.

## Key insights

- **Genuinely new claim**: an architectural artifact (the decoupled RoPE branch, retained but unused under NoPE training) gets repurposed by training itself into a usable salience signal — and this is empirically supported by strong statistics (branch/content norm ratio 3.48× vs 1.01×, score-variance concentration 67.6% in that 11% of dims, top-1 retention 0.987 from branch alone vs 0.0001 from content alone).
- **Correctly identifies a structural gap** in existing eviction literature: methods like H2O/SnapKV are validated in a setting where queries are known at compression time; the paper isolates and measures the *pre-query* compression setting where they demonstrably fail (0.00–0.33), which is a legitimate and underexplored problem framing, not just a strawman.
- **Formal impossibility results** (Proposition 1: exact universal merging requires keeping essentially all distinct rows; explicit RoPE distance/orbit inflation bounds) are genuine mathematical contributions that explain *why* NoPE enables something RoPE structurally cannot, rather than just observing an empirical difference.
- **Evidence supports** strong retrieval numbers (1.00 at 8×, 0.92 at 32× tier-1-only; 1.00 at 128× with recall tier) specifically on Kimi Linear 48B, needle-retrieval and perplexity-based metrics, with a "deployment-path" reproduction in a serving-style engine (not just a research harness) that closely matches the research-harness numbers.
- **Scope is explicitly narrow and honestly bounded**: the paper repeatedly states this only applies to NoPE-MLA, extends to only one tested model family, and the authors do not claim it generalizes to Kimi K3 or other checkpoints beyond stating plausibility.

## Caveats — stated and inferred

- **stated** — Single model evaluated: all core measurements are on Kimi Linear 48B; the only other released NoPE-MLA checkpoint doesn't exist, so cross-model generalization is untested. Kimi K3 extension is explicitly called "plausible... untested," with authors saying "we claim nothing for it."
- **stated** — Depth of the eviction mechanism (why exactly it works so well) doesn't fully replicate on a different architecture family (NoPE GQA hybrid, Granite-4.0-H): "selector ordering replicates... eviction depth does not — depth claims are MLA-conditional." The authors admit the underlying mechanism for this depth effect is still open, with three candidate explanations they proposed and refuted themselves.
- **stated** — Row reachability in the recall tier is probabilistic, not guaranteed (recall 0.9–1.0), except in a CPU-assisted deterministic variant; pure deletion (rather than archiving) loses rows irrecoverably and costs +15 nats — i.e., without the archive/recall design, results would be much worse.
- **stated** — Evaluation limited to needle-retrieval and held-out cross-entropy/perplexity tasks up to 65k context; beyond 65k is "extrapolation," and standard long-context benchmark suites (e.g., RULER, LongBench) are explicitly left as future work — meaning broader task generalization (reasoning, QA, summarization at scale) is untested.
- **stated** — MAUVE generation-quality figure (0.999 vs 0.962) is reported as "a small-N figure" (16 contexts × 256 tokens) — authors flag it as not statistically robust themselves.
- **inferred** — All primary results reported as exact fractions over small trial counts (e.g., 24, 12 trials per cell); the paper itself includes Wilson 95% confidence intervals showing many neighboring configurations are not statistically distinguishable at these sample sizes (e.g., 21/24 vs 9/12 could overlap substantially) — the headline "1.00 vs 0.92" retrieval numbers should be read with this uncertainty in mind despite the paper's careful framing.
- **inferred** — Baselines compared against (H2O, SnapKV, StreamingLLM) are evaluated in a setting explicitly acknowledged as outside their original design intent (pre-query compression); while this is the paper's whole point, it also means the comparison is somewhat asymmetric — these are not the strongest possible baselines *for this specific problem setting*, since few or no other query-independent selection baselines are tested.
- **inferred** — No wall-clock/latency benchmarks on the fused/production kernel path are given ("fused-kernel wall clock is unmeasured," stated directly); reported gains are in bytes-read/dims-per-token, not measured end-to-end serving speedups, so real-world throughput benefit is not directly demonstrated.
- **inferred** — Training-time cost/compatibility, and behavior under distribution shift (e.g., fine-tuned or instruction-tuned checkpoints vs. base model) is not addressed in the paper.
- **stated** — Extension to hypothetical future architectures/training regimes (Section 9 "Outlook") is explicitly labeled as "prospects (not claims)" and speculative, not evidence-backed.
