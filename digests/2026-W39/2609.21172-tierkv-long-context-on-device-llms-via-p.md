# TierKV: Long-Context On-Device LLMs via Predictive Multi-Tier KV Caching

**Authors:** Zhihao Shu, Md Musfiqur Rahman Sanim, Jie Hu, Kun Yuan, Minghai Qin, Gagan Agrawal, Wei Niu

**arXiv:** [2609.21172](https://arxiv.org/abs/2609.21172)

**Categories:** cs.LG, eess.SY

**Submitted:** 2026-09-18

**Relevance:** 9/10 — matched: LLM inference efficiency and long-context serving

---

## TL;DR
TierKV is a mobile LLM inference system that, before decoding starts, predicts how much KV-cache a request will need and splits tokens across three tiers — exact (uncompressed), SVD-compressed, and flash-offloaded — solved in closed form under a device's memory and accuracy budget. Compared to llama.cpp, MNN-LLM, and MLC-LLM across 8 text/vision/audio models on 3 phone SoCs, it improves prefill throughput up to 17.6x, cuts RAM-resident KV cache 12.5–34%, and extends max context length up to 2.6x, at the cost of modest decoding slowdown from reconstruction overhead. The core idea is turning KV-cache management from a reactive, after-the-fact compression/eviction problem into a proactive, per-request resource-allocation problem solved once per prompt.

## First-principles breakdown

**The underlying problem.** In autoregressive transformer decoding, each layer caches the Key and Value vectors of every previous token (the "KV cache") so it doesn't have to recompute them at each new step. This cache grows linearly with sequence length: `KV memory = 2 × layers × KV-heads × head-dim × seq-len × 2 bytes`. On a phone, physical RAM is small and mostly already claimed by the OS/system (e.g., a 12GB OnePlus 12 leaves only ~6.8GB usable), so a long context (tens of thousands of tokens, common in RAG, chain-of-thought, or multimodal inputs with thousands of image/video tokens) can single-handedly exceed the budget and get the app killed by Android's Low Memory Killer.

**Why prior fixes fall short.**
- *Low-rank (SVD) compression*: Key/Value matrices are approximately low-rank, so you can store a compressed `U_r Σ_r` factorization instead of the full matrix and reconstruct approximately when needed. But existing methods use a fixed rank chosen offline (not tailored per request) and reconstruct full tensors during attention, adding real compute overhead (measured: 30% extra compute on their test phone).
- *Token eviction* (e.g., H2O, SnapKV): permanently discards "unimportant" tokens based on attention scores seen so far. This is irreversible — if a later query in a multi-turn conversation needs information from an evicted token, it's gone.
- *Flash offloading*: moves KV data to disk/flash, which is slow (measured host-to-device bandwidth of only 1.66 GB/s) and can stall decoding waiting on I/O.
- *MHA2MLA-style latent conversion*: projects queries/keys into a shared low-dim latent space, but adds a per-token matrix-vector multiply whose cost scales with context length — the paper shows this drops throughput 46-75% on their test device as context grows.

**TierKV's mechanism, step by step.**
1. **Three-tier layout, decided per-request**: tokens 0 to boundary `n` are stored exact (Tier-0, protects "compression-sensitive" positions like attention-sink tokens); tokens `n` to `m` are SVD-compressed in RAM (Tier-1); tokens `m` to `L` are pushed to flash storage (Tier-2, bounds RAM but retains the full context rather than discarding it).
2. **Prediction before decoding**: Since mobile requests always run a full "prefill" pass (processing the whole prompt) before generating the first token, TierKV reuses those already-computed hidden states as a free signal. It builds a prompt "fingerprint" by weighting hidden states by their output-token entropy (uncertain/important tokens count more), then does a k-nearest-neighbor lookup against a local history database of past prompts+lengths to predict the eventual total sequence length `L̂`. This needs no extra model or training.
3. **Joint optimization (PMCO)**: Given the predicted `L`, a device memory limit, and an accuracy threshold, the system picks the two boundaries `n, m` and a compression level `R` (which selects per-layer SVD ranks, calibrated once offline per model) to minimize total decode latency (exact-attention cost + SVD-reconstruction cost + disk I/O cost) subject to a memory constraint and an accuracy constraint. Because the per-layer rank table is precomputed offline, and because latency/memory are (empirically) roughly linear functions of `n, m` for a given `R`, the online problem reduces to iterating over a small discrete set of compression levels and, for each, solving a simple linear/geometric problem for `n, m` — described as solvable in under 0.1s per request. A feasibility loop then trims `m` further if memory still overshoots.
4. **Runtime engineering to make the plan actually fast**: a fused "split-path" attention kernel processes exact and SVD-compressed blocks in one pass so reconstructed keys never leave on-chip memory (avoiding extra memory traffic); a "latent-space value accumulation" trick reorders the math so Values don't need full reconstruction before being combined with attention weights (cutting that path's FLOPs substantially); and an I/O scheduler overlaps flash-to-RAM prefetching with the SVD reconstruction compute so idle "bubbles" waiting on disk get filled with useful work instead of stalling.

## Key insights

- **Reframing KV-cache management as predictive, joint resource allocation rather than reactive eviction/compression** is the paper's central claimed contribution — deciding tier boundaries and compression rank together, ahead of decoding, rather than making these decisions independently or after the fact. The evidence (Table 10: PMCO vs. fixed/sequential heuristics) supports that joint optimization does better than naive heuristics on the same three-tier abstraction (26% vs 12.8-14.9% memory savings at similar/better latency), which is a real, isolated ablation.
- **Free length prediction from prefill hidden states** avoids irreversible eviction decisions and auxiliary model training — a genuinely useful trick if it generalizes, though it is only tested against one alternative (static mean-length) and one entropy-guided baseline (EGTP), not against more sophisticated learned predictors.
- **Retaining the full context across tiers instead of discarding tokens** is presented as solving the "circular dependency" problem of reactive eviction (you can't know a token is unimportant until you've seen the query that needs it). The multi-turn cache-reuse experiment (Table 9, N=45 trials) is the paper's most direct evidence for this: TierKV beats SnapKV by up to 33 points recall when facts must be recalled after compression happens under a generic warmup query — a plausible and well-targeted demonstration of the eviction failure mode.
- **Engineering contributions (fused kernel, latent-V accumulation, I/O-compute overlap)** account for a meaningful chunk of the measured speedup (Table 12 breakdown: pure PMCO/hierarchical caching alone would give 0.63x end-to-end vs llama.cpp; the kernel/overlap engineering brings it up to 1.10x). This means the headline "1.10x average end-to-end speedup" depends heavily on systems engineering, not just the allocation algorithm — worth noting since the abstraction (predictive tiering) is not by itself sufficient to win.
- The **17.6x prefill and 183x figures** are against weaker/partial baselines (MNN-LLM, and MLC-LLM which only supports one model at very short context) — the more informative comparison is the 1.2-1.6x prefill speedup over llama.cpp for text models, which is more modest.

## Caveats — stated and inferred

- **Decoding throughput regresses** — TierKV is consistently slower at decoding than FP16 baselines (e.g., Llama-3.2-1B: 6.0 → 4.3 tok/s, a 28% drop; SmolVLM2: 4.6 → 1.9 tok/s, a 59% drop) due to SVD reconstruction cost. The paper frames this as "offset" by prefill gains, but for workloads with short prompts and long generations, this framing may not hold. (stated, but framing/emphasis worth flagging)
- **Headline multipliers rely on weak/partial baselines**: MLC-LLM is only evaluated on one model at 2k context (giving the 183x figure), and MNN-LLM lacks support for several models entirely (dashes in Table 7). The "up to 17.6x" and "183x" figures in the abstract/intro are best case rather than representative. (inferred)
- **Accuracy degradation is nontrivial for some models/tasks**: Qwen2.5-3B loses 6.6-7.0 points across MMLU/ARC/GSM8K; Llama-3.2-1B loses 5.3 points on GSM8K. "Only minor accuracy degradation" in the abstract is an optimistic characterization of results that vary considerably by model. (inferred, though raw numbers are stated)
- **Length-prediction misprediction rates are non-trivial** (3.3% overprediction, 5.9% underprediction across three datasets) and the paper's claim that "misprediction introduces no additional accuracy loss" rests on the design (excess falls into full-rank Tier-2) rather than on directly measuring accuracy under misprediction across a wide range of conditions. (stated claim, but underlying accuracy-under-misprediction evidence is not shown directly)
- **No comparison against modern token-eviction or offloading systems as baselines for overall throughput/memory** — the paper only compares against eviction (SnapKV) in the narrow multi-turn cache-reuse scenario, not as a general baseline in Table 7's main throughput/memory comparison. Similarly, KVSwap (disk-aware offloading, cited in related work) is never directly benchmarked. (inferred)
- **Batch size 1 only**: all experiments use batch size 1, matching interactive single-user mobile inference, but this means nothing is said about behavior under concurrent requests or multi-app memory contention beyond the static "system reservation" accounting. (inferred from experimental setup description)
- **Quantization is only lightly explored**: weights-only Q8 is tested on one model (Llama-3.2-3B); the paper explicitly states quantized KV-cache storage and other lower-bit configurations are "left to future work." (stated)
- **Thermal throttling artifact observed but not deeply analyzed**: Figure 5 shows a throughput drop at ~7k tokens attributed to thermal throttling — an uncontrolled hardware confound acknowledged in a caption but not further analyzed for its effect on other reported numbers. (stated in passing, but under-addressed)
- **Offline calibration cost and portability**: per-layer rank profiles are calibrated once per model on "two NVIDIA A6000 GPUs" (<20 min/model) — this offline dependency on server-class hardware for deployment isn't discussed as a limitation, though it's a one-time cost. Not addressed in the paper as a potential barrier to rapid model updates or user-customized models.
- **Middle/later related-work and full experimental details are truncated** in the provided text (per the extraction), so any additional stated limitations in the (unseen) conclusion or later related-work sections could not be verified. Not addressed in the available text.
