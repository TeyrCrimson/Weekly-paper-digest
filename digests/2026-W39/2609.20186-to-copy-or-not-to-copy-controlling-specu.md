# To Copy or Not to Copy: Controlling Speculative Decoding via Intrinsic Model Signals

**Authors:** Roy Eisenstadt, Ido Cohen, Edo Cohen-Karlik, Lior Wolf, Itamar Zimerman

**arXiv:** [2609.20186](https://arxiv.org/abs/2609.20186)

**Categories:** cs.CL

**Submitted:** 2026-09-17

**Relevance:** 9/10 — matched: LLM inference efficiency and long-context serving

---

## TL;DR
SwitchSD fixes a blind spot in "copy-based" speculative decoding: existing heuristics (CopySpec, PLD) trigger context-copying whenever an n-gram repeats, even when the repetition is accidental (e.g., reused variable names in math reasoning), wasting compute on rejected drafts. The paper trains a tiny linear probe on a target LLM's internal hidden states to detect genuine "copy-intent" (AUC > 0.99) and uses it to gate when to copy from context versus fall back to a neural drafter (EAGLE3), yielding up to 15% throughput gains over EAGLE3 alone across Llama/Qwen models and coding/math/summarization benchmarks.

## First-principles breakdown

**The underlying problem — speculative decoding (SD).** LLM decoding is slow because tokens are generated one at a time, each requiring a full forward pass. SD speeds this up by having a cheap "draft" mechanism propose several candidate future tokens at once, then having the expensive target model verify all of them in a single parallel forward pass, accepting the longest correct prefix. The speedup depends on the "acceptance rate" — how often draft guesses match what the target model would have generated.

**Two families of drafters.**
1. *Neural drafting* (e.g., EAGLE/EAGLE3): a small auxiliary network predicts likely next tokens/features. It works reasonably everywhere but has a training/inference cost and moderate acceptance lengths.
2. *Copy-based drafting* (e.g., Prompt Lookup Decoding, CopySpec): if the current text prefix has appeared earlier in the context, just copy whatever followed it last time as the draft — free to generate, and when it's right, it can be right for very long stretches (e.g., copying an entire repeated docstring).

**Why copy-based methods fail sometimes.** The trigger for these methods is purely surface-level: "does this n-gram appear earlier?" But such overlaps can be coincidental — e.g., in a math derivation, the token "n" or a partial phrase like "Next, let's try n=" recurs because of the problem's structure, not because the model intends to literally repeat prior text. Firing a copy draft in these cases produces a 0-token acceptance (total waste): compute is spent generating and verifying candidates that get rejected — the authors call this a "speculation tax." Their analysis finds over 50% of copy triggers in reasoning tasks are these false positives.

**The core idea: copy-intent as a latent signal.** The authors hypothesize that "intent to copy" isn't just a text-level pattern but is represented internally in the transformer's hidden states (residual stream), separately from surface repetition. This builds on prior "linear representation hypothesis" work showing many features are linearly decodable from hidden states, and on "induction heads" — known attention circuits responsible for pattern-completion/copying behavior.

**Building the probe.**
- *Labels*: A token position is labeled "copy-mode" (Y=1) if it's part of a verbatim span of ≥5 tokens repeating earlier context; otherwise Y=0. This is a coarse, weak-supervision proxy — not a perfect definition of intent, but a practical stand-in for "sustained deliberate copying."
- *Training data*: Since long verbatim repeats are rare in normal text, they synthetically constructed a 1,000-prompt "CopyDiversity" dataset (via Claude Sonnet) spanning heavy-copy (e.g., "output this JSON exactly"), medium-copy (paraphrase-with-quoting), and light/no-copy (open-ended creative/reasoning) tasks — then ran the target model on these prompts to harvest labeled hidden-state/label pairs at scale.
- *Probe architecture*: for each transformer layer ℓ, a single linear layer + sigmoid (logistic regression) over the hidden state at that layer, no bias, trained with binary cross-entropy + L2 regularization. Deliberately minimal so it can only pick up a genuinely linear signal, and so it adds negligible runtime overhead.
- *Layer/threshold selection*: they scan all layers, pick the one maximizing validation F1 (typically an intermediate layer, e.g. layer 14 of 32 in Llama-3.1-8B), and pick a decision threshold τ via F1 maximization. They find attention-sublayer outputs beat MLP-sublayer outputs — consistent with copying being carried by induction-head-like attention circuits.

**Inference-time decision rule.** At each decoding step, copy-based drafting only fires if BOTH (a) the probe score at the chosen layer exceeds τ, AND (b) there's still a literal κ-gram (κ=5) match in the context — i.e., the latent signal must agree with a surface-level structural check. If either check fails, it falls back to the neural drafter (EAGLE3 or plain speculative sampling).

**Generating and verifying copy drafts.** When triggered, the system pulls up to W candidate continuations (recency-ranked) from repeated spans in context, each up to length D. To verify all W candidates in one target-model forward pass, they use "block-triangular attention": each candidate can attend to the original prefix and its own preceding tokens, but not to other candidates — enabling parallel verification of multiple copy hypotheses at once, then keeping whichever validated candidate is longest.

**KV-cache bookkeeping.** Since neural and copy drafters interleave, the neural draft model's KV cache can lag when copy-path tokens are accepted without passing through it. They "lazily" catch it up during the next drafting step rather than incurring an extra forward pass, amortizing the sync cost.

## Key insights

- **Genuinely new**: reframing "should I copy?" as a decision problem solvable from the model's own internal representations rather than from surface text statistics — and showing this signal is almost perfectly linearly separable (AUC>0.99, peaking at intermediate attention-sublayer representations). This is the paper's central claim and it's directly supported by probe evaluation data (F1/ROC curves, layer sweeps).
- **Orthogonality to draft model choice**: the switching mechanism is shown to work as an "orchestration layer" on top of both EAGLE3 and vanilla speculative sampling (SPS) with a separate small draft model, and consistently improves over the neural-only baseline in both cases — evidence it's a general add-on, not tied to one drafter architecture.
- **"Less is more" precision effect**: SwitchSD triggers copy mode less often than CopySpec/PLD/BanditSpec but achieves much longer accepted spans when it does (e.g., 5.88 vs. 1.83 mean accepted tokens on HumanEval/Llama-3.1-8B) — this is the mechanism actually driving the throughput gain, and it's a fairly clean, consistent pattern across all reported tables.
- **Comparison to a "black-box" statistical alternative (BanditSpec)** shows internal signals beat reward-based online exploration, especially dramatically on the largest model (Llama-3.3-70B), where BanditSpec's exploration collapses throughput to ~parity with vanilla decoding (0.99×) while SwitchSD still gets 1.48×. This is a meaningful, well-evidenced comparison since it isolates "white-box probing" vs. "black-box bandit" as the key variable.
- **Downstream system implication**: because copy-mode siphons off the "easy" tokens, the optimal neural-draft lookahead γ shifts down (e.g., 7→5 for Llama-3.3-70B) — a secondary, smaller finding about how regime separation affects other SD hyperparameters, but only demonstrated as a "chosen best γ" table rather than a deep study.
- **What's claimed vs. evidenced**: the claim that the probe captures true semantic "intent" (not just a more clever repetition detector) rests on indirect arguments — the representational bottleneck (probe sees only a single token's hidden state, not the full context/string), and post-hoc acceptance-length separation (Figure 3). This is suggestive but not conclusive proof of "intent" as a cognitive-style construct; the authors themselves hedge this in Appendix E, calling it "copy-readiness."

## Caveats — stated and inferred

- **Weak/proxy supervision for "copy-intent"** (stated): labels come from a heuristic (≥5-token verbatim match), not true ground truth for intent; the authors explicitly acknowledge this is a proxy and devote an appendix to defending it rather than proving it.
- **Synthetic, model-generated training data** (stated): the CopyDiversity probing dataset was generated using Claude Sonnet prompts and completions from the target model itself, which is a controlled/calibrated stimulus set rather than naturalistic data — raises questions about how well probes generalize to organic long-form text distributions outside the constructed templates (partially addressed via a WikiText-103 ablation showing worse performance, which is honest but confirms the method depends on curated data).
- **Evaluation limited to three benchmark types** (inferred): HumanEval (code), Math500 (math), CNN/DailyMail (summarization) — all somewhat structured/repetition-prone domains; no evaluation on open-ended dialogue, long-document QA, or multi-turn agentic workloads where copy patterns might differ substantially. The MT-Bench confusion-matrix ablation (Figure 4) is the only hint at a different domain, and it's used only for probe evaluation, not end-to-end throughput.
- **Only greedy/low-temperature results are primary**; temperature robustness is relegated to an appendix showing the advantage over EAGLE3 shrinks substantially as temperature increases (2.57× → 1.54× speedup, T=0 to T=1) (stated in Appendix A) — the core throughput numbers in the main paper are all at T=0, which is the easiest setting for any copy-based method and may overstate typical gains for stochastic/creative use cases.
- **Per-model/per-layer retuning required** (inferred): probe layer and threshold τ are selected per model (e.g., layer 14 for Llama-3.1-8B) via a held-out validation set — this implies the method needs a calibration pass for every new target model, which is operational overhead not deeply quantified (no discussion of cost/robustness of this calibration step, or sensitivity to validation-set choice).
- **No wall-clock/hardware cost accounting for probe overhead beyond "negligible"** (inferred): the paper asserts the linear probe adds negligible overhead but doesn't report separate latency breakdowns (e.g., probe inference time or block-triangular verification overhead as a fraction of total step time) — only aggregate tok/s numbers are given.
- **Comparisons include only relatively narrow baseline families** (inferred): heuristic (PLD, CopySpec), neural (EAGLE3), statistical (BanditSpec), and in the appendix SAMD/Lookahead — a reasonably broad set, but all baselines are from the "context-copy or neural draft" paradigm; no comparison to other advanced adaptive/multi-draft SD systems that may exist outside this immediate lineage (not addressed in the paper).
- **Self-reported ablations, no independent replication** (inferred): all ablations (data source, layer/sublayer, threshold) are run by the authors on their own setup; no external validation, and hyperparameters like κ=5, W (candidate count up to 10), D (max candidate length 20) appear fixed by design choice rather than swept/justified with ablations in the main text (values are stated in Appendix D as implementation details, not ablated).
- **"Preserving exact generation quality" is asserted but not directly measured** (inferred): the paper claims lossless generation (a property inherent to correct SD verification), but no explicit output-quality/exactness check (e.g., comparing generated text token-for-token against vanilla decoding) is reported in the results tables — this is standard for correctly implemented SD but is not independently verified in the text.
