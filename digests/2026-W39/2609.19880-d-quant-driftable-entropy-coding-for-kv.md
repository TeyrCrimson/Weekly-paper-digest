# D-Quant: Driftable Entropy Coding for KV Cache Quantization

**Authors:** Yi Su, Hong Liu, Guanghua Yu, Jianchen Zhu

**arXiv:** [2609.19880](https://arxiv.org/abs/2609.19880)

**Categories:** cs.CL

**Submitted:** 2026-09-17

**Relevance:** 9/10 — matched: LLM inference efficiency and long-context serving

---

## TL;DR
D-Quant compresses LLM KV caches by entropy-coding the quantized values (which follow a near-Gaussian distribution after rotation/normalization) instead of using fixed-width bits, but fixes the awkward variable-length problem with a "drift" step that nudges a few expensive symbols to cheaper neighbors so every token's stream fits a fixed-size byte container. This keeps memory access regular enough for parallel GPU attention kernels while getting entropy coding's compression benefit, hitting near-BF16 accuracy at 2.26 bits/value, ~7× KV memory reduction, and 3.5× decoding throughput gain on Qwen3-8B/Llama-3.1-8B.

## First-principles breakdown

**The problem.** During autoregressive LLM inference, the model caches the Key and Value vectors of every past token (the "KV cache") so it doesn't recompute attention from scratch each step. This cache grows linearly with sequence length × batch size, and for long-context or high-throughput serving it becomes the dominant memory/bandwidth cost. Quantization (storing each value with fewer bits) is the standard fix.

**Why fixed-width quantization is wasteful.** Standard quantization picks a bit width `b` and represents every value with one of `2^b` discrete levels (e.g., INT2 = 4 levels), sharing a scale/offset per group of values. The problem: this allocates the *same* number of bits to every symbol regardless of how likely it is. The paper shows that after two standard preprocessing steps — Hadamard rotation (spreads outlier energy across channels, a linear transform that doesn't change the values' information but reshapes their distribution) and mean removal — KV values end up looking almost exactly like a standard normal distribution: most values cluster near zero, few are in the tails. Fixed-width coding still spends equal bits on center and tail values, which is inefficient given this shape.

**Entropy coding, the classic fix — and why it doesn't directly work here.** Information theory (Shannon) says the minimum average bits needed to encode a symbol with probability `p` is `-log2(p)`; frequent symbols should get short codes, rare ones long codes (Huffman coding, arithmetic coding, and here specifically ANS/rANS — Asymmetric Numeral Systems, a fast table-driven entropy coder). Applying this to KV quantization symbols would reduce average bit usage substantially (the paper measures a real "coding gain" of ~0.7-0.9 bits/value over fixed-width). The catch: entropy-coded output is *variable-length* — some tokens compress to fewer bytes, some to more. But GPU attention kernels need every token's KV data at a predictable fixed offset/stride to decode and compute in parallel; irregular, variable-length streams break this.

**D-Quant's core trick: the "drift" mechanism.** Instead of allowing variable-length streams, D-Quant allocates each token's KV stream a *fixed-size byte container* (e.g., 33 bytes for keys, 23 for values). It entropy-codes the token's quantized values normally, but if the resulting bitstream would exceed the container's budget, it reassigns ("drifts") a small number of the most expensive (rare, long-codeword) symbols to nearby cheaper (more probable) symbols — just enough to squeeze under the byte budget. This is framed as a constrained optimization: minimize total reconstruction error subject to a total-code-length constraint. It's solved via a Lagrangian relaxation (turn the constraint into a penalty term weighted by multiplier λ) and bisection search over λ to find the tightest fit. Empirically, drift is rare and local: only ~0.75% of key symbols and ~5% of value symbols get moved, and never by more than one level — so most of entropy coding's benefit is preserved while guaranteeing every stream is exactly a fixed size.

**Calibration-free probability model.** Normally entropy coders need a probability table estimated from actual data (calibration). Since preprocessed KV values are empirically very close to N(0,1), D-Quant just derives the symbol probabilities analytically from the standard normal distribution's order statistics — no calibration data or offline profiling needed. They also apply a "sharpening" correction (raise probabilities to a power α=1.4) to account for the fact that drift systematically pushes the *realized* distribution to be more peaked than the raw analytic model predicts.

**Why this beats fixed-width at the same storage:** because the number of quantization levels is decoupled from the bit width. A fixed 2.26-bit budget forces `2^2.26 ≈ 4.8` (~4) levels; D-Quant can use 8 levels for keys and 6 for values at the same average storage, because most tokens' streams compress well below the ceiling and only get trimmed via drift when needed. More levels = finer reconstruction = lower error, even after accounting for the small amount of drift-induced degradation.

**System engineering.** They also built custom GPU kernels: an encoder that keeps each token's stream on-chip in a warp during the bisection search (avoiding materializing large distortion matrices), and a decoder organized by token rather than by attention head (since each entropy stream spans all KV heads of a token) so each stream is decoded once and consumed directly by the attention computation without ever fully reconstructing a dequantized BF16 tensor — the affine dequant is folded into the attention contraction itself.

## Key insights

- **Genuinely new**: the "drift" length-constrained assignment is the paper's central novel contribution — it's what makes entropy coding compatible with the fixed-stride memory access parallel attention kernels require. This is the mechanism that resolves the stated tension between entropy coding's compression and its incompatibility with parallel kernels.
- **Genuinely new (secondary)**: deriving a calibration-free entropy model directly from the standard normal distribution, justified by their own measurement that post-rotation/mean-removal KV distributions have a tiny "Normal Gap" (~0.0005–0.05 bits/value excess vs. an empirical model).
- **Decoupling levels from bit-width** is a real structural advantage over fixed-width quantization (INT2/INT4 etc.) — supported by their controlled ablation (Table 2, Appendix B) showing at matched storage budget, choosing alphabet size via entropy coding gives strictly lower reconstruction error than the nearest fixed-width scheme, and the appendix B experiment isolates this (same preprocessing/grouping, only coding format differs) showing ~2–2.3× lower KL divergence from the unquantized model at matched bits/value — this is good evidence the gain is from the coding mechanism itself, not confounded by other design choices.
- **Evidence supports** the headline claims: near-BF16 RULER/LongBench accuracy at 2.26 bits, outperforming KIVI/QuaRot/TurboQuant/OScaR baselines, with the accuracy gap widening at longer context (128K) — this is where prior methods degrade most and D-Quant holds up best.
- **System throughput/memory gains** (7× KV memory reduction, 3.5× decoding throughput, batch size scaling from 64→128 before OOM) are demonstrated with real kernels on an actual GPU (H20 96GB), not just simulated — a meaningfully more concrete efficiency claim than many quantization papers that only report theoretical bit savings.
- Separate K/V budget allocation (keys get more bits since key errors are amplified through softmax) is a reasonable, empirically supported design choice (ablation in Fig. 4 right panel) but is an incremental refinement, not the core novelty.

## Caveats — stated and inferred

- **Evaluated only on 8B-scale models** (Qwen3-8B, Llama-3.1-8B) — no results on larger models (30B+, 70B+) where KV cache pressure is often most acute, or on models with different attention structures (e.g., GQA/MQA variants beyond what's tested, MLA). *inferred*
- **Single GPU architecture tested** (NVIDIA H20 96GB) — no results on other hardware (A100/H100/consumer GPUs), so generality of the claimed kernel efficiency gains across hardware is unverified. *inferred*
- **Qwen3-8B's native context is 40K**; the 64K/128K RULER results rely on YaRN context extension, which the authors themselves note "degrades absolute performance" at those lengths — meaning part of the long-context evaluation is on a stressed/extrapolated setting rather than native capability, though they argue this is applied fairly to all methods. *stated*
- **Sharpening hyperparameter α=1.4** is fixed globally across all models/layers with no ablation shown for how sensitive results are to this choice, nor explanation of how it was tuned (risk of it being tuned to the test set). *inferred*
- **Container byte sizes (331/231 bytes) and specific level counts (8/6) are fixed hand-picked defaults** — the ablation (Fig. 4) shows sensitivity to these choices (performance degrades if levels increase too much or budget is skewed too far to keys), meaning results are somewhat dependent on careful manual tuning of these hyperparameters per setup rather than an automatic mechanism; not clear how this transfers to new models without re-tuning. *inferred*
- **No latency/throughput comparison against other quantization baselines' actual kernels** (KIVI, QuaRot, TurboQuant, OScaR) — Section 5.3 efficiency results compare D-Quant only against BF16, not against the compressed baselines' own throughput/memory numbers, so we don't know if D-Quant's system-level speedup advantage holds against realistic quantized competitors, only against uncompressed. *inferred*
- **Encoding overhead not quantified**: the paper mentions the drift/bisection encoding process adds computation ("D-Quant trades additional decoding computation for lower memory") but doesn't report prefill/encoding-time overhead numbers, only decode throughput; the claimed 3.5× throughput gain is specifically for decode at large batch sizes, and D-Quant is stated to be *slower* than BF16 at small batch sizes. *stated*
- **rANS/entropy coding decode complexity**: while kernels are described in detail, no wall-clock breakdown of encode vs. decode vs. attention compute time is given, making it hard to assess how much of the throughput number is attributable purely to memory savings vs. added compute cost trade-offs at various batch sizes. *inferred*
- **Bootstrap confidence intervals are reported only for the Appendix B KL-divergence comparison**, not for the main accuracy table (Table 3) — so statistical significance of the headline RULER/LongBench gains over baselines (especially close calls like OScaR) is not established. *inferred*
- **RULER results averaged over only 100 samples per task** per context length — a relatively small sample size for benchmarking, though this matches common practice in the field. *inferred*
