# RheoSampling: Resolving the One-Hot Dilemma in Stochastic Dynamic-Tree Speculative Decoding

**Authors:** Qiao Hu, Yepeng Weng, Bo Zhang, Takehisa Yairi

**arXiv:** [2609.21827](https://arxiv.org/abs/2609.21827)

**Categories:** cs.CL, cs.LG

**Submitted:** 2026-09-18

**Relevance:** 9/10 — matched: LLM inference efficiency and long-context serving

---

## TL;DR
EAGLE-3-style dynamic-tree speculative decoding builds its draft tree with deterministic top-K expansion, which is great under greedy decoding but collapses to one-hot choices under temperature sampling, tanking acceptance rate. RheoSampling fixes this by giving a single sampled token two separate probabilities — a "proxy" probability used only for tree construction/pruning, and its true probability used only for verification — which lets dynamic, context-aware trees incorporate real stochasticity while staying provably lossless. The paper backs this with a formal equivalence-class proof plus experiments on three LLMs and six benchmarks showing consistent acceptance-length and speedup gains over EAGLE-3's top-K baseline.

## First-principles breakdown

**The underlying problem: speculative decoding.** LLM decoding is normally sequential — one token at a time, each requiring a full forward pass. Speculative decoding speeds this up by having a cheap "draft" model propose several future tokens at once; the big "target" model then verifies them all in a single parallel forward pass, accepting the ones that match its own distribution and only paying full sequential cost for the rejected tail. To make verification *lossless* (i.e., the output distribution is statistically identical to just running the target model normally), there's a well-known rejection-sampling rule: accept a proposed token with probability `min(1, p(x)/q(x))`, where p is the target's probability and q is the draft's.

**From chains to trees.** Instead of drafting one linear sequence, tree-based methods draft a branching set of candidate continuations (a tree), so the target model can verify many possible paths in one pass, raising the odds that *some* path is accepted. Early trees were static/hand-designed (Medusa, SpecInfer). Newer ones (EAGLE-2/3) are "dynamic": at each layer, the draft model looks at the actual context and picks which branches are worth expanding, using an "expand-then-rerank" loop — expand top-K children per node, score each candidate path by multiplying together the draft probabilities along its root-to-node path, then globally prune down to a fixed budget of highest-scoring nodes.

**Why dynamic trees break under sampling (the "one-hot dilemma").** This expand/prune machinery is entirely deterministic: given the draft distribution, the tree structure is a fixed function of it — no randomness enters anywhere. That's fine at temperature 0 (greedy decoding), where the target model's own choice is also deterministic and the draft's top pick usually agrees with it. But at T>0, acceptance depends on the *ratio* p(x)/q(x), not on which token has the largest q(x). A tree method that always keeps only the highest-q token effectively "collapses" the draft into a one-hot point mass, throwing away the tail probability mass that stochastic sampling is supposed to explore — so acceptance rate craters. Static trees avoid this (they always include stochastic samples) but pay a different cost: since their structure doesn't adapt to context, they waste candidate slots on branches the model doesn't actually favor. Hence the "dilemma": you can have context-aware dynamic structure, or you can have real stochastic exploration, but (before this paper) not both — because both roles use the *same* probability number q(x), and that number is being asked to do two jobs: decide which branches survive to be part of the tree, and decide whether a token is finally accepted.

Why can't you just swap top-K for direct sampling? Two failure modes: (1) if you rank sampled tokens by their own q(x) to decide tree structure, that ranking criterion has nothing to do with acceptance likelihood at T>0, so pruning becomes arbitrary; (2) more subtly, if a token's own probability determines whether it survives pruning, then "conditioning on survival" warps its effective distribution away from the intended sampling distribution — breaking the lossless guarantee outright.

**RheoSampling's fix: dual-identity decoupling.** The key trick is to stop using one number for two jobs. At each expansion step with K candidate slots: deterministically take the top-m tokens by draft probability; then sample exactly *one* extra token Y from the residual ("tail") distribution over everything outside the top-m; fill remaining slots with the next highest-probability tokens. This single sampled token Y then gets two different probability values depending on which job is being done:
- **Construction (tree building/pruning):** Y is assigned a *proxy* probability `q_proxy(Y) = min(q(x_m), z)` (z = leftover mass beyond top-m). This proxy is engineered to always be ≥ the probability of any "fill" token, so Y is guaranteed to rank just after the top-m tokens, regardless of which token it turned out to be — its survival in the tree doesn't depend on its own realized identity. This independence is exactly what's needed to avoid the "conditioning distorts the distribution" trap above.
- **Verification:** Y is evaluated using its *true* sampling probability, so the rejection-sampling math stays statistically correct (lossless).

The tunable m is called the "rheostat": small m gives the sampled token a bigger proxy (more likely to survive pruning, more stochastic exploration) but weakens the deterministic tree backbone; large m preserves tree quality but risks the sampled token being pruned out entirely, wasting the stochasticity. Empirically m=1 (anchoring the sampled token right after the single best deterministic candidate) works best in most settings.

**RheoVerification (OT-based acceptance).** Standard multi-candidate verification (Recursive Rejection Sampling, RRS) checks candidates one at a time in sequence. The paper instead verifies the sampled token first against its true probability; on rejection, it computes a *residual* target distribution (`r = normalize(max(0, p − q̃))`) that redistributes the "leftover" target mass more globally across the remaining deterministic candidates, an approach motivated by Optimal Transport ideas from prior work (SpecTr). This squeezes out extra acceptance probability compared to sequential RRS, while a proof shows it remains lossless and dominates RRS under mild conditions.

**Sparse draft trick.** To avoid the cost of sampling over the entire vocabulary, they truncate the draft distribution to its top-128 logits (softmax over just those, rest set to -∞) before sampling Y. Since verification uses this same truncated distribution, losslessness is preserved, and because top-128 typically captures >90% of probability mass, acceptance rate is barely affected while sampling gets much cheaper.

**Formal losslessness proof.** The hard part isn't injecting one random token — it's that the *identity* of that token also affects which fill tokens appear at deeper layers, which affects path scores, which affects what survives global pruning. So the pruned tree itself is a random variable entangled with the sampled tokens. The authors handle this via an "equivalence-class" argument: group all possible unpruned trees that would prune down to the same R-node result, then use induction on the pruning budget R to show that, in expectation over this randomness, running their verification algorithm layer-by-layer reproduces exactly the target model's true autoregressive distribution p(Seq). This is Theorem 1, proved via supporting lemmas showing (a) the sampled token's local rank is always fixed at slot m+1 regardless of its identity, and (b) pruning is "ancestor-closed" (a node's score never exceeds its parent's).

## Key insights

- **Genuinely new framing**: identifying that dynamic-tree speculative decoding's stochastic-sampling failure stems from *overloading one probability value for two conflicting roles* (construction vs. verification) is a clean diagnosis, and the dual-identity (proxy vs. true probability) fix is a simple, elegant mechanism once you see the framing — this is the paper's core contribution.
- **First rigorous losslessness proof for stochastic dynamic trees**: prior dynamic-tree methods (EAGLE-2/3) either don't support true stochastic sampling or lack such a proof; the equivalence-class technique is presented as reusable machinery ("template") for future stochastic-tree analyses — this is a claimed contribution, and the paper does supply a full proof (Appendix C), though it is self-verified, not independently checked.
- **OT-based verification (RheoVerification) improves on standard RRS**: supported both by a closed-form per-layer acceptance-rate derivation (Theorem 3, Appendix D) showing Rheo "almost always dominates" RRSw under stated approximations, and by controlled ablation experiments (Table 3, Table 4) isolating the verification algorithm's contribution (+1.9% acceptance vs RRSw, +5.4% vs vanilla top-K in a fixed 3-slot setup).
- **Practical efficiency preserved**: the sparse (top-128) drafting keeps sampling overhead low, and end-to-end speedups (not just acceptance-length improvements) are reported as consistently positive — evidence that the theoretical acceptance gains actually translate to wall-clock benefit, not just an on-paper metric.
- **The rheostat m gives a tunable trade-off** between structural fidelity and stochastic exploration, with an ablation (Fig. 3) and temperature analysis (Fig. 4, "degeneracy asymmetry") that credibly explains *why* m=1 tends to be the sweet spot rather than just reporting it empirically.

## Caveats — stated and inferred

- **Single GPU, single architecture family for evaluation** — all experiments run on "a single NVIDIA A6000 GPU" with EAGLE-3 draft/target pairs only (Vicuna-13B, Llama-3.1-8B, DeepSeek-R1-Distill-8B). No comparison against other dynamic-tree competitors mentioned in Related Work (Opt-Tree, Sequoia) or other verification baselines (SpecHub, SpecTr, Greedy method) in the main results — only EAGLE-3 top-K is used as the baseline. (inferred)
- **Modest absolute gains**: acceptance-length improvements over top-K range from +0.14 to +0.22 tokens (roughly 3–4%), and speedup gains are smaller still (e.g., 2.84×→2.93×, ~3.2%) because the stochastic-token sampling/verification adds overhead. The paper acknowledges this overhead explicitly. (stated)
- **Small benchmark sample size**: each of the six benchmarks uses only 80 questions — a fairly small evaluation set per task, which could affect the precision of reported means even with 3 seeds. (inferred)
- **Default temperature T=1.0 is used for "standard" results**; behavior at other temperatures is explored only in a separate ablation (Section 5.4) and the paper notes that as T→0 the benefit of RheoSampling narrows or (for m=0) disappears entirely ("dual degeneracy" to the Top-K baseline). This suggests gains are temperature-dependent and may be small in some real deployment settings (e.g., low-temperature factual QA). (stated, in the sense that the degeneracy behavior is explicitly discussed)
- **Only one stochastic token is injected per node** — the method explores just one sample from the tail per expansion step; it's unclear how this scales if applications want richer stochastic diversity (e.g., multiple samples), and the paper doesn't explore multi-sample variants. (inferred)
- **No fine-tuning of draft models**: "All draft models use the officially released EAGLE-3 checkpoints without further fine-tuning" — the draft models were trained/optimized under the original (deterministic top-K) regime, not co-adapted for RheoSampling's hybrid sampling; it's unaddressed whether a draft model trained specifically for this scheme would do even better or whether results are conservative/optimistic as a result. (inferred, though the checkpoint reuse itself is stated)
- **Proofs rely on approximations in places**: the RRSw-vs-Rheo dominance comparison (Appendix D.3) explicitly uses an approximation ("the omitted tail contribution is negligible") rather than an exact bound, so the claim that "Rheo almost always dominates RRSw" is asymptotic/approximate, not a strict universal guarantee. (stated)
- **No discussion of memory/implementation complexity** overhead from maintaining dual probability bookkeeping (proxy vs. true) at scale, or interaction with batching in production serving systems — not addressed in the paper.
- **Ablation scope is limited to one model (Llama-3.1-8B) for most rheostat/temperature ablations**, with MT-bench used across models only for a subset; broader multi-model ablation coverage for these specific studies is not shown. (inferred)
