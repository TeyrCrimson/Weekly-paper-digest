# Where You Inject Matters: The Trust Region Effect in LLM Agents

**Authors:** Chengquan Guo, Xiaodong Liu, Weiwei Yang, Mingqian Feng, Jialin Song, Qiyao Ma, Carolyn Buractaon, Christopher White, Bo Li, Jianfeng Gao

**arXiv:** [2610.38867](https://arxiv.org/abs/2610.38867)

**Categories:** cs.AI, cs.CR, cs.LG

**Submitted:** 2026-10-28

**Relevance:** 8/10 — matched: Document-borne prompt injection

---

## TL;DR
LLM agents don't just react to *what* an injected instruction says — they react to *where* it's planted. The same malicious payload, placed in a README/TODO file, got followed by GPT-5.4 2.6× more often than when placed in a code or data file ("trust region effect"), and the authors build a learning-based attacker that exploits this by jointly optimizing injection content and placement. They show placement-aware attacks beat content-only attacks and even transfer, unseen, to a more robust victim model.

## First-principles breakdown

**The problem.** An LLM agent is a model that takes a user task, then loops: read an observation (tool output, file contents, webpage, email) → decide an action → repeat. Because agents consume arbitrary external content as part of their reasoning, an attacker who controls some of that content (a file in a repo, a Slack message, a webpage) can embed instructions that the agent mistakes for legitimate directives — this is "indirect prompt injection" (IPI). Unlike direct prompt injection, the user never sees or approves the malicious text; it's smuggled in via the environment the agent operates on.

**Why prior work falls short.** Almost all existing IPI research (AgentDojo, InjecAgent, RL-trained attackers like RL-Hammer/AutoInject) varies the *content* of the injected instruction — more persuasive wording, adversarial optimization of the text — while fixing *where* it's inserted (usually some arbitrarily chosen spot). A few papers (EIA, POISE, MUZZLE) touch placement, but only within one narrow surface (one webpage, one skill file), not across the heterogeneous mix of surfaces a real agent touches (code files, docs, chat messages, emails, calendars, etc.). So nobody had cleanly isolated "placement" as its own variable, separate from content, across a realistic diversity of surfaces.

**This paper's mechanism, step by step:**

1. **Build long-horizon, multi-surface tasks.** Short benchmark tasks only touch 1–2 files/tools, so there's nowhere to vary placement. The authors stitch together multiple atomic tasks from existing benchmarks (Terminal-Bench for coding, AgentDojo for tool-use, DecodingTrust-Agent for workflows) into longer composite tasks, so a single task naturally causes the agent to read many different surfaces (README, TODO, code files, CSV/JSON data, emails, Slack, Jira, calendars, bank transactions, etc.) — 36 surface types total across 3 domains.

2. **Define a placement as a tuple (surface, position).** Surface = *which* file/channel the injection lives in (e.g., README vs. data.csv). Position = *where within that surface* (START/MIDDLE/END). This cleanly separates two axes of "where."

3. **Hold content fixed, vary placement only.** For a given attack payload and task, they insert the *identical* injected instruction into different candidate surfaces/positions and measure "conditional ASR" (attack success rate, counted only among cases where the agent actually read the injected content — this controls for the confound that an agent might simply never see the payload). This isolates placement's causal effect from content's effect.

4. **Observe the trust region effect.** ASR varies hugely by surface even with identical content — e.g., README/TODO far outstrip code/data files for coding tasks; web pages/reviews are most dangerous in tool-use; GitHub/Slack beat Confluence/Jira in workflows. They also find end-of-file position beats start/middle (consistent with recency bias — injected text closer to the point of action has more influence), and that failed injections are mostly *ignored* (not refused) — meaning there's no active safety mechanism rejecting them, just a soft attention/trust pattern.

5. **Build a placement-aware attacker.** They train a small LLM (Qwen2.5-7B) with a two-stage RL recipe (GRPO, a policy-gradient RL method popularized by DeepSeekMath): Stage I does SFT warm-up + RL to optimize injection *content* only, with placement fixed to a pre-computed "best surface, end position" prior (so the reward signal isn't confounded by placement choice). Stage II then lets the model *also* choose placement from the full candidate set, continuing RL with a composite reward (format validity + attack success + preserved benign-task utility + an LLM-judge score for coherence/authority). This staged approach avoids the chicken-and-egg problem of jointly learning content and placement from scratch.

6. **Evaluate transfer and compare to naive baselines.** They also test whether an LLM can just be *prompted* to pick good placements (it can't reliably beat a simple frequency-based prior computed from training data), and whether the trained attacker transfers to a held-out, stronger victim model it never trained against.

## Key insights

- **Genuinely new:** A systematic, controlled (content held fixed) measurement of placement's causal effect on IPI success across heterogeneous real-world-like surfaces — prior work either varied content, or varied placement within one narrow surface. The "trust region effect" is a clean, reproducible behavioral finding, and the headline 2.6× number is a real controlled comparison, not a confound of different content or different exposure.
- **Supported by evidence:** Surface-level ASR differences are large and consistent across multiple agents (GPT family, Gemini, Grok, Claude) even though the *specific* ranking of which surfaces are risky is agent-dependent — so "trust region effect exists" is well supported, but "all agents trust the same regions" is explicitly refuted (trust structure is agent-specific).
- **Supported, more modestly:** End-of-surface positioning being more effective is shown consistently in 3 domains but the effect size is much smaller in coding (+0.4pp) than in tool-use (+11.7pp) — the recency effect is real but not uniform.
- **Claimed vs. supported on the attacker:** The claim "placement-aware optimization improves attacks beyond content-only" is supported by the ASR deltas in Table 5 (+20–48pp in several settings), but the authors themselves show an important caveat: a simple non-learned empirical frequency *prior* over surfaces is "highly competitive" and sometimes beats the learned placement policy — so the big win isn't necessarily "RL learns placement," it's "placement information helps," which can be captured cheaply without RL.
- **Interesting negative result:** LLMs prompted to pick good injection placements don't reliably beat a dumb frequency prior — suggesting models can't easily introspect/predict their own (or peer models') trust biases, which has implications for both attack and defense design.
- **Transfer result (notable but thin):** The learned attacker trained only against GPT-4o achieves 33.3% ASR against a held-out, more robust GPT-5.4 model, while fixed template attacks get 0%. This is presented as evidence the learned *content* (not placement, since all injections were delivered) generalizes — a single transfer experiment, not a broad robustness study.

## Caveats — stated and inferred

- **Stated:** The "trust region effect" is defined purely behaviorally (differences in ASR across regions) — the authors explicitly do not claim to know *why* agents behave this way or make any mechanistic/interpretability claim about internal "trust" representations.
- **Stated:** Only 3 testbeds, 30 benign tasks, 24 injection tasks, 36 surfaces — authors acknowledge this doesn't cover the full diversity of real-world agent environments and that scaling up requires nontrivial verification engineering.
- **Stated:** Scope is limited to indirect prompt injection; whether the trust region effect generalizes to other agent security risks (e.g., jailbreaks, direct injection, multi-agent collusion) is left as future work.
- **Inferred — small N behind headline numbers:** Several ASR comparisons are computed from very few trials per cell (e.g., the paper itself flags that Gemini-3.1-Pro opens README/TODO in <5% of runs, making its documentation-surface ASR "estimated from very few delivered cells and correspondingly unstable" — yet it's still reported as a data point in the cross-agent comparison figure).
- **Inferred — model/version instability:** The evaluated models (GPT-5.6, GPT-5.4, Gemini-3.1-Pro, Grok-4.6, Opus5/Sonnet5) appear to be near-future/hypothetical version numbers relative to current releases; findings are tied to specific model snapshots and agent scaffolds (OpenAI Agents SDK, Claude Agent SDK, AgentDojo's native pipeline) that may not generalize to other scaffolds or prompting/system-prompt configurations, which the paper does not vary.
- **Inferred — narrow attack surface for the learned attacker's training:** The RL attacker is trained and primarily evaluated against a single victim (GPT-4o) in one domain (tool-use); the single transfer test to GPT-5.4 (one model, one domain, 30 held-out contexts) is a thin basis for the broader claim of "transfers to a more robust victim."
- **Inferred — baseline strength ambiguity:** The comparison baselines for the attacker (template-based "Ignore-Previous," "TODO," "Important-Instr" attacks) are simple hand-written templates achieving 0% ASR against GPT-5.4; this makes the learned attacker look dramatically better, but it's not clear these represent the strongest possible non-learned baselines (e.g., no comparison to other published RL-based content attackers like RL-Hammer/AutoInject on the same testbed).
- **Inferred — deterministic verifiers may miss nuance:** Attack success and utility are scored by script-based verifiers rather than human or LLM judges for the main results; this is good for reproducibility but could miscount partial/ambiguous compliance (e.g., the "Attempt" category in Table 1 where the agent tries but fails the injected goal — borderline cases depend entirely on verifier design, which isn't fully detailed in the main text).
- **Inferred — reward design includes an LLM judge, which is itself a potential confound:** The RL reward (Eq. 7) partly relies on an LLM-based judge score (goal alignment, coherence, authority) whose own biases could shape what "effective" injection content looks like, but no analysis of judge reliability/agreement is given in the main text.
