# Post-Training Large Language Models with LLMON

**Authors:** Basel Shbita, Michael Hind, Chad DeLuca, Nathan Fulton, Shubhi Asthana, Farhan Ahmed, Anisa Halimi, Yada Zhu, Mauro Martino, David Cox, Dan Gutfreund

**arXiv:** [2610.38120](https://arxiv.org/abs/2610.38120)

**Categories:** cs.AI, cs.LG

**Submitted:** 2026-10-28

**Relevance:** 8/10 — matched: Document-borne prompt injection

---

## TL;DR
This paper post-trains Granite-4.1 (3B and 8B) models using LLMON, a tagging syntax that wraps instructions and data in uniquely-identified blocks and requires an explicit "exec" pointer before any instruction is actually followed. This cuts indirect prompt-injection attack success rates from 53–100% down to 0.02–5.6% on published benchmarks, while mostly preserving general capability, and the paper backs this with per-layer attention metrics showing the model learns to structurally separate "commands" from "content to read."

## First-principles breakdown

**The core problem.** A transformer's attention mechanism has no built-in notion of "this token is a command" vs. "this token is just data to read." Every token in the context window is equally capable of influencing the next-token prediction. Today's instruction-tuned models rely on soft, learned conventions — chat template formatting, position in the prompt, phrasing like "ignore previous instructions" — to figure out what to execute. This is why **prompt injection** works: if an attacker plants an imperative sentence inside a retrieved document, a tool's API response, or any other "data" the model reads, the model may treat it as a legitimate instruction simply because it looks like one, regardless of who actually authored it or where it's supposed to sit in the trust hierarchy.

**Why prior defenses are partial.** The paper categorizes prior work:
- *Instruction tuning / RLHF* (standard alignment) teaches implicit following behavior but gives no mechanism to disambiguate when multiple instructions are present.
- *Spotlighting* marks untrusted text with in-band delimiters (e.g., special formatting within the normal text stream) — but these delimiters are made of ordinary vocabulary, so an attacker can potentially mimic or escape them via clever phrasing, since nothing prevents regular subword tokens from recreating the "boundary."
- *StruQ / SecAlign* train on structured prompts where injected instructions are present but must not be followed — closer in spirit, but still rely on role-based separation (e.g., "system" vs "user" role) rather than a token-level binding mechanism.
- *Constrained decoding / prompting frameworks (DSPy, POML)* enforce structure only at the application or inference layer, never touching the model's internal representations.

**What LLMON actually does.** LLMON introduces 6 reserved special tokens (`<|open|>`, `<|close|>`, `<|open_end|>`, `<|self_close|>`, `<|:|>`, `<|.|>`) carved out of unused vocabulary slots (so no architecture change, no embedding resize). Using these, every piece of context is wrapped into a typed, uniquely-ID'd block: `instr<|:|>ID` for instructions, `data<|:|>ID` for passive content, `doc<|.|>...` for retrieved documents, `tool<|.|>...` for flattened tool schemas. Critically, there's a separate **execution block** (`exec`) that explicitly points to which instruction-ID to run and which data-ID to use as its input — analogous to a function call that takes explicit argument references rather than relying on positional/stylistic cues. The key semantic rule (the "privilege invariant"): only content reached through `exec.instruction` or `exec.system` is authoritative; everything reached through `exec.input` — regardless of how imperative it sounds — is inert material to be read. Because the delimiter tokens occupy a disjoint, reserved region of the vocabulary, ordinary text (including adversarial text) cannot "spell" one via subword composition, unlike an in-band delimiter made of regular characters.

**Why this requires teaching, not just syntax.** Merely defining a notation doesn't make a model obey it — the model must learn, through training, to actually prioritize the exec-bound span and ignore unbound ones. That's what the "post-training methodology" part does:
1. Build a 4.6B-token corpus (4.4M examples) by converting existing instruction-tuning, RAG, and tool-calling datasets into LLMON format.
2. Add **distractor augmentation**: for each example, inject 1–3 decoy instructions and 0–3 irrelevant data blocks into the context, but keep the `exec` pointer aimed only at the true target. The target output stays identical regardless of how many decoys are added. This forces the model's loss to penalize any reliance on surface cues (position, imperative phrasing) rather than the actual binding.
3. Add dedicated prompt-injection examples (130k) where an adversarial instruction sits inside a `data` block that no exec pointer references, and the correct output ignores it.
4. Train with full-parameter SFT (3 epochs, 4096 seq length, 8×H100 FSDP) on two base (not pre-instruction-tuned) models, Granite-4.1-3B and 8B, so LLMON behavior is learned fresh rather than bolted onto an existing chat format.
5. Follow with 5 stages of GRPO (reinforcement learning against a reward model, optimizing end behavior rather than token-level loss) and a final DPO stage trained on ~1k preference pairs specifically targeting injected-instruction scenarios in agentic tool use. This DPO stage is placed last deliberately so later general-capability training doesn't erode the injection-resistance behavior learned earlier.

**How they measure success mechanistically.** Beyond just checking final outputs, the authors define three attention-based metrics computed per transformer layer: Instruction Focus Ratio (IFR, share of attention on the target instruction vs. distractor instructions), Data Attention Score (DAS, same idea for data spans), and Leakage (LEAK, share of attention escaping to any distractor content). These let them show *where in the network* the binding behavior actually lives (they find it's concentrated in the late-middle layers, ~22-38, not uniformly nor at the final layer).

## Key insights

- **Genuinely new**: the idea of carving out reserved, disjoint-vocabulary tokens to express a hard structural boundary (rather than in-band delimiters made of ordinary text), combined with explicit pointer-based "execution binding" so privilege is a property of a reference, not of a role or position. This is a reasonably clean generalization/extension of StruQ/SecAlign-style structured training, with the specific innovation being the reserved-token / pointer-binding design.
- **Distractor augmentation at scale** (up to 3 competing instructions + 3 irrelevant data segments, with identical target outputs across variants) is a solid, well-targeted training signal for forcing the model away from positional/stylistic shortcuts — this is a concrete, verifiable technique, not just a claim.
- **The quantitative injection results are strong and well-evidenced**: ASR drops from 53-100% baseline to 0.02-5.6% on two independent published benchmarks (OPI, ASB), holding across two model scales. This is the paper's best-supported claim since it's measured on third-party benchmarks rather than self-authored test sets.
- **The interpretability contribution (IFR/DAS/LEAK) is a genuine value-add** beyond "it works" — it gives a plausible mechanistic story (binding is computed mid-to-late stack, collapses at the final layer) that is consistent across layers and metrics, lending credibility to the behavioral results rather than just correlating with them.
- **Important nuance the paper itself flags**: the defense is specific to *indirect* injection (data-borne attacks). On *direct* attacks (adversarial instruction is literally the user's own turn) and multi-turn/Crescendo-style attacks, robustness only roughly doubles and stays in the 28-37% range — far from solved. The headline "0.02-5.6%" number applies only to the indirect-injection setting; readers should not generalize it to "prompt injection solved."
- Capability preservation is a claimed contribution ("without architectural modification... preserving general capabilities") but the evidence shows a real, if modest, capability cost: unchanged at 3B, but a 1.4-point average drop at 8B, with math regressing 4.5 points (84.1→79.6) at that scale — a genuine tradeoff, not fully "free."

## Caveats — stated and inferred

- **stated**: Evaluated on only two model scales (3B, 8B) within a single model family/generation (Granite-4.1); unclear whether results transfer to other architectures, pretraining corpora, or larger scales where implicit instruction-following may already be stronger.
- **stated**: LLMON's delimiter tokens increase context length by ~7-15%; inference latency/throughput impact is not systematically measured (only claimed to be "largely amortized" by training-time sequence packing, which doesn't address inference-time cost at all).
- **stated**: The privilege invariant only protects against *indirect* injection; direct and multi-turn (Crescendo-style) attacks remain much weaker (28-37% robustness vs 80-85% for indirect) — the authors explicitly say this should be "one layer of defense" not a complete solution, and the behavior is learned/statistical rather than a guaranteed enforcement.
- **stated**: Training corpus is predominantly English; multilingual tag-overhead behavior and performance on morphologically rich languages or very long documents is not characterized despite multilingual benchmarks being included in capability eval.
- **stated**: The IFR/DAS/LEAK attention metrics show correlation, not established causation, between attention patterns and output correctness; attention weights are an imperfect proxy for actual information flow in transformers, and the relationship to generation quality "may not be monotonic."
- **inferred**: The adversarial red-teaming (ARES) judge is GPT-OSS-120B and the attacker is DeepSeek-V3.2 — both reasonably strong but not state-of-the-art frontier models; a more capable or differently-tuned attacker/judge pair might surface different (likely worse) robustness numbers, so the red-team results may understate real-world risk from stronger adversaries.
- **inferred**: The interpretability analysis (Figures 2-6, Table 4) is conducted on "a representative example" and then an aggregate, but it's unclear how many examples/how much variance underlies the aggregate numbers — no confidence intervals or variance are reported for IFR/DAS/LEAK, so the "representative" framing could be presenting a favorable case.
- **inferred**: All training and evaluation data (general, RAG, tool-calling, Alpaca, Dolly, prompt-injection) ultimately derive from the same corpora used for both the LLMON and the "Instruct" baseline models ("matched chat-template corpus"), which is good for fair comparison, but also means both models share the same underlying data distribution/potential biases — robustness to genuinely out-of-distribution attack styles not represented in that corpus is untested.
- **inferred**: No comparison against the most directly competing baselines mentioned in Related Work (StruQ, SecAlign, Spotlighting) is actually run empirically in this paper — the comparison is only conceptual/qualitative ("we differ in two respects"), not an experimental baseline table, so the claimed superiority over those methods is argued rather than measured.
- **inferred**: The 8B model shows a real capability regression (math -4.5 points, overall capability -1.4) that cuts against the "without catastrophic degradation" framing in the conclusion; "catastrophic" is a strong word chosen to make a real but non-trivial regression sound negligible.
