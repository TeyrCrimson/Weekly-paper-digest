# Trajectory-Level Speculative Decoding for Diffusion Language Models

**Authors:** Tianxiang Pan, Baitao Gong, Mo Guang, Hongwei Yong, Tianpeng Jiang, Yaqian Li, Zheng Cao, Kaiwen Long

**arXiv:** [2608.27514](https://arxiv.org/abs/2608.27514)

**Categories:** cs.CL, cs.AI

**Submitted:** 2026-08-27

**Relevance:** 9/10 — matched: LLM inference efficiency and long-context serving

---

## TL;DR
This paper introduces trajectory-level speculative decoding, extending speculative decoding (previously only usable in autoregressive LLMs) to diffusion language models (dLLMs) by drafting and verifying entire denoising trajectories (positions + tokens + unmasking order) rather than token sequences. Built on top of Fast-dLLM's dual-cache system, it cuts denoising steps by 30-40%, raises tokens-per-step from 2.6 to 4.3, and achieves 7-14x speedup over vanilla dLLMs (1.3x over Fast-dLLM) with under 1% accuracy loss. The method uses confidence-stratified tree drafting, blockwise-masked parallel verification, and a novel cross-block "inter-block speculation" mechanism enabled by dLLMs' bidirectional attention.

## First-principles breakdown

**Background: how dLLMs generate text.** Unlike autoregressive (AR) LLMs that predict one token at a time left-to-right, diffusion language models start with a fully masked sequence and iteratively "denoise" it — at each step, the model looks at all positions (using bidirectional attention, not causal) and fills in some masked tokens based on confidence. In principle this allows generating many tokens per step, which is why dLLMs are pitched as faster than AR models.

**The problem: low-confidence degeneration.** Existing dLLM decoding policies either (a) always unmask the top-k most confident tokens, or (b) unmask everything above a confidence threshold τ. Strategy (b), used by the strong baseline Fast-dLLM, collapses to decoding just 1 token per step whenever no token clears the threshold — which the authors measure happens in over 80% of steps on reasoning/code benchmarks. So even though the model architecturally could emit 32 tokens per block, it often emits 1-3. Their key empirical observation: when confidence is low, the correct token is still very often in the top-3 candidates — the position isn't "wrong," it's just "ambiguous." This is the same insight that motivates speculative decoding in AR models, but it can't be transplanted directly.

**Why AR speculative decoding doesn't transfer.** AR speculative decoding works by having a cheap "draft" model (or head) guess several next tokens in the fixed left-to-right order, then verifying all of them in one forward pass of the real model using causal masking; because generation order is fixed and deterministic, this verification is exact (mathematically identical to running the real model token-by-token). dLLMs break every assumption this relies on: there's no fixed generation order (tokens can be unmasked in any order), attention is bidirectional (not causal), and multiple different denoising paths can be equally valid. So a "draft" for a dLLM isn't just candidate tokens — it must also specify *which positions* get filled and *in what order*, i.e. a whole denoising trajectory.

**The method's mechanism, step by step:**
1. **Candidate collection**: at each step, for positions where confidence c(x) = max(softmax(logits)) falls below threshold τ, collect the top-k candidate tokens instead of discarding them.
2. **Tree-based trajectory drafting**: build a tree where the root holds all high-confidence tokens (accepted as-is), and children represent alternative continuations built from the low-confidence candidate pool. To avoid exponential blowup, only the root branches with top-k candidates; deeper levels use greedy top-1 expansion — giving O(width × depth) nodes instead of width^depth. Each root-to-leaf path is a full candidate denoising trajectory (a sequence of block-level token assignments).
3. **Blockwise parallel verification**: instead of causal masking (AR-style), they design an attention mask where each draft block can attend bidirectionally to the real (cached) prefix/suffix context, but different draft branches cannot see each other — this isolates competing trajectory guesses so they can all be scored in a single forward pass without contaminating one another. The verifier then walks the tree and accepts the longest run of tokens that match the model's own top predictions (greedy or longest-path selection).
4. **Inter-block speculation**: normally blocks are denoised one at a time. Since dLLM attention is bidirectional, the model can also peek at confidence in the *next* block (B_{t+1}) while still finishing the current one (B_t). If B_{t+1}'s early confidence exceeds a trigger condition, the method builds a small draft tree for B_{t+1} too and verifies both blocks jointly in the same pass — something impossible in strictly left-to-right AR decoding.

**Formal exactness result.** The authors prove (Theorem 1) that under idealized conditions — cached KV states, no inter-block speculation, deterministic top-1 decoding — their method produces byte-for-byte identical output to the Fast-dLLM baseline, via an induction argument that both decoders compute identical logits over identical context at each step. Beyond this idealized regime (i.e., with real top-k branching and inter-block speculation), exact equivalence is no longer guaranteed; the resulting divergence is termed "trajectory drift" — the cost paid for extra parallelism. They also give a probabilistic lower bound on expected accepted-token count that compounds multiplicatively across tree depth, justifying why root-level top-k diversity matters most while deeper levels can be greedy.

## Key insights

- **Genuinely new framing**: recasting dLLM speculative decoding as trajectory-space speculation (drafting position + order + token jointly) rather than token-space speculation is the paper's central conceptual contribution, and it's a reasonably clean articulation of why AR speculative-decoding machinery can't just be ported over.
- **Diagnosing "low-confidence degeneration"** as the actual throughput bottleneck (not incorrectness) is a useful empirical observation (>80% of steps affected) that motivates the whole design, though it's based on their own measurement on one baseline (Fast-dLLM).
- **Inter-block speculation** is a distinctive mechanism that exploits bidirectional attention for cross-block lookahead, something with literally no analogue in AR decoding — this is claimed and shown (via ablation, Table 4/8) to give an additional ~12% step reduction, which is real incremental evidence, not just a claim.
- **The exactness theorem** is a solid, evidence-backed claim: it's a real proof (not hand-wavy) and they empirically confirm exact logit/token match in a top-1, no-inter-block configuration (Appendix F). This gives credible grounding to the drift-vs-parallelism tradeoff framing, though this exact mode is not the one used for headline speedup numbers.
- **Reported speedups (7-14x vanilla, 1.3x over Fast-dLLM)** are supported by fairly thorough main-result tables across two model families (LLaDA, Dream) and four benchmarks, plus ablations isolating tree structure and inter-block contributions — this is more rigorous than a single headline number.
- Comparison to concurrent work (Spiffy, self-speculative decoding) is claimed as favorable (higher tokens/step, higher speedup), but the comparison is explicitly caveated by the authors themselves as a "reference," not a controlled reproduction.

## Caveats — stated and inferred

- **Comparison to Spiffy is not a controlled reproduction** — the authors state Spiffy is not open-sourced, so Table 9's comparison uses Spiffy's self-reported numbers under a different normalization/metric convention (NFE-based vs. their own step/latency-based). (stated)
- **Accuracy degradation is non-uniform and worst on the hardest reasoning problems** — Appendix G shows the ~1% average accuracy drop is concentrated on MATH level-4 problems (30.4→25.1, a ~5 point drop), which is masked by the "under 1%" headline average. (stated, but understated as a risk in the abstract/main text)
- **No formal guarantee of exactness in the deployed configuration** — Theorem 1 only holds without inter-block speculation and with deterministic top-1 decoding; the actual reported speedups use top-k tree drafting plus inter-block speculation, i.e., outside the provably exact regime, so real-world accuracy/behavior deviations ("trajectory drift") are only bounded empirically, not theoretically. (stated, described as future work: "developing provably lossless verification... remains an open challenge")
- **Evaluation limited to two model families and four/five benchmarks**, all under a fixed generation length (512 tokens) and fixed block size (32) for main results; longer-sequence results (up to 2048) are relegated to an appendix and show shrinking relative gains due to early EOS emission causing reversion to single-step decoding. (stated, in Appendix H)
- **Hardware-specific tuning**: the "optimal" tree configuration (W2D2) is explicitly hardware-dependent (A800 vs. H800 roofline differs), meaning reported speedups may not generalize across GPU types without retuning. (stated)
- **Implementation is not fully optimized** — the authors admit their tree verification is implemented at the "Python execution level" without fused CUDA kernels, so per-step overhead is "not yet fully amortized," implying reported speedups are a floor/ceiling ambiguity: real deployed speedup could be either better (with proper kernels) or the current numbers could be inflated relative to a naive implementation baseline comparison. (stated)
- **Independence assumption in the acceptance-rate bound** (Proposition 2) assumes per-level acceptance probabilities α_j are independent across tree levels, which is a simplifying assumption not justified empirically beyond fitting the observed 3.8 tokens/step number after the fact. (inferred)
- **No ablation on the effect of tree search strategy (greedy vs. longest-path) beyond one line** stating they "yield similar performance" without showing data. (inferred — claim made without a supporting table)
- **Single-GPU baseline experiments (A800)** — most main results are single-GPU; broader distributed/production serving conditions (batching, concurrent requests) are not addressed in the paper.
- **Task-specific speedup variance is large** (13.6x on GSM8K vs 4.6x-6.8x on HumanEval/code), suggesting the method's benefit is highly dependent on how "predictable"/low-entropy the task's token distribution is — code generation benefits much less, which somewhat undercuts the generality of the headline 7-14x range. (inferred from Table 2/3, though partially acknowledged in "task-specific analysis")
- **No comparison against a non-Fast-dLLM systems-level baseline or combination with other orthogonal optimizations** (sparse attention, quantization) that the paper claims are "conceptually feasible" but never actually tests. (stated as future/out-of-scope, "beyond the scope of this work")
