# Sliding-window beats linear attention

**Authors:** Alexia Jolicoeur-Martineau, Rhea Sanjay Sukthanker, Pashmina Cameron, Emy Gervais

**arXiv:** [2608.28444](https://arxiv.org/abs/2608.28444)

**Categories:** cs.CL, cs.LG

**Submitted:** 2026-08-28

**Relevance:** 9/10 — matched: LLM inference efficiency and long-context serving

---

## TL;DR
This paper shows that Sliding Window Attention (SWA) with attention sinks — a training-free, decades-old-in-spirit trick — matches or beats post-trained Linear Attention (LA) models on short-context knowledge/reasoning benchmarks, and crushes them (2-10x) on long-context tasks like Needle-in-a-Haystack and BABILong. SWA achieves this with zero post-training tokens, higher decoding speed, and lower memory than the LA methods it's compared against. The authors argue prior LA papers made an unfair comparison (against sink-free SWA) and recommend practitioners use SWA instead of investing in linearizing pretrained models.

## First-principles breakdown

**The core problem.** Standard Transformer self-attention lets every token attend to every prior token. This gives great quality but costs grow quadratically with sequence length (O(L²) compute) and, worse for deployment, the KV cache (the stored keys/values for all past tokens) grows linearly forever — memory that never shrinks as a conversation gets longer. This makes long-context inference expensive and eventually unsustainable.

**Attempted fix #1: Linear Attention (LA).** Standard attention computes a weighted average of values using `exp(q·k)` as weights (softmax attention). Linear attention approximates `exp(q·k) ≈ φ(q)·φ(k)` for some feature map φ, which lets you rearrange the math so you maintain a fixed-size running summary (state `s` and normalizer `z`) that gets updated per token instead of storing every past key/value. This makes inference cost O(1) per token instead of growing with context length — solving the memory problem in principle. But there's a catch: this fixed-size state must compress *all* history into a bounded object, which forces a hard choice about what to keep vs. discard, and empirically the compression loses information/expressivity. LA models are also hard to train because most GPU kernels and training infrastructure are built around softmax attention.

**Attempted fix #1b: Retrofitting instead of training from scratch.** Since training LA models from scratch is expensive, researchers proposed taking existing pretrained (quadratic-attention) LLMs and "linearizing" them post-hoc via lightweight fine-tuning (e.g., LoLCATs uses LoRA with only ~40M tokens, combining a learned kernel called Hedgehog with a bit of sliding-window attention). This became popular because it seemed to recover most of the original model's performance very cheaply.

**Attempted fix #2: Sliding Window Attention (SWA).** Instead of compressing history into a fixed state, SWA simply truncates it: each token only attends to the most recent `w` tokens. This bounds both compute and memory by `w`, regardless of sequence length. Naively this seems very lossy (you can't see anything beyond the window), but two things rescue it: (1) stacking layers means information can propagate further than one window's worth per layer — after `l` layers the effective receptive field is roughly `l·w` (analogous to how stacked convolutions expand receptive fields); (2) LLMs learn to dump disproportionate attention weight onto the first few tokens regardless of their content ("attention sinks") — these act as stability anchors, and if you slide the window past them without keeping them, performance catastrophically collapses. The known fix (from prior work, Xiao et al. 2024) is to always keep attending to the first `s=4` tokens ("sinks") in addition to the sliding window — SWA(w, s).

**What this paper actually does.** It's an empirical audit, not a new method: SWA-with-sinks already existed, and post-trained LA already existed, but nobody had directly compared LA-retrofit methods against SWA-with-sinks under matched conditions. Prior LA papers compared against plain (sink-free) SWA, which is a weak/broken baseline given the catastrophic-failure issue described above. The authors run head-to-head comparisons: take a pretrained model, either (a) apply various published LA-linearization recipes (LoLCATs, Hedgehog, SUPRA, Liger-GLA, MOHAWK, QRWKV variants, etc.), each requiring their own post-training tokens, or (b) simply swap in SWA(64,4) or similar at inference time with zero training, and compare downstream task accuracy, plus separately measure speed and memory.

## Key insights

- **Genuinely new contribution**: the direct, apples-to-apples comparison itself — showing that the "obvious cheap baseline" (SWA with sinks, no training) outperforms or matches methods that require dedicated post-training pipelines (tens of millions to tens of billions of tokens) across 11 model/size combinations (1.3B–70B params) and 6 standard benchmarks (MMLU, ARC-C/E, HellaSwag, PIQA, WinoGrande). This is evidence, not just a claim — Table 1/2 show SWA winning or tying in 9/11 cases on average score.
- **Strongly evidenced**: on long-context tasks (S-NIAH up to 4K tokens, BABILong up to 4K), SWA's advantage over LoLCATs and Liger-GLA is large and consistent (e.g., SWA recovers 17-23% of full-attention accuracy at 4K vs. LA methods recovering ≤5.8%). This is the paper's strongest and most novel empirical finding, and it directly contradicts the implicit promise of LA methods (that they'd be well-suited to precisely this long-context regime, since that's where quadratic cost bites hardest).
- **Practical claim, well supported**: SWA also wins on speed (highest decode throughput) and memory (lowest KV/state footprint at small window sizes) in their measured setup — so the recommendation isn't just "equally good, no training needed" but "better on every axis measured, including the ones LA was designed to fix."
- **What's a claim vs. evidence**: the paper explicitly frames its recommendation as a practical/engineering one ("switch to SWA instead of post-training linear models") rather than a claim that LA is fundamentally unfixable — it hedges that LA models "likely require to be trained from scratch or extensive post-training" to match SWA, which is stated as a hypothesis, not tested here (they didn't train an LA model from scratch to check).

## Caveats — stated and inferred

- **Training-free scope only** (stated): the paper explicitly restricts itself to training-free SWA and does not test whether post-training SWA (shown elsewhere, Yu et al. 2025, to help) would widen the gap further or how it'd compare to LA at matched training budgets — left as future work.
- **No scaling-law comparison at matched token budgets** (stated): the authors did not test LA methods across a range of post-training token counts to see if more tokens closes the gap; they only tested each LA method at its published token budget. Their central hypothesis that LA "likely requires training from scratch or extensive post-training" to match SWA is not directly tested.
- **No hybrid/full-attention-layer models tested** (stated): they deliberately excluded models mixing some full-attention layers with linear/windowed attention, which is how some modern efficient architectures are actually deployed — limiting generalization of the conclusion to pure-SWA vs. pure-LA setups.
- **Long-context evaluation is limited to ≤4K tokens** (inferred): despite motivating the work with "ever-growing" contexts and the promise of LA/SWA for long-context efficiency, S-NIAH and BABILong are only tested up to 4K tokens — quite short by modern long-context standards (100K+ often discussed), so it's unclear if trends hold at the context lengths where memory savings matter most.
- **Window sizes tested are small (64-512)** (inferred): all headline comparisons use very small windows (window=64 for the main knowledge/reasoning table). It's not explored whether LA methods might do relatively better (or SWA relatively worse) at larger windows more representative of real deployments, though Appendix A.4 does show some larger-window plots for speed/memory only, not accuracy.
- **Baseline currency/selection** (inferred): comparisons rely on numbers reported by third-party LA papers' own configurations rather than the authors re-tuning each LA method's hyperparameters or training budget optimally; it's possible some LA baselines are under-trained relative to what's achievable, though the LoLCATs comparisons at least use the method's own published recipe.
- **Speed/memory benchmarking on a small synthetic model** (inferred): the speed/memory experiments (Figure 2) use a small 4-layer, 1024-dim synthetic Transformer, batch size 1, on a single GPU (RTX PRO 6000) — not the actual full-size models (up to 70B) used in the accuracy experiments, so real-world throughput/memory differences at production scale on production hardware are not directly demonstrated.
- **No agentic/generative or real-world downstream tasks** (stated): the authors note evaluation could be extended to "extremely large models and complex metrics, such as agentic tasks" — current results rely on standard multiple-choice/QA-style benchmarks, which may not capture all failure modes relevant to real deployment.
- **Self-conducted additional experiments (Appendix A.2) use very small post-training budgets** (inferred): the authors' own linearization experiments in the appendix use only 0.1B tokens for LA methods (Gated DeltaNet, GLA, QRWKV6) — these badly underperform teacher/SWA, but since this is a small budget, it doesn't cleanly resolve whether more tokens would close the gap; it's suggestive rather than conclusive by the authors' own logic.
