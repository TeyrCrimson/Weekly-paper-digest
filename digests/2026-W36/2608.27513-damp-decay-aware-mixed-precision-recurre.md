# DAMP: Decay-Aware Mixed-Precision Recurrent-State Quantization

**Authors:** Tao Zhang, Jianchao Tan, Pingwei Sun, Yanqi Yu, Zixu Jiang, Yuchen Xie, Xunliang Cai, Ziqian Zeng

**arXiv:** [2608.27513](https://arxiv.org/abs/2608.27513)

**Categories:** cs.LG, cs.AI

**Submitted:** 2026-08-27

**Relevance:** 9/10 — matched: LLM inference efficiency and long-context serving

---

## TL;DR
Recurrent-state-based attention alternatives (Gated DeltaNet / Kimi Delta Attention) replace the growing KV cache with a fixed-size state matrix, but that state is normally kept in FP32, which wastes GPU memory and slows decoding. DAMP is a post-training, calibration-only method that identifies a small subset of "high-risk" state channels (via quantization-error energy and decay-based persistence) and stores just those at higher precision while quantizing the rest to INT8, cutting state storage by 69% with near-FP32 accuracy. It delivers up to 2.01x faster state-update kernels and up to 10.9% lower per-token decoding latency on two production-scale hybrid MoE models.

## First-principles breakdown

**The problem.** Standard "softmax attention" keeps a growing cache of key/value vectors for every past token (the KV cache) — memory grows linearly with sequence length. Newer hybrid architectures (Gated DeltaNet/GDN, Kimi Delta Attention/KDA) replace most attention layers with a *linear recurrence*: instead of storing every past token, they compress history into one fixed-size matrix S (a "recurrent state") per layer/head, updated every step. This bounds memory regardless of sequence length — but that state matrix is usually stored in FP32, and reading/writing it every decoding step is memory-bandwidth-bound, so it becomes a real latency and memory cost at scale (the paper measures 15GB of state memory and 24.3% of decode latency for one model).

**How the state update works.** At each step, the previous state S is decayed (multiplied by a learned "forget gate" Λ, either a single scalar per head in GDN or a per-channel vector in KDA), and then a rank-1 correction is added, computed from the current key/value/query and a "delta rule" that nudges the state toward reproducing the new value. This is analogous to an RNN's hidden-state update, but structured to approximate the delta (error-correction) rule.

**Why naive quantization fails.** The obvious fix is to store S in fewer bits (INT8, FP4, etc.), like KV-cache quantization. But unlike weights (fixed) or KV cache (append-only, each entry used once and never rewritten), the recurrent state is *repeatedly read, transformed, and rewritten*. This means any rounding error introduced when you quantize S doesn't just sit there — it gets multiplied through the decay/update matrix at every subsequent step, so small errors compound (the authors formalize this as an error-propagation recurrence: total error = newly injected error + all past errors filtered through subsequent decay/correction transforms). Empirically, this makes uniform low-bit quantization (INT4, FP4) collapse accuracy to near zero, and even INT8/FP8 measurably hurt complex-reasoning benchmarks.

**Key empirical observations that motivate DAMP.**
1. *Error concentration:* After a "Hadamard transform" (a standard trick that spreads out extreme values so a single large outlier doesn't blow the quantization range) is applied within each key-channel, most of the remaining INT8 quantization error is still concentrated in a small fraction of key channels — not spread evenly.
2. *Decay is stable:* Even though a channel's instantaneous decay (retention) value fluctuates token-to-token, the *relative ordering* of channels by average decay strength is highly consistent across prompts and tasks (Spearman correlation ~0.99). So you can estimate, offline, which channels "remember" injected errors the longest.

**DAMP's mechanism.** Combine these two signals into a per-channel risk score: `risk = quantization-error-energy × decay-based persistence`. Error energy is the average squared reconstruction error introduced when writing that channel in low precision (measured on calibration data). Persistence estimates, under a simplified geometric-decay model, how long an error injected into that channel keeps contributing squared error to the state before decaying away (channels with decay close to 1 persist ~forever, capped at a max value τ to avoid infinities). Multiplying the two gives a proxy for a channel's *total accumulated damage* if quantized coarsely, rather than just its momentary rounding error.

Using this score, DAMP picks (offline, during a one-time calibration pass on 32 unlabeled documents) the top-16 (of 128) key channels per head/layer to store in FP16, and stores the remaining channels in INT8+Hadamard. Because the selection is fixed after calibration (not recomputed per token), the state can be physically laid out as two contiguous regions (FP16 block + INT8 block) via a fixed permutation, enabling a fused CUDA kernel that does regular, coalesced memory access rather than needing per-token gather/scatter — this is what actually produces the latency/throughput wins, not just the storage reduction.

## Key insights

- **Genuinely new territory (claimed and reasonably well-supported):** the paper explicitly claims to be the first study of post-training quantization for GDN/KDA recurrent states specifically (as opposed to KV caches or Mamba-style SSM states, which prior work covered). Given the related-work section's coverage, this framing appears accurate for this specific mechanism.
- **The error-propagation formalization (Eq. 4–6)** — showing state quantization error compounds through the decay/correction transition matrix — is a useful conceptual contribution that explains *why* naive uniform quantization is so much worse here than for KV caches or weights, not just an empirical observation.
- **The decay-stability finding** (channel-wise retention ordering is consistent across tasks/prompts, ρ≈0.99) is the paper's most load-bearing empirical claim: it's what justifies doing channel selection *once offline* rather than dynamically per token. This is well supported by the calibration-split stability experiment (92% top-16 overlap across disjoint calibration sets, Table 5).
- **Practical result:** at 9.9 effective bits/value (~31% of FP32 size), DAMP recovers accuracy close to FP32 baseline where uniform INT8+Hadamard at the same 9.0 bits leaves a large gap (e.g., +21.6 points average on Qwen3.6, +8.0 points on AIME for Kimi-Linear) — this is a strong, concrete, apples-to-apples comparison since both use the same bit budget.
- **Ablations support the compound design choice:** the paper shows neither error-energy alone nor persistence alone matches the combined score across all selectors tested (Tables 2, 6), supporting that both signals matter — though for GDN specifically, persistence is shared within a head (not per-channel), so it doesn't actually change the ranking there (Appendix D notes this reduces to error-energy alone for GDN).
- **Systems contribution is inseparable from the algorithmic one:** the speedups (up to 2.01x kernel, 10.9% end-to-end TPOT) depend on the *static* nature of the layout enabling a fused kernel with regular memory access — a dynamic/token-wise selection method, even if more accurate, likely wouldn't achieve these numbers. The paper states this synergy explicitly in the conclusion.

## Caveats — stated and inferred

- **(stated)** The persistence score uses a simplified "decay-only scalar model" along the diagonal decay path — it does not model the full time-varying, key-dependent transition (the rank-1 delta-rule correction term is not captured in the persistence estimate, only decay is).
- **(stated)** DAMP-INT8 works well, but DAMP variants using INT4 or NVFP4 as the *low-precision tier* do not recover FP32 accuracy — the method only really solves the problem at the ~8-9 bit regime, not push down toward 4-bit.
- **(stated)** Evaluation is limited to two released checkpoints (Qwen3.6-35B-A3B, Kimi-Linear-48B-A3B) in one serving framework (SGLang); the authors caveat that accuracy and systems gains "may vary across architectures, hardware, and serving regimes."
- **(inferred)** Both evaluated models are from a narrow class (hybrid MoE with ~3B activated params, GDN or KDA specifically) — generalization to other linear-attention variants (e.g., plain Mamba/SSM, RWKV, other gating schemes) is untested and the related-work section itself notes Mamba requires different techniques, suggesting transfer isn't guaranteed.
- **(inferred)** The calibration set is small and specific (32 documents, 256 tokens each, from four Pile domains: math, PubMed, GitHub, StackExchange) — robustness to calibration-distribution mismatch (e.g., very different domains at deployment, such as multilingual or creative text) is not tested.
- **(inferred)** The main storage/speed budget (K_hi=16 of 128 channels, i.e., 12.5%) is chosen via a sweep that "saturates" around that point on AIME 2026 only (Figure 5) — the operating point is selected using accuracy on essentially the same benchmark family used for final evaluation, raising some risk of the budget being tuned to the eval suite rather than independently validated on a held-out selection criterion.
- **(inferred)** No comparison to any *dynamic/token-wise* mixed-precision baseline (only static uniform formats and static selector ablations are compared) — it's unclear how much accuracy is left on the table by choosing a static offline layout versus an (admittedly more expensive) adaptive scheme; the paper doesn't discuss this trade-off quantitatively.
- **(inferred)** Latency/throughput numbers are measured with fairly short, fixed request shapes (input 256 / output 64 tokens from ShareGPT) — behavior at very long contexts or highly variable batch composition (mixing short and long sequences) is not directly measured for the efficiency claims, though a separate RULER long-context accuracy experiment (Appendix B) does go out to 128K tokens for accuracy only, not speed.
- **(stated, via Appendix E)** A per-head-varying budget guided by decay (allocating more high-precision channels to slow-decay heads) was tried for GDN and found to reduce measured trajectory RRMSE but *not* improve downstream accuracy — an honest negative result showing the decay signal doesn't transfer cleanly to cross-head budget allocation, only within-head channel selection.
