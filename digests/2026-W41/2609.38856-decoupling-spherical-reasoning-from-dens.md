# Decoupling Spherical Reasoning from Dense Prediction for 360 Depth Estimation

**Authors:** Zhijie Shen, Chunyu Lin, Shuai Zheng, Feng Li, Runmin Cong, Huihui Bai, Yao Zhao

**arXiv:** [2609.38856](https://arxiv.org/abs/2609.38856)

**Categories:** cs.CV

**Submitted:** 2026-09-30

**Relevance:** 7/10 — matched: Metric and temporally-consistent monocular depth

---

## TL;DR
This paper separates "where to reason" from "where to predict" in 360° depth estimation: instead of modeling spatial context on the distorted equirectangular (ERP) grid, it lifts ERP features onto a compact, near-uniform set of Fibonacci-distributed nodes on the sphere, reasons there with a multi-relation graph, then injects that context back into dense ERP features via a conditioning module. The method (FSG + SCC) is dropped into an existing UniFuse-style dual-encoder pipeline and reports lower errors than prior panoramic depth methods on three benchmarks, at lower compute cost than the two closest competitors.

## First-principles breakdown

**The core problem.** A 360° panorama is really an image on the surface of a sphere. To use ordinary CNNs/Transformers, it gets "unwrapped" into a rectangle via equirectangular projection (ERP) — the same trick used in world maps. Just like a Mercator map grossly stretches Greenland, ERP stretches regions near the poles (top/bottom of the panorama) far more than regions near the equator. A fixed-size pixel window therefore covers very different amounts of real spherical surface area depending on latitude. Any network that defines "neighboring pixels" or "attention window" directly on the ERP grid is implicitly letting the projection's distortion — not the actual scene geometry — dictate which features get grouped together. That's a problem for depth estimation, which depends on consistent geometric reasoning about surfaces and structures.

**Why prior fixes are incomplete.** Earlier work attacked this in two ways: (1) distortion-aware convolutions that locally warp sampling locations to approximate spherical neighborhoods (Tateno et al., SphereNet, etc.), and (2) multi-projection fusion — adding cubemap faces or tangent-plane patches alongside ERP to give the network less-distorted local views (BiFuse, UniFuse, OmniFusion, HRDFuse). Both families still do their actual feature interaction/attention within some planar projection (ERP, cube faces, or tangent patches), so the learned "contextual relationships" are still shaped by whatever planar grid was chosen, not by true spherical geometry. Pure spherical-mesh methods (SphereDepth, S2Net, Elite360D) go further by representing/predicting directly on spherical meshes, but then the sphere becomes the *final* representation or an auxiliary branch, which the authors imply either sacrifices the dense, pixel-aligned prediction ERP gives for free, or only gets used as a side input rather than a shared reasoning layer across the whole feature hierarchy.

**This paper's idea: decouple reasoning from prediction.** Keep ERP for what it's good at — dense, pixel-aligned depth output — but insert a *separate, native-spherical reasoning stage* that intercepts ERP features at multiple scales, reasons about them correctly, and hands enhanced context back. This has three pieces:

1. **Fibonacci Spherical Graph (FSG) — the sampling/support step.** Pick N points on the unit sphere using the Fibonacci lattice construction (combining evenly spaced latitude bands with golden-angle longitude increments — a classic trick for near-uniform point distributions on a sphere, cheaper than true equal-area grids like HEALPix). Each such node queries (bilinear-samples) the ERP feature map at its corresponding image location, producing a feature vector per node. Because these nodes are roughly uniform *on the sphere* rather than uniform *on the ERP grid*, they don't over-sample distorted polar regions the way a naive ERP grid would.

2. **Multi-relation graph reasoning — the "thinking" step.** On this compact node set (e.g., 233 to 2584 nodes depending on feature scale, vs. tens of thousands of ERP pixels), build three types of graph edges per node: "local" (k nearest neighbors on the sphere), "dilated" (the next-k nearest, i.e., a slightly wider ring, capturing mid-range context), and "antipodal" (k nodes nearest the diametrically opposite point — letting a feature "see" directly across the panorama, something no local ERP window can do cheaply). For each relation, a graph-attention-like aggregation combines neighbor features weighted by fixed cosine-similarity-based affinities plus a learned transform of relative geometry (displacement + angular separation). The three relation outputs per node are then combined via node-wise, feature-dependent softmax weights (so each node learns how much to trust local vs. dilated vs. antipodal evidence). This runs through two residual graph blocks with a feed-forward refinement (standard Transformer-style block, but over graph nodes instead of a sequence).

3. **Spherical Context Conditioning (SCC) — the bridge back to dense prediction.** The enhanced node features must be transferred back onto the full ERP grid. Naively back-projecting (interpolating node features onto every pixel's viewing direction) and adding them to the original dense features would be lossy — interpolation smooths out detail the node graph never had in the first place. So SCC instead uses the back-projected spherical context G as a *conditioning signal*: it predicts a bounded multiplicative scale and additive shift (a feature-wise affine transform, like FiLM/AdaIN conditioning) from G, gates it per-pixel/channel based on how different G is from the original dense feature X, applies that gated affine transform to X, and separately injects a gated, G-derived context term — all added as a residual on top of the untouched dense feature X. This keeps a direct, undiluted path for dense pixel detail while letting spherical context selectively modulate it, rather than overwriting it.

This whole FSG→SCC block is inserted at four scales (1/4 to 1/32 resolution) inside an existing UniFuse-style ERP+cubemap dual-encoder depth network, refining ERP features before each fusion stage. Training uses a standard BerHu robust regression loss on depth plus a spherical-gradient loss (from prior work) that supervises depth variation measured correctly on the sphere rather than on the ERP grid.

## Key insights

- **Genuinely new framing (claimed and architecturally real):** explicitly splitting "where context gets aggregated" (native spherical space via a compact graph) from "where dense prediction happens" (ERP), rather than trying to make ERP convolutions distortion-aware or just fusing in another projection. This is a clear conceptual contribution, not just a bigger model.
- **Fibonacci lattice as a cheap, near-uniform spherical support:** avoids both ERP's latitude-biased sampling and the cost of full-resolution spherical processing (e.g., true spherical CNNs or HEALPix grids), by reasoning over a few hundred to ~2500 nodes rather than tens of thousands of pixels. The paper's own ablation (Table 2: ERP-grid nodes vs. Fibonacci nodes with everything else matched) is reasonably controlled evidence that the gain comes from node distribution itself, not just from having a graph. That's a legitimate, isolated finding.
- **Antipodal relation matters more than "dilated":** Table 3 shows adding antipodal connections helps clearly, while adding "dilated" (medium-range) alone doesn't — only combining all three helps most. This is a non-obvious, specific empirical insight (long-range/opposite-side context > simply widening the local window), though it rests on a single dataset (Matterport3D) and single ablation run.
- **SCC's conditioning (vs. naive residual fusion) does extra work:** Table 2 row 3 vs row 5 isolates SCC's gated-affine-conditioning design against plain additive fusion, showing consistent gains — supporting the specific design choice over a simpler alternative, though the comparison is only against one simpler baseline (not against other conditioning schemes like plain concatenation+conv).
- **Efficiency claim is evidence-backed, not just asserted:** Table 5 shows comparable-or-better accuracy than PGFuse/HUSH at noticeably lower FLOPs, training memory, and latency, which directly supports the "compact node set avoids full-resolution graph cost" claim — this is a real measured comparison, not just a theoretical argument.
- **What's claimed but less rigorously supported:** the latitude-wise breakdown (Table 4) claims Fibonacci sampling specifically helps the equatorial, low-distortion region most — the explanation given (ERP-grid over-allocates to high latitudes) is plausible given the construction, but the paper offers only one dataset's single-run numbers as evidence, and the actual mechanism (whether the gain is really about node placement vs. something else correlated with it) isn't independently verified beyond the Table 2 comparison.

## Caveats — stated and inferred

- **Single GPU, no variance/multiple-seed reporting** — inferred: all results (Tables 1–5) appear to be single runs; no error bars, standard deviations, or repeated-seed statistics are reported, so the margin of improvement over close competitors (e.g., HUSH, PGFuse) could partly be run-to-run noise.
- **Ablations run on one dataset only** — inferred: Tables 2, 3, and 4 (the mechanistic ablations isolating Fibonacci nodes, graph reasoning, SCC, and relation types) are all conducted solely on Matterport3D; generalization of these specific component effects to Stanford2D3D or Structured3D is not verified in the paper.
- **Backbone/capacity confound with some baselines** — inferred: HUSH is retrained with a ResNet-34 backbone (marked †) and some PGFuse numbers are re-evaluated (*) or taken from the PGFuse paper directly, meaning the baseline numbers come from a mix of original-paper results, re-evaluations, and retrainings rather than one uniform controlled protocol — this could introduce inconsistencies in how "fair" the comparison really is, beyond what reader can verify from the table alone.
- **Benchmarks are all indoor-scene datasets** — stated indirectly (Matterport3D, Stanford2D3D are "real indoor panoramas," Structured3D is "synthetic indoor scenes"): no outdoor or mixed-environment evaluation is presented, so claims of general superiority for "360° depth estimation" are only demonstrated for indoor scenes.
- **No ablation on the number of Fibonacci nodes N or neighborhood size k beyond the fixed configuration given in Table 6** — inferred: the paper reports a single chosen configuration per scale without showing sensitivity to these hyperparameters (e.g., would fewer/more nodes trade off accuracy vs. speed differently than reported).
- **Gate bias initialization and zero-init of affine predictor are presented as design choices without ablation** — inferred: Appendix A.4 describes specific initializations (zero-init affine, gate bias −2) that clearly matter for training stability/behavior at init, but no ablation shows how much these specific choices contribute versus alternatives.
- **AI-assisted writing disclosed** — stated: the authors explicitly disclose using generative AI for language editing/stylistic refinement of technical descriptions, though they state experimental analyses and numerical results were authored directly.
- **Code not yet released at submission** — stated: the reproducibility statement promises source code release but it is not yet available, so independent verification of the reported numbers is not currently possible from the paper alone.
- **Comparison baselines, while including a 2025/2026-dated "HUSH"/"PGFuse," are otherwise mostly pre-2024 methods (BiFuse, UniFuse, OmniFusion, HRDFuse, EGFormer, PanoFormer)** — inferred: it's not addressed in the paper whether more recent spherical or foundation-model-based depth approaches (if any exist beyond those cited) were considered, so "existing approaches" in the abstract refers specifically to this fixed baseline set rather than the full current state of the field.
