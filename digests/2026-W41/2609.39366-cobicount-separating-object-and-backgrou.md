# COBICount: Separating Object and Background Responses for Remote Sensing Object Counting Without Training on Target Data

**Authors:** Junjing Zheng, Zhiyi Zhou, Ningrui Yang, Hongying Meng

**arXiv:** [2609.39366](https://arxiv.org/abs/2609.39366)

**Categories:** cs.CV

**Submitted:** 2026-09-30

**Relevance:** 7/10 — matched: Onboard object detection from a moving UAV

---

## TL;DR
COBICount tackles "source-only" remote-sensing object counting: train on one annotated category (e.g., buildings) and deploy directly on unseen categories/domains (vehicles, ships) with zero target data or fine-tuning. It does this by splitting density-map prediction into three stages — generate candidate responses, accept compact object-like ones, and suppress responses tied to repeated background structures (roads, parking lines, roof/water edges) — all trained using only source point annotations. On RSOC Building → DOTA Large/Small Vehicle/Ship transfer, it reports the lowest mean MAE (174.132) among 12 baselines while using far fewer parameters/FLOPs (5.07M / 17.41 GFLOPs).

## First-principles breakdown

**The underlying task.** Point-supervised object counting: instead of bounding boxes, each training object gets one dot. A network predicts a nonnegative "density map" over the image; summing all pixel values gives the count. This is popular in crowd counting (MCNN, CSRNet, Bayesian Loss) and has been adapted to remote sensing (RSOC, PSGCNet, BDRNet), where images contain many small, densely packed objects that would be expensive to box.

**The problem with standard training/deployment.** Normally a counter is trained and tested on the same "domain" — same object category, sensor, resolution, background style. If you then apply that trained model to a different category (vehicles instead of buildings) or a different sensor/region, accuracy collapses. Two existing fixes both require extra data: *domain adaptation* needs target images (labeled or not) during training; *domain generalization* typically needs several different annotated source domains to learn what's domain-invariant. Both are often infeasible — you may not have access to the target region/sensor in advance, or multiple annotated sources.

**This paper's setting: source-only counting.** Train and pick the model using exactly one annotated source domain (point annotations, one category, consistent imaging conditions). Freeze the model. Then apply it, unmodified, to completely unseen target domains — no target images, labels, statistics, or validation signal are allowed to touch the model before freezing. This is strictly harder than domain generalization as usually practiced.

**Why it fails: "candidate origin ambiguity."** A density-map network trained on buildings doesn't just learn "building appearance" — it also picks up correlated background patterns (roof edges, road layouts, parking-lot grids near buildings) because point annotations never label *what's not an object*. When you feed it vehicle or ship images, some of these spurious patterns (road edges, parking grids, harbor boundaries) produce density "responses" just as strong as real object responses. A single scalar density value can't tell you whether it came from a real object or a lookalike background structure — hence "ambiguity." Crucially, MAE/RMSE (sum-based metrics) can hide this: a missed real vehicle and a spurious background blob can cancel out in the total count even though spatially the prediction is wrong.

**The fix: decompose into three sequential gates applied multiplicatively to a shared feature map.**
1. **Candidate Evidence (CE)** — deliberately over-generates responses so weak/small objects aren't lost early. It computes a base response map, a version with strong edges suppressed (so sharp lines are discounted, via a Sobel-filter-based correction), a "wider support" version (max-pooled to catch spread-out evidence), and a routed mixture of three density sub-branches (chosen per-pixel by a softmax "scale head" — not tied to an explicit object-size label). These four pieces are combined with fixed weights into one candidate map `C_all`.
2. **Candidate Acceptance (CA)** — learns four spatial gates from source point locations: one trained to be high right at point centers (narrow target), others trained against a wider Gaussian around each point. Multiplying these together produces an acceptance mask `A` that favors responses that are compact and centered the way real annotated objects are, without any hand-coded shape/connected-component rule.
3. **Bias Isolation (BI)** — learns/derives four "risk" maps: a directly-supervised background risk (trained against pixels far from any object, i.e., it has an actual label: not-near-object), plus three unsupervised risk maps for "line-like," "broad/diffuse," and "grid-like" responses, built from a mix of learned heads and fixed image-processing signals (Sobel edges, Laplacian for repeated texture, large-window average pooling for diffuse broad responses). These combine into a retention gate `V` where high risk → low retention. None of these risk heads are ever told "this is a road" or "this is a parking lot" — they only ever see source point supervision; the names ("line," "grid") are human-readable labels for what these channels end up correlating with.

The final density map is simply `C_all × A × V × M_eff` (M_eff is a fixed, non-learned mask that zeroes out black image padding). Summing this gives the predicted count. Training losses are all derived mechanically from the source point annotations: a density regression loss near objects, count losses (relative and log-scale), losses pushing CA's gates toward 1 near points and toward 0 far away, and "hard negative" losses that explicitly penalize the model's strongest remaining responses in regions with no annotated object (forcing BI to learn to suppress exactly the kind of false positives that cause transfer failure). There's also an auxiliary "Audit" head trained only for human inspection (visualizing which internal signals fire where) — it never feeds back into the count.

**Why this helps transfer specifically.** Because the acceptance and suppression behavior is learned as generic properties ("compact and point-centered" vs. "diffuse/linear/repeated and off-center") rather than being baked into one monolithic density-prediction branch, the hope is that these properties transfer across categories even when the specific background clutter differs between domains. The paper also adds diagnostic-point extraction (finding local peaks in the final map at inference) purely for location analysis — it doesn't affect the numeric count, which always comes from summing the continuous map.

## Key insights

- **Reframing counting generalization as a problem of response *provenance*, not just total accuracy** — the "candidate origin ambiguity" framing, and the demonstration that MAE/RMSE can hide spatially wrong but numerically-cancelling predictions, is a genuinely useful conceptual contribution, backed by their own diagnostic-point/Recall@32/Precision@32 analysis showing e.g. CAN gets Recall 0.279/Precision 0.079 on DOTA LV (lots of responses, mostly wrong places) while total MAE alone wouldn't reveal this clearly.
- **Architectural decomposition (CE/CA/BI) as three distinct, separately-supervised sub-problems** is the core proposed mechanism — claimed to generalize better than monolithic density regression because acceptance/suppression logic is about generic spatial patterns, not category-specific appearance. Evidence for this is the main MT-MAE result (174.132 vs. next-best 243.722, a claimed 28.6% reduction) plus an ablation section (mentioned but not shown in the excerpted text) indicating each of CE/CA/BI contributes.
- **It's efficient**: 5.07M params / 17.41 GFLOPs is markedly smaller than most baselines (e.g., MLDG-Count 24.81M/71.79 GFLOPs, MPCount 33.23M/143.79 GFLOPs), suggesting the gains aren't just from throwing more capacity at the problem.
- **What's NOT supported as strongly as it might sound**: all "background suppression" signals (line/broad/grid risk) are *inferred correlates* of source-domain clutter, not semantic background classifiers — the paper is careful to state this, but it also means there's no guarantee these learned correlates transfer to a target domain's specific clutter types (e.g., harbor structures vs. parking grids) — this is asserted as a strength but the mechanism is fundamentally still "whatever correlated with non-objects in the one source domain," which is the same transfer risk the paper is trying to escape, just addressed with more architecture rather than removed.
- The "lowest MAE among compared methods" claim is real within their protocol but is a comparison against baselines *retrained under this specific source-only constraint* (not necessarily against each baseline's best possible design for this exact task).

## Caveats — stated and inferred

- **DOTA Small Vehicle remains a clear failure mode** — Recall@32 0.238, Precision@32 0.301, and the paper devotes a full "Boundary Analysis" section to this, attributing it to small vehicles occupying only a few grid cells after stride-4 downsampling while parking lines/shadows/road edges remain strong. (stated)
- **Single source domain per experiment** — despite framing this as a strength (less data needed), it means all results hinge on whatever one source (mainly RSOC Building) happens to teach the model; the paper itself runs alternate-source tests (DIOR Airplane, DOTA Ship as source) and notes "its accuracy still depends on the source data." (stated)
- **Background-suppression heads have no ground-truth semantic labels** — three of four BI risk maps are trained only indirectly (via the final count/density loss and hard-negative penalties), so what they actually learn to suppress is unconstrained and could fail to generalize to a target domain's specific background clutter (e.g., harbor structures the source domain never saw). (inferred, though the authors are transparent that these are not classifiers)
- **Audit head outputs explicitly flagged by authors as unreliable** — "numerical values should not be read as reliable probabilities of unseen target classes" since vehicle/ship channels get no direct training label; included only for qualitative inspection. (stated)
- **Fixed, hand-tuned coefficients throughout** (e.g., the 0.34/0.24/0.22/0.20 weights in CE, the 0.72/0.58/0.48/0.60/1.00 weights in BI, threshold constants like 0.035, 0.28×max, etc.) — many "fixed implementation values" are seemingly manually chosen rather than learned or justified by a sensitivity analysis; the paper doesn't show how sensitive results are to these choices. (inferred)
- **Baselines retrained from scratch by the authors under a constrained protocol**, not necessarily using each baseline's best possible hyperparameters for this unusual source-only setting — the paper is transparent that these are "results obtained after retraining under this setting rather than numbers published for their original datasets," which is reasonable methodology but means baseline numbers could underrepresent what those architectures can do if better tuned for this exact transfer task. (stated, with inferred risk of baseline under-tuning)
- **Only one hardware/software configuration reported**, single random seed (3407) mentioned for training — no variance/multiple-seed results are shown in the provided text, so robustness of the headline MAE numbers to training randomness is unverified. (inferred)
- **Evaluation protocol conversions are lossy**: DOTA's oriented quadrilaterals and DIOR boxes are reduced to single centroid points for evaluation, discarding size/orientation information that could matter for small, rotated vehicles — plausibly part of why Small Vehicle performs worst. (inferred, though partially acknowledged implicitly in the boundary analysis)
- **No real-world/non-benchmark deployment test** — all evaluation is on established academic benchmarks (RSOC, DOTA, DIOR); generalization to genuinely novel sensors/resolutions outside these curated datasets is not addressed in the paper.
- **Middle-of-paper ablation details were truncated** in the provided text, so the specific quantitative contribution of each of CE/CA/BI individually (claimed in the conclusion) could not be verified against the actual ablation table from this analysis. (inferred limitation of this review, not a paper flaw per se, but worth flagging: the "CE/CA/BI each contribute" claim is taken from the conclusion's summary rather than independently checked here.)
