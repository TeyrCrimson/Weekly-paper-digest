# Embedded Bi-Temporal Building Damage Assessment for On-Board Data Reduction

**Authors:** Thomas Goudemant, Benjamin Francesconi, Marjorie Bellizzi, Adrien Dorise

**arXiv:** [2609.37013](https://arxiv.org/abs/2609.37013)

**Categories:** cs.CV, cs.AI

**Submitted:** 2026-09-29

**Relevance:** 7/10 — matched: Onboard object detection from a moving UAV

---

## TL;DR
The paper extends a prior ground/on-board bi-temporal building-damage-assessment pipeline (siamese YOLOX) by adding a latent-space shift-estimation-and-correction module that geometrically realigns pre/post-disaster features before fusion, substantially improving robustness to large co-registration errors while staying compatible with 64× latent compression. The authors then port the full pipeline to a Xilinx Versal VCK190 DPU and an NVIDIA Jetson AGX Orin, finding the core detector and compression deploy cleanly on both, but the robustness-giving operators (cross-attention, grid-sample-based alignment) only survive on the Jetson GPU. All results are on the xBD benchmark with synthetic test-time shifts, not real on-orbit data.

## First-principles breakdown

**Problem setup.** After a disaster, satellites can image the area quickly, but getting that imagery useful on the ground is bottlenecked by (1) uplink bandwidth to send a pre-disaster reference image to the satellite for comparison, (2) downlink bandwidth to send the full post-disaster scene back down, and (3) ground-processing latency before anyone gets an actionable damage map. The standard approach — bi-temporal change detection — compares a "before" and "after" image to flag newly damaged buildings (needed because a damaged-looking building might just always have looked that way; you need the "before" to disambiguate). But conventional pipelines are "ground-centric": both images are downlinked/transmitted in full and compared offline, which is slow and bandwidth-heavy.

**Core idea: push comparison on-board, compress what crosses the link.** Instead of sending a full pre-disaster image up and a full post-disaster image down, the system:
1. On the ground, encodes the pre-disaster image into a compact "latent" (an intermediate neural-network feature representation) using a shared encoder, then compresses it with a simple 1×1 convolution that reduces the number of channels by a factor r (up to 64×, shrinking ~3.15MB down to 57kB).
2. Uplinks only this tiny latent, decompresses it on board.
3. The satellite captures the post-disaster image, runs it through the same encoder, and compares the two latents using a detector (a "siamese" network — same weights applied to both images, enabling direct feature-level comparison) built on YOLOX-S (a fast, single-stage object detector with a CSPDarknet backbone producing features at three scales/strides: 8, 16, 32 — finer D3 captures geometric detail, coarser D5 captures semantic/object-level meaning, fused by a Path Aggregation FPN that mixes top-down and bottom-up information).
4. Downlinks only the output: bounding boxes + damage class per building, not pixels.

This is an evolution of the authors' own prior work (ref [9]), which already established siamese processing + compression + "shift augmentation" (randomly jittering images during training so the model learns some tolerance to misalignment) and used standard cross-attention as a robustness baseline.

**The two problems this paper actually tackles:**

1. **Large misregistration.** On-board geolocation isn't perfectly accurate, so the pre- and post-disaster images don't line up pixel-for-pixel — there's a shift. A plain siamese network compares features at matching (x,y) locations; if the images are shifted, it's comparing the wrong things, which hurts damage classification (though box localization is more stable because boxes are predicted in the pre-disaster frame). Shift augmentation alone only helps up to the range trained on (150px) and still degrades badly (mAP falls to 26.6% at 400px shift, from 56.6% nominal). Cross-attention (each location can "look up" information from any other location, à la Transformers) helps more because it's not restricted to the same spatial position — but its core operation (softmax over a huge similarity matrix) is a fixed-function operator that doesn't run on the Versal DPU hardware.

   The paper's new mechanism: an explicit **offset estimation and correction module**. Rather than letting the network implicitly learn to cope with shift (via augmentation) or search broadly (via attention), it explicitly computes the global (δx, δy) pixel shift between pre- and post-disaster images, then physically resamples (warps) the post-disaster features to undo that shift before fusion. Mechanically: take the finest/most detailed feature level (D3), downsample it cheaply (stride-4 conv to 32×32) to keep the search affordable, compute cosine correlation between pre and post features over a grid of candidate offsets (±13 cells = ±416px), and take a "soft-argmax" (a differentiable weighted average over the correlation grid) to get a sub-pixel shift estimate. Apply that shift via bilinear resampling ("grid sampling," a standard differentiable image-warping operation) to all three feature levels, scaled appropriately per stride. It's trained end-to-end with the normal detection loss plus an auxiliary loss that directly supervises the shift prediction against the known synthetic training shift.

   Why this works better: it doesn't need to memorize specific offsets (like augmentation) or do an expensive all-pairs search (like attention) — it geometrically estimates and corrects the shift, so it generalizes to shifts far outside the training range (robustness stays flat well past the 150px training limit, reaching 49.4% mAP at 400px vs 26.6%/43.0% for augmentation/attention).

2. **Embedded deployability.** It's not enough for an algorithm to work in Python on a GPU — it has to compile and run on actual spacecraft-grade hardware, which has hard constraints. Two targets are tested: a Xilinx Versal VCK190 (a DPU — "deep learning processor unit" — a fixed-function ASIC-like accelerator programmed via Vitis AI, int8 only, and critically requires the ENTIRE model to compile into a single subgraph or it just fails to run at all), and an NVIDIA Jetson AGX Orin (a general-purpose embedded GPU, programmed via TensorRT, much more flexible). The finding: the base detector, the compression step, and a "portable" convolution-based attention gate (CBAM-style: a local convolutional gating mechanism, not real attention — it re-weights features but can't fetch information from a different spatial location) all compile fine on the DPU. But real cross-attention (softmax over large similarity matrices) and the new grid-sampling-based alignment module do NOT compile/run correctly on the DPU — only on the Jetson's GPU via TensorRT.

## Key insights

- **Novel, well-supported contribution:** the explicit latent-space shift estimation+correction module. Evidence (Fig. 3, Fig. 4, Tab. 2) shows it beats both shift augmentation and cross-attention under large de-registration, extrapolates beyond its training shift range, and barely degrades when combined with 64× compression — this is a real, measured result, not just a claim.
- **Compression is nearly free for nominal accuracy:** 64× latent compression costs only ~1pp mAP while cutting uplink payload by two orders of magnitude — supports the claim that pre-disaster reference information is highly redundant/compressible for this task.
- **Clear negative result, stated explicitly by authors:** the DPU-portable "spatial-difference" attention gate does NOT deliver meaningful robustness to misregistration (behaves like plain siamese, 29.2% vs 49.4% for the proposed module at 400px) — a genuine, useful finding that tempers enthusiasm about "hardware-friendly attention" substitutes.
- **Deployment-reality insight:** this is presented as (to their knowledge) the first dual ground/on-board detector of its kind actually ported and benchmarked (latency/throughput/power) on two real embedded accelerators, not just simulated. The headline trade-off — Jetson GPU can run the fully robust pipeline but at ~40% latency cost and dropping to Versal-like energy efficiency, while Versal DPU is faster/more efficient but structurally cannot run the robustness-critical operators — is a concrete, hardware-grounded conclusion rather than speculation.
- **Honest bug disclosure:** they found and reported an unresolved ~3.24pp mAP drop when porting the alignment module to Jetson FP16, diagnosed (with reasoning, not just assertion) as a grid-sampling convention mismatch rather than quantization — a sign of methodological transparency rather than cherry-picking.
- Distinguish claim vs. evidence: the claim that this "moves closer to raw on-board inputs" is explicitly qualified by the authors themselves as only a step toward that goal (see caveats) — not full validation on raw/unprocessed sensor data.

## Caveats — stated and inferred

- **stated** — "This work is a step toward raw on-board data, not a validation on it." Inputs are L1C-like (ortho-rectified, calibrated, only coarsely co-registered RGB pairs from xBD), not raw sensor data; real on-board effects (sensor calibration, scale, rotation, cross-sensor pairs) are not evaluated.
- **stated** — Each real-world variability factor present in xBD (off-nadir drift, illumination, seasonal change across 19 events) is not evaluated separately/in isolation — so it's unclear how much the measured robustness generalizes to each factor individually.
- **stated** — The alignment module only handles a single global translational shift (δx, δy); it does not address scale or rotation misalignment — explicitly flagged as future work.
- **stated** — An open, unresolved porting bug causes a 3.24pp mAP drop for the full alignment model in FP16 on Jetson, attributed to a grid-sampling convention mismatch; the authors say this "must be resolved before this model is trusted in production."
- **stated** — The alignment/cross-attention robustness mechanisms are fundamentally non-portable to the Versal DPU (fixed-function operator set), so the "robust" pipeline is currently a single-vendor (Jetson/TensorRT) solution; the DPU path lacks a long-range robustness solution ("remains open").
- **inferred** — All quantitative results are from a single benchmark (xBD/xView2) with synthetic, post-hoc applied test-time shifts (not real physical misregistration from actual satellite geolocation/attitude errors), so real-world shift statistics/distributions may differ from the simulated ±416px sweep.
- **inferred** — No comparison to other state-of-the-art bi-temporal change-detection/damage-assessment architectures (e.g., transformer-based siamese networks cited in related work like SiamixFormer) — the only baselines are internal ablations (early fusion, siamese, shift-aug, cross-attention, portable attention), so it's unclear how this stacks up against the broader field's best models.
- **inferred** — Batch-size sweep on the DPU (VCK190) is not performed ("changing the batch size requires re-building [the DPU image], too costly to sweep"), so hardware comparisons across platforms are not fully controlled for this variable — the cross-platform efficiency comparison (Tab. 4) uses fixed, possibly non-optimal batch settings per platform.
- **inferred** — No uncertainty/variance reporting (e.g., error bars, multiple training seeds) for the mAP numbers in Tables 2–4, so the magnitude of some small deltas (e.g., 1pp differences) isn't clearly distinguishable from noise.
- **inferred** — The r=128 compression failure (single D3 channel breaks the offset estimator) suggests the method is closer to an information-theoretic edge than acknowledged elsewhere; the paper frames r=64 as "the aggressive-compression limit," but this was only tested at two compression levels (64, 128), not a fine-grained sweep, so the true breakdown point is not well characterized.
