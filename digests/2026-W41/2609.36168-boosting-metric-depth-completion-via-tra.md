# Boosting Metric Depth Completion via Training-Free Adaptive Response Geometry

**Authors:** Mia Zhang, Jizong Peng

**arXiv:** [2609.36168](https://arxiv.org/abs/2609.36168)

**Categories:** cs.CV

**Submitted:** 2026-09-28

**Relevance:** 8/10 — matched: Metric and temporally-consistent monocular depth

---

## TL;DR
Monocular depth-completion pipelines align foundation-model depth priors to metric scale using a fixed, hand-picked coordinate (raw depth, log-depth, or disparity), which leaves systematic depth-dependent calibration errors. This paper makes that coordinate choice an estimated, per-image parameter (via a Box-Cox-style family) fit jointly with the usual affine scale/offset, then propagates leftover residuals through a hard-constrained Poisson solve. The resulting training-free method beats three trained completion baselines (PriorDA, LDCM, Any2Full) on macro AbsRel and median normal-angle error across nine benchmark subsets.

## First-principles breakdown

**The underlying problem.** A monocular depth model (e.g., MoGe-3) looks at one RGB image and outputs a dense "relative depth" map. This map correctly captures shape/structure but not true scale — a photo of a dollhouse and a real room can produce the same-looking depth map. "Depth completion" tries to fix this using sparse ground-truth measurements (e.g., a few LiDAR points) scattered over the image: wherever you have a true depth, you can calibrate the model's output; the goal is to propagate that calibration to every pixel, including where there's no sensor data.

**Why the naive fix (affine fit) is insufficient.** The simplest fix: assume predicted value `h` relates to true depth `s` by `s = α·h + β` (a straight line — one scale, one offset). But different models are trained to output values that behave linearly in different coordinate systems — Depth Anything/MiDaS normalize in "disparity" (1/depth) space, ZoeDepth/Metric3D normalize in log-depth space, MoGe-3 in raw metric depth. If you apply the affine fit in the "wrong" coordinate for a given image, the fit systematically over/under-shoots at near vs far ranges — the true relationship is curved, not linear, in that coordinate. The paper shows this empirically (Fig. 1, 2): fitting a line in metric, log, or disparity space all leave different, visible banded errors across depth ranges.

**Why prior fixes don't fully solve it.** One alternative (Region-aware Scale Adaptation) tries fitting many *local* affine maps (one per semantic region via Segment Anything) instead of one global map. But with sparse/incomplete measurements, most small regions don't have enough calibration points to fit their own scale/offset reliably — so local flexibility is "underconstrained" exactly where you need it most.

**This paper's mechanism, step by step:**
1. **Unify the three coordinate choices into one family.** Using a Box-Cox transform `φ_λ(z)`, a single real-valued knob λ continuously interpolates between disparity (λ=−1), log-depth (λ=0), and raw metric depth (λ=1) — and allows values outside that range too (e.g., λ=2 or 7.66 were found optimal on some test images). So instead of the engineer picking the coordinate in advance, λ becomes a free parameter to be estimated per image.
2. **Estimate λ jointly with scale α and offset β from the sparse metric observations.** For every sparse pixel where you have both the model's prediction `h` and the true depth `s`, the equation `φ_λ(s) = α·φ_λ(h) + β` should hold. The paper fits (λ, α, β) by nonlinear least squares (Levenberg–Marquardt) directly minimizing the error in *meters* (not in the transformed space), so the fit optimizes for what you actually care about. Because there are only 3 parameters shared globally across the whole image, this stays well-constrained even when observations are sparse — unlike the per-region approach.
3. **Why this helps:** mathematically, λ controls a "depth-dependent gain" — i.e., how much a given depth increment "counts" differently at near vs far ranges (derived via `dφ_λ(z) = z^(λ-1)dz`, Eq 13). Picking the right λ absorbs the smoothly-varying miscalibration that a fixed coordinate's rigid weighting couldn't, before the simple affine step cleans up what's left.
4. **Hard-Dirichlet residual reconstruction.** After calibrating the whole dense map with (λ⋆, α⋆, β⋆), the result still won't exactly match the sparse ground-truth points (least-squares fit, not interpolation). So the method runs a Poisson-style optimization (borrowed from image editing / "Poisson blending") on log-depth that: (a) matches the gradient of the calibrated map, (b) stays close to the calibrated values, (c) penalizes curvature, while (d) being forced ("hard constraint," i.e., Dirichlet boundary condition) to exactly equal the true depth at every observed sensor pixel. This step is purely spatial/local and doesn't touch the global (λ,α,β) already estimated.

**End-to-end**, this is "training-free": no neural network is trained for completion; it's optimization applied at test time on top of an off-the-shelf frozen depth-prior model.

## Key insights

- **Genuinely new idea**: treating the response/output coordinate (depth vs log-depth vs disparity) as an unknown, estimated parameter rather than an architectural/training choice baked into the foundation model. This reframes "scale calibration" as a 3-parameter nonlinear fit instead of either a 2-parameter linear fit or an underconstrained per-region fit.
- **Supported by evidence**: on their benchmark (DIODE, ETH3D, iBims-1, ARKitScenes, 5 Tanks-and-Temples scenes under deliberately incomplete sparse observations), the full pipeline beats three trained baselines (PriorDA, LDCM, Any2Full) on both macro AbsRel (0.0301) and macro median normal error (14.04°) — without training any completion network. Ablations (Sec 4.4) show the response-estimation step alone improves over fixed-coordinate alignment, and the Dirichlet completion step further lowers AbsRel on every subset (though it *increases* normal error relative to the response-only stage).
- **Important nuance, not just a clean win**: the authors' own ablation (Appendix C) shows the "response-only" (no spatial completion) variant has *better* normal quality than the full pipeline on all nine subsets — meaning the spatial residual-correction step trades away some surface-orientation accuracy to gain metric depth accuracy. The paper is honest that these are two distinct axes of improvement, not a single monotonic gain.
- **Per-subset story is mixed, not uniform**: LDCM beats "Ours" on AbsRel on 4 of 9 subsets (iBims, ARKit, Barn, Meetingroom); Any2Full beats "Ours" on NMed on 2 subsets (Caterpillar, Truck). The paper's headline numbers are macro (averaged) wins, not universal per-subset dominance.
- Transfer experiments (Appendix E) show the method generalizes across different depth priors (MoGe-2, MoGe-2 Small, Depth Anything V2), with consistent AbsRel gains from the Dirichlet stage, though absolute accuracy still depends heavily on which prior is used.

## Caveats — stated and inferred

- **Single monotone response cannot fix everything** (stated): the authors explicitly note a fundamental limit — one global response per image "cannot resolve arbitrary spatial disagreements or correct depth-order reversals in the prior." If the underlying model gets relative depth ordering wrong somewhere, this method cannot repair it.
- **Normal-error trade-off from the completion stage** (stated): Dirichlet completion lowers AbsRel on every subset but *raises* macro NMed (11.46° → 14.04°), and response-only normal error is lower than the full method's on all nine subsets — explicitly flagged as a direction for future improvement, not a clean win.
- **Benchmark curation excludes a problematic scene** (stated): "Courthouse" from Tanks and Temples was processed but explicitly excluded after audit revealed depth-rendering errors near foliage (~20.8% of frames had notable far-pixel contamination); only partially correctable. While the exclusion is well-justified and transparently documented, it does mean the benchmark was hand-filtered to scenes where their/public reference-depth pipeline works cleanly — a form of selection in which scenes make the cut.
- **"Deliberately incomplete" synthetic sparsity, not real sensor data** (inferred): observations are constructed via a synthetic grid-stride/central/outer-removal protocol on top of existing dataset ground truth, not actual sparse LiDAR scans in the field. This is a controlled, synthetic missingness pattern; real-world sparse LiDAR patterns (e.g., actual scan-line structure, noise, dropout correlated with material/distance) may differ and aren't tested.
- **No training data / baselines retrained on this exact protocol** (inferred): PriorDA, LDCM, Any2Full are trained completion networks evaluated presumably in their stock/released form against this paper's specific synthetic incomplete-observation protocol; it's not stated whether these baselines were retrained or fine-tuned for this exact sparsity pattern, raising a possible train/test distribution mismatch favoring the training-free method, which adapts per-image regardless of sparsity pattern by construction.
- **PromptDA baseline essentially fails** (stated in data, not elaborated as a limitation of the comparison): PromptDA reports AbsRel near 0.99 (essentially degenerate) on most subsets, suggesting either an inference-protocol mismatch or the baseline being poorly suited to this setup — the paper relegates detailed discussion to an appendix (G.2) rather than treating it as a fully fair comparison in the main table.
- **Weight-sensitivity sweep shows only mild robustness tested over a narrow range** (inferred/stated): Appendix D sweeps λ_data and λ_lap only over 1e-4–1e-2, a narrow range, and finds "modest changes" — this doesn't establish robustness outside that narrow window, and the main experiments fix these weights without stated justification for the chosen values (1e-3, 1e-3).
- **No wall-clock/compute cost comparison** (inferred): the paper emphasizes "training-free" as an advantage but gives no runtime/compute comparison against the trained baselines at inference time — not addressed in the paper.
- **AI-assisted writing and figure generation** (stated): the authors disclose using GPT-5.6/GPT-6 for related-work retrieval, prose editing, and Claude Code for figure generation from their data — they state they verified all outputs, but this is worth noting as a transparency disclosure.
- **Single prior as primary result, others relegated to appendix** (inferred): the headline Table 1 results use only MoGe-3; broader prior-transfer results (Appendix E) are secondary and show accuracy varies noticeably by backbone (e.g., ETH3D AbsRel ranges 0.0180–0.0300 across priors), meaning the strong headline numbers are somewhat prior-specific.
