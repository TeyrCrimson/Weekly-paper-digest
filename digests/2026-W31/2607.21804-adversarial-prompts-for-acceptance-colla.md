# Adversarial Prompts for Acceptance Collapse in Speculative Decoding

**Authors:** Run Wang, Chaoyi Zhou, Xi Liu, Yi Zhu, Amir Salarpour, Pedram MohajerAnsari, Zhi-Qi Cheng, Feng Luo, Siyu Huang, Mert D. Pesé

**arXiv:** [2607.21804](https://arxiv.org/abs/2607.21804)

**Categories:** cs.CR, cs.CL, cs.LG

**Submitted:** 2026-07-23

**Relevance:** 8/10 — matched: Pre-inference input sanitization for generation stability

## TL;DR
ADSD is a prompt-suffix attack that exploits the internal accept/reject mechanism of speculative decoding: by crafting a short adversarial suffix, an attacker can make the draft model systematically propose tokens the target model is unlikely to accept, forcing repeated draft-verify rounds and inflating latency (e.g. +62.3% mean sample time on GSM8K) while leaving the final answer quality largely intact. The attack generalizes across speculative decoding strategies (tokenwise, blockwise, hierarchical), model architectures (Qwen, LLaMA-3, EAGLE-3), and transfers to unrelated task domains (code, summarization) without re-optimization.

## First-principles breakdown

**The problem domain: speculative decoding.** LLM inference is normally autoregressive — one token generated per forward pass, which is slow. Speculative decoding speeds this up by pairing a cheap "draft" model (or a lightweight head sharing the big model's hidden states) with the expensive "target" model. The draft proposes several candidate tokens quickly; the target then checks all of them in a single parallel forward pass. If the draft's tokens agree with what the target would have generated, multiple tokens get "accepted" for the price of one target pass — a big speedup. Critically, the *acceptance test* is designed so that whatever gets emitted is statistically identical to plain target-only decoding (i.e., "lossless"): a drafted token v is accepted with probability α(v) = min(1, p(v)/q(v)), where p is the target's probability for v and q is the draft's probability. If a token is rejected, everything after it in that batch is thrown away and the draft has to start over — turning the "free" speedup into wasted compute.

**Why this creates a vulnerability.** The acceptance rule is asymmetric: if the draft assigns *less* probability to a token than the target does (q(v) ≤ p(v)), it's always accepted. Rejection only happens when the draft is "overconfident" — assigning more probability to a token than the target would (q(v) > p(v)). So the attack surface is precisely this positive gap between draft and target confidence. Prior work on speculative decoding only tried to *improve* alignment between draft and target (better training, smarter verification), implicitly assuming the prompt is benign. Prior *security* work on speculative decoding looked at side-channel leakage or safety-steering, not at deliberately breaking acceptance. And prior "denial-of-service" attacks on LLMs generally worked by making outputs longer or exploiting scheduler/guardrail behavior — outside the decoding algorithm itself. ADSD is different: it attacks the accept/reject test itself via the prompt.

**Threat model.** The attacker only gets to append a short (~5 token) suffix to an otherwise normal prompt — no access to weights, KV-cache, or serving infrastructure. They're assumed white-box: they know the draft model, target model, tokenizer, and verification rule ahead of time, and use this to *offline* optimize a universal suffix that's then used at inference time.

**The mechanism — Soft-Collapse objective.** Define the "log margin" for a candidate token v at rollout step i as Δ(v) = log q(v) − log p(v). The acceptance probability can be rewritten as α(v) = exp(−ReLU(Δ(v))): only the *positive* margin (draft overconfident relative to target) reduces acceptance. The paper's core loss, Soft-Collapse (SC), is the expectation under the draft distribution of this positive margin: SC = Σ_v q(v)·ReLU(log q(v) − log p(v)). Maximizing SC pushes probability mass in the draft distribution toward exactly the tokens that the verifier is likely to reject — it's a differentiable surrogate aligned with the true (non-differentiable, sampling-based) acceptance mechanism, rather than a generic "make draft and target disagree" loss.

**Stealth — target-preservation term.** If you only maximize SC, you could easily also wreck the target model's own output (e.g., trigger a refusal or gibberish), which would flag the attack as anomalous or simply produce a useless slow request nobody would send. So ADSD adds a KL penalty between the *benign* target distribution (no suffix) and the *attacked* target distribution (with suffix), pushing the optimizer to keep the target's own behavior close to normal even as the draft is being sabotaged. The final loss combines both terms with weights λc (collapse) and λp (preservation), summed over a small calibration set of prompts and rollout steps, with earlier rollout steps weighted more heavily (since an early rejection wastes more of the speculative block than a late one).

**Search procedure.** Since the suffix is discrete text (not continuous embeddings), ADSD can't just do gradient descent directly. It uses gradient-guided beam search (similar in spirit to the GCG jailbreak-suffix method): at each suffix position, compute the gradient of the loss w.r.t. the token's embedding to shortlist promising replacement tokens, actually substitute each candidate and re-evaluate the true (non-relaxed) objective, keep the best few suffixes in a beam, and sweep left-to-right across all suffix positions for several rounds, finally picking the highest-scoring suffix.

**Why it's hard to defend against.** Perplexity-based filters (a common defense against adversarial suffixes) look at the whole prompt; a short 5-token suffix embedded in a long few-shot prompt barely moves the aggregate perplexity. Output-based defenses (checking if the final answer looks wrong) also often miss it because the case studies show the standalone draft model derails into nonsense, but the larger target model frequently "repairs" the trajectory and still emits a correct final answer — so the user-visible output looks fine even though the internal draft-verify process has already collapsed into slow, wasteful repeated rounds.

## Key insights

- **Genuinely new framing (claimed and reasonably well supported):** this is presented as the first attack targeting the internal accept/reject mechanism of speculative decoding itself (as opposed to output-length inflation, scheduler abuse, or safety-related attacks). The paper's related-work discussion supports that this angle hasn't been explored before.
- **The Soft-Collapse surrogate is the technical core**, and the ablation (Table 6) is the strongest evidence it matters: removing it collapses the attack back to near-benign performance (27.66s vs. 42.29s with full objective), showing that a generic "maximize disagreement" objective is not sufficient — the surrogate must specifically target the asymmetric, verifier-relevant direction of disagreement.
- **The target-preservation KL term is what buys stealth**, not just performance: removing it produces an even bigger slowdown (49.67s) but tanks GSM8K accuracy from 0.821 to 0.703, which the authors treat as violating the attack's stealth requirement. This is a real trade-off the paper explicitly quantifies, not just an assumed benefit.
- **Transferability across architectures and decoding strategies is the most surprising/useful empirical result**: a suffix optimized only for Qwen2.5-14B/0.5B on GSM8K still degrades LLaMA-3-70B/8B, EAGLE-3 (a fundamentally different auxiliary-head architecture, with the largest relative degradation of all settings: −76.9% block efficiency), and blockwise/hierarchical speculative decoding variants — suggesting the vulnerability is structural to the draft-target acceptance rule rather than an artifact of one specific model pairing.
- **Domain transfer without re-optimization** (suffix tuned on GSM8K applied to HumanEval and CNN/DailyMail) shows the attack isn't narrowly overfit to math QA, though — importantly — the paper's own data shows this transferred suffix *does* damage task quality noticeably on the new domains (pass@1 drops 0.829→0.683, ROUGE-1 drops 0.227→0.048), which undercuts the "stealthy across domains" framing even though latency transfer is strong.
- Baseline comparison (random suffix, adapted GCG) supports that ADSD's verifier-aware objective outperforms generic adversarial-suffix search for this specific goal (largest slowdown, smallest accuracy cost among the three).

## Caveats — stated and inferred

- **White-box assumption is a major limitation** (stated): the attacker needs offline access to both draft and target model weights/distributions and knowledge of the exact verification rule. No black-box or transfer-only threat model (attacking a closed API without model access) is evaluated. The paper's own limitations section acknowledges the analysis is "limited to white-box optimization and a representative set of draft-target pairs."
- **No proposed or evaluated defense** (stated): Section 6 explicitly says defense design and evaluation is "left to future work"; only a sketched mitigation (online acceptance-rate monitoring) is discussed conceptually, with no experiments showing it works or what its false-positive/overhead costs would be.
- **Stealth claims are inconsistent across the paper's own results** (inferred): the abstract and main results frame the attack as "preserving task quality," but this holds cleanly only on the GSM8K in-domain results (0.821→0.802 accuracy). When the same suffix transfers to HumanEval and CNN/DailyMail (Table 3), task quality drops substantially (pass@1 0.829→0.683; ROUGE-1 0.227→0.048), and the ablation without the KL term shows accuracy dropping to 0.703 — so "stealthy while degrading performance" is a narrower claim than the headline suggests, true mainly for the calibration domain.
- **Small calibration/evaluation footprint** (inferred): suffix search uses only N=10 calibration prompts, suffix length m=5, and specific fixed hyperparameters (beam size 4, K=64 rollout steps); it's not clear from the text how sensitive results are to these choices, and no ablation over suffix length or calibration set size is presented.
- **Single-seed / limited statistical reporting** (inferred): most tables report a single latency/accuracy number without confidence intervals; only Table 2 includes ± uncertainty ranges. It's unclear how much run-to-run variance affects the headline percentages (e.g., the 62.3% figure).
- **Baselines may be weak or under-tuned** (inferred): the "random search" and "adapted GCG" baselines are the only comparisons; GCG was designed for jailbreaking, not for this latency-collapse objective, so its underperformance may partly reflect objective mismatch rather than ADSD's search strategy being fundamentally superior — the paper doesn't test alternative adaptations of GCG or other adversarial-suffix methods more thoroughly tuned for this task.
- **Simulation/testbed-only evaluation** (inferred): all experiments run on the authors' own GPU testbeds (single A100, 4-node tensor-parallel cluster, single RTX 4090) rather than in a real production serving stack (e.g., vLLM/TGI with continuous batching, multiple concurrent users, real schedulers) that the paper's own "systemic impact" argument (Section 3.2) relies on to justify severity. The claimed batching/co-tenant amplification effects are argued qualitatively, not measured.
- **Task-quality metrics may be incomplete** (inferred): GSM8K accuracy is the primary "stealth" proxy; no human evaluation or broader quality/coherence assessment of the outputs is reported beyond accuracy/ROUGE/pass@1, so subtler quality degradation could be underestimated.
- **Attack requires knowledge of the exact verification/decoding strategy variant** (inferred): although the paper shows the same suffix transfers across tokenwise/blockwise/HSD settings, all three still use the same underlying Qwen2.5 14B/0.5B pair; it's not fully disentangled whether transfer works because of shared model pair or because the vulnerability is truly strategy-agnostic.
