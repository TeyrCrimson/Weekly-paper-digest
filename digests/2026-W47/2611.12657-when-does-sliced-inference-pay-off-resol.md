# When Does Sliced Inference Pay Off? Resolution, Tiling and Dense Fusion for Small Object Detection

**Authors:** Stefan Becker, Jens Bayer, David Münch, Wolfgang Hübner

**arXiv:** [2611.12657](https://arxiv.org/abs/2611.12657)

**Categories:** cs.CV

**Submitted:** 2026-11-09

**Relevance:** 8/10 — matched: Onboard object detection from a moving UAV

---

## TL;DR
The paper rigorously disentangles "tiling helps small-object detection" from "higher resolution helps small-object detection," and shows that most of SAHI-style sliced inference's reported benefit is actually a resolution artifact that disappears once you train a single pass at matching resolution. It then introduces SCAHI, a dense-fusion alternative to box-merging (NMS/WBF) that combines detector outputs before boxes are decided, which recovers and extends tiling's benefits especially on very large images (DOTA) where single-pass training can't reach native resolution.

## First-principles breakdown

**The problem.** Small objects in high-resolution aerial/drone imagery (people, cars from a drone or satellite) are hard to detect because by the time a detector downsamples a huge image to its fixed input size, small objects shrink to a few pixels. The standard fix, "sliced inference" (e.g., SAHI), cuts the big image into overlapping tiles, runs the detector on each tile (so each object appears larger relative to the tile), then merges the per-tile detections (boxes) back into one set of detections for the full image, typically via NMS or Weighted Boxes Fusion (WBF).

**Why prior evaluations are misleading.** Papers proposing tiling methods almost always compare "tiling" against a "single full-image pass at some low resolution" (e.g., 640px). But tiling implicitly does two things at once: (1) it shows each tile at a larger *effective scale* (objects look bigger), and (2) it processes more total pixels/compute (every tile is a separate forward pass). If you instead just trained and ran the whole image at a higher input resolution, you might get scale benefit #1 without needing tiling at all — a confound nobody had isolated by holding resolution constant.

**What this paper does differently.** They treat "resolution" as an explicit, controlled variable. For each detector, they train a single-pass model at both a low and a high input resolution, and separately run tiled configurations with box fusion, then compare apples-to-apples under pre-registered hypotheses (fixed in advance, evaluated once on held-out test data — essentially the computer-vision analogue of pre-registered clinical trial methodology, to avoid p-hacking/cherry-picking).

**Finding 1 — resolution beats tiling when trainable.** On VisDrone (images ~1360px wide, small enough to train a single pass at native resolution), a single pass trained at 2048px always beats tiling+box-fusion at 1280px, for every detector that could be trained at that size. Also, raising resolution is more compute-efficient than making the model bigger (YOLOv10s@2048px beats YOLOv10m@1280px at near-equal FLOPs).

**Finding 2 — but tiles still carry extra information that box fusion throws away.** Box fusion only ever sees each tile's *final decoded boxes* — by the time fusion happens, information has already been collapsed/discarded, and worse, when an object straddles a tile seam, one tile sees a truncated/cut fragment of it. That fragment's box doesn't overlap enough with the full box from the neighboring tile to get suppressed by NMS (IoU too low), so you get both a true positive and a spurious duplicate false positive at every seam.

**The fix — SCAHI.** Instead of merging decoded boxes, SCAHI merges the *dense, pre-decision* outputs (raw per-position predictions: position, size, class confidence) from every pass (the whole image plus all tiles) into one shared 3D volume indexed by (x, y, log-object-size). Two key mechanisms:
1. **Coverage-aware border weighting**: each tile's predictions are weighted by a raised-cosine taper that fades near tile borders (where predictions are based on truncated/cut views of objects). Crucially, the tapers of adjacent overlapping tiles are normalized to sum to exactly 1 at every pixel ("partition of unity") — so a border fragment from tile A is automatically down-weighted relative to the full view of the same object from tile B's interior, and they get correctly fused into one detection instead of two.
2. **Peak extraction on a fine grid**: objects are read off as local maxima ("peaks") in this accumulated volume. The grid resolution (cell size) must be fine enough relative to object size, or two adjacent/crowded objects collapse into a single peak (under-detection). They tune this "cell factor" per dataset.

This is essentially voting/accumulation (like Hough transforms or nnU-Net's Gaussian-weighted sliding-window segmentation aggregation) applied to object detection fusion, where the hard part — unlike segmentation, where the accumulated map *is* the answer — is that you still need to separate individual object instances out of the accumulated evidence afterward.

## Key insights

- **Genuinely new empirical claim**: much of the published literature's "tiling helps" result is confounded with resolution, not a real property of tiling itself. This is a methodological correction to a widely-used technique (SAHI), not just a new result — the paper directly measures and separates the two effects.
- **Genuinely new method (SCAHI)**: fusing dense pre-NMS outputs with coverage-normalized spatial weights, rather than fusing decoded boxes, measurably removes tile-seam duplicate/fragment errors and recovers accuracy that box fusion wastes. Evidence supports this specifically for YOLO-family anchor-free dense detectors; for FCOS the dense fusion only ties box fusion (the authors attribute this to a coarser pre-specified peak grid for FCOS, not a fundamental limitation — but this is somewhat of an ad hoc post-hoc explanation).
- **The regime-dependence insight is well supported**: on VisDrone (resolution trainable) tiling-without-SCAHI doesn't pay off; on DOTA (images too large to train natively) tiling clearly does pay off, and SCAHI amplifies that further (+4.3 to +5.6 mAP50 over best single pass, +2.3 to +4.0 mAP50 as a drop-in replacement for SAHI's own merge step). The DOTA result is the strongest, most actionable claim: "if your images exceed trainable resolution, SCAHI is a close-to-free upgrade over SAHI."
- **What's claimed vs. supported**: the ablation evidence (border taper, peak-grid resolution) is reasonably rigorous — they isolate each component's contribution. But several of the most favorable numbers (refined peak grid, decomposition analysis) are explicitly post-hoc / exploratory, not part of the pre-registered hypothesis tests — the paper is honest about this distinction, which is unusual and a point in its favor, but readers should weight the pre-specified verdicts (sometimes "not confirmed," e.g., Q3 on VisDrone val) more than the flashier post-hoc headline numbers in the abstract.

## Caveats — stated and inferred

- **Limited detector family generalization** (`stated`): SCAHI requires dense per-position outputs (anchor-free heads like YOLO, FCOS, GFL); it does not support query-based detectors (e.g., RT-DETR) without a yet-unbuilt sparse variant. Almost all experiments are on YOLO; only one non-YOLO detector (FCOS) was tested, with a different/simpler training recipe, so cross-family comparisons are explicitly called non-comparable.
- **Post-hoc selection weakens headline numbers** (`stated`): the "refined peak grid" that produces much of VisDrone's improvement was discovered after seeing validation results, not pre-registered; the authors themselves note its held-out (test-dev) gain is about half its validation-set estimate — a textbook case of optimistic bias from post-hoc tuning, which they disclose rather than hide.
- **Mixed/not-fully-confirmed pre-registered results** (`stated`): Q3 (tiles+SCAHI beat best single pass) was explicitly "not confirmed" on VisDrone val under the pre-specified criteria (failed for YOLOv10m, untestable for YOLOv12m); only test-dev numbers (not part of the formal verdict) support it more broadly. This is disclosed, but a less careful reader of just the abstract would miss that the claim is weaker than it sounds.
- **FCOS result undermines the "SCAHI always wins" framing** (`stated`): on DOTA, SCAHI and box fusion perform "on par" for FCOS, and the paper's own explanation (grid too coarse, selected via a flawed calibration criterion that can miss rare crowded scenes) is itself admitted as unresolved ("a selection criterion that accounts for crowded recall is left for future work").
- **Hardware/compute generalizability** (`stated`): all latency/compute numbers come from a single RTX 5090 GPU, single machine type, batch size 1/exclusive use — not necessarily representative of other hardware, and the resolution-vs-tiling tradeoff is explicitly said to depend on "image size, object density and available memory, so the boundary will shift with hardware and detector."
- **Small number of datasets** (`inferred`): only two datasets (VisDrone, DOTA) are used to support a fairly general claim about "when tiling pays off." Both are aerial/drone imagery; it's unclear whether the resolution-vs-tiling tradeoff generalizes to other small-object domains (e.g., microscopy, satellite SAR, retail shelf images) — not addressed in the paper.
- **DOTA evaluation quirks** (`stated`): the DOTA devkit ignores objects below 8px and other "difficult" objects by default; a secondary analysis counting them is only partially reported, and DOTA images are re-encoded JPEGs (potential compression artifacts affecting small-object visibility).
- **FCOS sensitivity to a pipeline cap** (`stated`): the paper notes that without a detection-count cap on very dense images, SCAHI actually falls *behind* box fusion at 1024px for FCOS (−1.8 mAP50), and the Q3 gain shrinks — meaning at least one headline result is sensitive to an evaluation engineering choice (cap of 200,000 detections/image), a red flag for robustness of the magnitude of reported gains.
- **"Compute, not efficiency" tradeoff is understated in the abstract** (`stated` in body, downplayed in abstract): the abstract leads with accuracy gains but the body states plainly that tiling (with or without SCAHI) costs far more compute/latency than a single pass (e.g., 5.5× FLOPs, several× latency on DOTA) — SCAHI itself adds relatively little fusion overhead, but the tile passes themselves dominate cost. The method is pitched for "accuracy-oriented offline processing," not latency-sensitive use, which is a real but easy-to-miss caveat if only skimming the abstract.
- **LLM-assisted authorship** (`stated`): the paper discloses that a "general-purpose assistant (Claude, Anthropic)" helped draft experimental designs, analysis plans, manuscript text, figures, and that an LLM coding agent implemented code and ran experiments, under author direction/review. This is disclosed transparently, but it's a relevant provenance note for a reader assessing how independently the experimental pipeline (including evaluation ports) was built and vetted — the authors state results were checked against reproducible scripts and official reference implementations, but this is still a methodological novelty worth flagging rather than a standard peer-reviewed-lab-only pipeline.
- **Single-run, single-GPU latency and small calibration splits** (`inferred`): calibration splits (594 VisDrone images, 141 DOTA images) used for all tuning decisions are fairly small, and all timing figures come from one exclusive run per table — variance/robustness of these specific numbers across runs or hardware is not deeply characterized beyond one disclosed ~±10% fusion-time variability note.
