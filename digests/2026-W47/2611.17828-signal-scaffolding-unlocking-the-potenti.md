# Signal Scaffolding: Unlocking the Potential of Lightweight Models for Self-Supervised Monocular Depth Estimation

**Authors:** Zhijie Wang, Li Zhang, Yujie Chen, Shibiao Deng, Xin Gao, Houzhi Zhou, Jiangshuo Zhang

**arXiv:** [2611.17828](https://arxiv.org/abs/2611.17828)

**Categories:** cs.CV

**Submitted:** 2026-11-13

**Relevance:** 7/10 — matched: Metric and temporally-consistent monocular depth

---

## TL;DR
The paper argues that lightweight self-supervised monocular depth models underperform not because of insufficient capacity but because standard pretrain-then-finetune pipelines fail to unlock what little capacity they have. It introduces "Signal Scaffolding" (SS), a three-phase training schedule (ImageNet init → self-supervised photometric training → gradually-ramped distillation from a larger teacher) applied to a new 1.5M-parameter architecture, ReForgeDepth. On KITTI/Cityscapes the combination reportedly beats other sub-5M-parameter methods and runs in real time on phone-class hardware, without adding parameters, data, or inference cost.

## First-principles breakdown

**The underlying task.** Monocular depth estimation means predicting a per-pixel depth map from a single RGB image. Since a single 2D image is geometrically ambiguous (infinite 3D scenes project to the same image), models need either ground-truth depth (supervised, expensive to collect via LiDAR) or an indirect supervisory signal. Self-supervised approaches use video: given frames at time t and t±1, a network predicts depth at t and a separate PoseNet predicts the camera's motion between frames; using depth + motion + camera intrinsics you can "warp" a neighboring frame to reconstruct the target frame (classic multi-view geometry/reprojection). If the warped image matches the real target frame well, the predicted depth and pose were consistent with the actual 3D scene. Training minimizes this photometric reconstruction error (a combination of SSIM and L1 distance) instead of needing any depth labels. Standard tricks (from Monodepth2, a well-known prior work) handle cases where this signal is unreliable: taking the per-pixel minimum error across source frames deals with occlusions, and "auto-masking" removes pixels where the camera is static or the scene is at infinity (where reprojection is trivially perfect and uninformative). An edge-aware smoothness penalty regularizes untextured regions where photometric error gives no signal at all.

**The lightweight problem.** For deployment on phones/edge devices, models must be small (a few million parameters). Small models historically plateau at a fairly fixed, mediocre accuracy band, and the field's answer has mostly been architecture tweaks (better blocks, hybrid CNN-Transformer designs) — this paper's related-work section surveys several such lines (Lite-Mono, MViTDepth, PuriLight, etc.). The authors' core empirical claim is that this plateau isn't purely an architecture/capacity ceiling: the same small model trained differently reaches noticeably better accuracy with zero extra parameters or data. They attribute this to "capacity-training mismatch" — small networks have little redundancy, so naively fine-tuning them (as if they were a scaled-down version of a large network's pipeline) wastes much of what little representational capacity they do have, because the training signal doesn't match what a low-redundancy network can actually absorb at each stage.

**Signal Scaffolding (SS), the proposed training strategy.** Instead of the usual two-stage pipeline (pretrain on ImageNet, then fine-tune on the self-supervised photometric objective), SS adds a third, more carefully staged phase:
1. Phase I: standard ImageNet classification pretraining (as usual).
2. Phase II: pure self-supervised photometric training on the target domain (driving video) — this lets the small model first adapt its own representations to the task domain before any external signal is injected.
3. Phase III: knowledge distillation from a larger "teacher" network (Flex-Large, a bigger model from related work), but only introduced gradually. Both student and teacher predict relative (scale-free) inverse depth, so their outputs are first median-aligned per image, then compared in log space (so errors are relative, not dominated by far-away large depth values) — this is the standard scale-invariant depth loss formulation. Crucially, the distillation loss's weight ramps up from zero over the first several epochs of Phase III (a "warm-up" schedule) rather than being applied at full strength immediately — the paper's ablations show this ramping matters a lot (constant or immediate-full-strength distillation underperforms).

The intuition: by first letting the student converge on its own task-adapted representation (Phase II) before exposing it to an external teacher signal, the teacher's guidance is "aligned" with representations the student can actually use, rather than being an arbitrary target the low-capacity network can't absorb (as happens in naive distillation, which has a hard ceiling set by mimicking teacher outputs directly from the start).

**ReForgeDepth architecture (the vehicle for testing SS).** This is a separate architectural contribution, needed to have a concrete small network to validate SS on:
- *Gated Multi-Dilation Block (GMD)*: replaces stacking three separate dilated-convolution blocks (each with its own feed-forward network) with one block containing three parallel depthwise dilated convolutions sharing input-conditioned gates (a squeeze-and-excitation-style mechanism that learns how much to weight each dilation branch per input) and anisotropic kernels (taller than wide, matching the vertical structure common in road scenes). This gets similar/better receptive-field coverage at lower parameter/FLOP cost than three sequential blocks.
- *Detail-Compensated Global Interaction (DCGI)*: at the end of each encoder stage, extracts the "high-frequency residual" (local features minus their locally-pooled average) to preserve fine edges/details that compact networks otherwise blur away, then applies a lightweight channel-wise attention (cross-covariance attention, which computes attention over channels rather than spatial positions — cheaper for high-res feature maps) to add global context back in.
- *RGB Boundary Residual (BR)*: a decoder-side add-on that runs a fixed (non-learned) Sobel edge filter on the input RGB image, encodes that edge map, and fuses it via a learned gated residual into the final depth output to sharpen boundaries without added model capacity (Sobel filters are a classical, non-learned image-gradient edge detector).

The ablations show each component (GMD, then DCGI, then BR) adds incremental accuracy at lower parameter/FLOP budgets than a prior lightweight baseline (Lite-Mono)'s equivalent blocks.

## Key insights

- **Claimed and reasonably well-supported**: the training-strategy reframing itself. Table 4/6/8/12 show that applying SS to several different lightweight backbones (not just ReForgeDepth) consistently improves Abs Rel error with identical parameters/data, and ablating phases (Table 6/12) shows each phase contributes; skipping the self-supervised Phase II while keeping Phase I+III degrades results, supporting the "alignment before distillation" narrative rather than distillation alone explaining the gain.
- **Claimed and evidenced**: the benefit is inversely related to model size — smaller/lower-redundancy students benefit more from SS than larger ones (Lite-Mono-tiny gains ~0.004-0.005 Abs Rel vs. Lite-Mono-8M's ~0.001). This supports their framing that the effect is about recoverable capacity in small models specifically, not a generic distillation trick.
- **Claimed, more speculative**: the "transitivity analysis" argument that gains come mainly from the student's recoverable capacity rather than teacher quality (e.g., swapping student from B to A under the same teacher raises gain by 3.6 points vs swapping teacher under the same student raising it only 1.0 point). This is a post-hoc arithmetic argument over a handful of data points, not a controlled causal experiment — informative but not strong proof.
- **Architecture contribution (ReForgeDepth)**: achieves state-of-the-art accuracy-vs-parameter trade-off among sub-5M models on KITTI/Cityscapes, and the per-module ablation (Table 11) does show incremental, isolated gains for GMD, DCGI, and BR individually when trained from scratch — this is a well-controlled ablation.
- **Practical note on FLOPs vs. latency**: the paper observes FLOPs don't predict real on-device latency because of operator-level hardware support differences (e.g., PuriLight's frequency-domain ops run slowly on mobile despite modest FLOPs) — a useful, generalizable observation for anyone optimizing edge models, though it's a secondary point in this paper.

## Caveats — stated and inferred

- **Moving objects degrade accuracy** (stated): the authors explicitly note photometric consistency breaks down around moving objects, and this is listed as a limitation with future work (motion-aware masking) proposed but not implemented.
- **No ground-truth depth caps achievable accuracy** (stated): acknowledged directly as a second limitation inherent to the self-supervised paradigm.
- **Single-dataset-family validation** (inferred): core results are on KITTI and Cityscapes (both outdoor driving scenes), with Make3D used only as a zero-shot generalization check; there's no evaluation on indoor or non-driving domains, so claims of general lightweight-model applicability may not transfer.
- **Reliance on an unpublished/own-family teacher model** (inferred): the best results depend on "Flex-Large," which is cited as a different paper by an overlapping author set (Zhu et al., ECCV 2026, same corresponding author) and listed as "2026" — i.e., possibly unpublished/concurrent work from the same group. This makes independent reproducibility of the top numbers harder and raises a mild self-referential-baseline concern.
- **Baseline currency is mixed** (inferred): comparisons include some very recent (2025–2026) lightweight methods, which is good, but key competing numbers (e.g., Flex-Nano, Flex-Small/Medium/Large) all come from the same likely-same-lab unpublished "Flex" family, reducing the number of truly independent comparison points at the top of the table.
- **"We find," "might," "likely," hedging language throughout** (inferred): the paper itself repeatedly hedges its central causal claim ("the root cause may lie...", "might stems from...", "is likely the student's recoverable capacity") — this is honest, but it signals the mechanistic explanation (capacity-training mismatch) is an interpretation of correlational ablation results, not a mechanistically verified cause.
- **Gains are numerically modest in absolute terms** (inferred): most SS improvements are single-digit-to-low-double-digit percentage reductions in Abs Rel (e.g., 0.110→0.102, or ~0.001–0.005 absolute), and the smallest-model gains, while relatively largest in percentage terms, are still small absolute numbers; whether this constitutes "unlocking latent potential" versus incremental tuning gains is a matter of framing.
- **Hardware/runtime benchmarking scope** (inferred): real-time claims rest on only two specific devices (MacBook Air M2, iPhone 12/A14) using Apple Core ML Float32, not representative of the broader edge-device landscape (e.g., Android/other NPUs, INT8 quantization scenarios common in production deployment).
- **No statistical uncertainty reported** (inferred): all tables report single-run point estimates (e.g., Abs Rel to three decimal places) with no variance/seeds/confidence intervals, so small differences between closely-ranked lightweight methods (e.g., 0.106 vs 0.102) are not statistically characterized.
- **LLM-assisted writing** (stated): the authors disclose using an LLM to polish language only, not for technical content or experiments — not a scientific caveat per se, but worth noting as disclosed.
