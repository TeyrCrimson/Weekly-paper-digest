# Test-Time Selective Adaptation for Cross-Modal UAV Object Tracking with Token Shift

**Authors:** Yun Xiao, Hailong Ye, Zhicheng Zhao, Lei Liu, Amir Hussain

**arXiv:** [2611.15059](https://arxiv.org/abs/2611.15059)

**Categories:** cs.CV

**Submitted:** 2026-11-11

**Relevance:** 8/10 — matched: Onboard object detection from a moving UAV

---

## TL;DR
TSAT is a test-time adaptation (TTA) method for UAV cameras that switch between visible and thermal imagery mid-track, designed to fix the localization drift that happens right when the modality switches or the target jumps position. It derives two self-supervised training signals purely from the live test video (no labels) — one from artificially shifting feature tokens and checking the tracker's response moves accordingly, one from predicting the previous frame's location from current features — and only applies updates (to LayerNorm parameters only) when a reliability filter judges the signal trustworthy. On the CM-UOT benchmark it improves a strong baseline tracker (SARLA) by ~2.2–2.6 points on precision/success metrics and beats prior general-purpose TTA methods, with the gains concentrated specifically after modality switches and under large spatial displacement.

## First-principles breakdown

**The underlying task.** Object tracking: given a box around a target in frame 1, predict its box in every subsequent frame. "Cross-modal UAV tracking" means the drone switches between visible-light and thermal cameras over time (to save power/bandwidth) rather than fusing both streams simultaneously. A tracker trained offline on paired data has to cope with: (a) the two modalities looking very different (different textures, contrast), and (b) the target's on-screen position jumping between frames because of the drone's own motion, the sensor switch, or slight misalignment between the two cameras.

**Why offline training isn't enough.** Existing cross-modal trackers (including the paper's chosen baseline, SARLA) learn, during training, representations that are robust to modality and spatial variation in general. But that's a fixed, "frozen" model at test time — it has no mechanism to correct itself when a specific test video's switch or jump doesn't match what it saw in training. Errors from one frame (bad box prediction) feed into the next frame, because trackers use the current prediction to decide where to search next — so one bad frame compounds into "drift" that the tracker never recovers from.

**Why generic test-time adaptation (TTA) doesn't fix this.** TTA is the general idea of fine-tuning a model slightly, online, using only the unlabeled data it's currently seeing (no ground truth) — e.g., TENT minimizes prediction entropy, CoTTA averages predictions over augmentations. These were built for classification/segmentation, where "I am confident" is a decent proxy for "I am correct." But for tracking, confidence doesn't capture *where* the target is — a tracker can be very confident and still point at the wrong (but similar-looking) object. These methods have no notion of spatial correctness or temporal consistency of a track, so adapting with them can even make things worse (the paper's Table II shows several TTA baselines dropping below the no-adaptation baseline after a modality switch).

**TSAT's mechanism — three pieces that work together:**

1. **Token Shift Equivariance (TSE)** — a self-supervised "spatial sanity check" that needs no labels. The tracker represents the search region as a grid of feature tokens. TSAT artificially shifts this token grid by a known amount (e.g., move it 2 tokens right, 1 down), feeding both the original and shifted grid through the same prediction head to get two response maps. If the tracker is behaving correctly, the predicted target location in the shifted version should move by *exactly* the amount the grid was shifted (that's "translation equivariance" — shift the input, the output shifts the same way). TSAT measures the actual shift in the predicted center (found via SoftArgmax — a smooth, differentiable approximation of "take the peak location" by weighting all grid positions by their response score) and penalizes the difference between this and the known, imposed shift. Because the "ground truth" here is the artificial shift that TSAT itself chose, this gives a free, always-available, annotation-free supervisory signal about whether the tracker's spatial responses are well-behaved.

2. **Temporal Backward Prediction (TBP)** — a self-supervised "temporal sanity check." The tracker (SARLA) already feeds in the previous frame's region as context when predicting the current frame. TBP reuses this: it runs the same prediction head "backwards" — asking it to localize the target within the *previous* frame's region using features that have already absorbed current-frame information. Since we know where the target was in the previous frame (it's stored, not labeled by a human — just carried over from the tracker's own prior output), the backward-predicted center should land at that stored location (zero displacement in local coordinates). The gap between the two is the TBP loss. This exploits frame-to-frame consistency to catch and correct errors before they accumulate.

3. **Reliability-aware Update Gating (RUG)** — a filter to stop bad signals from corrupting the model. Even unlabeled self-supervised signals can be wrong (e.g., if the response map is itself garbage, because of a modality switch confusing the network). RUG measures "entropy" of the response map — how spread out/uncertain it is (low entropy = one confident peak, high entropy = spread/uncertain). If entropy is too high, that frame is skipped entirely for adaptation. Even for frames that pass, each individual TSE shift and the TBP loss are checked against a running average threshold (an exponential moving average of recent losses) — unusually high losses (likely noise) are excluded from that update. Only the surviving signals contribute to the actual gradient update.

**What actually gets updated.** Only the scale/bias ("affine") parameters of LayerNorm layers inside the Transformer backbone are fine-tuned online — everything else (attention weights, FFN, prediction head) stays frozen. This is a common lightweight TTA trick: LayerNorm parameters are cheap to tune and let the network re-calibrate feature statistics to the new (possibly thermal-vs-visible) distribution without risking catastrophic forgetting of the pretrained representation.

**Putting it together at inference:** every 10 frames, TSAT computes TSE and TBP losses on the current (gated) sample, combines them in a weighted sum (weights 220 and 50, found via tuning), and takes one small gradient step (lr 6e-5) on the LayerNorm parameters before continuing to track subsequent frames.

## Key insights

- **Genuinely new**: Converting a geometric property of trackers (translation-equivariance of the response map under token shifts) into a free, annotation-free adaptation signal (TSE) is the paper's core novel idea — prior TTA work for classification uses confidence/consistency-under-augmentation, but not controlled spatial shift-and-check specific to localization outputs.
- **Genuinely new (secondary)**: Reusing the tracker's own "previous frame reference features" to run a backward localization task (TBP) as a temporal self-supervision signal, without any extra network, is a clean reuse of existing architecture rather than a new module.
- **Incremental but useful**: RUG's two-stage gating (sample-level entropy gate + per-branch dynamic loss gate) is engineering on top of known TTA reliability tricks (EATA-style sample selection), adapted to a tracking-specific response-entropy signal plus branch-specific moving thresholds.
- **What the evidence actually supports**: On CM-UOT, TSAT improves the SARLA baseline (+2.2–2.6 pts across PR/NPR/SR) and beats 13 other TTA baselines, especially in the "after modality switch" regime (+2.5–3.0 pts) and under the largest spatial displacements (>100px, where several competitors degrade). Ablations (Table IV) show both TSE and TBP individually help, combine additively, and RUG adds further gains — this is reasonably well-supported by the ablation table. The claim that TSE as *offline* training augmentation is insufficient and *online* TTA is what matters is also directly tested (Fig. 8) and supported.
- **What's weaker evidence**: Generalization claims ("across tracking frameworks and datasets") rest on exactly two additional settings: OSTrack (modified to accept 3 inputs) and one additional dataset (CMOTB), with smaller gains (+0.6–2.2 pts) than the main CM-UOT result — this is suggestive, not a sweeping demonstration of generalization.
- Random-seed analysis (4 seeds, std ≤0.3 pts) supports that the reported gains aren't a fluke of one run, which strengthens confidence in the main number, though 4 seeds is a small sample.

## Caveats — stated and inferred

- **(stated)** Failure mode: when the target shift at a modality switch is large enough to move the target entirely outside the search region, TSE/TBP signals become insufficient and TSAT cannot recover (Fig. 9, explicitly discussed in Limitations).
- **(stated)** Reliability assessment is "indirect": a confident-looking response can still lock onto a distractor (similar-looking object) rather than the true target, since entropy/loss-based gates have no notion of target identity — the authors explicitly flag this as unresolved.
- **(stated)** Added test-time compute overhead: FPS drops from 106.41 to 72.87 and FLOPs rise from 51.1G to 72.2G versus the baseline — a real throughput cost for the accuracy gain, openly reported rather than hidden.
- **(inferred)** Single dataset for the main comparison: nearly all head-to-head numbers against 13 TTA baselines and other trackers come from one benchmark (CM-UOT), which the same research group also created/published (ref [7]); independent-benchmark validation is thin (only one supplementary dataset, CMOTB, with much smaller margins).
- **(inferred)** Baseline dependency: TSAT is only ever demonstrated bolted onto SARLA (the authors' own prior tracker) as the primary host; the one generalization test onto OSTrack required modifying OSTrack's architecture to accept a third input, meaning the method isn't shown to be a drop-in wrapper for arbitrary off-the-shelf trackers without re-engineering.
- **(inferred)** All compared TTA methods (TENT, CoTTA, EATA, SAR, PURA, etc.) are re-implemented by the authors "following the corresponding paper or official implementation" rather than using independently verified reproductions — possible, though unstated, risk of suboptimal tuning for competitors, especially since several of them perform *worse* than the no-adaptation baseline (Table II), an unusually poor showing that isn't deeply investigated.
- **(inferred)** Heavy hyperparameter sensitivity is visible in the ablation tables (entropy threshold, update interval, learning rate, N shifts all have fairly narrow sweet spots with several-point swings), but no sensitivity/robustness analysis is given for how these would need to be retuned on a genuinely different deployment scenario (different drone, different sensor pair) — only tested within CM-UOT/CMOTB variants.
- **(inferred)** Hardware/real-time claims rest on a single RTX 4090 GPU figure; no discussion of feasibility on actual "resource-constrained UAV platforms" the paper motivates the work with — the authors themselves flag this as future work, which is a tacit admission the current method isn't shown to run on edge hardware.
