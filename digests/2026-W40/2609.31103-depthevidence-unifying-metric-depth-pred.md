# DepthEvidence: Unifying Metric Depth Prediction and Geometric Reasoning in Multimodal Language Models

**Authors:** Jiangning Wei, Yuan Yao, Miaomiao Cui, Mingsheng Li, Humen Zhong, Shuai Bai, Zhibo Yang

**arXiv:** [2609.31103](https://arxiv.org/abs/2609.31103)

**Categories:** cs.CV, cs.AI

**Submitted:** 2026-09-25

**Relevance:** 9/10 — matched: Metric and temporally-consistent monocular depth

---

## TL;DR
DepthEvidence is a 4B-parameter vision-language model that predicts its own dense metric depth map and then feeds object-pooled depth features back into the language model as "geometry tokens," so it can answer spatially- and numerically-constrained questions (e.g., "which objects are 1.30–1.33m away and to the right of the cabinet?"). It reports the best average dense-depth accuracy (δ1) among the compared methods and the largest gains on a new Depth-VQA benchmark testing object-level metric and relative depth reasoning, while mostly preserving general VQA performance. The core claimed mechanism — an object-aligned "dense-to-language interface" with auxiliary supervision before/after language interaction — is shown via ablation to matter beyond simply adding more metric-depth training signal.

## First-principles breakdown

**The problem.** A VLM asked "which objects between 1.30m and 1.33m from the camera are to the right of the cabinet?" must (1) understand which pixels belong to which named object, (2) know the absolute (metric) depth of each object, and (3) keep that numeric information intact while reasoning through language generation — language models are good at qualitative reasoning ("closer/farther") but bad at preserving and manipulating raw numbers once they're converted into tokens and mixed with other context. Prior systems either (a) output a dense depth map as a separate task without linking it to the language reasoning about specific objects (specialized depth estimators like UniDepth, Metric3D), or (b) do spatial reasoning in language without solid metric grounding (SpatialVLM, SpatialRGPT), or (c) predict depth and text jointly but without an explicit mechanism forcing the numeric depth to survive into the answer (DepthLM, DepthVLM). The authors argue none of these explicitly binds per-object depth evidence to object identifiers *and* keeps that evidence numerically recoverable through the language model's later processing.

**The architecture (three levels of depth understanding).**
- *Level 0 — dense metric depth prediction.* A camera-conditioned decoder (a DPT-style coarse-to-fine transformer decoder) takes multi-scale visual features from the vision encoder plus the final language-model's hidden states (reshaped spatially), and fuses them. Camera intrinsics (focal length, principal point, field of view, aspect ratio) are turned into a small vector and injected into every decoder layer via FiLM conditioning (a technique that scales and shifts feature maps based on an external condition vector) — this lets the same network adapt its depth predictions to different cameras. A separate lightweight "high-resolution RGB" branch adds fine-grained appearance/edge cues back into the decoder through learned gated residual connections, recovering sharp depth boundaries that get lost when everything is routed through compressed visual tokens. Output: a full-resolution metric depth map, trained with a mix of standard depth losses (absolute error, scale-invariant log error) plus structural losses (derivative, Laplacian, and an edge-focused local scale/shift-invariant loss) that sharpen object boundaries.
- *Level 1 — instance-level depth.* Given an object (specified either by a bounding box or a natural-language description), the model must report a single depth statistic (center, mean, median, nearest, farthest point depth).
- *Level 2 — compositional reasoning.* Multi-object questions requiring relative comparisons (closer/farther, ordering) or metric comparisons (numeric gaps, thresholds, ranges, margin-based decisions with an "ambiguous" fallback).

**The dense-to-language interface (the key new mechanism).** For each referenced object, the model pools the dense depth map and decoder features within that object's region (box), producing a "regional feature" and summary depth statistics. These, plus the object's normalized box coordinates, are projected by a small two-layer network into exactly 2 continuous "geometry tokens" per object — not discrete/quantized tokens, but continuous vectors, tagged with a learned per-object identity embedding and a slot embedding (so token 1 vs token 2 of the same object are distinguishable). These geometry tokens are inserted into the language model's input stream right after each object's textual identifier (e.g., after "obj_1:"), forming what they call a "geometry bank." Crucially, these tokens are not used as generation targets (the model isn't trained to output them) but the model's answer-generation tokens can attend to them, and gradients from the answer loss flow back through them into the projector — so the language model learns to actually use this geometric evidence.

**Why supervise it explicitly (geometric supervision).** If you only train on the final answer, there's no guarantee the intermediate geometry tokens still contain usable metric information after being mixed into the transformer's context (information can get "washed out" by attention/interaction with other tokens). So the authors add auxiliary loss heads that try to reconstruct the five depth statistics (center/mean/median/nearest/farthest) from the geometry tokens both *before* (raw) and *after* (contextual) they interact with the rest of the sequence, plus a ranking loss that supervises relative ordering across objects. This is analogous to adding an information bottleneck check to make sure the encoding is "readable" at both ends of the interaction.

**Inference trick.** Because the geometry tokens are only available after depth prediction runs, naively you'd need to re-run the full multimodal encoding once you have them (a "two-pass" approach). Instead they cache the initial prefix encoding and append geometry tokens as a causal continuation — avoiding re-encoding the image and question, at a measured ~4.7% latency/throughput cost versus no interface at all (Appendix E).

**The Depth-VQA benchmark.** Since no existing benchmark tests exactly this three-level structure, the authors built one: two large LLMs (Qwen3.7-plus, Seed-2.1-Turbo) propose object boxes/categories, SAM 3 segments them, and the same two models generate and cross-verify (one generates, the other checks) Level-1/Level-2 question-answer pairs, followed by manual auditing of 1% of training data and 100% of benchmark data. 1,503 total questions across Level-1 (757) and Level-2 relative (370) / metric (376) tracks, drawn from six driving/indoor datasets.

## Key insights

- **Claimed and evidence-supported:** The central contribution — binding dense predictions to specific objects via continuous, identifier-anchored tokens with before/after supervision — is directly ablated (Table 6, Table 9) and shows a real, non-trivial effect: removing the interface costs ~4-8 points of accuracy on the two Level-2 tracks, and a control that adds equivalent auxiliary numeric supervision *without* the interface only recovers part of that gap (leaving the full interface ahead by 4-5.5 points). This is a genuinely useful piece of evidence distinguishing "the interface itself helps" from "just training on more numbers helps."
- **Claimed and evidence-supported:** Leading average dense-depth δ1 across nine datasets (0.7972) versus other depth-aware VLMs and being competitive with (though not uniformly beating) specialized single-task depth estimators like UniDepth V2 (0.7945) — the margin over the best VLM baseline (DepthLM-12B, a 3x larger model) is substantial (+0.10).
- **Claimed and evidence-supported:** Large, consistent gains over general-purpose VLMs (Qwen3.7-plus, Gemini-3.1-Pro-Preview, Seed-2.1-Turbo) and other depth-aware VLMs on the new Depth-VQA benchmark, and also beats an "agent pipeline" baseline (external depth estimator + LLM reading a text table of depth stats) — this is a meaningful comparison point since it shows tight architectural integration outperforms a naive tool-use approach.
- **Claimed, partially supported:** "Broadly preserving general VQA performance" — true for most benchmarks (MMMU, MMBench, HallusionBench, AI2D, CC-OCR improve or hold), but MMMU-Pro regresses by 2.25 points, which the paper doesn't dwell on.
- **Useful methodological idea generalizable beyond this paper:** camera-intrinsics-conditioned FiLM layers for scale-aware depth decoding, and the "supervise before and after context interaction" pattern as a general recipe for keeping non-linguistic evidence (not just depth) numerically faithful when injected into an LLM's context.

## Caveats — stated and inferred

- **stated** — The system assumes access to accurate camera intrinsics and explicit/correct object references (boxes or grounding); performance is sensitive to calibration and grounding errors, especially for narrow depth ranges or decision margins (Section 7.3).
- **stated** — Geometry-token conditioning adds inference latency and memory versus no interface (Appendix E: +4.71% end-to-end latency, +3.37 GiB peak memory vs. no-interface baseline).
- **stated** — Future work items are listed as open, i.e., not solved here: robustness to noisy intrinsics/object references, inference cost scaling with object count, and generalizing the interface to other geometric evidence types.
- **inferred** — The Depth-VQA benchmark used for the headline reasoning results was constructed and verified largely by the same class of LLMs (Qwen3.7-plus, Seed-2.1-Turbo) being partly used/compared elsewhere in the field, with only 1% of training data and 100% of benchmark examples manually checked (not 100% of training data) — there's some risk of systematic bias or artifacts from LLM-generated QA construction, even with cross-verification.
- **inferred** — Comparisons on Level-0 dense depth call specialized single-task depth estimators (Metric3D, UniDepth V2, Depth Anything variants) "baselines," but several of these show near-zero δ1 on out-of-domain data (e.g., Depth Anything V2 outdoor scores 0.0000 on SUN RGB-D and Booster) — these look like clearly mismatched/degenerate baseline configurations (e.g. indoor-trained models evaluated outdoor and vice versa) rather than fair SOTA comparisons, inflating DepthEvidence's average-δ1 ranking somewhat; the paper does separately note UniDepth V2 is very close (0.7945 vs 0.7972) and beats DepthEvidence on several individual datasets.
- **inferred** — No error bars, confidence intervals, or repeated-run variance are reported anywhere for any benchmark number, so it's unclear how much of the reported deltas (some quite small, e.g., the 0.0027 δ1 margin over UniDepth V2) are meaningful versus noise.
- **inferred** — The paper doesn't report failure-mode analysis on the interface (e.g., what happens when object grounding is wrong, or how errors compound across Level-0→1→2) beyond the qualitative examples in Figure 4/Appendix F, which are cherry-picked "corrected by the interface" cases.
- **inferred** — All evaluation uses ground-truth camera intrinsics supplied to the model (Section 5.2, Appendix C.3) — a real-world deployment without known/calibrated intrinsics is not evaluated, which is a fairly strong assumption for "in the wild" spatial reasoning claims.
- **inferred** — The K=2 continuous-geometry-tokens-per-object design choice is only briefly justified via an appendix reference not included in the provided text ("Appendix A.3.2 discusses the choice of K=2"), so the sensitivity of results to this hyperparameter is not addressed in the visible text.
