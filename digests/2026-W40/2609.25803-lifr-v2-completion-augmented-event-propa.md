# LiFR v2: Completion-Augmented Event Propagation for High-Rate Dense Prediction

**Authors:** Tao Wan, Xiaoshan Wu, Yifei Yu, Bo Wang, Xiaoyang Lyu, Muxin Liu, Aoxuan Pan, Zhongrui Wang, Xiaojuan Qi

**arXiv:** [2609.25803](https://arxiv.org/abs/2609.25803)

**Categories:** cs.CV

**Submitted:** 2026-09-22

**Relevance:** 7/10 — matched: Metric and temporally-consistent monocular depth

---

## TL;DR
LiFR v2 predicts dense semantic segmentation, monocular depth, or both at any timestamp between RGB frames by propagating an RGB keyframe's features using events, then using a new Event-Guided Completion Module (EGCM) to fill in content (newly visible/disoccluded objects) that propagation can't recover, while a History Retrieval Module (HRM) reuses previously-completed features across a streaming sequence of queries. It generalizes the earlier LiFR-Seg (segmentation-only) to depth and multi-task prediction, introduces a new synthetic benchmark (SHF-Emerge) targeting rapid object emergence/disocclusion, and reports gains over propagation-only baselines (e.g., SHF-Emerge mIoU 54.28%→56.13%, depth RMSE 1.564m→1.118m) at over 100 FPS.

## First-principles breakdown

**The problem.** RGB cameras sample the world at a fixed, relatively low rate (e.g., 20Hz → 50ms between frames). For tasks like autonomous driving, anything that happens between two frames (a pedestrian stepping out from behind a parked car, a car changing lanes) is invisible to a system that only reacts to the latest frame — a "perceptual blind interval." Event cameras, in contrast, report per-pixel brightness *changes* asynchronously at microsecond resolution — they're temporally dense but only encode change, not absolute appearance, so they can't stand alone as a full picture of the scene.

**Why prior approaches fail.**
- *Direct RGB-event fusion* (e.g., EISNet, CMNeXt): combines an RGB frame with concurrent events to improve prediction *at that frame's time*, but doesn't extrapolate the representation forward to a later query time when no new RGB exists.
- *Frame interpolation* (TimeLens-XL): synthesizes an RGB image at the query time from events *and* the two bracketing real RGB frames — but needing the future frame makes this "non-causal" (can't run online, only useful in hindsight).
- *Recurrent fusion methods* (RAMNet, CFRNet): update an internal state causally using frames+events, but are specialized to depth and don't explicitly separate "moving existing content around" from "recovering content that was never seen."
- *LiFR-Seg (the authors' prior work)*: explicitly "propagates" — warps — RGB-derived features to the query time using event-estimated motion (optical flow-like fields), which works well for content that existed in the keyframe and just moved. But propagation is fundamentally a relocation operation: if a pixel's content didn't exist anywhere in the source RGB image (e.g., a person emerging from behind a bus), there's no feature to move there. This is called the "source-support constraint."

**This paper's mechanism — three stages per query timestamp:**
1. **Event-Guided Propagation** (inherited from LiFR-Seg): An optical-flow network (E-RAFT-based) estimates a motion field from the keyframe time to the query time using event data, plus a "ScoreNet" that estimates per-pixel confidence/reliability of that motion. "Softmax Splatting" (a differentiable forward-warping operation) then moves the keyframe's RGB features to the query time, weighting contributions by the confidence scores, so unreliable motion estimates contribute less.
2. **History Retrieval Module (HRM)**: A transformer-style attention block where the just-propagated features act as queries, and a small memory bank of past feature states (initialized from the keyframe, later filled with completed states from previous queries in a streaming sequence) act as keys/values. This lets the current prediction "look up" relevant temporal context (e.g., an object glimpsed and completed two queries ago) rather than only relying on this step's propagated features. Rotary position encoding plus learned spatial/temporal embeddings tell the attention mechanism where each memory token is and how "old" it is.
3. **Event-Guided Completion Module (EGCM)** — the core new contribution: takes the HRM-refined (or bypassed) visual features and combines them with features from a dedicated event encoder (via a small conv-based "feature completion module") to predict an *additive residual* — new content the propagation pathway couldn't supply. A learned "spatial gate" (a sigmoid-activated small network) decides, per-pixel, how much of that residual correction to actually apply, since event activity doesn't always mean useful new content is there. The event encoder itself is pretrained offline via knowledge distillation: it's trained to mimic a frozen, task-trained *image* encoder's features (extracted from the *actual* future RGB frame, which is unavailable at inference) using an L1 feature-matching loss plus relational/similarity-matching losses borrowed from a related method (ScaleEvent). This teaches the event branch to encode task-relevant appearance-like information, not just raw motion, without ever needing future RGB at inference time.

The completed feature is then decoded by the task's original decoder (SegFormer, MoGe-2, or MTMamba, depending on task), and the completed feature at a chosen layer is written back into the memory bank for future queries — closing the streaming loop.

**Multi-task generality.** The same propagation→HRM→EGCM pipeline is inserted as a lightweight adapter between different backbones' encoders and decoders: SegFormer for segmentation, MoGe-2 (ViT) for depth, and MTMamba (Swin) for joint segmentation+depth, each with task-specific choices of which feature levels get HRM/EGCM applied.

**SHF-Emerge benchmark.** A new synthetic (CARLA-based) benchmark specifically constructed with frequent rapid object emergence and disocclusion, designed to stress-test exactly the failure mode (missing source support) that motivates EGCM, since existing benchmarks (DSEC, M3ED) may not contain enough of these hard cases to differentiate propagation-only vs. completion-augmented methods.

## Key insights
- **Claimed contribution**: EGCM as an explicit, decoupled mechanism for recovering content invisible to propagation (as opposed to implicit recurrent state updates in RAMNet/CFRNet), with the insight that this should be a *gated, additive residual* conditioned on event features that are themselves distilled to encode task-relevant (not just motion) information.
- **Evidence supports**: Gains are real but modest on "easy" benchmarks (DSEC, SHF-DSEC — ~0.3-0.6 pt mIoU over LiFR-Seg) and become much larger specifically on the benchmark designed to showcase the method (SHF-Emerge: +1.85 mIoU overall, and a striking +22pp Person-class IoU in one ablation, 33.13%→55.14%). This pattern — small general gains, large gains on a self-authored adversarial benchmark — is consistent with the claim that EGCM targets a specific failure mode, but also means the headline numbers are partly a function of a benchmark the authors built themselves.
- **Ablations are reasonably well isolated**: No-completion vs. residual-without-gate vs. full EGCM cleanly separates the value of completion itself (biggest jump) from the added value of gating (smaller but consistent further gain), and the offline distillation ablation shows the event encoder pretraining matters far more on SHF-Emerge than on M3ED-D — supporting the "distillation matters most under abrupt visibility change" narrative rather than being a universal win.
- **Generality across tasks (seg/depth/multi-task) and backbones is genuinely demonstrated**, not just claimed — the same module design is shown to transfer with only lightweight per-task interface changes, which is a nontrivial engineering/architecture result.
- **Speed**: >100 FPS for single-task variants is a real practical strength if accurate, since it means the causal pipeline can plausibly run faster than typical RGB frame rates it's designed to exceed.

## Caveats — stated and inferred

- **Illustrative-only scenario framing** (stated): The paper's own Fig. 1 caption explicitly notes the collision-avoidance illustration is not a closed-loop evaluation — the motivating scenario (pedestrian emergence causing collision risk) is not actually tested end-to-end in any control/safety loop.
- **SHF-Emerge is a synthetic, author-created benchmark** (inferred): Built specifically to showcase the method's target failure mode (CARLA-simulated rapid emergence/disocclusion). The largest reported gains concentrate almost entirely on this benchmark and on its "Person" class specifically, raising the possibility the benchmark's own construction favors the proposed mechanism. No independent/third-party emergence benchmark is used to cross-check.
- **Real-world driving results (DSEC) show only marginal gains** (inferred from Table I/II): mIoU 74.37% vs. LiFR-Seg's 73.82% (+0.55pp), depth RMSE 3.375 vs. 3.381 (nearly identical) — the method's core real-world benefit on the most standard, real (non-synthetic) benchmark is small, suggesting most of the demonstrated value is either synthetic-benchmark-specific or in less common conditions (M3ED aerial/quadruped, night).
- **Baselines adapted rather than natively causal** (stated): EISNet and CMNeXt were originally designed for co-temporal (same-timestamp) fusion, not anytime prediction; the authors "adapt" them to the causal protocol themselves. This means the RGB-event fusion baselines may be handicapped by an adaptation the original authors never intended/tuned for, potentially inflating LiFR v2's relative advantage.
- **No comparison against other recent completion/inpainting-style event methods** (inferred): Related work section covers many event-fusion and video-propagation methods but the empirical comparison set is fairly narrow (RAMNet, CFRNet, EISNet*, CMNeXt*, TLX) — several newer methods cited in Related Work (e.g., Depth AnyEvent, ScaleEvent, AIMDepth, MambaSeg) are not benchmarked against, so it's unclear how LiFR v2 compares to the current state of the art beyond its own baselines.
- **Distillation supervision requires future RGB at training time** (stated implicitly in method, not flagged as limitation): EGCM's event encoder is pretrained using the actual target-time RGB image as a frozen teacher signal. This is fine since it's offline/training-only, but the paper doesn't discuss how distillation quality/domain gap affects generalization to scenes very different from the distillation data, nor whether this teacher-dependency limits portability to new domains without paired future-RGB training data.
- **Person-class IoU improvement in ablation table (52.99%→55.14%, and 33.13%→55.14% for full pipeline) is a small, cherry-pickable single class** (inferred): while illustrative of the completion mechanism's intended effect, single-class deltas on a synthetic benchmark are more volatile/easier to showcase than aggregate mIoU; no variance/confidence intervals or multiple-seed results are reported anywhere in the paper.
- **No reported failure cases or error analysis for EGCM** (inferred): the paper shows only qualitative examples where the gate correctly identifies new content; it doesn't discuss cases where the gate over-triggers (hallucinating structure from spurious event noise) or under-triggers, despite this being a plausible risk given the residual-correction design.
- **Compute/latency benchmarked on a single high-end GPU (RTX 5090) with CUDA graph replay** (inferred): "100+ FPS" figures use aggressive inference optimization (batch size 1, CUDA graphs, amortized keyframe cost) on top-tier hardware; real-time performance on embedded/automotive-grade compute (relevant to the stated driving/robotics use case) is not addressed in the paper.
- **Acknowledgments section is a placeholder** ("[To be completed...]") (stated/visible in text): suggests this may be a pre-camera-ready or non-final draft, worth noting as a sign the paper may still be under revision.
