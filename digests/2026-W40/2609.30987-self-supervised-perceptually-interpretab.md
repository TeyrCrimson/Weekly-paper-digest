# Self-Supervised Perceptually Interpretable Monocular Depth Estimation

**arXiv:** [2609.30987](https://arxiv.org/abs/2609.30987)

**Categories:** cs.CV

**Relevance:** 8/10 — matched: Metric and temporally-consistent monocular depth

## TL;DR
PIMDE is a self-supervised monocular depth estimation model that, instead of feeding RGB directly into a black-box CNN, splits the image into four perceptual feature maps (chromatic, structural, luminance) and runs a separate depth-estimation branch on each, then fuses the branch outputs with fixed, empirically-derived weights. This lets the authors attribute the final depth map to specific perceptual cues via a subtraction-based analysis, while matching accuracy of established self-supervised baselines on KITTI. The core claim is interpretability-without-accuracy-loss, not a new accuracy record.

## First-principles breakdown

**The underlying task — self-supervised monocular depth estimation (MDE):** Estimating a per-pixel depth map from a single RGB image is ambiguous (a single 2D image can come from infinitely many 3D scenes), so it's normally learned from data. "Self-supervised" here means training without ground-truth depth (e.g., LiDAR): instead, the model exploits video — given a target frame and a nearby frame, it predicts (a) depth for the target frame and (b) the camera's motion between frames (via a "PoseNet"). Using depth + camera motion + camera intrinsics, you can warp the neighboring frame to reconstruct what the target frame *should* look like (differentiable "view synthesis"). The training signal is simply: make the reconstructed image match the real target image (a "photometric reprojection loss," combining SSIM and a robust pixel-difference loss). This trick avoids needing depth sensors and is standard practice since Monodepth2 (a key prior baseline used here).

**Why prior MDE models are opaque:** These networks take raw RGB pixels and pass them through convolutional layers whose internal features mix color, texture, and lighting information in ways that are not human-interpretable. If the model gets depth wrong (e.g., over a shadow or a textureless wall), there's no principled way to say *why* — was it confused by color, lack of texture, or lighting? Existing interpretability tools are "post-hoc" (e.g., saliency maps highlighting which pixels mattered) but don't explain *which perceptual property* (color vs. texture vs. brightness) drove the prediction.

**This paper's mechanism, step by step:**
1. **Decompose the image into Perceptual Feature Maps (PFMs).** Convert RGB to the CIE-Lab color space, which separates chromatic opponency (red-green "RG", blue-yellow "BY") from lightness (L). This is motivated by how human vision reportedly processes color via opponent channels. The L (lightness) channel is further decomposed with a 2D Discrete Wavelet Transform (a multi-resolution frequency decomposition) into a low-frequency "light-dark" (LD) map (capturing coarse brightness) and a high-frequency "coarse-fine" (CF) map (capturing fine texture/edges). Result: 4 separate single-channel maps (RG, BY, CF, LD), each isolating one perceptual cue.
2. **Parallel depth branches.** Each PFM is fed into its own depth-estimation sub-network, all sharing identical architecture (based on R-MSFM, a recurrent multi-scale refinement depth model — depth is predicted, then iteratively refined over several steps, each step incorporating multi-scale features). Because all branches share the same architecture, any difference in their outputs is attributable to differences in the *input cue*, not to arbitrary architectural choices — this design borrows from "Additive Convolutional Neural Networks" (ACNN), a prior interpretability framework by some of the same authors, applied in other domains, now extended to depth.
3. **Fusion with learned-but-fixed weights.** Each branch outputs a full inverse-depth map ("PIDE"). These are combined via a weighted sum into the final depth prediction. The weights are not learned end-to-end by gradient descent directly; instead there's a two-stage process: first train with uniform weights, then measure each branch's "influence" by removing it and seeing how much the fused output changes (a leave-one-out/ablation-style measurement), then convert those influence scores into normalized (softmax) fusion weights, which are frozen for final training. This keeps the fusion transparent — you always know how much a branch counts.
4. **Training loss.** Same photometric reprojection + edge-aware smoothness loss as standard self-supervised MDE (Monodepth2-style), applied to the final fused output, *plus* the same loss applied to each individual branch's output (auxiliary supervision) so each branch produces a coherent standalone depth estimate rather than a meaningless intermediate feature.
5. **Interpretability analysis.** To explain a prediction, compute the full fused depth map, then recompute it with one branch removed; the pixel-wise difference (ΔD map) shows spatially where and how strongly that cue mattered. This is quantified with summary statistics (mean absolute difference, RMS difference, relative difference) per branch (Table 3).

## Key insights

- **Genuinely new:** applying an ACNN-style additive/decomposable architecture to self-supervised depth estimation, using a perceptually-motivated (not arbitrary) decomposition (opponent color + wavelet texture/luminance) as the basis for separate, individually-interpretable branches, with a principled (influence-based, not manually tuned) fusion weighting scheme.
- **What the evidence actually supports:** On KITTI (Eigen split), PIMDE achieves accuracy broadly comparable to (not clearly better than) baselines like Monodepth2 and SGDepth — mixed results across metrics, with the paper's RMSE/RMSE-log numbers looking notably better but AbsRel/δ-accuracy roughly on par or slightly worse than the best baselines. The interpretability claim is supported reasonably well: the single-branch ablation (Table 2) and subtraction-based branch analysis (Table 3, Figure 4) consistently show the CF (fine texture/edge) branch as the strongest individual contributor, and this is internally consistent across both the quantitative single-branch results and the ΔD visualization — a genuine, non-trivial cross-check.
- **Interpretability mechanism is architecture-native, not post-hoc**, distinguishing it from prior saliency-map approaches — the branch structure itself is the explanation.

## Caveats — stated and inferred

- **Single dataset (KITTI only)** — stated as future work: "extend the evaluation to additional datasets and domains to further assess generalization." No cross-dataset or cross-domain validation currently exists (e.g., no indoor scenes, no non-driving imagery).
- **Fixed, small, hand-chosen set of 4 PFMs** — stated as future work ("automatic selection of PFMs"); the choice of exactly RG/BY/CF/LD is a design decision not systematically justified against alternative decompositions.
- **Accuracy is "comparable," not superior** — inferred: Table 1 shows PIMDE does not clearly beat the strongest baseline (Monodepth2/SGDepth) on AbsRel or δ-accuracy metrics, only on RMSE/RMSE-log/SqRel; the paper's framing emphasizes interpretability as the payoff rather than claiming a new SOTA, which is consistent with the actual numbers but worth flagging since the abstract's "comparable performance" claim is only partially true metric-by-metric.
- **Baselines are somewhat dated** — inferred: comparison methods (DF-Net, Monodepth, Monodepth2, EPC++, Struct2depth, SGDepth, Ranjan) are all from 2017–2020; no comparison to more recent (2022–2024) self-supervised MDE methods like Lite-Mono or SQLdepth, both of which are cited in the references but not benchmarked against.
- **No ablation on the auxiliary branch loss weight (λ_b) or on the two-stage fusion-weight procedure itself** — inferred: hyperparameters (λ, β, α, λ_b) are stated but simply borrowed from R-MSFM ("[12]") without independent tuning or sensitivity analysis for this new architecture.
- **Interpretability validation is qualitative/visual plus a leave-one-branch-out statistic, not validated against any ground-truth notion of "true" cue importance** — inferred: there's no external check (e.g., human study, causal intervention beyond removal) confirming the ΔD maps reflect genuinely correct attributions rather than artifacts of the fusion/training procedure.
- **Increased computational cost** — stated implicitly via numbers: PIMDE-6 uses 15.26M params / 248.94B FLOPs versus much lighter single-branch RGB models; the paper reports this but does not compare FLOPs/params directly against baseline methods in Table 1, making the efficiency trade-off hard to judge.
- **"To the best of our knowledge, first framework..." claim** — stated by authors; not independently verifiable from this text alone.
