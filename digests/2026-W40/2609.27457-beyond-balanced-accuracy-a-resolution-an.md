# Beyond Balanced Accuracy: A Resolution and Parity-Controlled Benchmark for Vision-Language and Vision-Only Defect Assessment in UAV Power-Line Inspection

**Authors:** Linghao Zhang, Siyu Xiang, Junwei Kuang, Peiyu Yi

**arXiv:** [2609.27457](https://arxiv.org/abs/2609.27457)

**Categories:** cs.CV

**Submitted:** 2026-09-23

**Relevance:** 8/10 — matched: Onboard object detection from a moving UAV

---

## TL;DR
This paper audits claims that vision-language models (VLMs) beat task-specific vision backbones (CNNs/ViTs) on UAV power-line defect inspection, using a new 56,972-item benchmark (ElecVQA-Bench) built from the public InsPLAD dataset. Once six evaluation confounds are controlled — matched test partition, item set, label space, replication, input resolution, and side information — the apparent VLM advantage mostly evaporates or reverses across seeds. The authors conclude their contribution is a benchmark-audit methodology, not evidence of general VLM superiority.

## First-principles breakdown

**The problem.** UAV imagery of power-line assets (insulators, towers, etc.) is screened for defects (rust, missing caps, nests, etc.). Two model types are used: (1) vision-only backbones like ResNet-50 or Swin Transformer, trained end-to-end on labeled crops to output a class; (2) VLMs like InternVL or Qwen-VL, which take an image plus a text prompt (asset name, defect decision tree, candidate answers) and generate a text answer. Recent papers report VLMs winning. This paper asks: is that a real capability gap, or an artifact of how the comparison was set up?

**Why prior comparisons are suspect — the six "evaluation choices":**
1. **Partition** — comparing models on *different* test files (e.g., a 7,851-item 7-class file for CNNs vs. a 2,021-item binary file for VLMs) inflates apparent gaps purely from file mismatch, not model quality.
2. **Evaluated item set** — even with equal file sizes, if the exact items differ (e.g., one model scored on a subsample), results aren't comparable.
3. **Label space** — binary "defect/normal" screening is a much easier task than 7-way fine-grained typing; conflating the two changes which model looks better.
4. **Replication** — a single train/test seed can flip sign; results must be checked across multiple seeds/splits.
5. **Input resolution** — VLM image preprocessors tile input into patches (e.g., 448px tiles, up to 12 tiles), giving the model access to far more raw pixels than the conventional 224×224 input fed to CNNs. This alone can manufacture an apparent capability edge that's really just a resolution/pixel-budget advantage.
6. **Side information** — VLMs are given text hints (asset name, defect decision tree, a list of plausible answers for that asset) that the vision-only classifier never sees. This makes any VLM-vs-CNN comparison a "system-level" comparison (whole pipeline vs whole pipeline), not an apples-to-apples encoder comparison.

**The mechanism — how they test this.** They built ElecVQA-Bench via a deterministic, auditable pipeline (region-of-interest crops at 4 expansion ratios, 3 task types — grounding/binary/7-way typing — leakage-aware splits grouped by parent image, SHA-256-logged manifests). They then run a formal "Parity Audit" (Algorithm 3): a checklist that fails a comparison if test files, item counts, label spaces, or side-information differ, and flags results as "PASS with caveat" if replication is thin or side-information is asymmetric. They also instrument resolution/pixel-budget directly — logging patch counts, visual token counts, and input hashes per item — so they can retrain vision backbones at resolutions matched to what the VLM preprocessor actually consumes (empirically ~768px-equivalent for InternVL, ~2.94 tiles), rather than defaulting to 224px.

They further separate confounds with targeted controls: a "source-pixel-matched" control (giving InternVL the same raw pixel budget as Qwen sees, even though tiling/tokenization differ), a prompt ablation (strip the decision-tree text to isolate how much of VLM performance is really "vision" vs "language grounding"), and a re-split/retrain regime (crop-level, image-level, and clustered "tower" splits with multiple seeds) to check whether any advantage survives proper statistical testing (McNemar's exact test, Holm correction for multiple comparisons, cluster-level sign-flip randomization).

**What they find, mechanically:** Once test files and label spaces match, binary screening shows a 0.03-point gap (noise) between Swin-T and the best VLM. At 7-way typing, most of a huge (~20-24 point) apparent CNN deficit disappears simply by giving the CNN the same pixel budget the VLM effectively uses — but this doesn't explain why one VLM (Qwen) beats another VLM (InternVL) by 7-14 points even when both get matched source pixels, and even though Qwen uses 56% fewer visual tokens. So resolution explains the vision-only-vs-VLM gap but not the VLM-vs-VLM gap — something else (tokenizer, pretraining data, architecture) is driving that, which they don't isolate. Finally, a 14-tower/3-seed full replication reverses which family wins depending on seed, and no advantage survives Holm-corrected multiple comparison testing.

## Key insights

- **Genuinely new/useful:** The six-axis parity-audit protocol (Algorithm 3) is a reusable methodological checklist that could generalize beyond this domain to any cross-family (VLM vs. specialist model) benchmark claim. The instrumented pixel-budget audit (logging actual tiles/tokens/hashes per item) is a concrete, verifiable way to expose resolution confounds that are typically invisible because papers don't report VLM preprocessing details.
- **The headline empirical finding is a debunking, not a discovery:** much of the literature's claimed VLM superiority on this task appears to be an artifact of mismatched partitions, label spaces, and especially unequal input resolution, rather than a genuine representational advantage.
- **A secondary, better-supported finding:** the balanced-accuracy metric is shown (via a formal proposition) to conflate qualitatively different error profiles (miss-dominated, hallucination-dominated, abstention-dominated) — and they document that a "top" zero-shot model achieving near-zero miss rate is actually abstaining on 20% of defective items, which balanced accuracy hides. This is a clean, well-evidenced point.
- **What's NOT supported despite being investigated**: the paper does not explain why Qwen3-VL-8B outperforms InternVL3.5-8B even under matched pixel/token budgets — this is reported honestly as an open question, not resolved.
- **Distinguishing claim from evidence:** the authors explicitly frame their contribution as a "benchmark-audit" rather than a verdict on VLM vs. CNN superiority — the text itself is careful to say no family-level advantage "survives multiple-comparison correction," which is a narrower and more defensible claim than "VLMs don't work" or "CNNs are better."

## Caveats — stated and inferred

- **Small rare-class counts dominate macro-averages (stated).** Two classes (`peeling-paint`, 4 test instances; `torned-up`, 5 instances) can swing the 7-way macro-recall metric by 22.9 points in either direction — the authors explicitly flag this as destabilizing headline comparisons.
- **System-level, not encoder-level, comparisons (stated).** Every cross-family comparison fails the parity-audit's side-information check by construction, since VLMs receive text hints (asset name, decision tree, candidate answers) that CNNs don't. The authors repeatedly caution these are whole-system, not pure-vision, comparisons.
- **Single accelerator, single lab, single dataset (inferred).** All ~205 GPU-hours ran on one RTX PRO 6000 GPU; results derive entirely from one benchmark (ElecVQA-Bench/InsPLAD) — generalization to other inspection datasets or domains is untested and not addressed in the paper.
- **Two-seed replication for the main adaptation results (stated as a limitation).** The authors themselves note "two seeds remain too few for a precise seed-variance estimate," yet several headline numbers (Table 4/5) rest on 1-2 seeds; only the later 14-tower/3-seed replication is more robust, and that one reverses sign across seeds.
- **Mechanism behind the Qwen-vs-InternVL gap is unresolved (stated).** The paper explicitly states "the experiment does not isolate the mechanism" for why Qwen outperforms InternVL under matched pixel/token budgets, leaving tokenizer, pretraining corpus, and architecture as untested candidate explanations.
- **Selection advantage in resolution sweep (stated).** The 448px setting is flagged as "the highest-scoring point of a four-point sweep evaluated on the test set," i.e., partially selected post hoc on the test set itself — a form of leakage/optimistic bias the authors themselves flag and try to correct for by also reporting 672/896px as the "controlled comparison."
- **Hosted API models lack version pinning (stated).** Two models (Qwen3.8-27B, Qwen3.5-122B) were accessed via hosted API without a stable weight-revision hash, so those specific results are "provenance snapshots rather than version-pinned reproductions."
- **No confidence/probability signal available (stated).** Because outputs are discrete tokens rather than scores, a full cost-curve analysis (varying decision threshold) is not possible; the abstention-cost framework is used as a substitute but is an "accounting device rather than a new theory."
- **Prevalence mismatch with real-world deployment (stated).** The benchmark's defect prevalence (37.9%) is a construction artifact, roughly 1-2 orders of magnitude higher than real field prevalence; cost-ratio crossover findings calibrated on this benchmark are explicitly flagged as not directly transferable to field conditions without re-basing.
- **No comparison against other published SOTA methods or truly out-of-domain baselines (inferred).** The vision-only baselines are limited to ResNet-50 and Swin-T (ImageNet-initialized); no larger or more modern vision backbones (e.g., ConvNeXt, DINOv2 features) are tested, so it's unclear whether the findings generalize to stronger vision-only models — not addressed in the paper.
- **Middle/later sections truncated in the provided text** (e.g., full Section 6 discussion, conclusion, and some appendix tables were cut off), so some stated limitations or future-work caveats from the authors' own discussion section may be missing from this summary — noted here rather than inferred content being fabricated.
