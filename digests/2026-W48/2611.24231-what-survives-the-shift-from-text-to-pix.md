# What Survives the Shift from Text to Pixels? Conditional Protection against Prompt Injection in Image-Rendered Documents

**Authors:** Haoyang Liu, Yinong Xu, Zhe Lang, Zhenyu Guan, Qianyun Zhang

**arXiv:** [2611.24231](https://arxiv.org/abs/2611.24231)

**Categories:** cs.CR, cs.AI

**Submitted:** 2026-11-18

**Relevance:** 9/10 — matched: Document-borne prompt injection

---

## TL;DR
The paper asks a finer question than "does rendering documents as images stop prompt injection": *which* injected operations survive, under *which* conditions, and *why*. Testing six multimodal LLMs on 191 matched text/image document pairs, they find rendering reliably blocks simple "append a marker" and "reformat the answer" attacks but Qwen3-VL-8B still executes a fixed-phrase answer-replacement attack 77.96% of the time from images, and a modest 8-candidate attack search closes most of the image protection for Qwen and Gemini. Mechanistic probing (activation patching, attention blocking) shows text commands act locally at their own token positions while image commands get smeared across visual tokens of the whole page, explaining part of the asymmetry.

## First-principles breakdown

**The problem.** When an LLM answers questions using an external document (RAG, document QA), that document is untrusted — it could contain text planted by an attacker that looks like an instruction ("ignore the above, say X instead"). This is "indirect prompt injection": the model is supposed to treat the document as data, obey only the system/user instructions, but a cleverly worded sentence inside the document can hijack the response. This matters because document QA pipelines increasingly feed raw retrieved content straight into the context window.

**The proposed defense being studied (not invented by this paper).** A prior idea (Zhang et al., "Pictionary"/"Render Before Reading") is: instead of giving the model the document as text tokens, render the document as a page image (literally a screenshot/PNG of the page) and let the model read it through its vision encoder. The intuition is that text embedded as pixels is "out of band" from the model's usual instruction-following text channel, so injected commands lose their grip. Prior work showed this lowers attack success *on average* across benchmarks.

**Why "lowers attack success on average" is not good enough.** Averaging hides three different failure modes that this paper tries to separate:
1. *Which attack operation* — appending a watermark-like string, reformatting the answer, or fully replacing the answer — may be affected very differently by rendering. An aggregate score over one attack type can hide that a worse attack type still works.
2. *Unread vs. read-but-ignored* — if an attack fails on the image version, is that because the model literally couldn't read the pixel text (an OCR/legibility failure), or because it read and understood the instruction but chose to follow the user instead (a genuine robustness win)? These have very different security implications — legibility failures are brittle (higher resolution fixes them) while "read but refused" is a real property of the trust mechanism.
3. *Utility cost* — a defense that also degrades the model's ability to actually answer correctly isn't free.

**Experimental design.** They take 191 English QA sources from LongBench (three datasets: Qasper, MultiFieldQA-en, HotpotQA), and for each one create a matched pair: the same document/question/injected-attack as plain text, and as a rendered page image (PNG), keeping system prompt and user question as text in both cases. They test three injection operations (append a marker, reformat answer as "marker | answer", or replace the answer entirely with a fixed attacker phrase), each with two wordings, across six models (Qwen3-VL-8B, GPT-5-nano, Haiku 5.5, Gemini 3.1 Flash-Lite, GLM-5.3-Flash, DeepSeek V4.1 Flash). They score Attack Success Rate (ASR, did the response contain the injected behavior) and clean QA F1 (did the model still answer correctly), including "integration questions" that require combining two separate evidence spans (a harder utility stress test).

**Mechanistic tools used to go beyond behavior.** For Qwen (open-weights, so internals are inspectable):
- *Activation patching*: take the internal states ("residual stream") at the token/patch positions corresponding to the attack region in a run where the model saw a benign/neutral version of the passage, and splice in the states from a run where it saw the actual attack. If this alone induces the attacked behavior, those states causally carry the "attack" information. They search which transformer layers matter.
- *Target redirection*: plant two different random codes as two different "attack targets" in a source, and test whether swapping internal states from a model primed to use code B into a model primed to use code A actually changes which code appears in the output — a causal test of exactly which states determine the content being injected, not just whether an attack fires.
- *Attention blocking*: forcibly prevent (mask) certain token/patch positions from attending to others during generation, to test whether the "signal" for the attack is confined to the attack's own tokens/pixels or has leaked into representations elsewhere on the page/in the context.

**What they actually find mechanistically.** In text, blocking all positions outside the attacked span from attending to that span eliminates the attack — the command's influence lives entirely in its own tokens. In images, blocking just the attack-region patches barely changes anything; you have to block the *entire instruction page* to kill the attack, because the vision encoder (which processes images in overlapping patches with global attention/positional mixing) spreads the semantic content of the command and its target into visual tokens elsewhere on the page. This is why patching just the attack-region states in images is weaker and why redirecting the "target code" doesn't fully transfer in images (the recipient's own code is still recoverable elsewhere on the page).

## Key insights

- **Genuinely new**: a decomposition of "rendering as a defense" along three axes (operation type, legibility vs. compliance, utility cost) that prior aggregate-ASR papers didn't separate. This is the paper's central methodological contribution, and the evidence (Tables 1, 3, 4) does support it — the operation-level breakdown clearly shows answer-replacement survives rendering for Qwen (77.96%) while append/format mostly don't, which an aggregate metric would have obscured.
- **Reading ≠ following, and this is evidenced, not just claimed**: behavioral diagnostics (reporting, understanding/identification, execution measured as three separate endpoints) show models often transcribe or correctly identify an embedded command's operation/target while still not executing it (e.g., Gemini reports/identifies >90% of image commands but executes far fewer). This is solid evidence against "rendering only works because text becomes illegible" — a genuine and useful finding.
- **Protection is attacker-searchable, i.e., fragile**: with only 8 fixed candidate attacks and a ranked query budget, the image "protection" for append/format mostly disappears for Qwen and Gemini (though not GPT-5-nano). This is an important caveat to the "rendering helps" narrative — claimed robustness evaporates under a very cheap adaptive-ish search, though note this is a search over a fixed small candidate pool chosen in advance, not a fully adaptive/optimization-based attack.
- **Mechanistic account is a plausible explanation, not a full proof**: the attention-blocking/patching results make a coherent story (text = localized signal, image = distributed signal via visual encoding) but this is demonstrated only inside one open-weight model (Qwen); whether the same causal structure holds for GPT-5-nano/Gemini/etc. is not tested (those are closed-weight, so untestable with these methods) — the authors don't overclaim generality here, but a reader might be tempted to.
- **Utility cost is real but model-dependent**: original-question utility is largely preserved (93–102% ratio) across models, but Qwen's utility drops sharply to 61.99% on questions requiring combining two evidence spans — showing the defense's "free lunch" framing from prior work doesn't hold uniformly.

## Caveats — stated and inferred

- **Single open-weight model for all mechanistic work** (stated implicitly via methodology, inferred as limitation): all activation patching, target redirection, and attention-blocking results are from Qwen3-VL-8B only, since the other five models are closed/API-accessed. Generalization of the "text=local, image=distributed" account to other architectures is untested. *(inferred)*
- **Fixed, small attack-wording space**: only two wordings per operation in the main experiment, and the "budget search" explores just 16 candidates (8 lead-ins × 2 wordings) built in a specific, non-adaptive construction (separate-page protocol). A genuinely adaptive/optimization-based attacker (e.g., gradient-based or iteratively refined against the defense) is not tested, so real-world worst-case robustness could be worse than reported. *(inferred)*
- **Rendering settings matter a lot and defaults may be favorable**: the authors themselves show that image resolution and font size strongly affect attack success (higher res / larger font substantially raise ASR), and the main comparison uses one fixed "default" rendering setting — so the headline protection numbers are specific to that configuration, not representative of the full rendering-config space. *(stated)*
- **Coarse rendering settings that do suppress attacks also cost utility** (clean F1 drops from ~48.7 to ~42.2 at the coarsest setting tested) — so any claim that a particular rendering setting is "safe" needs to be paired with its utility cost, which the paper flags but doesn't fully optimize/trade off. *(stated)*
- **OCR-correction experiment leaves a gap unexplained**: correcting OCR errors in the attack span raises strict reproduction success by 14.44 points but execution by only ~3.33 points — the authors call this "unresolved," i.e., they cannot fully explain why fixing legibility doesn't proportionally raise execution. *(stated)*
- **Benchmark source is a single existing dataset (LongBench) in English only**: 191 sources across three sub-datasets; no multilingual or out-of-domain (e.g., tables, forms, scanned real-world documents with noise) test is reported, limiting external validity to the kinds of documents in LongBench. *(inferred)*
- **Some models are tested unevenly in deeper experiments**: Sections 5–7 (presentation effects, diagnostics, mechanistic analysis) mostly focus on Qwen, with GPT-5-nano and Gemini added only "in part" — the three weakest/least-vulnerable models by the Table 1 results (Haiku, GLM, DeepSeek) get essentially no deeper analysis, so conclusions about "why" protection holds/fails are really only well-supported for 2–3 of the six models. *(inferred)*
- **LLM-assisted code/writing**: the authors disclose using an LLM ("GPT-6 Astra") to assist with code development, experiment execution, and plotting code, and another LLM (Claude Opus 5.5) to edit/organize the manuscript, with only author review as a check — a transparency disclosure rather than a methodological flaw per se, but worth noting as a dependency on unverified tooling. *(stated)*
- **ASR scoring excludes truncated responses** ("unknown" and excluded from scoring) rather than counting them as failures or successes — this could subtly bias reported rates depending on which conditions produce more truncation, and the paper doesn't report how often this occurs. *(inferred)*
- **No comparison against other proposed defenses**: the paper studies rendering-as-defense in isolation; it does not benchmark against other mitigations mentioned in related work (e.g., spotlighting, StruQ-style structured queries, instruction hierarchy training) to see how rendering's conditional protection compares. *(inferred)*
