# IDEA: Intent-Dominance Evidence Audit for Inference-Time Backdoor Detection in GUI Agents

**Authors:** Zhizhuo Kou, Sizai Hou, Jian Yang, Ge Sun, Junyu Luo, Wenkai Zhang, Sirui Han, Yike Guo

**arXiv:** [2611.24102](https://arxiv.org/abs/2611.24102)

**Categories:** cs.CV

**Submitted:** 2026-11-18

**Relevance:** 8/10 — matched: Document-borne prompt injection

---

## TL;DR
IDEA is a runtime detector that catches backdoored GUI agents (open-weight vision-language models that click/type on screens) at inference time, without knowing the trigger or having attack examples. It works by probing whether a step's action is still controlled by the instruction (via counterfactual instruction redirects) versus controlled by some unreferenced screen region (via causally ablating candidate regions), and flags a step when either signal deviates from what clean steps show at the same "unusualness." Across five attack types on Qwen2.5-VL-3B it beats 13 adapted baselines, especially on hard near-manifold triggers, while also pointing to the suspected trigger region.

## First-principles breakdown

**The setting.** A "GUI agent" is a vision-language model that takes a screenshot + a natural-language instruction (e.g., "Click Done") and outputs an action (a click coordinate, a typed string). Organizations download open-weight agent checkpoints from model hubs. A "backdoor" is a change baked into the model's weights during training/fine-tuning: on normal screens the agent behaves correctly, but whenever a specific visual pattern ("trigger," e.g. a small icon, a banner, a tiled texture) appears anywhere on screen, the model instead performs an attacker-chosen action (click a phishing button, type a malicious string) — regardless of what the instruction actually asked for. This is a supply-chain risk: the backdoor passes normal QA/acceptance testing because it only activates in the attacker's chosen trigger condition.

**Why existing defenses don't apply.** Prior "inference-time backdoor detectors" (STRIP, SCALE-UP, IBD-PSC, TeCo, DeDe, Mahalanobis/kNN/PCA outlier screens, etc.) were built for image classifiers or CLIP-style embedding models — they assume a discrete classification output or a global embedding space, and typically detect a poisoned sample by checking if its output/representation is unusually invariant or an outlier. GUI agents instead map (screenshot, instruction) → continuous coordinate/text actions, and nobody had built a per-step detector for this setting, nor one that also tells you *which region* of the screen is responsible.

**Core idea: intent–evidence dominance inversion.** The authors' insight is behavioral, not statistical: on a clean step, the *instruction* is what determines the action — changing the instruction changes the action, and the visual evidence supporting the chosen action is located where the instruction points. On a backdoored step, this control relationship flips: an unreferenced screen region (the trigger) hijacks the decision, so either (a) the instruction loses its grip on the action (changing the instruction barely changes anything), or (b) the evidence region dominates far more than the instruction does. This is "intent-evidence dominance inversion," and it's trigger-agnostic — you don't need to know what the trigger looks like, only that *some* region exerts outsized causal control while the instruction's control shrinks.

**How to measure "control" without trusting the model's own attention** (since the model itself might be compromised, you can't just read its attention weights — you need causal interventions):

1. **Intent Counterfactual Probing (ICP):** Take the screenshot, generate a few "redirect" instructions that name *other* visible elements (from accessibility tree/OCR), e.g. "Click on the 'X' element" instead of "Click Done." Only keep redirects the agent actually complies with on their own (checked via a cheap teacher-forced likelihood test — Eq 1). For each valid redirect, measure how far the model's internal decision state (last hidden layer at the point where the action is decided) moves compared to the original step. The median of these movements is `Sint`, the "intent scale." On a clean step, since the instruction drives the action, redirecting it should move the state a lot. If a trigger has hijacked control, redirecting the instruction barely matters — `Sint` stays small.

2. **Region Causal Audit (RCA):** Propose candidate screen regions (from UI element boxes, OCR boxes, gradient attribution, plus a fallback grid) and *ablate* each one by replacing its visual tokens with a blurred version — a genuine causal intervention (remove region → see if decision changes), not just reading saliency. Measure how far the decision state moves for the most impactful region; that's `Emax`, the "evidence scale," and the responsible region becomes the candidate trigger location `R⋆`. On a clean step, no single region should carry outsized unique control (the instruction is dominant); on a backdoored step, removing the trigger region should snap the decision back toward normal.

3. **Why you can't just threshold these two numbers directly:** both `Emax` and `Sint` naturally grow when the screenshot is just unusual for non-malicious reasons (an atypical clean screen already sits far from the "typical" clean manifold). So raw thresholds confuse "weird screen" with "triggered screen." The fix: fit a regression ("clean law") of log(Emax) and log(Sint) against a presence score `n0` (Mahalanobis distance of the decision state from the clean mean) using only clean calibration data. For any test step, compute residuals `u` (how far evidence exceeds what's expected at that presence — "excess evidence") and `v` (how far intent falls short of what's expected — "intent deficit"). A trigger should produce large positive `u` and/or large positive `v`; the final score `ρpc = sqrt(max(u,0)² + max(v,0)²)` captures either kind of inversion (so an attack only needs to break the clean law on one of the two axes, and the two cannot cancel each other out, unlike a naive ratio of the raw scales).

4. **Statistical guarantee via conformal calibration:** rather than hand-picking a threshold, they use split-conformal prediction: hold out two disjoint clean calibration sets (B1 fits the "clean law," B2 sets the final alarm threshold `Tα`), guaranteeing that on exchangeable clean data the false-positive rate is provably ≤ α (e.g., 1%) in finite samples — not just asymptotically. There's also a cheap pre-filter "presence gate" (a plain Mahalanobis outlier check) that skips the expensive full audit for the ~95-97% of steps that look like ordinary clean screens, keeping runtime overhead low (~9-10%) since the full ICP+RCA audit only runs on the small flagged minority.

**What happens at test time (Algorithm 1):** for each step, run the agent, compute its decision state and Mahalanobis "presence." If presence is below a low threshold, skip (no alarm, cheap). Otherwise, run the K instruction redirects and M region ablations, compute u and v against the pre-fit clean law, combine into ρpc, and alarm if ρpc exceeds the conformal threshold — returning the suspected trigger region to a human operator (the system never auto-"fixes" the action, since a compromised model might just misbehave again).

## Key insights

- **Genuinely new framing:** reconceiving backdoor detection as a *causal control* test ("who dominates the decision, instruction or region?") rather than an outlier/classification test. This is plausibly the first step-level, per-action, attack-agnostic, zero-attack-data detector for GUI agents specifically (as opposed to image classifiers/CLIP).
- **The either-side scoring (Eq. 5) is empirically load-bearing, not decorative.** Ablations show that using only `u`, only `v`, or their sum/difference each fail badly on at least one attack family (e.g., "u only" collapses to 0.435 TPR on Grounding; "v only" collapses to 0.178 on Adaptive-Blend; a log-ratio that lets the two cancel drops to 0.513 on Adaptive-Blend), while the max-style either-side rule stays >0.89 on every family. This is a well-supported claim — directly validated by the ablation table, not merely asserted.
- **Presence-conditioning matters empirically too:** removing the clean-law conditioning (using a raw unconditional log-ratio) drops performance substantially, especially on near-manifold triggers (Grounding), confirming the "atypical clean screens confound raw thresholds" argument is not just theoretical.
- **The conformal FPR guarantee is a real, checkable property** (not just a design aspiration) — the paper reports measured FPRs close to target and discusses where the guarantee is marginal (varies under app-resampling bootstrap) versus per-draw, which is an honest nuance.
- **Localization is a genuine extra output** (region hypothesis for every alarm), useful for human triage, though the paper itself cautions it's "a pointer, not a segmentation" (IoU with true trigger box is often low even when the center-hit rate is high).
- **Claimed vs. evidenced generalization:** the two "held-out/blind" victims (a truly novel trigger type, and a different backbone) are the strongest evidence for generalization since the scoring rule was frozen before seeing them. But results are mixed here — IDEA is not the best detector on either held-out case individually (the Mahalanobis screen or the log-ratio ablation beat it on one axis each); the claimed advantage is *consistency* (staying ≥0.88 on both) rather than peak performance anywhere, which is a more modest and more credible claim than "best everywhere."

## Caveats — stated and inferred

- **Single small backbone for the core evaluation** — all five main attack families are only trained/tested on Qwen2.5-VL-3B; broader backbone testing is secondary. (stated — "Limitations": "our five-family evaluation currently focuses on a single 3B backbone for computational tractability.")
- **Statistic design was not blind to the test data it's evaluated on** — the exact form of ρpc (the either-side max-norm) was finalized *after* observing results on all five development attack families; the authors themselves flag this and rely on two held-out victims as the real blind test. (stated)
- **Mixed/non-dominant results on held-out (blind) victims** — on the held-out noise-tile blend, IDEA underperforms the Mahalanobis screen (0.975 vs 0.998 TPR); on the held-out backbone (OS-Atlas-7B) with the Grounding-style trigger, IDEA underperforms the log-ratio ablation (0.883 vs 0.948). No single baseline is competitive on both, but neither is IDEA the top scorer on either individually. (stated, in Sec 5.2, "IDEA is not the best score on either held-out victim")
- **Backbone transfer to 7B models is inconsistent** — on UI-TARS-1.5-7B, IDEA (0.921 TPR) is beaten by the log-ratio, the Mahalanobis screen, and a one-class SVM baseline, attributed to the clean-law fit transferring poorly (gate pass rate nearly double on clean steps for that backbone). Held-out clean FPR also consistently exceeds the 1% nominal target across all tested 7B backbones (e.g., 0.017–0.023 observed vs 0.01 target). (stated)
- **One attack family is explicitly a known blind spot** — Adaptive-Blend (full-screen, no localized trigger region, trained to still obey instruction redirects) is the closest case to defeating the method's theoretical assumptions (Proposition 1), and on it IDEA ties with or loses to simpler baselines on tighter FPR targets (0.569 at α=0.005, below several distance-based baselines) and has lower AUROC than the plain Mahalanobis screen. (stated)
- **Localization is coarse** — region overlap (IoU>0.5) with the true trigger box is low for several attack families (e.g., 0.000 for Popup, 0.011 for Adaptive-Blend), even when the "hit" (center-in-box) rate is high; authors explicitly call R⋆ "a pointer for the operator, not a segmentation." (stated)
- **Calibration-size sensitivity** — on hard families (Grounding, Adaptive-Blend), performance degrades meaningfully with fewer clean calibration steps (e.g., Adaptive-Blend falls to 0.715 TPR, below the simple screen, at n=200), and below ~200 calibration steps the method can't even certify the target FPR. Real deployments without a few hundred clean labeled calibration steps per app context may not get the stated guarantees. (stated)
- **The "episode-disjoint" split still has a confound the authors admit is not removed** — positive (triggered) and negative (clean) test steps differ systematically by episode membership (triggered steps are drawn from training episodes, clean are held-out episodes), which is explicitly called a confound the split doesn't eliminate. (stated)
- **Scope is narrow by design** — only "parametric" backdoors (trigger baked into weights) are addressed; runtime/environmental injection attacks, memory/knowledge-base poisoning, and prompt-based attacks are explicitly out of scope, so real-world "supply chain risk" coverage is partial. (stated)
- **Marginal, not conditional, FPR guarantee** — the conformal bound holds marginally over clean calibration draws, not per-draw; the paper shows the bootstrap 95% interval for some families exceeds the 1% target (e.g., 0.0121 for Popup) and the worst single seed reaches 0.023. Practitioners relying on "finite-sample guarantee" language should note this nuance. (stated)
- **No comparison against adaptive/white-box attackers who know about IDEA itself** — all five attack families were trained without any awareness of this specific defense; an attacker with knowledge of ICP/RCA could plausibly craft a trigger that satisfies the instruction-redirect behavior AND resists region ablation (breaking both assumptions in Proposition 1), which the paper's own proof sketch acknowledges is the theoretical escape route. (inferred, though foreshadowed by the paper's own discussion of Adaptive-Blend as "the closest such case")
- **Modest overhead claim is measured only in a narrow, favorable setup** — the "9-10% overhead" figure is from steps that mostly fail the cheap gate (97%+ of clean traffic skips the expensive audit); environments with naturally more unusual-looking clean screens (higher gate-pass rates) would see substantially higher real-world overhead, as the UI-TARS-1.5-7B experiment itself shows (9.6% gate-pass rate vs ~5% elsewhere). (inferred)
- **LLM-assisted code/writing** — the authors disclose using generative AI tools to help write code and edit prose, though they state research design/conclusions were human-determined; included for transparency, not as a weakness of the science itself. (stated)
