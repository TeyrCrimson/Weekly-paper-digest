# Accord: Universal Online Metric Localization and Dense Mapping from one Camera and an IMU

**Authors:** Jaafar Mahmoud, Arthur Movsesyan, Cuong Huynh, Mikhail Iumanov, Sergey Zagoruyko, Sergey Kolyubin

**arXiv:** [2611.25279](https://arxiv.org/abs/2611.25279)

**Categories:** cs.CV

**Submitted:** 2026-11-18

**Relevance:** 8/10 — matched: Metric and temporally-consistent monocular depth

---

## TL;DR
Accord is an online dense mapping system that fuses visual-inertial odometry (VIO) poses with a pose-conditioned depth foundation model (Depth Anything 3), fixing the residual per-image scale drift that such hybrid pipelines otherwise leave uncorrected. It anchors each short keyframe window to metric 3D points triangulated from VIO poses, then uses bidirectional dense-depth agreement between co-visible images to detect and remove leftover scale errors without touching the trajectory. Using one fixed configuration across six camera/IMU platforms (five public + a new phone/GoPro dataset), it reports the best or second-best mean F-score at 5 cm versus five recent dense-mapping baselines.

## First-principles breakdown

**The problem.** To build a usable 3D map for a robot or AR app from just a camera + IMU, you need two things simultaneously: (1) *metric scale* — distances in real-world units (meters), and (2) *dense geometry* — a full surface, not just a sparse point cloud. VIO (visual-inertial odometry, e.g., VINS-Mono, OpenVINS) gives you (1): by fusing camera motion with accelerometer/gyroscope readings, it can recover true metric scale (IMU acceleration has known physical units), but it only tracks a sparse set of feature points — not enough to reconstruct a wall or floor. Meanwhile, modern "feed-forward" depth/geometry foundation models (DUSt3R, VGGT, Depth Anything 3) take one or more images and predict dense depth for every pixel in a single network pass — great geometry, but the scale is ambiguous (the model doesn't know if it's looking at a dollhouse or a building) and it doesn't know which way is "down" (gravity).

**Why naively combining them isn't enough.** The natural idea (used by prior work like DAVIO, which this paper builds on) is: feed the depth model the VIO's metric camera poses as a conditioning signal, so its depth output should come out already in meters. In practice this doesn't fully work — the network's depth predictions still carry small *per-image* multiplicative scale errors (a few percent) that don't show up as internal inconsistency within one window (because the model's own consistency checks only test agreement between nearby frames, which can all share the same bias). A 2% depth error at 3 meters range is 6 cm — bigger than the paper's 5 cm evaluation tolerance. These errors also don't show up if you later rescale/align the whole map to ground truth (as many prior SLAM evaluations do) — which is precisely why the paper insists on evaluating maps placed purely by their own estimated trajectory, with no post-hoc scale fitting.

**The paper's fix — two-level scale correction:**
1. *Metric anchor (Sec 4.1):* Within each 5-keyframe window, the paper triangulates 3D points from feature matches using the VIO filter's poses (these points are, by construction, correctly metric since they come straight from the IMU-fused trajectory). It then computes a single per-window log-scale offset (`oj`) that best aligns the depth model's predicted depths to these triangulated points (robust weighted mean via Huber loss). This removes the *window-level* average scale error, but — crucially — cannot catch an error that is common to *all* images inside the window, because if a pose error stretches the whole window's triangulated baseline, every depth estimate inside that window shifts together and looks "self-consistent."
2. *Cross-window agreement correction (Sec 4.2 — the paper's namesake "Accord"):* To catch the remaining per-image bias, take two images from *different* windows that observe the same physical surface. Unproject image i's depth into image j's frame and compare to image j's own predicted depth there; do this in both directions (i→j and j→i). If i overestimates depth by factor eᵢ and j by eⱼ, the forward comparison gives roughly (eⱼ − eᵢ) and the backward gives (eᵢ − eⱼ); occlusion effects contaminate each direction with the *same* sign, so averaging half the difference of the two directions cancels occlusion noise while keeping the true scale disagreement. Collecting such pairwise disagreements across the whole map, the paper solves a global least-squares system for a per-image correction cᵢ, with a small L2 regularizer anchoring the *average* correction within any connected group of images to zero — i.e., it only removes disagreement between images, never shifts the overall metric scale established by step 1. This runs asynchronously in its own process so it doesn't block the real-time mapper; corrections lag the live map by about one window.
3. *Context keyframes (Sec 4.3):* feeding the depth model a couple of older (2–20s prior), nearby keyframes as extra context (not just the current window) improves the depth predictions themselves, giving the network more multi-view evidence per prediction.

**System architecture:** three concurrent processes — (a) VIO filter tracking pose/keypoints at sensor rate, (b) a GPU worker running the depth model per 5-keyframe window and building a factor-graph "submap" per window (pose + log-scale node, loop closure via depth-verified relative poses), (c) the asynchronous scale-correction process feeding back per-image corrections. A live map fuses the latest submaps into 4 cm voxels.

## Key insights

- **Genuinely new:** the explicit identification that pose-conditioned depth models retain *per-image* scale bias that is invisible both to within-window self-consistency checks and to standard map-level similarity alignment used in prior SLAM evaluation protocols — and a label-free, training-free correction (the "Accord" agreement measurement) that isolates this bias via bidirectional depth comparison across non-adjacent, co-visible views while provably preserving the metric mean scale. The bidirectional averaging trick to cancel occlusion artifacts while retaining scale-error signal is a neat, specific mechanism (backed by a first-order error analysis in the appendix).
- **Evaluation protocol is itself a contribution/claim worth flagging:** the paper argues that competing work (ScaRF-SLAM, FoundationVIO) evaluates using local 10 m-segment registration to the ground-truth scan, which "forgives" accumulated drift; Accord instead aligns the whole trajectory once and never fits scale to the reference, which the authors argue is a stricter, more realistic test. This reframing is used to justify why Accord looks better under their protocol but closer or behind under others (e.g., FoundationVIO's own protocol on ORI).
- **What the evidence actually supports:** on the four public datasets with ground-truth scans, Accord has the best mean F-score@5cm, and wins or is runner-up on nearly every individual sequence (12/17 best, 16/17 top-two) — fairly broad, not a single-benchmark cherry pick. The ablation (Table 4) supports that the anchor step contributes the largest single gain, with context keyframes adding a smaller additional boost. The scaling test (Table 5) supports that bigger depth backbones monotonically improve results, i.e., the architecture is "backbone-agnostic" and improves with better foundation models, a forward-compatible design claim.
- **Weaker/more mixed evidence:** on the smartphone benchmark (uncalibrated consumer hardware, the paper's secondary device-generality claim), Accord wins on the Note 9 but is slightly behind FoundationVIO on the iPhone — the "universal across devices" claim is only partially supported. The GoPro walk has no ground-truth scan at all, so it is purely qualitative, not evidence of accuracy.

## Caveats — stated and inferred

- **No ground-truth scan for the GoPro evaluation — stated.** The authors explicitly call this "qualitative," with no quantitative accuracy claim possible.
- **Phone benchmark reference is not true ground truth — stated.** The reference comes from LiDAR-iPhone RTAB-Map output, which the authors themselves describe as "the best estimate available, not ground truth in the survey sense," and lever arms between phones were not measured, limiting claimed trajectory accuracy to a coarse bound.
- **Degraded performance in large-scale/outdoor settings — stated.** The paper states "every pipeline scores far lower on Hilti-Oxford and Oxford Spires... confirming that large-scale heritage and outdoor environments remain challenging for every method, Accord included," and depth beyond 20 m is simply dropped (explicit range limit), so far building facades/quad edges outdoors go unmapped.
- **Trajectory is a hard dependency and sometimes fails — stated.** The authors note the system's accuracy is capped by the underlying VIO filter: "the trajectory is the filter's," it "drifts on Hilti-Oxford's construction site," "fails on three of the phone recordings," and loop closure "makes it worse than the filter's own" on one Oxford Spires sequence. The whole scale-correction mechanism explicitly does not fix trajectory/pose errors, only depth scale — so odometry drift remains an unaddressed, acknowledged failure mode.
- **One configuration tuned on only 3 development sequences, inferred generalization risk — stated as design, but inferable as a limitation.** All hyperparameters (Table 7) were selected on EuRoC V1_01/V1_02 and ORI R01 only, then frozen for every other dataset/platform; while framed as evidence of universality, this is also a small, non-independent calibration set, and no sensitivity/robustness analysis of these hyperparameters across platforms is given — *inferred* possible overfitting risk to the specific scene types in those three sequences.
- **Baseline comparisons depend on re-running others' released code with possibly suboptimal settings — inferred.** E.g., MASt3R-Fusion's configuration was hand-picked per dataset by testing both of its shipped configs on a single development sequence and keeping the better one; VGGT-SLAM 2.0 is given the ground-truth reference scale (marked †) since it has no metric scale of its own, which is a structurally unfair-but-flagged comparison; ScaRF-SLAM's mapper is run without its own pose estimator (on Accord's poses), which could overstate Accord's relative advantage on trajectory-dependent metrics. These are disclosed but not neutral-ground comparisons.
- **Discrepancy with a concurrent work's self-reported numbers — stated but unresolved.** The paper reports its own re-run of FoundationVIO scores lower (64.5%) than FoundationVIO's own paper (73.1%) under FoundationVIO's own protocol, attributing this gap to their re-implementation but offering no root-cause explanation ("we have no explanation for the difference" is stated elsewhere regarding a separate depth-model/input discrepancy in Appendix H) — suggests some baseline reproduction uncertainty.
- **Compute cost not benchmarked against resource-constrained deployment — inferred.** Table 6 shows Accord uses 11.1 GB GPU and requires an RTX 4090 with a "Giant" backbone; this is far from being deployable on an actual smartphone despite being marketed for "everyday devices" — the phone data was collected by phones but processed offline on a desktop GPU, which the text doesn't contradict but also doesn't address directly (not addressed in the paper whether/how this could run on-device).
- **Each sequence result averaged over only 3 runs — inferred as a modest statistical base.** Given stochastic elements (dropped windows when the GPU worker is busy, live playback timing), 3 runs is a thin sample for reporting "mean" scores with no variance/confidence intervals shown in the main tables.
- **Missing ablation on the cross-window agreement correction in isolation — inferred.** Table 4's ablation adds "anchor" then "context keyframes" cumulatively, but does not show the correction step's (Sec 4.2) contribution in isolation separately from the anchor — it's unclear how much of the overall gain versus DAVIO baseline is attributable specifically to the headline "Accord" cross-view agreement mechanism versus the anchor alone.
