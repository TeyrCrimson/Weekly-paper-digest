# UniMetric: Universal Metric Scale Recovery for Visual Geometry Foundation Models

**Authors:** Lei Yang, Yuner Zhang, Ziyang Liu, Ziying Song, Kai WU, Yiyang Gao, Jiangtao Su, Yiming Li

**arXiv:** [2610.16945](https://arxiv.org/abs/2610.16945)

**Categories:** cs.CV

**Submitted:** 2026-10-12

**Relevance:** 9/10 — matched: Metric and temporally-consistent monocular depth

---

## TL;DR
UniMetric is a training-free method that recovers absolute metric scale for visual geometry foundation models (GFMs) by querying a vision-language model for plausible object height ranges, measuring those same objects' heights in the model's (unitless) 3D reconstruction, and solving a convex optimization to find the single scale factor that best reconciles all these constraints. Applied uniformly to a model's point cloud and camera translations, it cuts mean depth error, 3D reconstruction error (Chamfer distance), and camera trajectory error by 54–84% across nine GFMs and twelve benchmark subsets, without any sensors or retraining. The authors also release MetricBench, a new evaluation suite designed specifically to expose scale errors rather than hide them via standard alignment tricks.

## First-principles breakdown

**The underlying problem.** Modern "geometry foundation models" (GFMs) — VGGT, π3, Depth Anything 3, etc. — take a video or set of images and output 3D structure (per-pixel depth/points) and camera poses, all in one shared but *arbitrary* unit of length. That is, the model might correctly say "object A is twice as far as object B" but has no idea whether that distance is 2 meters or 2 kilometers. This is a core limitation inherited from how these models are trained (relative geometry from multi-view images, no metric ground truth baked in). For robotics, embodied AI, or using internet videos to train "embodied" foundation models, you need distances in real physical units (meters), not an arbitrary scale.

**Why prior fixes don't work here.** Two standard routes exist: (1) add a metric sensor (LiDAR, stereo depth, IMU) to directly observe true scale — but this requires special hardware not available for arbitrary internet video; (2) train a separate "metric depth" model on datasets with ground-truth distances (e.g., ZoeDepth, UniDepth, Metric3D) — but these models just encode the scale statistics of whatever training data they saw, don't generalize to unseen GFMs/scenes without retraining, and still require curating metric-labeled data. The paper wants a third route: recover scale directly from the *content* of the scene and the GFM's own output, with no new sensors or training.

**Core insight.** Individual object sizes are uncertain (e.g., "a car is somewhere between 1.4 and 1.8 m tall") but not useless. If you look at many objects in a scene — a car, a pedestrian, a door — and ask "what scale factor would make all of these simultaneously plausible," the overlapping constraints narrow down the possible scale far more than any single object could. This is analogous to triangulation/survey calibration: many noisy measurements, averaged correctly, converge on the truth. The paper even proves this formally (Proposition 1): if you have many independent, zero-mean-error scale estimates from different objects, their average's mean-squared error shrinks as 1/N with more observations — i.e., it's a consistent estimator.

**The three-stage mechanism:**
1. **Metric Prior Acquisition** — Feed each video frame to a vision-language model (Seed1.8), which identifies familiar objects (cars, people, doors), returns a plausible height *interval* (not a single number — e.g., "1.4–1.8 m") plus a confidence score, and identifies the dominant ground/support surface. A segmentation model (SAM 2.1) then converts these boxes into precise pixel masks.
2. **Semantic–Geometric Alignment** — This connects the VLM's "real-world" guess to the GFM's "unitless" reconstruction. Using the GFM's predicted camera pose, the object's and the support surface's pixels are projected into 3D points. A plane is fit to the support-surface points per frame to get a "vertical" direction (important because the GFM's camera axis isn't guaranteed to align with gravity). The object's height is then measured as its extent along that direction, in the GFM's native unit. Dividing the VLM's known real height interval by this measured unitless height interval gives a *candidate range of scale factors* that would make this one object's height correct.
3. **Global Scale Recovery** — Every object/frame observation contributes one interval of "acceptable" scale factors, weighted by VLM confidence and an object-category reliability score. The method then solves a 1D convex optimization: find the scale value that minimizes the total squared "distance" to all these intervals (zero penalty if inside an interval, squared distance to the nearest edge if outside). If all intervals overlap, the optimal solution sits in that overlap (fully consistent); if they conflict, it finds the best compromise. This is solved cheaply via golden-section search over a single scalar.

The final scalar is applied identically to all 3D points, depth maps, and camera translation vectors (not rotations/intrinsics), so the whole reconstruction — static scene plus camera path — gets converted to metric units with one factor, without ever retraining the GFM.

**Why this validation is tricky (MetricBench).** The standard way papers evaluate monocular/GFM depth is to align predicted and ground-truth scale first (median scaling or full similarity-transform fitting), which by construction erases any scale error before measuring remaining error. That approach can't tell you whether a model's *raw* scale is right. MetricBench instead evaluates on twelve real-sensor-referenced subsets (driving, roadside, embodied robots) using rigid (rotation+translation only, no scale-fitting) alignment, so scale errors remain visible in the metrics (Abs Rel, Chamfer distance, trajectory ATE).

## Key insights

- **Genuinely new idea**: using uncertain, open-vocabulary VLM-derived object size priors as a *joint* calibration signal for scale, rather than as single confident references (as in older SLAM work using fixed category height priors) or as training signal for a dedicated metric-depth network. The novelty is the "many weak/uncertain constraints jointly narrow down one shared unknown" framing plus the convex interval-reconciliation formulation.
- **Claimed vs. evidenced contributions**: 
  - The theoretical claim (averaging reduces error under zero-mean, uncorrelated, bounded-variance error assumptions) is a clean but idealized math result — it's evidenced only by a *controlled* experiment with exact relative heights (ground-truth hi), not by the full real-world pipeline. This isolates semantic-prior noise from reconstruction noise, which is a reasonable experimental design choice, but means the headline math result doesn't directly characterize real-world performance.
  - The benchmark-level claim ("improves every one of 9 models on 3 tasks across 12 subsets") is well-supported by extensive tabulated results (108 model-subset depth pairs, 107/108 CD pairs, 81/90 ATE pairs improved) — this is the strongest, most evidenced part of the paper.
  - Ablations (Table 8) support the specific design choices: keeping intervals rather than collapsing to midpoints, weighting by confidence/category reliability rather than uniform weights, and combining multiple anchors rather than relying on one — all show measurable accuracy drops when removed/simplified. This is solid internal validation.
  - Comparison against metric-depth baselines (Table 7) — UniMetric beats Depth Pro, UniDepth v2, Depth Anything V2, ZoeDepth on calibrating the same GFM output on 2 subsets (nuScenes, FusionPortable) — but it's only tested on 2 of 12 subsets, so it's a narrower piece of evidence than the main benchmark result.
- The method is explicitly presented as "universal" (works across 9 different GFM architectures) and "training-free" — both are directly demonstrated by the breadth of the model comparison.

## Caveats — stated and inferred

- **Stated**: The method "depends on the quality of semantic priors and reconstructed object measurements, including the availability of anchors with measurable heights" — i.e., scenes without recognizable, measurable familiar objects (or with heavily truncated/occluded ones) won't work. (stated)
- **Stated**: "A shared scale corrects global scale discrepancies but cannot resolve local geometric distortions or trajectory drift" — e.g., it can't fix a wrong rotation, bad relative geometry, or trajectory shape errors; it only rescales. The paper's own results confirm this: on DROID (near-static camera) and two other model-subset pairs, ATE actually got slightly worse after correction, and in one case (π3 on DROID) Chamfer distance increased slightly. (stated)
- **Oracle gap acknowledged**: Table 7 shows an "Oracle" that fits scale separately per metric via ground truth still substantially outperforms UniMetric (e.g., δ1 82.0% vs 92.9% on nuScenes), meaning there's a real, acknowledged gap to the best-possible single-scale correction. (stated, via their own oracle comparison)
- **Dependency on a specific, large proprietary/large VLM and segmentation model** (Seed1.8 + SAM 2.1): the paper doesn't test with smaller/open VLMs or ablate VLM choice, so it's unclear how much of the benefit depends on using a strong, likely large/expensive VLM for height elicitation. (inferred)
- **Hand-crafted prompt augmentation per dataset**: the paper notes "CEAR and FusionPortable prompts additionally include category-size tables" and "VGGT-Ω uses dataset camera intrinsics on 3EED" — meaning the pipeline is not fully uniform/off-the-shelf across subsets; some scene-specific prompt engineering or metadata injection is used, which could inflate benchmark numbers on those subsets relative to a truly zero-touch deployment. (inferred)
- **No live/zero-shot deployment test on "Internet videos"**: despite motivating the work via "using Internet videos for embodied pretraining," all evaluation is on curated, sensor-referenced academic datasets (KITTI, nuScenes, Waymo, etc.) with controlled camera/scene conditions — the actual target use case (arbitrary web video) is untested. (inferred)
- **The theoretical consistency result (Proposition 1) requires i.i.d.-like idealized assumptions** (zero-mean, pairwise-uncorrelated, bounded-variance errors) that likely don't hold exactly for real VLM biases (e.g., systematic over/under-estimation of certain object categories), and the paper's own controlled study only varies budget up to 50 observations with still-nontrivial residual error (1–2% MARE), not a proof the assumptions hold in practice. (inferred, though the controlled experiment partially stated this limitation implicitly by showing diminishing/uneven returns across subsets)
- **Fictional/implausible citation flag**: the paper repeatedly references "GPT-6 Astra" (OpenAI, 2026) as real, current, deployed technology — this is not a verifiable or presently-existing model as of the knowledge available here, which raises a question about the paper's real-world grounding/dating of its motivating context (possibly a forward-looking or placeholder citation). This doesn't invalidate the technical method but is worth flagging. (inferred)
- **No failure-mode statistics beyond isolated examples**: the paper shows aggregate suite improvements and a handful of qualitative failure cases (DROID stationary camera, CEAR/Humanoid Everyday ATE regressions) but doesn't systematically quantify how often/why the method fails or by how much in the worst case beyond these anecdotes. (inferred)
