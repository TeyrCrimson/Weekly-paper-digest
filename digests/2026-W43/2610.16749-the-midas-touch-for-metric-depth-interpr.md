# The Midas Touch for Metric Depth: Interpretable Metricization for Generalizable Depth Perception

**Authors:** Mengtan Zhang, Yu Ma, Shiqi Jiang, Yi Feng, Wei Ye, Xieyuanli Chen, Hanli Wang, Qijun Chen, Rui Fan

**arXiv:** [2610.16749](https://arxiv.org/abs/2610.16749)

**Categories:** cs.CV

**Submitted:** 2026-10-12

**Relevance:** 9/10 — matched: Metric and temporally-consistent monocular depth

---

## TL;DR
MTDv2 is a hybrid framework for converting foundation-model relative depth maps into accurate metric depth using sparse observations (LiDAR, RGB-D, stereo correspondences), combining a training-free explicit "segment-wise affine transformation + geodesic depth propagation" algorithm with a learnable neural refinement stage built on the same geometric principles. It extends the authors' earlier CVPR work (MTD) by adding data-driven multi-path propagation and depth-aware segmentation, aiming to keep the interpretability of explicit methods while closing their accuracy gap to deep networks. Experiments across 16 public datasets report state-of-the-art zero-shot depth completion and strong results on downstream novel-view-synthesis and visual-odometry tasks.

## First-principles breakdown

**The core problem.** Monocular foundation models (MiDaS, Depth Anything) predict *relative* depth — correct up to an unknown, spatially-varying scale and shift — because they're trained on mixed datasets without consistent metric ground truth. Many robotics/AR applications need *metric* (absolute, in meters) depth. You typically have a few sparse ground-truth metric measurements (LiDAR points, RGB-D pixels, stereo matches) and want to use them to "lift" the dense relative depth map into a dense metric one.

**Why existing approaches fail.**
- *Global affine fitting*: fit one scale `a` and shift `b` (depth_metric = a·depth_relative + b) over the whole image using least squares against the sparse points. Problem: the true relative-to-metric relationship actually varies locally (different objects/materials cause the network's relative predictions to deviate differently from true depth), so one global transform is too rigid.
- *Data-driven depth completion networks*: feed the RGB image + sparse points into a CNN/transformer trained end-to-end. Problem: these networks are sensitive to how sparse/dense/noisy/unevenly distributed the input points are, and they don't reliably generalize the relative-depth geometric prior that foundation models already learned — e.g., they can fail badly when sparsity patterns differ from training, and their accuracy still depends on ad hoc preprocessing (e.g., morphological densification) that introduces its own errors.

**MTD(v2)'s mechanism, step by step:**

1. **Segment-wise affine scale recovery.** Divide the image into superpixel-like local segments using *both texture and relative-depth cues* (not just texture, as in the original MTD) — this keeps segments geometrically coherent so a single affine transform per segment is a good approximation. For segments containing enough sparse metric observations ("qualified" segments), solve a per-segment weighted least-squares fit of `a,b` against the sparse points (Eq. 1).

2. **Propagating scale to unobserved segments.** Segments without any sparse points ("unqualified") can't fit their own `a,b`. The paper builds a bipartite graph connecting each unqualified segment to its K nearest qualified segments (by centroid distance), with edge weights that decay exponentially with distance (Eq. 2). The unqualified segment's `(a,b)` is then a weighted average of its qualified neighbors' parameters (Eq. 3) — essentially a smooth interpolation of scale across the scene.

3. **Pixel-level refinement via "geodesic" dynamic programming.** After segment-wise metricization you get a coarse metric map, but exact sparse observations aren't perfectly honored at their own pixels, and segment boundaries can show discontinuities. The paper models local depth propagation error using a first/second-order Taylor approximation: propagating depth from one pixel to its neighbor via a local surface model incurs an error bounded by the integral of local curvature (`ϕ = sqrt(z_uu² + z_vv²)`) along the path. This defines a "geodesic cost" between any sparse-observation pixel and target pixel — basically, "cost of propagating depth along a path = accumulated local surface curvature," so flat, smooth paths are cheap and highly curved/discontinuous paths are expensive. They use dynamic programming (similar to shortest-path algorithms) to find, for every pixel, the minimum-cost path back to an observed pixel, then propagate depth values along these optimal paths using local surface modeling (gradient + Hessian), iteratively fusing propagated and current depth estimates (Eqs. 9–11). This is the "single-path" explicit refinement, inherited from MTD.

4. **Data-driven multi-path refinement (the actual new MTDv2 contribution).** The explicit pipeline above is limited by handcrafted surface models and hard "pick-one-best-neighbor" propagation rules, which struggle on thin structures and complex geometry. MTDv2 adds a neural network that: (a) extracts textural features from the RGB image and geometric features from the explicitly-metricized depth + sparse observations, (b) predicts *residual corrections* to the geodesic cost and to the propagated depth (rather than predicting depth from scratch) — this keeps the network "on rails" of the interpretable formulation, and (c) predicts "propagation logits" that turn the previous single best-neighbor choice into a softmax-weighted combination over all 8 neighbors (Eq. 14) — i.e., a "soft"/multi-path version of the same propagation idea, aggregating depth proposals from multiple directions instead of committing to one. Finally, a predicted per-pixel "anchoring confidence" re-asserts the known sparse observations into the refined map at each iteration (Eq. 16).

5. **Training without expensive dense ground truth.** Since the explicit stage already gives a dense, reasonably-scaled depth map, the network doesn't need to learn metric scale from scratch — it only needs to learn *residual* corrections. This lets them train on large amounts of unlabeled real images using pseudo-labels generated by another metric depth model (MoGe-2), because the pseudo-labels' own errors/biases are implicitly accounted for through the same explicit-refinement process at training time (train/test consistency argument), rather than requiring accurate real dense ground truth.

## Key insights
- **Claimed and plausibly well-supported**: combining an interpretable, training-free geometric algorithm with a complementary learned residual-correction stage can outperform either explicit-only (MTD) or black-box data-driven depth completion networks, especially under extremely sparse/noisy/non-uniform observations — the paper reports consistent gains on 16 datasets and degradation patterns (prior methods fail more on challenging datasets like ScanNet/HAMMER/nuScenes) that support the "robustness under sparsity" claim.
- **Novel idea with genuine mechanistic grounding**: recasting local depth propagation as a geodesic-cost shortest-path problem derived from a provable error bound on first-order surface approximation (Eq. 4–7) is a legitimate theoretical anchor, not just a heuristic — and extending it to a learnable "soft multi-path" version (rather than discarding the geometric formulation for an opaque network) is the paper's central architectural novelty over MTD v1.
- **Training-data trick**: using pseudo-labels from an existing metric depth model plus the "explicit-refinement applied identically to pseudo-labels and real sparse observations" argument to justify supervision without expensive real dense ground truth is a reasonably clever way to sidestep the usual synthetic-to-real domain gap — but note this makes the learned component's quality ceiling partly bounded by the pseudo-labeling model's (MoGe-2) own biases, which isn't deeply interrogated.
- **Evidence support vs. claims**: the paper demonstrates gains in RMSE/MAE across many datasets and also shows applicability to stereo-matching-style correspondence inputs and two downstream tasks (NVS, VO). However, the magnitude of the "up to 47.5% RMSE reduction" figure is an aggregate/best-case number across a range (4.0–47.5%), and the text itself notes at least one dataset (DDAD) where RMSE *increased* relative to baselines despite MAE improving — i.e., the improvement is not universally monotonic across all metrics/datasets.

## Caveats — stated and inferred

- **Computational cost — `stated`**: inference time breakdown shows relative-depth backbone + refinement-network backbone together account for ~50% of total inference time, and the paper explicitly says "computational efficiency of MTDv2 remains limited," with segment-wise scale recovery running on CPU only (no GPU acceleration) and the propagation head adding "substantial inference overhead."
- **Fragility to bad relative-depth estimates — `stated`**: the explicit refinement preserves the initial geometric structure from the relative-depth network, so if that network produces errors (e.g., under poor illumination, shown in their own failure case Fig. 7b), the error propagates through and is not corrected by either MTD or MTDv2; the data-driven stage helps only when similar failure conditions are represented in training data.
- **Dependence on accurate extrinsic calibration — `stated`**: the method assumes accurate camera–range-sensor calibration as provided by public datasets; real-world calibration drift from mounting/mechanical changes is explicitly flagged as unaddressed, with the authors pointing to future integration of online calibration methods.
- **Mixed result on at least one dataset — `stated`**: on DDAD, MTDv2 shows a slight RMSE increase versus baselines even though MAE improves, meaning some larger errors may persist; this is acknowledged but not deeply analyzed.
- **Pseudo-label training dependency — `inferred`**: the learned refinement head is trained using pseudo depth labels generated by a single external model (MoGe-2) rather than real ground truth; the paper argues this is acceptable because of the "consistent discrepancy" logic, but no direct ablation is shown comparing training against real dense ground truth vs. pseudo-labels, so the extent to which pseudo-label biases leak into the learned component is not independently verified.
- **Retraining of some baselines, not others — `inferred`**: PromptDA is explicitly retrained under the same setting for fairness, while other baselines (CFormer, BP-Net, LRRU, DMD3C, Marigold-DC) are evaluated using official/released weights; since training data and conditions differ across these baselines (and DMD3C's training data reportedly already includes nuScenes, one of the evaluation datasets), the comparison setup is not perfectly matched across all methods, which could favor MTDv2 to an unclear degree.
- **Ablation/benchmark selection — `inferred`**: the 16-dataset evaluation is extensive, but the detailed ablation study (component-wise contributions, propagation step count, sensitivity to density) is referenced only in sections not fully included in the provided text excerpt; the degree to which each specific architectural choice (soft multi-path vs. single path, residual geodesic-cost correction, geometry-aware superpixels) independently contributes is asserted qualitatively in the discussion but the quantitative ablation tables were not visible in the given text.
- **No real-time or embedded deployment evaluation — `inferred`**: given the stated ~50% inference time in backbone computation and reliance on CPU-only superpixel segmentation, the method's practicality for latency-sensitive robotics/AV applications (a motivating use case in the introduction) is not demonstrated — not addressed in the paper beyond the stated efficiency limitation.
- **Hyperparameter sensitivity — `inferred`**: several scaling factors (ρ_z, ρ_ϕ, λ_ϕ, ϵ, η_t schedule, K-nearest-neighbor count) are fixed by the authors without a reported sensitivity analysis in the provided text, raising the question of how tuned these are to the specific benchmarks used.
