# Decomposed Entailment for Factuality Checking and Hallucination Detection

**Authors:** Achir Oukelmoun, Nasredine Semmar, Gaël De Chalendar

**arXiv:** [2608.05823](https://arxiv.org/abs/2608.05823)

**Categories:** cs.CL

**Submitted:** 2026-08-06

**Relevance:** 9/10 — matched: Post-inference detection and repair of degenerate output

---

## TL;DR
HallDetect decomposes LLM-generated text into atomic claims and verifies each against a multi-granularity library of source chunks using a compact DeBERTa-v3 NLI model, aggregating scores so a single confidently contradicted claim flags the whole response. Under a controlled protocol where all methods use the same 4-bit quantized backbones and consumer GPU budget, it beats comparably-resourced baselines on 3 of 4 benchmarks while showing much lower variance across model families than generative "LLM-as-judge" approaches. The authors explicitly do not claim it beats full-precision or API-based state-of-the-art detectors, only comparably-resourced ones under a frugal compute budget.

## First-principles breakdown

**The problem.** LLMs sometimes generate content unsupported by (or contradicting) their source document — "hallucinations." Detecting this automatically matters because many LLMs are black-box APIs (no internal access), and using another LLM as a judge is expensive, slow, and hard to reproduce, plus judges can favor outputs that resemble their own style ("self-preference bias"). Cheap surface metrics (ROUGE, embedding similarity) don't capture logical contradiction — a sentence can be lexically close to the source yet assert the opposite.

**Why checking the whole response at once fails.** If you feed the entire generated response and the entire source document into one classifier and ask "does this doc entail this response," a single false sentence buried among many true ones gets averaged out — the model sees mostly-consistent content and the local error is diluted. This is the "dilution effect" the paper repeatedly demonstrates.

**The fix: decompose then verify locally.** This isn't new — the paper builds on prior "decomposition-based factuality" work (FActScore, PropSegmEnt, ACUEval, SummaC). The idea: split the response into individual atomic claims (one factual assertion each), then check each claim independently against the source. HallDetect's specific combination of design choices:

1. **Phase I — Claim extraction (generative).** A quantized LLM (Llama-3.1/Gemma-2/Mistral, 4-bit) reads the response and outputs up to `min(10, 4×sentences)` atomic claims, copied verbatim (not paraphrased) so the checker verifies what was actually said, not a cleaned-up version.

2. **Phase II — Multi-scale chunking (of the source, not the response).** The source document is split into chunks at 5 granularities (1, 2, 4, 8, 16 roughly-equal pieces), doubling each time ("dyadic"). Why: evidence for a claim might be one sentence, or might be spread across a whole section — you don't know in advance at what "zoom level" the relevant support (or contradiction) will be most visible. Checking at only one scale (e.g. whole-document) is exactly what causes the dilution problem above. This produces up to 31 overlapping chunks total, regardless of document length — bounding cost.

3. **Phase III — Contrastive NLI verification (discriminative, not generative).** For each claim, a small (435M-parameter) DeBERTa-v3 model fine-tuned for natural language inference (NLI — the standard 3-way classification task: does premise entail/contradict/stay neutral toward hypothesis) scores every (chunk, claim) pair. Instead of running the claim against every chunk and averaging, HallDetect independently finds (a) the single chunk that most strongly *entails* the claim and (b) the single chunk that most strongly *contradicts* it, and takes the difference: `Score = max_entailment_prob − max_contradiction_prob`. This means one supportive sentence anywhere is enough to count as support, and separately, one contradicting sentence anywhere is enough to count as contradiction — the two searches are decoupled. "Neutral" claims (no chunk strongly supports or contradicts) score near zero, which the paper treats as "unsupported addition" rather than "contradicted."

4. **Phase IV — Aggregation (asymmetric).** Per-claim scores are combined via geometric mean into a final "FED score" (Factuality Entailment Decomposition score). Crucially, if *any* single claim has a non-positive score (contradiction ≥ entailment), the whole geometric mean is forced to 0, meaning the response is flagged as hallucinated (FED score = 1) regardless of how well-supported everything else is. This encodes an "auditing" philosophy: one confident lie should sink the whole output, mirroring how a human fact-checker would treat it.

**Why it's called "frugal."** The only autoregressive (expensive, slow, token-by-token) generation happens once, and only over the short response text (≤512 tokens) for claim extraction — the long source document is never fed into a generative model. All source-verification work goes to the small 435M NLI encoder doing single non-autoregressive forward passes (<1GB VRAM), run in parallel with extraction on one consumer GPU. Competing baselines like generative chain-of-thought judging must read the *entire* long document generatively, and SelfCheckGPT-style consistency checking requires 5 separate full generations — both far costlier.

**Evaluation setup.** Everything — including the baselines (a plain document-level NLI check, a CoT LLM judge, SelfCheckGPT-style consistency scoring, and a raw embedding-similarity score) — is run at matched 4-bit quantization on the same three backbone families, tested across four benchmarks: news summarization (QAGS-CNN/DM), dialogue (TofuEval), adversarially perturbed summaries (FalseSum), and biomedical QA (PubMedQA).

## Key insights

- **What's genuinely new:** the specific combination of (a) generative atomic-claim extraction, (b) independent best-entailment/best-contradiction search over a *multi-scale* chunk library (rather than one fixed granularity), and (c) an asymmetric, single-contradiction-sinks-it aggregation rule. The authors are explicit that each individual ingredient (decomposition, NLI verification, multi-scale chunking) has precedent — the novelty is the combination and the "reference-free, black-box, low-compute" packaging.
- **The evidence supports:** stability across backbone families — HallDetect's F1 stays in a narrow 0.734–0.771 band on the primary benchmark while the generative CoT baseline swings wildly (0.321–0.589 F1) depending on backbone, suggesting discriminative encoder-based verification is more robust to quantization noise than autoregressive reasoning. It also supports the "dilution effect" claim: a monolithic (non-decomposed) NLI baseline has much higher precision but far lower recall than HallDetect on QAGS-CNN/DM, consistent with localized errors being averaged away when checked holistically.
- **The evidence does NOT clearly support:** general superiority — wins are only 3 of 4 benchmarks (weak/marginal on TofuEval; loses to simpler embedding/consistency baselines on PubMedQA), and results reflect one specific operating point (0.5 threshold) that favors a recall-heavy method on high-hallucination-rate datasets. The claim-level "audit trail" is illustrated only qualitatively (one worked example in an appendix), not validated quantitatively against ground truth.
- Positioning is scoped carefully by the authors: no claim of beating full-precision or API-based state-of-the-art detectors, nor beating the closest discriminative competitor (MiniCheck), which is explicitly *not* compared against.

## Caveats — stated and inferred

- **No comparison to closest competitors (stated):** MiniCheck, SummaC, and QAFactEval — the discriminative detectors most similar in spirit and budget — are discussed but never empirically benchmarked; the authors call a MiniCheck comparison "the single most important next experiment."
- **Confounded ablation (stated):** the "monolithic NLI" baseline differs from HallDetect in *both* decomposition and multi-scale chunking simultaneously, so the paper cannot isolate which factor drives the recall gains it attributes to "decomposition."
- **Recall-oriented threshold, no PR/AUROC curves (stated):** the asymmetric aggregation is deliberately biased toward flagging, pushing recall to 0.95–1.0 at moderate precision; only a single fixed 0.5 threshold is reported, which the authors admit flatters the method on high-hallucination-base-rate datasets. No threshold-free analysis is given.
- **Efficiency claims are architectural, not measured (stated):** parameter counts, VRAM, and pass counts are reported, but no actual wall-clock time or energy measurements — so the "frugality" advantage over e.g. a single long-context LLM call with KV caching is asserted, not demonstrated.
- **Single deterministic runs, no variance/significance testing (stated):** all reported numbers are from one run each; no confidence intervals or repeated-run variance are given, despite the paper's own emphasis on "stability" as a key selling point.
- **Backbones are dated (stated):** Llama-3.1, Gemma-2, and Mistral-7B are all 2024-era models; no testing on newer model families.
- **Weak absolute performance on some domains (stated):** TofuEval results are low for every method tested (best F1 0.362), and on PubMedQA simpler embedding/consistency baselines sometimes match or beat HallDetect — the authors attribute this to backbone prior knowledge rather than genuine grounding, but this is speculative.
- **Only intrinsic hallucinations covered (stated):** the method can't verify claims requiring external world knowledge (extrinsic hallucinations), since it only checks against the supplied source document.
- **Claim-level audit trail not quantitatively validated (inferred):** the "claim-to-span localization" contribution is demonstrated via one hand-picked worked example in an appendix rather than evaluated against any claim-level ground truth, despite being listed as a main contribution.
- **Anonymized/unverifiable code release (inferred):** the code link is to an anonymous review host, so independent reproduction isn't currently possible from the paper alone.
- **English-only, single-domain-style benchmarks (stated in Ethics section):** all datasets are English; generalization to other languages is unaddressed.
- **Coreference is called out as the main failure mode (stated):** chunking can sever pronouns from distant antecedents, propagating spurious contradictions — a structural weakness of the chunking approach that isn't otherwise mitigated.
