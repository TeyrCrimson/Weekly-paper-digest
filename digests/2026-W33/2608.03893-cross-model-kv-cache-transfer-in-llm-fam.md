# Cross-Model KV Cache Transfer in LLM Families: A Closed-Form Linear Mapping for Prefill Reuse

**Authors:** Taekyung Heo, Rasoul Shafipour, Ritchie Zhao, Maximilian Golub, Mohammad Mahdi Kamani, Ritika Borkar, Makesh Tarun Chandran, Pantea Zardoshti, Bita Darvish Rouhani

**arXiv:** [2608.03893](https://arxiv.org/abs/2608.03893)

**Categories:** cs.LG

**Submitted:** 2026-08-04

**Relevance:** 9/10 — matched: LLM inference efficiency and long-context serving

---

## TL;DR
This paper shows that KV caches from different-sized models within the same LLM family (e.g., Qwen3 14B and 32B) share substantial linear structure, and exploits this with a closed-form, gradient-free per-head ridge regression mapper that lets a "target" model reuse a "source" model's prefill KV cache instead of recomputing it. On 4 of 6 tested model pairs the mapper retains 73–98% of standalone accuracy while running 2.7–25× faster than re-prefill; on the 2 failing pairs, swapping in a small nonlinear MLP recovers up to +37pp accuracy.

## First-principles breakdown

**The problem.** In production LLM serving, systems often route a request between different-sized models in the same family — e.g., start cheap on an 8B model and escalate to a 32B model mid-conversation for quality, or cascade down for cost savings. "Prefill" is the initial forward pass over the prompt/context that builds the KV (key-value) cache used for attention during generation — it's expensive and scales with model size and prompt length. Normally, every time you switch models, the new model has to redo this entire prefill pass from scratch, even though the old model just did (almost) the same computation. Prefix caching only helps within one fixed model, not across a swap. The paper asks: can the receiving model just directly reuse the sending model's already-computed KV cache, skipping prefill entirely?

**Why this is hard.** Different model sizes in a family have different numbers of layers, and their internal representations are not identical — so you can't just copy layer *l*'s KV in the small model to layer *l* in the big model. Prior work (C2C, LatentAlign, IAM, DroidSpeak) addresses this with trained neural networks (fusers, adapters, attention-pattern substitution) or require identical architectures — all needing gradient-based training or strong constraints. This paper instead asks a more basic question: is the relationship between source and target KV values *linear enough* that a simple regression, fit on a small calibration set with no backprop, would work?

**The key empirical finding (§2.3).** They restrict to "matched-KV" pairs — source and target share the same number of KV attention heads and same per-head dimension (common in a model family even as depth/width scale). Using ordinary least-squares probes, a *single* source layer already explains 56% of variance (R²) in the target's keys and 32% in values on Qwen3 14B→32B; using several source layers jointly bumps this to 79%/65%. This is much higher linear structure than one might expect, and motivates a linear (not deep-learned) mapper.

**The mapper, three components (§3):**
1. **Per-head ridge regression.** For every (target layer, target head), fit an independent linear map from concatenated source KV features to target KV features: `Ŷ = XW + b`. Ridge regression (L2-regularized least squares) is used instead of plain OLS because the input feature matrix is large and correlated (top-k source layers are similar to each other), making OLS numerically unstable; ridge's regularization term stabilizes the matrix inversion. This has a closed-form solution `W* = (XᵀX + λI)⁻¹XᵀY` — no gradient descent needed.
2. **Cross-layer source selection.** Since source and target have different layer counts, each target layer picks its own "top-k most predictive" source layers (by R²) and concatenates their KV as the regression input, rather than using a fixed 1:1 layer mapping. This turned out to be the single largest contributor to mapper quality.
3. **Content-space (RoPE-stripped) mapping.** RoPE (Rotary Position Embedding) rotates keys based on token position before they're cached. This positional rotation is arbitrary/model-specific and pollutes the linear fit. The mapper strips RoPE from source keys (an exact, cheap operation since the rotation is orthogonal), does the linear mapping in this "content-only" space, then re-applies the target's own RoPE rotation at the target's positions. This decouples the fit from the specific context length/position distribution used during calibration, so it generalizes to longer contexts than were seen during fitting.

**Fitting procedure.** Calibration uses only 500 short text sequences (1024 tokens each) from FineWeb-Edu — no labels, no downstream task signal, just matching KV activations between the two models on the same text. Fitting takes under 1.5 hours on one 8×H100 node with zero gradient-based training.

**Why it sometimes fails, and the fix (§4.4–4.5).** They find that R² (how well the linear fit reconstructs KV values) does NOT reliably predict downstream task accuracy across pairs — two pairs with identical calibration R² can have wildly different retention. The reason: attention doesn't weight all KV error equally — it reads keys/values through the query projection and softmax weighting, so error that lands in "attention-sensitive" subspaces (measured via a new "error concentration" metric, and via cosine similarity between mapped and ground-truth attention outputs) hurts accuracy much more than error of the same magnitude elsewhere. Attention-output cosine similarity correlates with downstream retention (Pearson r=+0.57) far better than R² (r=−0.20). On pairs where linear ridge fails badly, replacing it with a small nonlinear MLP (2 hidden layers, otherwise same fitting setup) doesn't reduce error more in aggregate, but redistributes the error away from attention-sensitive subspaces, recovering up to +37pp accuracy.

## Key insights

- **Genuinely new finding:** cross-model KV caches within a family have strong linear structure — this hadn't been shown before and is the empirical foundation that makes a training-free (no backprop) mapper viable at all. This is well-supported by the R²/heatmap evidence (§2.3, Appendix B).
- **Genuinely new mechanism:** the combination of top-k cross-layer source selection + RoPE-stripped content-space fitting + per-head ridge is simple, closed-form, and cheap to fit (~1 hr, no GPUs needed for gradients), which is a real practical advantage over prior neural-fuser approaches (C2C, LatentAlign) that need gradient training per pair.
- **Genuinely new diagnostic:** attention-output cosine similarity as a better cross-pair predictor of transfer quality than reconstruction R². This reframes how to evaluate/screen KV-transfer mappers — a useful conceptual contribution even though it's currently only computable *after* fitting (a stated limitation, see below), not a true a priori predictor.
- **What's supported vs. overclaimed:** the "practical" framing is supported for 4 of 6 tested pairs (73–98% retention, big latency wins). But 2 of 6 pairs (both Ministral, larger depth/capacity gaps) fail badly with the linear mapper (42–44% avg retention) and only partially recover with an MLP add-on — so "cross-model KV cache transfer transfer is practical" is a claim that holds conditionally, not universally, and the paper is reasonably transparent about this tiered outcome.
- The multi-turn (CoQA) and latency results are a genuine practical validation beyond single-shot benchmarks, showing the approach doesn't obviously degrade over many turns of repeated handoff (within the 10-turn window tested).

## Caveats — stated and inferred

- **Matched-KV precondition is restrictive** (stated): the method only applies when source and target share KV head count and per-head dimension. Mismatched-KV pairs are explicitly untested — "whether ridge transfer can succeed under mismatched-KV conditions is left to future work."
- **Scope limited to within-family, dense, full-attention models** (stated): hybrid attention (sliding-window/local) and attention-recurrent architectures (e.g., SSM-hybrid models like Nemotron 3) are explicitly out of scope.
- **Cross-family transfer untested** (stated): whether this works between different model families (e.g., Qwen3→Llama) is left as future work, not evaluated.
- **k selection uses in-sample benchmarks** (stated): the number of source layers k is chosen by sweeping and picking the value that maximizes accuracy on the same log-likelihood benchmarks (ARC-C, HellaSwag, WinoGrande, MMLU) that are then reported as results — a form of leakage. The authors quantify this (Appendix H) and bound the effect at ≤2.49pp, and add held-out benchmarks (PIQA, BoolQ, ARC-Easy) showing consistent retention, which partially mitigates but doesn't fully eliminate the concern.
- **Two of six pairs fail substantially** (stated): Ministral 3B→14B and 8B→14B retain only 42–44% average accuracy (11–15% floor-normalized) with the linear mapper — a large practical failure mode, not a minor edge case.
- **Attention-output cosine is a post-hoc diagnostic only** (stated): it requires already fitting the mapper, so it cannot be used to screen deployment candidates in advance — undermining its practical utility as currently presented, despite being framed as a key contribution.
- **Single calibration domain** (stated): calibration is done only on FineWeb-Edu; a domain-substitution test (Wikipedia, CodeAlpaca) shows some sensitivity (CodeAlpaca costs −5.24pp on HellaSwag) and the authors admit this doesn't bound narrower single-domain calibration (e.g., medical/legal text).
- **Latency measurements exclude some real-world overhead** (stated, Appendix G): synthetic-input latency isolates compute cost only; end-to-end cost of actually shipping the mapped cache to the target process is not measured. Mapper storage/loading overhead (paging 4–12GB mappers from host memory) is computed analytically, not measured (stated).
- **Small number of families/pairs (inferred):** only 3 model families and 6 pairs total are tested — a fairly narrow evidence base for a claim about general "LLM families." Generalization to other family types (different architectures, MoE, non-Mistral/Qwen/Llama lineages) is unverified.
- **Multi-turn evaluation is single-pair (stated):** the CoQA multi-turn drift experiment is run only on one pair (Qwen3 14B↔32B) for ~10 turns; the authors themselves note "linear large-to-small drift would still accumulate over very long sessions," meaning long-horizon stability beyond 10 turns is unverified.
- **No comparison against other trained baselines empirically (inferred):** the paper cites C2C, LatentAlign, IAM, DroidSpeak as prior work in a qualitative feature-comparison table (Table 6) but does not run any of them as an empirical baseline against the proposed ridge mapper on the same benchmarks — so the accuracy/speed advantage over prior trained approaches is asserted, not directly measured.
- **MLP fix is not free** (inferred): the MLP that recovers the two failing pairs still requires gradient-based training (Adam, 20 epochs) — reintroducing the training cost the closed-form method was designed to avoid, and the paper's own framing that it "combines with" the linear approach undersells that this is a departure from the gradient-free selling point for exactly the hardest cases.
