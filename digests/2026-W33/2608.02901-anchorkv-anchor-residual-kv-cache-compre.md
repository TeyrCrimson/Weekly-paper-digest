# AnchorKV: Anchor-Residual KV Cache Compression

**Authors:** Malik Khalaf, Yara Shamshoum, Nitzan Hodos, Yuval Sieradzki, Assaf Schuster

**arXiv:** [2608.02901](https://arxiv.org/abs/2608.02901)

**Categories:** cs.LG, cs.CL

**Submitted:** 2026-08-03

**Relevance:** 10/10 — matched: LLM inference efficiency and long-context serving

---

## TL;DR
AnchorKV compresses the LLM KV cache by up to 20× without evicting any tokens: each head keeps a few "anchor" tokens exactly and represents every other token as a scaled projection onto its nearest anchor, spending a byte budget on quantized residuals only for the tokens whose approximation error most affects attention output. At matched byte budgets it beats eviction methods (SnapKV, PyramidKV, AdaKV) and quantization (TurboQuant) across Llama-3.1-8B/70B and Mistral-24B on RULER, LongBench, and needle-in-a-haystack, retaining 99.3% of full-cache accuracy at 20× on the 70B model. A fused Triton kernel decodes directly from the compressed representation, giving ~19× lower decode memory and higher serving throughput.

## First-principles breakdown

**The problem.** During autoregressive decoding, a transformer must attend to the key and value vectors of every previous token. These are cached (the "KV cache") so they aren't recomputed each step. At long context lengths (e.g., 128K tokens), this cache can be as large as the model weights themselves — for Llama-3.1-8B it's 16GiB in bf16. Since the cache must be read at every decoding step and held per-request, it — not compute — limits how many requests a GPU can serve and how fast.

**Why prior approaches fail.**
- *Eviction* (H2O, SnapKV, PyramidKV, AdaKV): score each token's importance using attention statistics gathered during prefill, keep only the top-scoring subset, and permanently discard the rest. This gives unbounded compression (a discarded token costs zero bytes) but is irreversible: the scoring only sees the queries available at prefill time, and if a *later* query needs a token that was discarded, it's gone. The paper shows this is not a rare edge case — eviction baselines collapse (accuracy drops below 16%) on tasks requiring retrieval against distractors or whole-context aggregation.
- *Quantization* (KIVI, TurboQuant, KVQuant): keep every token but store it at lower bit-width. This never loses reach (nothing is discarded) but accuracy degrades sharply as bit-width drops toward 1-2 bits, capping practical compression near 5×.

**AnchorKV's mechanism.** The key idea is to decouple "is this token kept" (always yes) from "how many bytes does this token get" (variable, decided by expected impact on the output).

1. *Anchor selection.* At the end of prefill, each KV head picks k anchor positions: the most recent W tokens (a "recency window," always kept verbatim) plus a mix of high-attention-score positions (via SnapKV-style scoring — how much attention recent "observation" queries paid to each earlier token) and randomly sampled positions (for directional coverage of the vector space, since attention-selected anchors alone don't necessarily span the space well).

2. *Anchor-residual representation.* Every non-anchor token vector x_i is assigned to its most-similar anchor (by cosine similarity) and represented as a scaled copy of that anchor: γ_i · x_a(i), where γ_i is a single scalar coefficient (the projection coefficient). This costs just an anchor index + one scalar instead of a full D-dimensional vector — the residual r_i = x_i − projection is initially *dropped*. This alone is a big compression win, but introduces approximation error for tokens that don't align well with their assigned anchor.

3. *Attention-output-aware residual budgeting.* Rather than spending the remaining byte budget arbitrarily, AnchorKV computes, via a first-order Taylor expansion of the softmax attention output, how much error each token's dropped residual would introduce into the final attention output (Eq. 5–6). This "utility" score separates key-side errors (which perturb attention weights, modulated by how different that token's value is from the current output) from value-side errors (which directly perturb the output). The top-utility tokens (pooled across heads, split between key and value residuals) get a quantized 2-bit residual restored, using a randomized Hadamard rotation (to spread outlier energy across coordinates) plus a Lloyd-Max codebook (optimal quantization levels for a Gaussian-ish source after rotation).

4. *Budget accounting.* A single user knob θ (retained fraction of full cache) is translated via exact byte accounting (Eq. 9, detailed per-tensor in Appendix A.1) into how many residual "slots" a layer can afford after anchors and metadata are paid for.

5. *Guarantee.* Because no token ever leaves the softmax (unlike eviction), the compressed cache's output error is bounded (Theorem 1) as a sum of a value-error term (attention-weighted, so ignores low-attention mistakes) and a key-error term (bounded by the worst-case single key error, since one bad key can skew the whole softmax normalization). This is fundamentally different from eviction's failure mode, where a wrongly-dropped token contributes infinite error if a later query needs it.

6. *Efficient decoding.* A FlashAttention-style fused Triton kernel reconstructs keys/values tile-by-tile on the fly (never materializing the dense cache), applying RoPE to keys after reconstruction (keys are stored pre-RoPE because rotation destroys the directional similarity anchor-assignment relies on).

## Key insights

- **Genuinely new**: reframing KV compression as "how many bytes per token" instead of "keep or discard," via an anchor + residual decomposition that guarantees every token remains representable (even crudely) rather than absent. This directly targets eviction's core failure mode (irreversible loss) while pushing compression far past quantization's ceiling.
- **The output-error-aware residual allocation** (first-order Taylor/softmax-Jacobian utility score, Eq. 5-6) is a more principled criterion than raw attention score or residual norm alone — the ablation (Figure 5) shows this utility metric outperforms cosine similarity, residual norm, or attention score used individually, and the gap widens as compression tightens.
- **Evidence supports**: consistent gains over eviction and quantization baselines at matched byte budgets across 3 model scales (8B/24B/70B) and 3 benchmark families (RULER, LongBench, needle-in-haystack), with AnchorKV at 20× beating every eviction baseline at 10× — i.e., roughly a 2× effective memory advantage at equal accuracy. This is a real, reasonably broad empirical result, not a single cherry-picked setting.
- **Scale trend**: retention improves with model scale (93.5% at 8B → 99.3% at 70B on RULER-32K at 20×), which the paper argues matters because larger models are exactly where the cache is most expensive — this is a claimed and evidenced trend, though only 3 scale points support it.
- **Systems payoff**: the claimed practical benefit (19× lower decode memory, ~2× larger serving batch, 1.26× throughput gain) is backed by a real fused kernel implementation and profiling, not just an accounting estimate — though it's demonstrated only on the 8B model.
- Ablations (Figure 5) support that both anchor randomization and per-head pooled residual allocation matter, especially at tight budgets — these aren't just decorative components.

## Caveats — stated and inferred

- **No training-time interaction studied** — AnchorKV is training-free and applied purely at inference (stated), but this also means no evidence is given on how it interacts with speculative decoding, prefix caching/sharing across requests, or chunked/streaming prefill for very long contexts beyond what's tested (inferred).
- **Efficiency profiling is single-model, single-GPU** — the memory/throughput/latency results (Figure 6, Appendix E) are reported only for Llama-3.1-8B-Instruct on one A100-80GB at batch size ≤6; no efficiency numbers are given for the 70B model or multi-GPU serving setups (inferred).
- **Batch size 1 for main accuracy results** — the core accuracy comparisons (Figure 2, RULER/LongBench tables) are run at batch size 1 (stated in Section 4.1/B.1); real-world serving batches many concurrent requests with heterogeneous compression needs, and no accuracy results are given at larger batch sizes (inferred).
- **Baselines run via a third-party library (KVPress) with default settings** — eviction baselines (SnapKV, PyramidKV, AdaKV) are run through KVPress's default configuration rather than each method's original tuned settings (stated); this could understate baseline performance if the defaults are suboptimal for these specific benchmarks (inferred risk).
- **Comparison converts two different knobs (token budget vs. bit-width) into "matched bytes"** — the paper acknowledges eviction and quantization "expose incomparable knobs" and converts both to a byte-based footprint for fairness (stated), but this conversion involves modeling choices (e.g., treating discarded eviction tokens as literally zero-cost) that could favor whichever method's overhead model is more generous (inferred).
- **Theoretical error bound is a first-order/asymptotic approximation** — the utility scores (Eq. 6) rely on a first-order Taylor expansion of softmax and an "incoherence approximation" assuming per-token errors are zero-mean and independent (stated); this is an approximation, not exact, and its tightness is not directly validated against the true output error except via downstream accuracy and one appendix analysis (Appendix D.1, not shown in the excerpt) (stated assumption, inferred limitation).
- **All evaluation is on public instruction-tuned checkpoints with greedy decoding** — no sampling-based generation, no RLHF/agentic long-context workloads, and no evaluation beyond 128K context (the models' native window) are reported (inferred).
- **Fixed hyperparameters across all models/tasks** — the paper explicitly uses one configuration (W=32, k=S/128, ρ=0.7, κ=7, 2-bit residuals) for every model and benchmark (stated as a strength/simplicity claim), but no sensitivity analysis is shown for how performance would change on tasks/domains far outside RULER/LongBench/needle-in-haystack (inferred).
- **Code not yet released** — "Our code will be released upon acceptance" (stated), meaning results are not currently independently reproducible.
- **Comparison baselines are relatively recent but the field moves fast** — TurboQuant, AdaKV, PyramidKV are reasonably contemporary, but no comparison is made against other anchor/codebook-style shared-representation methods explicitly named as related work (CentroidKV, ClusterKV, CommVQ) despite being the closest prior family (inferred gap — the paper positions itself against them narratively in Related Work but doesn't benchmark against them empirically in the provided text).
