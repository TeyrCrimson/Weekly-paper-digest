# QEvict: Recoverable Quantized KV Eviction for Attention-Drift-Robust Long-Context Decoding

**Authors:** Ayushman Garg, Akshita Gupta, Shaswata Bhattacharya, Abhishek Gupta, Sandeep Kumar, Manoj Kumar

**arXiv:** [2608.05326](https://arxiv.org/abs/2608.05326)

**Categories:** cs.LG, cs.CL

**Submitted:** 2026-08-05

**Relevance:** 10/10 — matched: LLM inference efficiency and long-context serving

---

## TL;DR
KV-cache eviction methods for long-context LLM decoding make permanent, irreversible discard decisions, but the paper shows token importance drifts during generation, so useful states get thrown away and never come back. QEvict fixes this by routing contiguous windows of cached tokens across three tiers — full precision, quantized (INT2, recoverable), and evicted — letting quantized windows be "promoted" back to full precision if they become important again. Across LongBench, RULER, and GSM8K on three 7-8B models, QEvict beats matched-memory eviction baselines and stays competitive with quantization baselines at roughly half the memory.

## First-principles breakdown

**The underlying problem.** During autoregressive decoding, an LLM keeps a "KV cache" — the key and value vectors for every previously seen token — so it doesn't have to recompute attention over the whole sequence each step. This cache grows linearly with sequence length and can exceed the size of the model weights themselves at long context, which limits how many requests can be served at once (batch size) and slows inference.

**Why prior eviction approaches exist and where they fail.** One popular fix is eviction: use attention scores (a proxy for "how much the model currently cares about token i") to identify low-importance tokens and delete their KV entries, e.g. StreamingLLM (keep only "sink" tokens + recent window), H2O/SnapKV/AdaKV (keep accumulated "heavy hitters"). The core assumption behind all of these: once a token looks unimportant, it will stay unimportant, so deleting it is safe. The paper's central empirical claim is that this assumption is false — a token that seems irrelevant under the current query can become critical later (e.g., when the model needs to resolve a coreference or retrieve evidence for a new reasoning step). Because eviction is a one-way door, information lost during a "low relevance" period can never come back, even if it's needed 50 steps later.

A second, independent problem: doing eviction at the granularity of individual tokens ignores the fact that language is locally coherent (nearby tokens/sentences form entities, discourse structure, etc.). Deleting isolated tokens can shred locally-coherent context.

**Diagnostics introduced to measure this drift.** Before proposing a fix, the authors build measurement tools using a full, uncompressed ("FullKV") model run as ground truth:
- *Future Missed Mass (FMM)*: of all the attention the uncompressed model pays to a given state in future decoding steps, what fraction was assigned to states a compressed policy already threw away? High FMM = policy is discarding stuff that turns out to matter.
- *Global LIR (Late/Long-term Importance Revival)*: how often does a window that had been inactive (out of the "important" set) for a while later become important again? This directly tests the irreversibility assumption.
- *Selection Churn*: Jaccard distance between the retained-token sets at consecutive decisions — measures how jittery/unstable the eviction policy is.

Using these, they show (Section 3): (1) grouping tokens into contiguous *windows* rather than deciding token-by-token drastically reduces churn and FMM — window aggregation smooths out noisy fluctuations; (2) at a matched memory budget, plain binary eviction throws away a "middle" region of moderately-important content that a full-cache model still attends to substantially; (3) importance is mostly stable but a meaningful minority of windows do get reactivated after being inactive (deployed full-precision tier shows ~6.18% revival rate vs ~0.98% for an oracle ranking, showing the practical scoring/allocation adds noise beyond the "true" dynamics).

**The proposed mechanism — QEvict.** Instead of a binary retain/delete choice, each contiguous window of tokens is assigned to one of three tiers under a fixed total byte budget:
1. **Full precision** tier — highest-confidence/most important windows, kept exactly, always available for exact attention.
2. **Quantized (INT2) recoverable** tier — medium-importance windows, compressed to 2-bit representations but still included in attention computation (so they still contribute, just approximately) and still accumulate importance scores.
3. **Evicted** — lowest-importance windows, deleted entirely (this is the only truly irreversible action).

Periodically (every Ω generated tokens), the system recomputes a cumulative attention score per window (summed/averaged attention received across query heads and recent decoding steps), re-ranks all candidate windows (current full-precision, current quantized, and windows that just aged out of the "recent" region), and reassigns tiers via top-K selection: top Kf windows → full precision, next Kq → quantized, rest → evicted. Because quantized windows remain live and keep accumulating scores, a window that regains importance can be "promoted" back to full precision (dequantized), while one that loses importance can be "demoted." Only falling out of both the full and quantized capacity actually deletes a window — hence "recoverable eviction."

To avoid compounding quantization error every time a window bounces between tiers, QEvict uses a **write-once quantization ledger**: a window is quantized only the first time it's demoted, and that same low-bit representation is reused for all future demotions instead of re-quantizing from a reconstructed (already lossy) version.

**Engineering details.** Keys are quantized per-channel (pre-RoPE, storing original positions so rotary embeddings can be reapplied after dequantization) and values per-token, following practice from KIVI. The system uses FlashAttention-2 for standard decoding steps but falls back to SDPA (which exposes explicit attention probabilities) at prefill and routing events, since computing cumulative window scores requires seeing the actual attention weights.

## Key insights

- **Genuinely new framing**: reconceiving KV-cache management as a 3-state (full/quantized/evicted) *dynamic routing* problem with bidirectional promotion/demotion, rather than the field's standard one-shot binary eviction. This is the paper's core claimed contribution and is fairly novel relative to the cited baselines (Table 1 shows no prior method combines selective eviction + low-bit retention + window routing + dynamic recovery).
- **New diagnostics (FMM, Global LIR, Selection Churn)** are a genuinely useful contribution independent of QEvict itself — they give the field a way to quantify irreversibility harm and selection instability, which prior eviction papers apparently didn't measure directly.
- **Evidence supports**: at matched memory budgets, QEvict's macro-averages beat the strongest eviction baseline on LongBench (all six model/budget settings tested), and it's competitive with (sometimes beats) quantization-only baselines at less memory (e.g., within 1.2-1.8 points of best quantization baseline using ~half the KV memory at 10%). RULER and GSM8K results support similar trends, and gains widen as budget shrinks (5% budget), which is consistent with the claimed mechanism (recoverable tier matters most when budget is tight).
- **Ablation in Appendix K (Q→F promotion)** is the most direct causal test of the "recoverability" hypothesis: enabling promotion (vs. one-way demotion-only) improves FMM, quantized-tier score agreement, and attention-mass retention, and shows 639 actual promotion events occur — evidence the mechanism is actually exercised, not just theoretically available. However, this ablation explicitly uses "different source articles" between conditions, so the authors themselves caveat it as "directional evidence... rather than a paired estimate."
- **Efficiency claims are mixed/backend-dependent** (see caveats) — this is presented honestly rather than oversold.

## Caveats — stated and inferred

- **Backend-dependent efficiency, not a clean win** (stated): With FlashAttention-2, QEvict cuts peak GPU memory by ~29.7% but *reduces decoding throughput* (TPOT/throughput are worse than Full-KV: 146.35ms vs 59.74ms TPOT, 218 vs 535 tok/s). Only under eager/SDPA execution does QEvict improve both memory and throughput. The authors admit current kernels aren't fused and this is future work.
- **Requires exposing attention probabilities at routing events** (stated): this forces periodic fallback from FlashAttention-2 to SDPA, adding overhead — the paper acknowledges this limits FlashAttention-2 throughput and needs fused kernels to fix.
- **Fixed-size, non-adaptive windows and decoder-only-only evaluation** (stated): authors explicitly note "the present evaluation also focuses on decoder-only models and fixed-size contiguous windows, leaving adaptive window boundaries and broader model architectures for future study."
- **Model scale limited to 7-8B** (inferred): all three evaluated models (Llama-3.1-8B, Qwen2.5-7B, Mistral-7B) are in a narrow, relatively small parameter range; no evidence given for how the approach scales to larger models (e.g., 70B+) where cache pressure is most acute.
- **Diagnostic experiments (Section 3, Appendix I) use a very small sample**: "two input articles across all 32 transformer layers, yielding 64 layer-level traces" — this is a small, likely cherry-picked-domain sample for characterizing FMM/churn/LIR; generalization to diverse text types isn't demonstrated (inferred).
- **Q→F promotion ablation (Appendix K) uses mismatched conditions** (stated by authors): "the current pilot conditions use different source articles. The comparison should therefore be interpreted as directional evidence... rather than a paired estimate of its exact causal effect." This is the key ablation validating the core recoverability mechanism, yet it's admittedly not a controlled comparison.
- **No comparison against a hypothetical "quantize everything, never evict" baseline at matched budget for the main benchmark tables beyond KIVI/KVQuant/ZipCache** — these are used, but they're compared at "measured operating points" rather than exactly matched budgets in some cases (e.g., "∼20%", "∼22%"), which loosens the apples-to-apples comparison (inferred).
- **Baselines' recency**: DefensiveKV/Layer-DefensiveKV are cited as "2026" (i.e., contemporaneous/very recent), so baselines aren't stale — this is a point in the paper's favor, not a caveat, but worth noting there's no comparison to non-attention-based or learned-eviction methods outside this specific family (inferred).
- **GSM8K reasoning gains are large but on a benchmark with known contamination/memorization concerns** — the paper cites Mirzadeh et al. 2024 (GSM-Symbolic) in its own reference list, which specifically critiques GSM8K's reliability as a reasoning benchmark, yet doesn't address this tension when reporting GSM8K accuracy gains (inferred).
- **No wall-clock or memory numbers for the ablation studies (window size, quantized fraction, precision)** — Appendix G reports only accuracy on 4 selected tasks at a single 5% budget; broader budget × ablation interaction isn't shown (inferred).
- **Complexity/overhead of the ledger and migration bookkeeping** (position tracking, RoPE re-rotation, persistent quantization metadata) is not evaluated for memory overhead in isolation — Appendix B.4 lists these as included in the budget accounting but doesn't break down how much each component costs, making it hard to assess how much of the "budget" is consumed by bookkeeping versus actual KV data (inferred).
